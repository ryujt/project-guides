# 다이어그램 편집 링크 전달 가이드

Claude Code·Codex에서 **다이어그램 작성·수정을 요청받아 결과 Markdown을 완성했으면**, tools.camp API로 보기·편집 링크를 생성해 콘솔과 최종 답변에 표시한다. `jobflow`(job flow)·`navigation`·`state`·`layout`·Mermaid 등 다이어그램 종류에 공통으로 적용한다. 각 전용 가이드의 문법은 그대로 유지한다.

## 적용 범위

- 요청한 다이어그램과 제목·이해에 필요한 설명을 포함한 완성 Markdown을 보낸다. 가이드·프롬프트 자체를 편집하는 작업, 코드에서 다이어그램 용어를 언급한 작업, 기존 도표를 읽기만 하는 작업은 전송 대상이 아니다.
- 사용자가 파일만 저장하거나 외부 전송을 하지 말라고 요청하면 링크를 생성하지 않고 그 이유를 보고한다. 별도 제한이 없으면 다이어그램 작성 요청의 마무리 단계로 진행한다.
- 원본 파일은 유지한다. 연결된 문서·소스 파일을 재귀적으로 수집해 보내지 않는다. 여러 산출물이면 문서별로 링크를 만들고 파일명·제목과 대응시킨다.

## 실행 순서

1. 해당 문법 기준으로 Markdown을 완성하고 펜스·링크·다이어그램 의미를 확인한다. 검토·수정이 끝난 최종본을 UTF-8 파일로 저장한다.
2. Markdown 원문의 UTF-8 크기가 **64 KiB(65,536바이트) 이하**인지 확인한다. JSON 직렬화 후의 요청 본문 크기와 구분한다. 초과하면 제목·설명·닫힌 코드 펜스를 유지해 문서나 시나리오별로 나눠 보내고 원문을 임의로 자르지 않는다.
3. [링크 생성 도구](tools/create-editor-link.py)에 완성한 파일을 전달한다. 이 가이드가 있는 폴더를 기준으로 스크립트 경로를 찾고, 입력 파일 경로는 작업 위치에 맞게 전달한다. 설치 사본에서도 같은 상대 위치에 도구가 있다.

   ```bash
   python3 tools/create-editor-link.py diagram.md
   ```

   위 예시는 스크립트 경로의 기준을 보여 준다. 실제 실행에서는 두 파일의 위치에 맞는 경로를 각각 사용하고, 공백이 있는 경로는 인자로 안전하게 전달한다. 실행 환경에 Python 3가 없으면 아래 계약에 맞게 사용 가능한 HTTP 도구로 같은 요청을 전송한다.
4. 도구는 실제 성공 응답의 `url`을 콘솔 표준 출력에 한 줄로 표시한다. 최종 답변에는 `[다이어그램 보기·편집](반환된 url)` 형태로 같은 주소를 표시한다. 여러 링크는 제목과 함께 나열한다. `editorUrl`은 응답의 보조 편집 주소이며 기본 전달 링크는 `url`이다.
5. 사용자는 링크를 클릭해 브라우저에서 확인·편집한다. 브라우저 자동 실행은 사용자가 요청했을 때만 수행하고, 열기나 렌더링을 실제 확인한 경우에만 확인했다고 보고한다.

도구를 실행하지 않고 API 호출 예정이나 로컬 파일 경로만 적는 것은 링크 전달 완료가 아니다. 편집 링크가 만들어진 뒤 내용을 다시 고쳤으면 최종본으로 새 링크를 생성한다.

## API 계약

- 요청: `POST https://ogmqkh3edxrhn5as6ohnde2o7a0euirv.lambda-url.ap-northeast-2.on.aws/api/v1/mdedit`
- 헤더: `Content-Type: application/json`
- 인증: 없음
- 본문: 완성 Markdown 문자열을 `markdown` 필드에 넣은 JSON. 개행·따옴표·코드 펜스는 JSON 직렬화로 보존하고 문자열을 직접 이어 붙이지 않는다.

```json
{"markdown":"# 처리 흐름\n\n```mermaid\ngraph LR\n A --> B\n```"}
```

성공은 HTTP `201`이며 다음 필드를 반환한다. 아래 주소는 응답 형태의 예시이며 실제 전달에는 API가 반환한 값을 쓴다.

```json
{
  "url": "https://tools.camp/단축코드",
  "editorUrl": "https://tools.camp/mdedit#script=..."
}
```

## 실패와 검증

- 도구의 요청 제한 시간은 30초다. 파일 읽기·UTF-8·크기 검사 실패, 네트워크 오류·시간 초과, `201` 이외 상태, 잘못된 JSON·유효한 `url` 누락은 실패로 처리한다. 원본은 유지하고 오류와 링크 미생성을 보고한다.
- 자동 재시도·임의 URL 생성으로 성공을 꾸미지 않는다. 원인 수정 후 다시 요청하고 실제 반환된 HTTPS tools.camp 주소만 사용한다.
- API 성공은 링크 생성의 확인이다. 다이어그램 파싱·배치·브라우저 렌더링 성공까지 증명하지 않는다. 정적 검사·API 호출·실제 화면 확인을 구분해 보고한다.
- 이 지침을 수정하거나 설치 도구를 검증할 때는 합성 Markdown과 임시 파일을 사용한다. 저장소의 가이드·사용자 프로젝트 문서 전체를 API 테스트 본문으로 보내지 않는다.
