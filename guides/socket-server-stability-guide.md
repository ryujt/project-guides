# 소켓 서버 안정성·설계 가이드

장수명 연결 서버에서 **한 접속자의 오류·정체가 서비스 전체를 멈추지 않게** 계약을 정하고, 그 계약을 결함 주입과 장시간 운전으로 검증한다. 동시 접속 수·처리량 수치는 안정성의 대용 지표가 아니며, "정상 부하에서 통과"는 적대적·느린·응답 없는 접속을 검증하지 않았다는 뜻일 수 있다. 모듈 경계와 계약 양식은 [모듈 경계 가이드](./module-boundary-guide.md)를 기준으로 한다.

## 입력과 실행 범위

- 입력: 대상 서버와 연결 역할, 전송·와이어 프로토콜과 메시지 상한, 스트림 모델과 페이로드 성질, 전달·복구 보장, 목표 동시 접속·메시지 크기·전송률·지연, 실행 환경과 엣지 구성, 허용된 시험 자원.
- 기본 적용 대상은 TCP·WebSocket 등 장수명 연결을 사용하는 서버다. 프레이밍·제어·종료 규칙은 선택한 프로토콜에 맞게 적용한다. 데이터그램이나 독립 스트림을 제공하는 전송에는 해당 전송의 유실·순서·흐름 제어 계약을 별도로 확인하며 TCP의 전제를 그대로 적용하지 않는다.
- [모듈 경계 가이드](./module-boundary-guide.md)의 최소 맥락으로 수신 루프·연결 상태·전송 큐·종료 경로부터 읽고, 같은 자원을 만지는 직접 호출자와 조립 위치를 검색한다. 와이어 계약·전달 보장·역압·종료·복구 정책을 바꾸면 영향을 받는 클라이언트와 중계 계층의 공개 계약까지 범위를 넓힌다.
- 이미 허용된 구현·검증은 자율 진행한다. 운영 데이터 변경, 커널·엣지 설정 변경, 외부 유료 부하 발생은 기존 권한과 시험 환경을 확인하고 없으면 해당 실행만 보류한다.
- 이 가이드는 장수명 연결 고유의 결정(적용 범위, 연결 수명, 전달 모델, 역압, 생존 판정, 다중 노드, 결함 주입·장시간 검증)만 소유한다. 적용할 정책·한도·기한·시험 길이는 서비스 요구와 측정으로 정하며, 예시를 기본값이나 필수 구조로 복사하지 않는다. 용어는 특정 흐름의 보내는 쪽을 '상류', 받는 쪽을 '수신자', 방향을 특정하지 않는 상대편을 '피어'로 쓴다. 양방향 연결은 흐름마다 역할이 달라질 수 있다.
- 로그 필드·레벨·보존은 [상세 로깅 가이드](./detailed-logging-guide.md), 테스트 계층 선택·실패 분류·자원 충돌 격리는 [통합 검증 프롬프트](../prompts/comprehensive-test-prompt.md), 재시도 계층 단일화와 쓰기 소유권은 [모듈 경계 가이드](./module-boundary-guide.md), 상태 확인·복구·운영 항목은 [PRD 작성 가이드](./prd-writing-guide.md), 세션 상태 기계 표기는 [상태 다이어그램 가이드](./state-diagram-guide.md)가 소유한다. 같은 규칙을 다시 정의하지 않는다.

## 1. 적용 범위 — 스트림 모델과 페이로드 성질부터 고른다

아래 두 축을 먼저 확정한다. 이 선택이 전달 모델(5절)과 역압(6절)을 갈라놓으므로, 모델을 적지 않은 채 다른 절의 규칙을 복사하지 않는다.

| 스트림 모델 | 특징 | 이 가이드에서 특히 볼 절 |
| --- | --- | --- |
| 공유 브로드캐스트 | 한 상류의 같은 바이트를 다수 수신자에게 중계 | 5(전달 모델)·6(역압)·8(상류)·9(다중 노드) |
| 연결별 독립 대화 | 연결마다 내용이 다른 요청·응답·알림 | 3(수명)·4(검증)·6(역압)·11(관측) |
| 단방향 수집 | 다수 송신자로부터 서버가 데이터를 수집 | 3·4·6·7(정원·용량)·8(상류)·12(경로) |

- 여러 노드로 배치한다면 위 모델에 더해 9절의 라우팅·구독·복구 계약을 적용한다. 다중 노드는 별도의 배치 축이며 공유 브로드캐스트에만 해당하지 않는다.
- **대체·폐기 가능**: 최신 상태로 과거를 대체해도 된다는 애플리케이션 계약이 있을 때만 오래된 항목을 버린다. 증분 데이터에 선행 항목 의존성이 있으면 임의로 건너뛰지 말고 유효한 스냅샷이나 재동기화 지점부터 이어 간다.
- **유실을 허용하지 않음**: 어느 시점부터 서버가 전달 책임을 지는지 정하고, 흐름 제어·영속 저장·재전송 중 필요한 수단을 갖춘다. 연결 종료만으로 복구가 보장되지는 않는다. 수용하지 못한 요청은 명시적으로 거절하고, 이미 수용한 데이터의 보관·재생·중복 처리 계약을 둔다(5·9절).

페이로드 성질은 이름이나 형식이 아니라 업무 의미로 결정한다. 같은 상태 데이터라도 변경 이력 보존이 필요하면 폐기할 수 없다. 성질이 다른 흐름을 한 연결에 얹으면 논리 채널별 예산과 처리 정책을 정한다.

## 2. 서비스 지속 불변식 — 실패의 영향 범위를 제한한다

가장 먼저 고정할 불변식은 **예상 가능한 입력 오류·연결 단절·느린 피어가 무관한 연결의 서비스를 중단시키지 않게 한다**는 것이다. 메시지 거절, 논리 채널 종료, 연결 종료 중 프로토콜과 데이터 일관성을 지킬 수 있는 최소 범위를 선택한다. 공유 상류나 저장소의 장애는 해당 의존성을 쓰는 흐름에 영향을 줄 수 있으므로 영향 범위와 대기·거절·재연결 정책을 따로 정한다. 메모리 손상처럼 안전한 계속 실행이 불가능한 내부 결함은 프로세스 격리·중단·복구 대상으로 구분한다. 요청을 계약으로 옮길 때는 "무엇을 확인하면 지켜졌다고 말할 수 있는가"까지 함께 적는다.

| 요청·요구 | 계약으로 옮긴 형태 |
| --- | --- |
| 연결 오류의 영향 격리 | 결함별 격리 범위를 정하고 아래 여섯 결과를 검사하며, 위반이 남아 있으면 미완료로 보고 |
| 다양한 상황·시나리오로 검증 | 계층별 결함 주입 매트릭스(프레이밍·제어·애플리케이션 메시지·전송·자원·교차 격리)를 설계 산출물로 관리 |
| 결함 수정과 재발 방지 | 확인된 결함마다 재현 → 수정·회귀 검증 → 영향을 받는 계약과 통합 경로 재검증 |
| 장시간 접속 중 끊김 여부 | 시험 기간·부하·허용 종료·자원 증가 기준과 복구 기한을 실행 전에 고정(13절) |
| 느리거나 응답 없는 접속 처리 | 선택한 역압 정책과 각 기한의 기준 시각·의미를 코드·문서·테스트에서 일치시킴 |
| 구현 방식·성능 선택 근거 | 전달 모델과 런타임 선택은 측정한 용량 범위와 경로 전제로 판단(7·12절) |

연결 단위로 격리해야 하는 결함 주입 뒤 확인할 여섯 결과: ① 프로세스 생존과 진단 경로 응답, ② 예상하지 않은 런타임 검사 실패·미처리 예외·크래시 없음, ③ 영향 없어야 하는 연결의 정상 진행과 전달 계약 유지, ④ 여유 정원에서는 신규 접속 성공·포화 상태에서는 정책에 따른 거절, ⑤ 문제 메시지·채널·연결만 정해진 사유와 범위로 처리, ⑥ 이후 종료 요청에서도 기한 안에 배출·정리. 프로세스 재시작으로 ①을 대체하지 않는다. 한 연결의 오류로 무관한 전역 상태를 되돌리지 않는다. 공유 의존 장애·프로세스 상실 시험은 별도의 영향·복구 기준을 쓰며, 해당 없는 항목에는 **왜 해당 없는지**를 적는다.

## 3. 연결 수명과 소유권

연결 자원의 해제 시점은 "애플리케이션이 끊기로 결정한 시점"이 아니라 **그 자원을 참조하는 마지막 주체가 사라진 시점**이다. 수동 메모리 관리 런타임에서는 해제 후 사용으로, GC 런타임에서는 누수와 유령 소비자로 같은 위반이 나타난다.

| 참조 주체 | 해제·정리 가능 시점 | 위반 시 증상 |
| --- | --- | --- |
| 진행 중 I/O(제출·대기 중인 송수신, 쓰기 syscall에 머무는 스레드, 아직 호출되지 않은 콜백·해소되지 않은 future) | 해당 완료·복귀가 모두 끝난 뒤 | 재사용된 슬롯에 과거 완료가 도착, 해제된 버퍼를 커널이 읽음 |
| 프레이밍 파서 콜백 | 콜백이 모두 복귀한 뒤 | 파서가 해제·교체된 버퍼에서 다음 헤더를 읽음 |
| 공유 페이로드 참조 | 모든 큐·전송·캐시 참조가 풀린 뒤 | 전송 중 내용 변경, 정지 피어가 메모리를 영구 고정 |
| 연결 부속 자원(세션 맵 항목, 타이머, 구독, 작업 태스크) | 연결 종료 처리의 일부로 반드시 함께 | 누수, 죽은 연결로 보내는 유령 전송, 취소되지 않은 작업 누적 |

콜백 안에서 종료를 결정해도 그 콜백이 참조 중인 자원을 회수하지 않도록 상태 전이와 회수를 분리한다. 수신 루프가 콜백 진입 전에 "진행 중 I/O 없음"으로 표시한다면 그것만으로 해제를 허용하지 않는다. 취소·닫기 요청과 실제 I/O 완료·참조 해제는 구분한다. 정상 배출 기한을 넘기면 런타임이 제공하는 중단 경로를 쓰되, 중단 요청만으로 버퍼 재사용이 안전하다고 가정하지 않는다. 안전한 정리를 제한 시간 안에 끝낼 수 없는 실행 단위는 격리·재시작하는 복구 경로를 정하고 정상 배출 성공으로 보고하지 않는다.

연결 종료 처리는 여러 번 호출되어도 자원·정원·구독을 한 번만 반납해야 한다. 슬롯·세션을 재사용한다면 세대 번호나 재사용되지 않는 식별자로 과거 완료를 구분하고, 종료·취소·완료가 경합하는 경우를 검증한다. 낡은 완료 결과를 현재 세션에 적용하지 않되, 해당 작업이 소유한 버퍼·참조는 정리한다. 내부 불변식 위반이나 메모리 손상을 정상적인 연결 오류로 숨기지 않는다.

읽기 EOF·반닫힘·정상 종료 핸드셰이크·강제 단절을 구분하고, 읽기가 끝난 뒤 남은 응답을 보낼지와 미완성 메시지 처리 방식을 정한다. 기동·인증·활성·배출·종료의 각 상태에서 허용되는 I/O와 기한을 계약으로 남긴다. TCP keepalive는 경로 수준의 생존 보조 신호이며 애플리케이션 처리 진행을 증명하지 않는다. 사용할 경우 환경의 기본값을 확인하고 서비스의 탐지 기한에 맞춰 설정한다.

## 4. 프레이밍·입력 검증과 접근 통제

바이트 스트림에서는 한 번의 읽기와 한 메시지의 경계가 일치하지 않는다. 파서는 분할 입력·여러 메시지가 합쳐진 입력을 처리하고, 전송 측은 부분 쓰기와 재개 위치를 추적한다. 길이를 미리 알 수 있으면 **본문 누적 전에 길이 필드와 산술 오버플로를 검사**하고, 길이를 미리 알 수 없는 형식은 누적 크기·조각 수·완료 기한을 처리 중 제한한다. 파서와 애플리케이션 버퍼의 소유권은 3절에 따라 명시한다.

| 검사 단계 | 검사 항목 | 거절 방법 |
| --- | --- | --- |
| 접속·핸드셰이크 | 초기 입력 상한·완료 기한·인증 전 정원. HTTP 기반 WebSocket이면 헤더·대상 호스트·필요한 Origin 허용목록·서브프로토콜도 검사 | 프로토콜이 허용하는 거절 응답과 종료; 핸드셰이크 미완료 상태의 무제한 누적 금지 |
| 와이어 프레임·종료 | 선택한 프로토콜의 길이·타입·분할·종료 규칙. WebSocket이면 예약 비트·방향별 마스킹·opcode·제어 프레임 크기·종료 코드·문자 인코딩 | 프로토콜 오류·정책 위반·크기 초과를 구분하고, 종료 코드는 해당 프로토콜의 허용 범위 사용 |
| 애플리케이션 메시지 | 메시지 공통 필드·버전·세션·순서, 선언 길이와 실제 길이, 역할별 허용 타입, 대상 자원 접근 권한 | 복구 가능한 메시지 오류는 거절, 경계를 복원할 수 없거나 보안 정책상 연결을 유지할 수 없으면 종료 |
| 구조화 본문(JSON 등) | 바이트 상한 선검사, 파싱 중 깊이·필드 수·복잡도 한계, 이후 스키마·중복 키·문자열 정책 검사 | 한계를 지원하는 파서나 제한된 실행 환경을 선택하고, 파싱 후 검사만으로 파싱 중 자원 소진을 방어했다고 보지 않음 |

필수 제어가 본문 큐에 밀리지 않도록 예약 예산과 처리 우선순위를 두되, 제어 자체에도 수신률·메모리·처리 비용 상한을 둔다. 응답 의무와 폭주 처리 규칙은 선택한 프로토콜에 맞춘다. 압축을 쓰면 압축 전후 크기·복잡도·메모리·CPU 한계를 함께 정하고, 검증 이전의 입력으로 비용이 큰 작업을 수행하지 않는다.

인증 수단은 클라이언트 기능과 신뢰 경계에 맞게 선택한다. 쿠키·헤더·단기 티켓·상호 TLS 등을 일률적으로 강제하지 않으며, 장기 토큰을 URL에 남기지 않는다. 브라우저의 Origin 검사는 인증·자원별 인가를 대체하지 않는다. 인증 이후에도 구독·송신 대상의 권한을 검사하고, **연결 중 권한 변경**(만료·회수·대상 삭제)의 재검사 시점과 처리(강등·종료·재인증)를 정한다. 비신뢰 구간의 전송 보호와 TLS 종단 이후의 신뢰 경계도 명시한다. 피어 입력의 로그 정제는 [상세 로깅 가이드](./detailed-logging-guide.md)를 따른다.

와이어 계약은 [모듈 경계 가이드](./module-boundary-guide.md)의 계약 양식으로 한 곳에 적고 양쪽 구현이 참조한다. 장수명 연결에서는 배포 이후에도 구버전 피어가 남으므로 버전 협상·호환 범위·미지원 메시지 처리와 강제 재연결 필요 여부를 정한다.

## 5. 전달 모델과 공유 메모리

같은 데이터를 여러 수신자에게 보낼 때 아래 모델을 비교한다. 기존 런타임의 큐·버퍼 소유권을 먼저 확인하고, **메시지 크기 × 수신자 수와 보관 시간**이 만드는 비용을 측정해 선택한다. 서로 조합할 수 있으며 독립 대화 서버에 공유 팬아웃 구조를 억지로 추가하지 않는다.

| 모델 | 성립 조건 | 깨지는 지점 |
| --- | --- | --- |
| 수신자별 큐·복사 | 수신자 수 × 메시지 크기 × 대기 항목 수가 예산 안 | 큰 메시지 × 많은 수신자에서 메모리·CPU가 증가 |
| 불변 공유 블록 + 참조 추적 | 여러 수신자가 동일한 직렬화 결과를 안전하게 참조하고, 참조 수명에 상한을 둘 수 있음 | 참조 추적 비용, 정지 피어가 블록을 오래 고정 |
| 단일 링버퍼 + 덮어쓰기 | 수신자가 같은 바이트열을 오프셋만 달리 받고, 밀린 데이터 폐기와 재동기화가 허용됨 | 수신자별 내용 분기, I/O가 참조 중인 영역 덮어쓰기, 항목 경계 없는 이어보내기 |
| 브로커·노드 간 팬아웃 | 수신자가 여러 노드에 흩어져 있음 | 중복 전달, 노드 간 순서, 구독 누수 — 9절 먼저 |

선택과 무관하게 한 바이트 스트림의 쓰기 순서와 부분 쓰기 재개는 한 소유자가 통제한다. 런타임이 순서와 수명을 보장하는 제출 방식을 제공하면 그 계약을 이용하고, 그렇지 않으면 큐에서 직렬화한다. 이미 시작한 단일 와이어 프레임의 바이트 사이에 다른 프레임을 끼워 넣지 않는다. WebSocket 제어 프레임은 분할 메시지의 프레임 사이에 삽입할 수 있으므로, 큰 메시지의 분할 여부와 제어 지연을 함께 검토한다([RFC 6455 §5.4](https://www.rfc-editor.org/rfc/rfc6455.html#section-5.4)).

복구용 캐시는 스트림·버전·기준 순서가 유효할 때만 재사용한다. 건너뛰기를 허용하면 수신자별 커서와 연속성 판정 기준을 둔다. 필터링으로 의도적으로 빠진 항목과 유실을 구분하고, 의존성이 끊긴 수신자만 재동기화한다.

공유 메모리가 임계를 넘으면 즉시 회수 가능한 양과 I/O 완료 뒤 회수될 양을 구분한다. 회수 반복은 진행이 없으면 멈추고, 새 작업의 수용 제한·피어 종료 등 다음 정책으로 넘어간다. 필수 제어·정리 작업에 필요한 여유도 **전역 메모리 한도 안에서** 예약한다. 논리 채널별 예산은 공정성을 돕지만 이미 막힌 공통 전송 경로를 해소하지는 못한다. 전송 지연 격리가 필요하면 별도 연결이나 해당 보장을 제공하는 전송을 검토한다.

**전송 완료와 업무 완료를 구분한다.** `send` 성공은 상대에게 전달되었다는 보장이 아니며([POSIX send](https://pubs.opengroup.org/onlinepubs/9799919799/functions/send.html)), 라이브러리의 완료 통지도 문서화된 범위까지만 의미한다. 필요한 경우 애플리케이션 ACK가 수신·처리·영속 저장 중 무엇을 확인하는지 정한다. ACK 유실과 연결 단절 뒤 결과가 불명일 수 있으므로, 재전송·결과 조회·멱등 처리는 [모듈 경계 가이드](./module-boundary-guide.md)의 실패·재시도 계약을 따르고 재생 범위는 9절에 적는다.

## 6. 느리거나 응답 없는 접속

"느림"과 "무응답"은 다른 문제다. 역압은 ① 전달 계약을 지키며 부하 줄이기, ② 반복 정체에 대한 제한 강화, ③ 더 진행할 수 없을 때 종료·정리로 설계할 수 있다. 모든 서버가 세 단계를 거칠 필요는 없다. 폐기 가능한 페이로드는 오래된 항목을 버리거나 재동기화하고, 유실을 허용하지 않는 페이로드는 흐름 제어·제한된 영속 저장·신규 수용 거절을 사용한다. 저장 공간과 저장 지연에도 상한을 둔다. 종료는 3절의 수명 계약을 따른다.

| 증상 | 판정 신호 | 가능한 대응 |
| --- | --- | --- |
| 미송신 항목이 신선도를 잃음 | 적재 후 경과·메시지 만료 시각 | 폐기 허용 여부와 선행 데이터 의존성에 따라 건너뛰기·재동기화 |
| 큐·처리 예산이 초과됨 | 대기 바이트·항목·작업 수·대기 시간 | 생산 억제·병합·거절·격리; 필수 제어까지 처리할 수 없으면 종료 |
| 제출한 데이터가 빠지지 않음 | 첫 제출 후 경과·최근 진행 시각·미배출 바이트 | 배출·진행 기한 초과 시 중단·정리 |
| 복구가 반복됨 | 정의한 시간 창 안의 복구 횟수·실패율 | 속도·동시성 제한 강화 또는 해당 연결 종료 |
| 무응답·초기화 정지 | 하트비트 응답 부재·핸드셰이크/인증 미완료·미완성 메시지 정지 | 상태별 기한 초과 시 종료·정리 |

배출 지연은 항목이 **전송 계층에 처음 넘어간 시각**부터 재고, 큐 대기는 적재 시각부터 따로 잰다. 신선도·배출·전체 처리 기한은 목적과 기준점이 다르므로 값의 대소 관계를 일률적으로 강제하지 않는다. 각 기한은 메시지 크기·경로 RTT·전송률·런타임 정체·허용 지연으로 정하고, 경과 시간은 단조 시계로 측정한다. 조금씩 바이트를 보내며 정지 타이머만 갱신하는 입력도 전체 완료 기한이나 진행률 정책으로 제한한다.

신선도에 따른 자동 폐기는 허용된 페이로드에만 적용한다. 제어 메시지에는 프로토콜상 응답 기한을 적용하고 재적재로 대기 시간을 초기화하지 않는다. 하트비트는 어떤 응답을 어떤 요청과 대응시킬지 정한다. **임의의 수신 활동은 반대 방향의 읽기나 애플리케이션 처리가 진행된다는 증거가 아니다.** 배출 상태를 관측할 수 없으면 애플리케이션 ACK·시퀀스 회신 등을 진행 신호로 쓰되, 각 신호가 확인하는 범위를 명시한다.

느린 쪽이 DB·외부 호출·디스크일 때도 수신 루프를 막거나 작업을 무한 생성하지 않도록 동시 작업과 대기 큐를 제한한다. 생산 억제가 필수 제어까지 막는 구조라면 데이터와 제어의 처리 경로를 조정한다. 정책 판정용 보조 자료에도 상한·만료·포화 동작을 두고, 그 포화를 피어의 프로토콜 위반으로 오인하지 않는다. 재시도 계층의 일반 규칙은 [모듈 경계 가이드](./module-boundary-guide.md)를 따른다.

## 7. 입장·정원·용량

정원은 역할·용도별로 정하고, 진단과 거절 응답을 위한 여유를 남긴다. 만석과 프로세스 불건강을 구분하고, 생존·준비·신규 수용 가능 신호를 실제 라우팅 정책과 맞춘다. 상태 확인의 일반 의미는 [PRD 작성 가이드](./prd-writing-guide.md)를 따른다.

| 결정 | 근거로 삼을 값 | 확인 방법 |
| --- | --- | --- |
| 정원 | 목표 동시 접속 + 역할별 예약 + 진단·거절 여유 | 초과 접속이 정책대로 거절되고, 만석 중에도 진단 경로가 응답하는지 |
| 연결당 큐·작업 예산 | 최대 메시지·동시 작업·프레이밍·제어 비용, 허용 대기 시간 | 최대 허용 메시지가 선택한 버퍼링·스트리밍 방식으로 처리되고 초과 입력은 제한되는지 |
| 전역 메모리 임계 | 실행 환경의 메모리 한도에서 런타임·연결 고정 비용·파서·압축·TLS·공유 데이터·커널 버퍼의 관련 비용과 회수 지연 여유를 고려 | 같은 비용을 중복 계산하지 않았는지, 임계 발동과 메모리 고갈이 겹치지 않는지 |
| fd·백로그 | 프로세스 한계, 수용 대기열 설정, 엣지 동시성 | 필요한 최소 자원 미달 시 기동 실패 또는 축소 정원을 명시하고, 고갈 중 기존 연결이 유지되는지 |
| 공정성 | 연결·사용자·테넌트·주소별 동시성·신규 접속률·작업량 | 다수 연결이나 고비용 요청으로 한 주체가 전체 예산을 독점하지 못하는지 |

인증 전에는 주소·초기 연결 예산을, 인증 후에는 신뢰할 수 있는 사용자·테넌트 예산을 적용할 수 있다. 공유 주소를 쓰는 정상 사용자와 주소를 바꾸는 공격자를 고려해 IP 제한만으로 공정성을 보장하지 않는다. 한 연결의 읽기·파싱·팬아웃이 실행 루프를 독점하지 않도록 회차별 처리량과 작업 동시성을 제한한다.

용량은 바이트와 **건수** 두 축으로 계산하고 측정으로 확인한다. 아래는 공유 브로드캐스트의 단순 계산식이며, 독립 흐름은 흐름별 비용을 합산한다.

```text
요구 전송 대역[바이트/초] = 수신자 수 × 평균 메시지 크기[바이트] × 초당 메시지 수
요구 CPU 시간[초/초] = 초당 처리·전송 작업 수 × 작업당 CPU 시간[초]
연결 큐 메모리[바이트] = 연결별 대기 바이트 합계 + 항목·큐 관리 비용
공유 메모리[바이트] = 살아 있는 고유 블록 크기 합계 + 참조·메타데이터 비용
증폭 작업량[작업/초] = 접속자별 요청률 × 요청당 유발 작업 수의 합계(병합·제한 적용 후)
```

평균뿐 아니라 최대 메시지·버스트·압축과 암호화·팬아웃 증폭을 반영한다. 처리·배출 가능한 대역과 코어 예산에는 운영 여유를 남긴다. 기본값은 측정한 용량 범위에서 고르고, 설정은 기동 시 단위·범위·정책상 관계를 검증한다. 예를 들어 전체 메시지를 큐에 넣는 구현이라면 허용 최대 메시지가 큐의 본문 예산에 들어가야 한다.

## 8. 상류와 증폭 제어

송신자를 제어할 수 있다면 전송 계층의 흐름 제어에 더해 애플리케이션의 미확인 건수·바이트·기한을 계약으로 정할 수 있다. 제어할 수 없는 송신자에게도 수신·파싱·작업 예산을 적용하고, 초과 시 거절·일시 중단·연결 종료 중 가능한 정책을 선택한다.

- 매 메시지 확인 후 다음 메시지를 보내면 처리량이 확인 왕복 시간의 영향을 받는다. 윈도우나 묶음·주기 확인은 지연·메모리·재전송 예산을 함께 계산해 선택한다. 확인의 의미는 5절을 따른다.
- 메시지 크기·링크 속도·처리 시간을 기한 산정에 반영하고, 재시도가 무한 반복되지 않게 전체 시간과 횟수를 제한한다.
- 애플리케이션 읽기 버퍼는 파싱 방식·메시지 분포·메모리 예산으로 정한다. 확장 실패 시 작은 버퍼로 계속할 수 있는지는 증분 처리 가능 여부로 판단한다. 커널 버퍼 조정은 12절의 환경 검증을 따른다.
- 확인·크레딧 응답도 송신 큐 예산을 소비한다. 요청은 보내면서 응답을 읽지 않는 피어와, 흐름 제어를 무시하는 피어를 시험한다.
- 상류·공유 자원에 거는 조회·재전송·동기화 요청은 병합 창·최소 간격·동시 상한·기한으로 제한하고, 7절의 증폭 작업량을 측정한다. 높은 빈도의 보조 신호는 의미를 보존할 수 있을 때만 샘플링·병합한다.
- 세션 전환은 낡은 결과를 식별할 수 있어야 한다. 현재 세션과의 일치 판정만 필요하면 고유 식별자를 쓸 수 있고, 신구 순서나 소유권 우선순위가 필요하면 세대·리비전 등 비교 가능한 기준과 발급 주체를 둔다. 재시작·노드 이전 뒤에도 기준이 충돌하지 않게 한다.
- 상류 교체 중 수신자에게 보일 상태, 기존 연결 유지 여부, 대기 기한, 데이터 연속성·재동기화 방식을 정한다. 새 상류가 기존 이력을 이어 줄 수 있다고 가정하지 않는다.

## 9. 다중 노드와 재연결

TCP·WebSocket 연결은 수립된 전송 경로와 종단에 묶인다. 로드밸런서나 프록시가 애플리케이션 세션·구독·미처리 메시지까지 자동으로 인계한다고 가정하지 않는다. 한 노드의 상실이 재접속 폭주로 번지지 않게 클라이언트의 지연 분산과 서버의 수용 예산을 함께 둔다. 단일 노드에서도 재연결 후 전달 의미와 재생 지원 여부·범위를 정한다.

| 결정 | 정할 내용 |
| --- | --- |
| 대상→노드 라우팅 | 자원·토픽의 소유 여부와 라우팅, 소유자 이전 중 연결 처리. 단일 소유가 필요하면 네트워크 분할·재시작 중 중복 소유를 막는 기준 |
| 노드 간 전달 | 중복·순서 보장 범위, 브로커 단절 시 버퍼·거절 정책, 구독 생성·해지·만료와 누수 점검 |
| 배포·드레이닝 | 신규 수용 중단 → 필요 시 이전 통지 → 기한 내 배출 → 잔여 작업 처리·종료. 무조건적인 최대 연결 수명은 강제하지 않고 필요성·재연결 비용으로 선택 |
| 재연결 후 의미 | 최대 1회·최소 1회 등 전달 계약, 중복 제거 키·보관 창, 미확인 작업의 결과 조회·재처리 책임 |
| 재생·재동기화 | 커서 의미·보관 기간·재생 상한, 커서 만료 시 오류·스냅샷·전체 재동기화 중 처리, 재생과 실시간 데이터 전환 경계 |
| 버전 혼재·롤백 | 새 서버와 기존 연결, 구버전 클라이언트, 브로커 메시지의 호환 범위와 롤백 가능 조건 |

재연결·구독 복원 시에도 인증·인가를 다시 적용한다. 재생 요청은 현재 권한과 대상 범위에 묶고, 이미 접근권이 사라진 데이터를 커서만으로 노출하지 않는다. 스냅샷과 이후 변경의 기준 순서를 연결해 재생→실시간 전환에서 누락·중복을 처리한다. 클라이언트가 재전송할 수 있는 기간과 서버의 중복 판정·데이터 보관 기간이 어긋나면 안전하게 재처리할 수 없는 요청의 거절·조회 정책을 정한다.

## 10. 클라이언트 측 계약

연결 단절의 원인은 서버 밖에도 있으므로 클라이언트의 상한·기한·복구 책임을 함께 정한다. 서버와 클라이언트가 비교하는 순서·ACK·시간 창의 의미를 맞추되, 역할이 다른 타이머 값을 무조건 같게 만들지 않는다.

| 클라이언트 책임 | 규칙 |
| --- | --- |
| 자기 큐 | 바이트·항목·대기 상한을 두고, 폐기 가능 데이터는 병합·재동기화, 보존 대상은 생산 억제·제한된 저장·명시적 실패로 처리 |
| 수신과 처리 분리 | 무거운 처리로 수신·제어 루프가 막히지 않게 하고 처리 지연을 관측. 작업 수·기한을 제한하고 세션이 바뀐 뒤 낡은 결과를 적용하지 않음 |
| 재시도·실패 창 | 재연결 담당 루프를 하나로 두고 예산·지터·복구 조건을 정의. 인증 실패·프로토콜 불일치와 일시 장애를 구분하고 같은 조건의 무한 재접속을 방지 |
| 중복·순서·ACK | 합의된 전달 의미에 맞춰 중복·순서를 처리하고, 약속한 처리·저장 시점 이전에 ACK하지 않음 |
| 중단·복귀 | 프로세스 중단·백그라운드 동결·네트워크 전환 뒤 기존 연결·커서의 유효성을 확인하고 필요한 재연결·재동기화를 수행 |

사용자에게 보이는 상태와 오류는 실제 연결·처리·복구 상태와 일치시킨다. 단말의 처리 속도와 버퍼 한도도 서비스가 유지할 수 있는 전송률에 반영한다.

## 11. 관측과 진단

정체를 사후에 설명할 수 있는 최소 지표 집합을 **설계 단계에서** 정한다. 아래에서 해당하는 항목을 선택한다. 필드·레벨·보존은 [상세 로깅 가이드](./detailed-logging-guide.md), 메트릭의 라벨 범위와 운영 기준은 [PRD 작성 가이드](./prd-writing-guide.md)가 소유한다.

```text
연결: 정원·활성·역할별 수·수용/거절·종료 사유·재연결률·핸드셰이크/인증 지연
큐와 지연: 대기 바이트·항목·미배출 바이트·최고 대기량·대기/배출/처리 지연·미확인 메시지
정책 발동: 폐기·병합·재동기화·생산 억제·거절·기한 초과·중단·메모리 회수
전달·복구: 수용/ACK·중복·순서 누락·재생량·커서 만료·복구 시간
자원: 공유 참조 수와 바이트·프로세스/컨테이너 메모리·fd·진행 중 작업·구독 수
런타임 포화: 이벤트 루프·스케줄러 지연·GC 일시 정지·태스크·스레드 수
```

구조화 이벤트는 연결 ID·세션 식별자·요청 ID 등으로 연결 수명을 재구성할 수 있게 한다. 이미 닫은 연결에서 예상대로 발생한 취소·후속 오류와 새로운 결함을 분류한다. 종료 과정이라는 이유로 예상 밖 실패까지 무시하지 않는다. 진단 경로는 데이터 경로 정체와 만석 중에도 응답할 자원을 확보하고, 노출 범위·접근 통제를 정한다. 클라이언트와 공유하는 상관 ID가 있다면 비밀값을 포함하지 않게 한다. 로그 수집기의 정체·실패가 데이터 경로를 막지 않는지와 배포·시험 도구가 잔여 프로세스·컨테이너를 남기지 않는지도 확인한다.

## 12. 경로·환경 전제

측정과 운영의 전제를 적지 않으면 같은 코드가 환경에 따라 다른 결론을 만든다.

| 경로 구간 | 확인할 전제 | 확인 방법 |
| --- | --- | --- |
| 소켓·커널·컨테이너 | 버퍼 설정·오토튜닝 여부, 지연 ACK·전송 묶음 설정, fd·백로그·연결 추적·메모리 한계, 필요한 I/O 기능 지원 | 실제 설정 조회, RTT·대역·자원 한계 조건에서 처리량·기한 재측정 |
| TLS | 종단 위치, 핸드셰이크 비용·세션 재개, 연결당 버퍼, 인증서 교체와 기존/신규 연결 | 교체 중 연결 동작과 접속 폭주 시 CPU·메모리 측정 |
| 엣지(프록시·LB) | 유휴·최대 연결 시간, 버퍼링, 신뢰할 프록시와 클라이언트 주소 복원, 프로토콜·상태 검사·드레이닝 | 실제 엣지를 통과하는 장시간 연결·배포·거절 시험 |
| 클라이언트 망 | NAT 유휴 만료, 망 전환, 반열림, 중간 장비의 단절·제한 | 대표 단말·망과 지연·손실 주입으로 복구 확인 |
| 측정 환경 | 서버·생성기의 배치, CPU·메모리·커널·링크 경합, 런타임·라이브러리 버전과 빌드 설정 | 서버·생성기 비용을 구분하고 실제 경로에서 결과 재확인 |

커널 버퍼는 기본 동작을 확인한 뒤 필요할 때 조정한다. 자동 조정 유지나 고정 크기 중 하나를 보편 규칙으로 삼지 않고, 경로의 대역·RTT·메모리 예산과 운영체제의 설정 의미를 확인한다. 하트비트가 유휴 연결을 유지해야 한다면 경로상 최소 유휴 타임아웃과 스케줄러 지연을 고려해 여유를 두고 주기를 정한다. 런타임의 병렬성 모델에 따라 루프·스케줄러·락·CPU 중 무엇이 먼저 포화하는지 측정한다. 루프백이나 같은 호스트 생성기에서 얻은 비율을 실제 망의 보장으로 쓰지 않는다.

## 13. 검증 설계 — 결함 주입·장시간·부하

검증 계층 선택과 실패 분류는 [통합 검증 프롬프트](../prompts/comprehensive-test-prompt.md)를 따른다. 여기서는 소켓 서버에 필요한 검증 종류와 판정을 정한다. 적용한 프로토콜·전달 모델·위험에 맞춰 시나리오를 선택한다.

| 검증 종류 | 시나리오 | 합격 판정 |
| --- | --- | --- |
| 프레이밍·수명 경계 | 헤더·본문 분할/합침, 부분 쓰기, 미완성 입력의 EOF, 종료·취소·완료 경합, 슬롯 재사용 | 메시지 경계·순서·참조 수명 유지, 중복 정리·낡은 완료의 영향 없음 |
| 결함 주입 매트릭스 | 프레이밍·제어·애플리케이션 메시지·전송(리셋·반열림·읽기 정지)·자원 한도·교차 격리 | 연결 격리 대상은 2절의 여섯 결과, 공유 의존·프로세스 장애는 정해진 영향·복구 기준 |
| 적대적 클라이언트 | 흐름 제어 무시, 제어 폭주, 과도한 분할·크기·복잡도, 입력 조금씩 보내기, 권한 없는 구독·전송 | 입력·작업 비용이 제한되고 사유·영향 범위가 계약과 일치 |
| 전달·복구 | ACK 전후 단절, 중복 전송, 재생 중 실시간 합류, 커서 만료, 권한 변경, 노드 상실·버전 혼재 | 합의한 유실·중복·순서·인가 계약 유지, 결과 불명과 재처리 가능 범위 식별 |
| 장시간 운전 | 기준선 + 정체·중단·복귀·합류/이탈 반복을 주입하는 실행 | 아래 수치 기준과 정상 부하 복귀 후 자원·연결 회복 기준 충족 |
| 부하·용량 | 목표 정원·메시지 분포·건수·버스트, RTT·손실·재배열·대역 제한을 넣은 경로 | 지연·거절·역압이 정책대로 발생하고 측정한 포화 지점·여유·미측정 범위를 명시 |

정책 단위 시험에서 모사한 결과와 실제 전송·런타임 경로에서 일으킨 결과를 구분한다. 실제 경로 검증에는 다음과 같은 주입을 사용할 수 있다.

```text
읽기 정지: 피어가 수신만 중단하고 소켓은 열어 둠
리셋·반열림: 운영체제에 맞는 중단 방식 또는 시험 경로의 패킷 차단으로 만들고 실제 발생을 확인
정체: 허용된 시험 프로세스·컨테이너를 일시 정지하거나 처리 지연을 주입
자원 고갈: 시험용 정원·fd·메모리·작업 한도를 낮춰 한계 경로를 통과
공유 의존 장애: 시험 브로커·저장소 단절 또는 노드 상실 후 영향·복구를 관측
```

시험은 허용된 환경에 한정하고 주입·복원·잔여 자원 정리를 확인한다. 장시간 운전의 판정은 실행 전에 수치로 정한다: 워밍업, 최소 길이, 표본 간격, 비교 구간, 지표별 허용 증가폭, 의도하지 않은 종료 허용 기준, 복구 기한. 길이는 연결 수명·재인증·만료·정리 주기 등 확인할 현상을 포함하도록 정하고, 짧게 축소한 시험으로 장시간 검증을 대체했다고 보고하지 않는다. 메모리는 캐시 안정화·GC·부하 변화를 고려해 비교하며, 누수는 반복 후 회수되지 않는 자원과 증가 추세로 판정한다.

**판정의 선행 조건은 의도한 트래픽과 시나리오가 실제로 발생했다는 증거다.** 목표 부하·합류/이탈·결함 주입이 관측되지 않으면 해당 검증은 통과가 아니다. 기준선과 주입 구간을 구분하되, 주입 구간을 제외해 과부하나 누수를 숨기지 않는다. 주입 중 최고 자원 사용량·영향 범위와 주입 후 회복도 각각 평가한다. 정상 피어의 의도하지 않은 종료와 주입한 피어의 정책상 종료를 별도로 집계한다.

판정은 고정 대기 후 성공으로 간주하지 않고, 기한이 있는 이벤트·지표 조건으로 확인한다. 같은 포트·프로세스·공유 자원을 쓰는 시나리오는 격리하거나 순차 실행한다. 지연은 평균과 함께 꼬리 분포·최댓값을 보고, 양 끝 벽시계의 단순 차로 편도 지연을 단정하지 않는다. 생성기가 목표 전송률을 유지하지 못한 구간과 누락된 요청·측정 표본도 따로 집계한다.

검증 오라클은 전달 의미를 반영한다. 폐기를 허용하면 순서·재동기화 유효성을, 보존 대상이면 ACK된 데이터와 재생·중복 처리 결과를 확인한다. 무작위 입력·순서 시험은 재현 가능한 시드와 실패 입력을 남긴다. 사용할 수 있는 런타임 검사(메모리·경합·누수·예외 추적)를 위험에 맞게 적용하며, 검사 모드의 성능 수치를 일반 모드 성능으로 쓰지 않는다. 재현 가능한 결함은 수정 전 실패와 수정 후 성공을 확인하고, 이전 버전·환경을 확보하지 못하면 그 한계를 남긴다. 공유 구현을 고치면 영향을 받는 소비자·통합 경로를 재검증한다. 환경 때문에 건너뛴 시나리오는 통과로 세지 않는다.

각 시나리오는 `주입 · 대상 역할 · 기대 처리/종료 사유 · 영향 없어야 하는 대상 · 관측 지표 · 복구 기준`을 한 행으로 기록한다.

## 14. 검증과 완료

구현 뒤 적용한 항목을 실제 출력과 대조한다. 해당 없는 항목에는 이유를 적는다.

1. 프로토콜·스트림 모델·페이로드 성질·실패 격리 범위가 정해져 있고, 연결 오류와 공유 의존·프로세스 장애의 판정이 구분되어 있다.
2. 선택한 역압·기한·인증·전달·복구 정책이 서로 모순되지 않고, 각 정책을 발동시키는 시나리오와 정상 피어에 대한 대조가 있다.
3. 최대 허용 입력이 처리되고, 초과 입력·정원·큐·작업·메모리 한계에서는 정의한 거절·흐름 제어·정리가 동작한다. 특정 연결·사용자의 부하가 무관한 연결을 고갈시키지 않는다.
4. 정상 종료에서 연결에 속한 진행 중 작업·활성 연결·공유 참조·구독이 정리되고, 완료·취소 경합에서도 중복 반납·해제 후 사용이 없다. 강제 중단과 배출 기한 초과는 정상 배출과 구분해 보고된다.
5. 장시간 운전에서 의도한 트래픽·주입이 관측되고, 종료·예상 밖 오류·자원 증가·주입 후 회복이 13절에서 미리 정한 기준을 만족한다.
6. 대상 경로에서 기한·재시도·전달·용량 가정을 확인하고 바이트·건수 비용과 환경 전제를 기록했다. 회귀 검증·런타임 검사·일반 모드 시험의 실행 범위와 미실행 사유가 구분되어 있다.

결함이 있으면 원인을 고치고 영향 범위를 재검증한다. 조건 변화 없는 재시도를 반복하지 않고, 반복 횟수나 통과 시나리오 수로 완료를 판정하지 않는다. 필수 검증이 환경 때문에 막히면 미완료 항목과 필요한 환경을 적는다.

최종 보고: 선택한 적용 범위와 불변식, 기한·예산·정원 값과 근거, 실행한 검증 종류와 명령, 통과·실패·미실행, 발견한 결함과 회귀, 측정한 용량 범위와 환경 전제, 남은 위험. 문서 정적 검토·모사·실제 경로 시험을 구분하고, 실행하지 않은 시험 결과나 루프백 수치를 실제 망의 보장으로 적지 않는다.
