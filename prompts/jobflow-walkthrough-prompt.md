# Job Flow 상세 설명서 생성 프롬프트

지정된 `jobflow` 다이어그램을 **전체 흐름 → 작은 사건 → 전체 재요약**으로 설명한다. 원본 표기와 흐름은 보존하고 비전문가도 책임·분기·결과를 이해하게 한다.

## 입력과 실행 규칙

- 필수 입력: `jobflow` 펜스가 있는 문서 경로. 특정 도표만 지정하면 그 범위, 별도 지정이 없으면 입력 문서의 모든 jobflow를 다룬다.
- 먼저 도표 위치/제목을 색인하고, 설명에 필요한 주변 문맥과 지정 근거 코드만 읽는다. 저장소 전체를 읽지 않는다. [모듈 경계 가이드](../guides/module-boundary-guide.md)의 맥락 확대 기준을 따른다.
- 이미 허용된 설명서 작성은 자율 진행한다. 원본 문서·코드·기존 사용자 변경은 보존한다. 미확인 동작을 설명으로 보충하지 않는다.
- 표기 의미는 [jobflow 가이드](../guides/job-flow-diagram-guide.md)를 따른다. 헤더의 조율자 관점과 실제 직접 호출을 구분하고 DSL을 다른 형식으로 바꾸지 않는다.

## 산출물

기본은 원본과 같은 폴더의 `jobflow-walkthrough.md`다. 같은 폴더의 여러 원본을 다루면 `{원본명}-jobflow-walkthrough.md`로 구분한다. 사용자 지정/기존 설명서 위치를 우선한다.

기존 파일이 다른 목적의 사용자 문서인지 먼저 확인하고 무관한 내용을 덮어쓰지 않는다. 서두에 원본 링크·도표 제목/순서·기준 버전 또는 관찰 시점을 남긴다.

## 도표별 구성

1. **전체 흐름**: 원본 도표를 그대로 인용하고 한 문장으로 목적과 결과를 설명한다.
2. **등장 객체**: 선언된 이름과 실제 책임을 짧게 설명한다. 헤더와 주변 문맥/계약에서 확인한 실제 조율자만 표시한다. `master:`만으로 조율자 존재를 확정하지 않는다. `scope:`는 관찰 경계이므로 내부에 조율자가 없다고도 추정하지 않는다.
3. **표기 읽는 법**: 실제 등장하며 오해하기 쉬운 표기만 풀어 쓴다.
4. **에피소드**: 원본 흐름을 하나의 작은 사건 단위로 나눠 순서대로 설명한다.
5. **다시 한 장으로**: 에피소드의 핵심 결과를 순서대로 짧게 재요약한다.

설명은 쉬운 말로 쓰되 임의 역할 비유가 실제 책임을 바꾸지 않게 한다. 코드 이름은 보존하고 첫 등장에 책임을 병기한다.

## 에피소드 규칙

- 사건은 진입·검증/분기·요청 전달·결과 반영·후처리 같은 의미 단위다. 줄 수를 맞추려고 하나의 분기를 쪼개지 않는다.
- 전체 인용은 원본과 동일해야 한다. 에피소드에는 해당 원본 줄을 변형 없이 인용한다.
- 모든 원본 흐름 줄이 적어도 한 에피소드에서 설명돼야 한다. 연결을 이해하기 위한 중복은 허용하되 중복임을 알 수 있게 한다.
- 독립 `jobflow` 블록에는 원본의 실제 헤더(`orchestrator:`/`master:`/`scope:` 등)와 `Object:` 선언을 유지한다. 문법을 바꾸거나 지원 여부를 추측해 자동 변환하지 않는다.
- 헤더가 커서 조각마다 복제하는 것이 불필요하면 **전체 도표의 원문 행 참조 + 짧은 인용 + 설명**으로 바꿀 수 있다. 이를 독립 렌더링 가능한 jobflow라고 표시하지 않는다.
- 에피소드 제목은 “입력을 검증한다”, “실패 이유를 돌려준다”처럼 사건을 설명한다. 아래에 무엇이 일어나는지, 조건별 차이, 관찰 가능한 결과를 적는다.

## 의미를 추측하지 않을 것

- 화살표 없는 단독 줄은 가이드와 주변 분기를 확인한다. 모든 단독 액션을 “아무 일도 하지 않음”으로 설명하지 않는다.
- `.result`는 반환 결과 표기다. 연속 `.result`만 보고 값이 변형 없이 전달된다고 단정하지 않는다. 값의 동일성은 명시된 계약/코드로 확인한다.
- `.message.X`는 원본 경계에서 무엇을 누구에게 전달하는지 설명한다. 전송 방식·동기/비동기·전달 보장은 표기만으로 추론하지 않는다.
- 조율자 관점의 `A → B`를 A가 B의 구현을 직접 호출한다는 의미로 바꾸지 않는다.
- 원본의 누락·오류·모호함은 설명서의 “원본 확인 필요”에 남긴다. 원본을 고친 도표를 원문이라고 인용하지 않는다.

## 검증과 완료

- 지정한 도표 목록과 설명서 장이 대응한다.
- 전체 인용은 원본과 동일하고 에피소드가 모든 흐름 줄을 설명한다.
- 도표 이름/헤더·객체·분기·결과 의미가 보존됐다.
- 확인되지 않은 런타임 동작을 단정하지 않았다.
- 원본 링크·근거가 유효하며 원본 파일은 바뀌지 않았다.

문법 대조와 실제 렌더링을 구분하고 렌더러가 없으면 그 한계를 적는다. 원본 오류 때문에 렌더링할 수 없어도 원문 보존과 설명 정확성을 따로 평가한다. [협업 프롬프트](./multi-agent-task-prompt.md)의 유한 검토 기준에 따라 사실 오류를 수정하고 영향 부분을 재검증한다.

최종 보고에는 설명서 위치·대상 도표 수·원문/누락 대조 결과·원본 확인이 필요한 항목을 적는다.
