# 검증 우선 구현 프롬프트

설계서나 요구사항을 구현한다. 설계를 바꿀 수 있는 외부 가정을 먼저 확인하고, 작은 제품 단위를 검증한 뒤 같은 코드를 조립한다. 외부 가정 없이 한 모듈에서 끝나는 작은 수정은 기존 테스트와 변경 보고로 충분하다.

## 입력과 작업 위치

설계/요구사항·대상 범위·성공 기준, 관련 구현·공개 계약·테스트, 실행 환경·허용 권한과 비용을 확인한다. 기존 변경을 보존하고 허용된 구현·실행·수정은 자율 진행한다.

제품·검증 코드와 기록은 사용자 지정·기존 관례를 우선한다. 검증 위치 관례가 없으면 `examples/<재사용 단위나 시나리오 이름>/`, 기록은 가까이의 README를 쓴다. 새 기록의 일시는 `YYYYMMDD-HHMMSS`, 링크는 상대 경로로 작성한다.

책임·계약·영향 조사는 [모듈 경계 가이드](../guides/module-boundary-guide.md), 테스트 선택·진단·자원 보호는 [통합 품질 검증](./comprehensive-test-prompt.md)을 따른다.

## 가정부터 검증

- 외부 동작·시간·권한·비용·동시성·호출 순서 중 틀리면 설계나 요구 충족이 달라지는 가정을 찾는다.
- 질문별 통과 기준·필요 상대/환경·선행 관계를 실행 전에 정한다. 경계를 넘는 가정은 양쪽을 지나는 최소 실행으로 먼저 확인하고, 양쪽 구현이 끝날 때까지 미루지 않는다.
- 기존 공개 진입점을 우선 재사용하고 선행 단위부터 검증한다. 질문·근거·명령/환경·판정·남은 일을 기존 기록에 짧게 남긴다.

실패를 관찰하면 종속 작업을 멈추고 수정·재검증한다. 실행 조건만 부족한 경우, 로컬 실물로 재현할 수 있으면 그 검증을 먼저 통과시키고 재현 수단이 없으면 독립 작업을 먼저 마친다. 남은 가정·영향·진행 범위를 기록해 조건부로 진행할 수 있으나, 완료나 기존 경로 전환 조건을 면제하지 않는다. 사용자가 이미 허용한 진행 범위는 따른다.

## 증거와 제품 코드

- **대역**: 제품 규칙을 확인한다. 대역이 만든 외부 동작의 판정값은 외부 가정의 증거가 아니다.
- **로컬 실물**: 실제 프로세스·컨테이너·공식 에뮬레이터 등으로 해당 환경의 연결·프로토콜·순서를 확인한다. 재현 수단이 있으면 실행한다.
- **실제 환경**: 지정 서비스·인프라에서 확인하고 시간·비용·용량은 관찰 환경과 범위를 함께 적는다.

가정은 그 가정이 말하는 대상에서 관찰한다. 필요한 증거 수준을 낮추거나 가정이 틀려도 통과하는 시험으로 대체하지 않는다.

제품 구현은 한 곳에 두고 검증·조립 코드가 같은 공개 진입점을 호출하게 한다. 탐색 코드·복사본·대역 성공을 제품 경로 통과로 보지 않는다. 구현·adapter·연결을 바꾸면 제품 경로로 다시 검증한다.

실행 근거와 건너뛴 범위를 남기고 **통과·부분 검증·실패·미실행**을 구분한다. 빌드·타입 검사나 0건 실행을 동작 통과로 보고하지 않는다. 필요한 제품 검증과 공개 계약·사용법이 갖춰져야 재사용 단위를 확정한다.

## 조립과 완료

1. 검증한 제품 코드를 그대로 연결한다. 계약 불일치는 소유 모듈에서 고치고 관련 단위·소비자·연결을 재검증한다.
2. 실제 조립 위치를 거쳐 제품 진입점부터 최종 결과까지 정상·중요 실패/복구 흐름을 실행한다. 단위 통과가 전 구간 통과를 대신하지 않는다.
3. 기존 경로 교체·기본 진입점 전환은 새 경로가 대역·시험용 구현으로 대신한 연결 없이 전 구간 검증을 통과한 뒤에 한다. 이미 전환된 상태를 이어받으면 임의로 되돌리지 말고 그 상태부터 검증하며 이행·롤백 순서를 지킨다.
4. 최종 변경 상태의 필요한 검증·프로젝트 필수 검사를 수행하고, 결함 수정 후 영향받는 범위를 재검증한다. 새 변경·실패·미해결 위험이 없으면 전체 검증을 반복하지 않는다.

관찰이 설계와 다르면 의존 작업을 멈추고 증거·영향·대안을 남긴다. 오류 무시·성공 기준 완화로 우회하지 않는다. 허용 범위의 수정은 진행하며 미정인 요구·계약은 필요한 입력을 확인하고 설계·검증 기준을 갱신한다.

분업과 독립 검토는 [협업 프롬프트](./multi-agent-task-prompt.md)를 따른다. 요구 구현과 필요한 검증이 모두 끝나야 완료다. 실패·미구현·미검증 가정/제품 경로·확정 미완 단위가 남으면 명시한다. 최종 보고에는 변경·실행 결과와 증거 수준·설계 차이·남은 일을 간결히 적는다.
