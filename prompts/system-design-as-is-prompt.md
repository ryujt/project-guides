# AS-IS 설계 분석 문서 생성 프롬프트

## 분석 범위와 조사 순서

사용자가 지정한 시스템·기능 범위의 현재 구현을 분석한다. 범위를 따로 줄이지 않은 시스템 분석은 대상 UI 전체가 기준이다. 대표 기능·페이지를 고른 뒤 나머지를 임의로 범위 밖으로 돌리지 않는다. 파일을 적게 만드는 규칙은 내용을 요약하거나 조사 대상을 줄이는 규칙이 아니다.

1. 기준 커밋·작업 트리 변경·관찰 환경과 사용자 지정 범위를 확인한다. 확인한 코드·화면 관찰과 추론·미확인을 구분하고, 원본 코드와 사용자 변경을 보존한다.
2. UI가 있으면 라우트 등록·중첩/하위 라우트·메뉴·화면의 링크와 작업 버튼·접근 가드·조건부 진입점을 대조해 전체 페이지와 장면을 찾는다. 목록과 상세뿐 아니라 생성·편집·설정·작업 화면 및 직접 URL로만 여는 페이지도 조사한다. 메뉴 목록이나 대표 경로만으로 전수 조사를 끝내지 않는다.
3. 각 페이지의 사용자 과업과 실제 진입·종료·실패/대체 경로를 찾아 시나리오 목록을 만든다. 화면 이동을 좌우하는 이벤트 handler·폼 처리·API client·가드·복귀 처리까지 따라가 조건과 도착 결과의 근거를 확인한다. import나 API 목록만으로 이동을 추정하지 않는다.
4. [페이지·장면 목록](../guides/system-design-output-guide.md#페이지장면-목록)과 [시나리오별 상세 분석](../guides/navigation-diagram-guide.md#시나리오별-상세-분석)을 기준으로 Navigation·Layout·HTML을 작성한다. 새 페이지·과업·분기가 발견되면 목록과 관련 산출물을 함께 갱신한다.
5. 접근할 수 없는 페이지·조건·장면은 근거와 부족한 자료를 미확인으로 남긴다. 조사 비용·분량을 이유로 제외하거나 미확인 목록만 채운 결과를 전체 분석 완료로 보고하지 않는다. 제외는 사용자 지정 범위 또는 실제 시스템 경계에 근거하고, 제외 대상과 이유를 기록한다.

## 파일 저장 위치

[공통 산출물 배치 가이드](../guides/system-design-output-guide.md#저장-위치와-고정-구조)의 고정 구조를 적용해 `docs/design/{DATE}/as-is/`에 작성한다. 날짜·폴더 재사용·상대 링크·파일 분리 규칙은 이 가이드를 따른다. 아래에서는 각 문서의 내용을 정의한다.

## system-design-as-is.md

`system-design-as-is.md`에는 다음 내용을 담는다.

- 개요: 분석 범위·기준선·근거와 제외/미확인 범위
- 시스템 구조
  - Mermaid로 작성한 시스템 구성도와 간단한 설명
- 핵심 용어 목록
- 기능 목록

기능 목록은 실제 진입점과 연결하고, UI 기능에서는 `navigation.md`의 시나리오 절로 이동할 수 있게 한다. 전체 페이지·장면 목록은 `screen-layout.md`, 시나리오 색인과 상세는 `navigation.md`를 원본으로 두고 링크한다. 기준선·검증·미확인 기록은 이 분석서에 모으며, 별도 조사 문서를 늘리지 않는다.

## job-flow 폴더

[Method-R](../guides/method-R.md)의 설계 깊이에 따라 `as-is/details/job-flow/`에 작성한다. 표기는 [Job Flow 가이드](../guides/job-flow-diagram-guide.md)를 따른다.

각 파일 안에서 시나리오별로 제목을 나누고, 한 다이어그램에 모든 흐름을 담지 않는다. 예를 들어 회원가입·로그인 시나리오, 장바구니 시나리오처럼 구분한다. 각 다이어그램 바로 아래에는 주요 흐름을 짧은 문장 목록으로 설명한다.

| 파일 | 작성 내용 |
|---|---|
| `macro.md` | [매크로 설계 기준](../guides/method-R.md#3-매크로-설계-시스템을-하나의-경계로-보기)에 따라 대상 시스템과 외부 객체의 시나리오를 작성한다. |
| `system.md` | 분석 대상 시스템을 구성하는 독립 서비스 간의 협력을 시나리오별로 표현한다. 서비스가 하나뿐이면 생략한다. |
| `<service-name>.md` | 서비스마다 파일을 생성하고, 해당 서비스의 내부 흐름을 시나리오별로 표현한다. 파일명에는 실제 서비스의 영문 이름을 사용한다. |

파일 분리는 서비스 단위까지만 한다. 각 서비스의 내부는 모듈과 상세 수준으로 재귀적으로 확대하되, 시나리오·확대 대상별로 하위 제목을 나누어 해당 서비스 파일에 모두 담는다. 시나리오·모듈·상세별로 Job Flow 파일을 추가하지 않는다.

## navigation.md

사용자의 화면 이동 흐름을 `as-is/navigation.md` 한 파일에 작성한다. 표기는 [Navigation 가이드](../guides/navigation-diagram-guide.md)의 `navigation` 문법을 따른다.

- 처음에 전체 시나리오 색인을 두고 `시나리오 | 사용자 과업·진입 조건 | 관련 페이지 | 상세 절 | 확인 상태·근거`를 연결한다. 기능·페이지 목록의 과업을 빠짐없이 대조하고, 대표 시나리오 몇 개로 대신하지 않는다.
- [시나리오별 상세 분석](../guides/navigation-diagram-guide.md#시나리오별-상세-분석)의 내용과 분할 기준을 적용한다. 한 파일 안에서도 과업별 제목·다이어그램을 유지하며, 정상 흐름과 적용되는 실패·권한·취소·복귀 분기를 실제 근거까지 분석한다.
- 작성 전에 [Navigation 작성 샘플](../examples/diagram/navigation/document-template.md)을 확인하고 [고정 구성·화면 확인 링크 기준](../guides/navigation-diagram-guide.md#문서-구성과-화면-확인-링크)을 적용한다. 각 시나리오의 `화면 확인 링크` 표를 항상 표시하며, 공통 페이지 표나 다른 시나리오로 대신하지 않는다.
- 각 다이어그램 아래에는 주요 흐름을 짧은 문장 목록으로 설명하고, 분기 조건·결과·근거·미확인은 해당 시나리오 안에서 찾을 수 있게 한다. Job Flow의 짧은 출력 규칙을 Navigation의 상세 설명을 생략하는 근거로 쓰지 않는다.
- 각 시나리오의 `화면 확인 링크` 표에서 등장 페이지의 기본 화면과 해당 과업에 사용하는 장면을 `screen-layout.md`의 해당 절 및 `details/screens/<screen-id>.html`의 해당 장면으로 직접 연결한다. 화면 이름·식별자·HTML 대응은 [공통 기준](../guides/system-design-output-guide.md#페이지장면-목록)을 따른다.

UI가 없으면 해당 없음과 이유를 기록한다. UI가 있지만 다른 화면으로 이동하지 않는 과업은 현재 페이지·동작·결과 장면을 설명하고 Layout·HTML로 연결한다. 이동이 없다는 이유로 페이지나 과업을 누락하거나 가상의 이동을 그리지 않는다.

## screen-layout.md

분석 범위의 모든 화면 배치를 `as-is/screen-layout.md` 한 파일에 작성한다. 처음에 [전체 페이지·장면 목록](../guides/system-design-output-guide.md#페이지장면-목록)을 두고, 표기는 [스크린 레이아웃 가이드](../guides/screen-layout-guide.md)의 `layout` 문법을 따른다.

- 페이지별로 하위 제목을 나누고, 각 화면의 영역 배치와 포함 관계를 그린다. 같은 페이지의 장면별 차이는 해당 절에 모으며, 공통 셸만 재사용하고 다른 페이지의 본문을 하나로 뭉개지 않는다.
- 각 다이어그램 아래에는 영역별 역할·입출력·상호작용을 설명한다. 적용되는 로딩·빈값·오류·권한 상태와 반응형 배치 차이도 함께 적는다.
- 같은 화면의 배치 설명은 이 파일의 해당 절을 원본으로 두고, 다른 문서에서는 링크로 참조한다.

UI가 없으면 화면 0개라는 사실과 이유를 기록하고, 가상의 화면을 만들지 않는다.

## details/screens 폴더

[화면별 HTML 규칙](../guides/system-design-output-guide.md#화면별-html)에 따라 현재 화면의 실제 모양을 재현하는 바닐라 HTML을 `as-is/details/screens/`에 생성한다. 전체 화면과 Navigation 등장 화면의 누락·링크·화면 확인은 [공통 검증 기준](../guides/system-design-output-guide.md#검증)으로 확인한다.

## 검증과 완료

[시나리오 검토 기준](../guides/navigation-diagram-guide.md#검토와-확인)과 [산출물 검증](../guides/system-design-output-guide.md#검증)을 적용한다. 작성자 외 검토자는 원본의 라우트·작업 진입점에서 누락된 과업과 분기를 찾고, 성공 경로뿐 아니라 실패·취소·권한·직접 진입의 반례를 대조한다. 필수 누락·사실 오류·깨진 대응을 수정한 뒤 영향받는 경로를 재검토한다. 파일 존재나 정적 검사 통과만으로 상세 분석 완료를 판정하지 않는다.

분석서와 최종 보고에는 전체 대상·작성·제외·미확인 페이지/시나리오와 미재현 장면, 실제 수행한 정적 검사·브라우저 확인·다이어그램 렌더링을 구분해 기록한다. UI 전체를 분석하지 못했으면 남은 범위와 필요한 근거를 밝히고 부분 분석으로 보고한다.

Markdown 문서·다이어그램의 tools.camp 링크 생성 여부 확인과 전달은 [편집 링크 전달 기준](../guides/diagram-editor-link-guide.md)을 따른다.
