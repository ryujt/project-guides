# AS-IS 설계 분석 문서 생성 프롬프트

## 파일 저장 위치

문서 생성 일시를 `YYYYMMDD-HHMMSS` 형식으로 기록해 폴더를 생성한다. 예: `./docs/design/20261014-183025/as-is/`.

문서는 다음 구조로 나누어 저장한다.

```text
as-is/
├── job-flow/
├── system-design-as-is.md
├── navigation.md
└── screen-layout.md
```

## system-design-as-is.md

`system-design-as-is.md`에는 다음 내용을 담는다.

- 개요
- 시스템 구조
  - Mermaid로 작성한 시스템 구성도와 간단한 설명
- 핵심 용어 목록
- 기능 목록

## job-flow 폴더

[Method-R](../guides/method-R.md)의 설계 깊이에 따라 `details/job-flow/`에 작성한다. Job Flow 파일의 배치는 이 절을 우선하며, 표기는 [Job Flow 가이드](../guides/job-flow-diagram-guide.md)를 따른다.

각 파일 안에서 시나리오별로 제목을 나누고, 한 다이어그램에 모든 흐름을 담지 않는다. 예를 들어 회원가입·로그인 시나리오, 장바구니 시나리오처럼 구분한다. 각 다이어그램 바로 아래에는 주요 흐름을 짧은 문장 목록으로 설명한다.

| 파일 | 작성 내용 |
|---|---|
| `macro.md` | 분석 대상 시스템을 하나의 객체로 보고, 사용자·외부 시스템·외부 조직과의 관계를 시나리오별로 표현한다. |
| `system.md` | 분석 대상 시스템을 구성하는 독립 서비스 간의 협력을 시나리오별로 표현한다. 서비스가 하나뿐이면 생략한다. |
| `<service-name>.md` | 서비스마다 파일을 생성하고, 해당 서비스의 내부 흐름을 시나리오별로 표현한다. 파일명에는 실제 서비스의 영문 이름을 사용한다. |

파일 분리는 서비스 단위까지만 한다. 각 서비스의 내부는 모듈과 상세 수준으로 재귀적으로 확대하되, 시나리오·확대 대상별로 하위 제목을 나누어 해당 서비스 파일에 모두 담는다. 시나리오·모듈·상세별로 Job Flow 파일을 추가하지 않는다.

## navigation.md

사용자의 화면 이동 흐름을 `as-is/navigation.md` 한 파일에 작성한다. 표기는 [Navigation 가이드](../guides/navigation-diagram-guide.md)의 `navigation` 문법을 따른다.

- 시나리오별로 하위 제목을 나누고, 진입 조건·화면 이동·분기·관련 API와 처리·최종 결과를 표현한다.
- 각 다이어그램 아래에는 주요 흐름을 짧은 문장 목록으로 설명한다.
- 화면 배치는 `screen-layout.md`의 해당 화면 절로 연결한다. 두 문서에서 같은 화면 이름을 사용한다.

UI나 화면 이동이 없으면 해당 없음과 이유를 기록한다.

## screen-layout.md

분석 범위의 모든 화면 배치를 `as-is/screen-layout.md` 한 파일에 작성한다. 표기는 [스크린 레이아웃 가이드](../guides/screen-layout-guide.md)의 `layout` 문법을 따른다.

- 화면별로 하위 제목을 나누고, 각 화면의 영역 배치와 포함 관계를 그린다.
- 각 다이어그램 아래에는 영역별 역할·입출력·상호작용을 설명한다. 적용되는 로딩·빈값·오류·권한 상태와 반응형 배치 차이도 함께 적는다.
- 같은 화면의 배치 설명은 이 파일의 해당 절을 원본으로 두고, 다른 문서에서는 링크로 참조한다.

UI가 없으면 화면 0개라는 사실과 이유를 기록하고, 가상의 화면을 만들지 않는다.

다이어그램을 작성·수정한 경우 Markdown을 완성한 뒤 [편집 링크 전달 기준](../guides/diagram-editor-link-guide.md)을 적용한다.
