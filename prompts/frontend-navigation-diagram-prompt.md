# 프론트엔드 네비게이션 다이어그램 작성 프롬프트

## 목적

프로젝트의 **화면(페이지) 이동 흐름**을 문서화한다.
네비게이션 다이어그램은 "사용자가 어느 화면에서 어느 화면으로 이동하는가"에 집중한다.
프로세스·상태 전환·컴포넌트 내부 동작 등 자세한 내용은 이 문서의 대상이 아니며 별도 다이어그램에서 다룬다.

## 범위 (react.js 기준)

* **분석 대상은 `pages/` 폴더와 라우터 정의뿐이다.** (`App.tsx`, `router.tsx` 등 라우트가 선언된 곳)
* **다이어그램의 노드는 "라우터(주소)를 가진 페이지"만 사용한다.**
  즉 라우트 경로(`/`, `/login`, `/classrooms/:roomId/start` 등)에 바인딩된 페이지 컴포넌트만 화면 노드로 표기한다.
* **라우트가 없는 내부 컴포넌트는 노드로도, 설명으로도 등장시키지 않는다.**
  예: 게이트/다이얼로그/패널/카드/스텝 컴포넌트(`RoomAccessGate`, `PaidHostAccessGate`, `EndDialog`, `WaitingHostCard`, `*Step`, `*Dialog`, `*Panel` 등)와 `features/`·`components/` 하위의 요소는 모두 제외한다.
* **URL이 바뀌지 않는 페이지 내부 전환은 표기하지 않는다.**
  `PageA(StepB)` 처럼 같은 주소에서 컴포넌트만 바뀌는 전환, 탭 전환, 해시 스크롤 등은 네비게이션이 아니다.

## 지시사항

`/Users/ryu/projects/project-guides/guides/navigation-diagram-guide.md` 의 표기법을 따르되,
**위 "범위" 규칙이 가이드와 충돌하면 범위 규칙을 우선한다.**
라우트를 가진 페이지 사이의 이동을 중심으로, 사용자가 이용할 수 있는 화면 이동 시나리오를 설명한다.

### 세부 요구사항

1. **라우트 맵을 먼저 파악한다.**
   * 라우터 정의에서 `경로 ↔ 페이지 컴포넌트 ↔ 접근 조건`을 추출한다.
   * 이 맵에 등장하는 페이지 컴포넌트만 이후 다이어그램의 노드 후보가 된다.

2. **전체 네비게이션 다이어그램을 먼저 제시한다.**
   * 라우트를 가진 페이지 사이의 이동만으로 전체 화면 이동 흐름을 하나의 ```` ```navigation ```` 다이어그램으로 요약해 문서 맨 앞에 둔다.
   * 노드는 페이지, 엣지는 화면 이동이다. 이동을 일으키는 조건·트리거는 짧은 엣지 레이블로만 적는다.
   * 세부 분기·예외·내부 처리는 넣지 않는다.
   * 전체 다이어그램 바로 아래에 핵심 흐름을 짧은 문장 불릿으로 설명한다.

3. **전체 다이어그램 이후, 시나리오 단위의 상세 설명을 이어서 작성한다.**
   * 각 시나리오는 사용자의 목적(예: 회원가입, 강의실 개설, 참여, 강의 시작 등)을 기준으로 나눈다.
   * 상세 다이어그램에서도 **노드는 라우트를 가진 페이지로 한정한다.**
   * 화면 이동을 이해하는 데 꼭 필요한 조건(로그인 여부, `next` 복귀, 방 유형 등)은 엣지 레이블로 표현한다.
   * 각 코드 블록은 ```` ```navigation ```` 언어 태그로 감싼다.

4. **화면 이동에 영향을 주는 분기만 포함한다.**
   * "어느 화면으로 가느냐"를 가르는 분기(예: 로그인 상태에 따라 목록 vs 로그인 화면)는 엣지 레이블로 구분해 표기한다.
   * 화면이 바뀌지 않는 검증 실패·에러·내부 재시도는 다이어그램에 노드로 넣지 말고, 필요하면 산문 설명으로만 언급한다.

5. **각 시나리오마다 상세 설명을 덧붙인다.**
   * 시나리오 제목, 트리거 조건(어느 페이지·액션에서 시작하는지), 이동하는 페이지, 화면 이동을 가르는 조건을 명시한다.
   * 근거로 삼은 라우터·페이지 파일 경로를 함께 밝힌다.

### 표기 규칙 요약 (가이드 참조 + 범위 규칙 우선)

* 화면 노드: 라우트를 가진 페이지 이름만 사용 — `HomePage`, `LoginPage`, `ClassroomListPage` 등
* 화면 이동: `PageA --> PageB : 조건 또는 트리거`
* 라우트가 없는 내부 컴포넌트·프로세스 노드(`(process)`, `(gate)`, `*Dialog` 등)는 사용하지 않는다.
* API 호출·내부 로직·상태 전환은 이 다이어그램에서 표기하지 않는다. (별도 다이어그램의 대상)

## 산출물

* **라우트 맵 → 전체 네비게이션 → 시나리오 상세** 순서를 따르는 마크다운 문서 하나.
  1. **라우트 맵** — `경로 / 페이지 컴포넌트 / 접근 조건` 표.
  2. **전체 네비게이션** — 라우트를 가진 페이지 사이의 이동을 요약한 ```` ```navigation ```` 다이어그램 1개 + 짧은 불릿 설명.
  3. **시나리오별 상세** — 각 시나리오마다 제목 + 상세 설명(트리거, 이동 페이지, 화면 이동 분기 조건, 근거 파일) + ```` ```navigation ```` 다이어그램.
