# 프론트엔드 사용자·회원 시스템 설계 생성 프롬프트

회원 영역의 화면 흐름과 인증·API·데이터 계약을 설계한다. **UI는 상호작용, 인증 서비스는 신원·세션, 회원 모듈은 프로필·서비스 계정 상태를 소유**한다. 코드 변경은 포함하지 않으며 부분 변경은 [기능 설계 프롬프트](./feature-design-prompt.md)를 따른다.

## 파일 저장 위치

사용자 지정·기존 위치를 우선한다. 위치가 없으면 `docs/design/{DATE}/frontend-user/frontend-user-design.md`에 작성한다. `{DATE}`는 생성 일시의 `YYYYMMDD-HHMMSS` 형식이다. 한 문서로 충분하면 상세 파일을 만들지 않고 문서 간 링크는 상대 경로로 쓴다.

## 작성 내용

- 요구·범위·적용할 회원 기능과 성공 기준
- 구조·소유권·공개 API와 인증·세션·데이터 계약
- 전체 화면 흐름과 필요한 상태·배치 설명
- 주요 결정의 이유·위험, 검증 방법·미확정 사항

가입·로그인·세션 복원·로그아웃·정보 변경·탈퇴·접근 제어 중 실제 필요한 흐름만 고른다. 채택하지 않은 인증 방식이나 기능의 화면을 강제하지 않는다.

## 작성 기준

- [모듈 경계·최소 맥락 기준](../guides/module-boundary-guide.md)에 따라 실제 라우트·공개 API·상태 소유자부터 확인하고, 확인된 사실·설계 선택·미확정을 구분한다.
- route guard는 표시·이동을 제어하며 실제 요청의 인증·권한·계정 상태는 서버가 확인한다. 기존 인증 서비스에 위임한 책임을 중복 구현하지 않는다.
- 인증 방식·보안 설정은 공식 자료와 대상 공급자 계약으로 확인한다. 개인정보 보유·삭제 등 정책이 부족하면 선택지와 잠정안으로 남기고, 민감 정보 처리·오류·복구의 세부사항은 해당 모듈 계약에 둔다.
- 세션 복원 중·익명·만료·거부를 구분하고 복구 행동과 보호 콘텐츠의 노출 조건을 정한다. 로그아웃·잠금·탈퇴의 접근 차단, 서버·IdP 세션 폐기, 삭제 작업의 완료 시점을 구분한다.
- 실제 접근 패턴에 필요한 데이터·고유성·동시성·만료·쓰기 소유권을 정한다. IdP와 앱 저장소 변경을 하나의 트랜잭션으로 가정하지 말고 부분 실패·재처리 책임을 명시한다.
- 탈퇴의 확인·차단·유예·불가역 삭제와 완료 조건은 확정된 정책을 따른다. 일부만 삭제된 상태를 전체 완료로 표시하지 않으며, 삭제·보존·복원 가능성을 추측으로 확정하지 않는다.

## 다이어그램과 검증

[Navigation](../guides/navigation-diagram-guide.md)·[State](../guides/state-diagram-guide.md)·[Layout](../guides/screen-layout-guide.md)은 전용 DSL을 따른다. 화면 이동과 내부 상태·협력을 구분하고 각 그림 아래 주요 흐름을 짧게 설명한다.

다이어그램을 작성·수정한 경우 Markdown을 완성한 뒤 [편집 링크 전달 기준](../guides/diagram-editor-link-guide.md)을 적용한다.

적용한 흐름의 성공·주요 실패·만료·복구가 화면과 계약에서 일치하는지, 권위·쓰기·외부 부분 실패의 책임이 명확한지 검토한다. 문법·링크 확인과 실제 렌더링·보안 검증을 구분하고 수행한 것만 기록한다. 핵심 보안·삭제 정책이 미확정이면 구현 준비 미완료로 남긴다. 문서 위치·범위·검증 결과와 한계·남은 결정을 보고한다.
