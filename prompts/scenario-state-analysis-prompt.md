# 시나리오 기반 상태 전이 분석서 생성 프롬프트

사용자가 지정한 업무·시스템의 **시나리오 기반 상태 전이 분석서**를 작성한다. 이 문서는 사용자가 겪을 상황을 미리 검토해 설계를 고치고, 같은 상황을 E2E 테스트로 재현하는 기초 자료다. 현재 동작을 묻는 요청은 AS-IS, 목표 동작을 설계하는 요청은 TO-BE 관점으로 작성한다. 업무 사례를 모델링하는 요청은 주어진 상황과 가정을 기준으로 삼는다.

[공통 작성 가이드](../guides/scenario-state-analysis-guide.md)에 따라 다음 순서로 작성한다.

1. [참여자별 시도와 독립 사건](../guides/scenario-state-analysis-guide.md#참여자별-시도와-독립-사건) 기준으로 범위 안의 참여자·시도·사건·시작 상태를 대조한다. 일반 이용자와 운영자, 외부 연동 주체가 각각 먼저 일으킬 수 있는 행동에서 결과 확인과 후속 행동까지 따라간다. 사용자가 보는 결과나 할 수 있는 일이 달라지는 상황을 가능한 한 빠짐없이 찾는다. 업무 상태가 그대로인 거절, 응답을 놓친 뒤 다시 확인하는 경우도 포함한다.
2. 시나리오마다 어떤 조건을 준비하고 누가 어떤 순서로 행동하면 어디서 무엇을 확인할 수 있는지 쓴다. 각 사례에 식별자를 부여하고 해당 상태도의 분기, 상태 소유자와 연쇄 변화의 근거를 연결한다. 상태도를 그릴 때는 [예제 폴더](../examples/)에서 비슷한 전이 조건의 절을 참고하고, 해당 예제가 없으면 대상의 상태 정의를 사용한다.
3. 사용자가 막히거나 결과를 잘못 이해할 수 있는 지점을 찾는다. 관련 시나리오에 확인한 동작, 수정 제안 또는 결정할 질문, 변경 뒤 다시 확인할 결과를 연결한다. 기대 결과를 결정할 근거가 부족하면 미확인·미결정으로 남긴다. 기존 설계서·상태 정의는 필요한 절을 상대 링크로 참조한다.

각 그림에 [상태도 하단 설명](../guides/state-diagram-guide.md#상태도-하단-설명)을 붙이고, 사례의 준비·판정 가능 여부에 따라 [테스트 케이스와 설계 검토 항목](../guides/scenario-state-analysis-guide.md#테스트-케이스와-설계-검토-항목)의 소제목을 적용한다.

시스템 검증이 목적이면 [시스템 검증용 사례의 깊이](../guides/scenario-state-analysis-guide.md#시스템-검증용-사례의-깊이)를 적용한다. 업무별 검증과 복합 사건의 연쇄를 함께 다뤄 분권이 필요한 경우 `scenario-state-analysis.md`는 공통 전제와 사례 색인을 담고 상세 문서를 상대 경로로 연결한다. 작은 범위는 한 문서에서 같은 구성을 사용한다. 사용자가 지정한 위치에 저장한다. 같은 범위·관점의 분석서를 갱신할 때는 기존 파일과 시나리오 식별자를 재사용한다. 새로 작성하고 지정 위치가 없으면 `docs/design/{DATE}/scenario-state-analysis.md`에 저장한다. `{DATE}`는 생성 일시의 `YYYYMMDD-HHMMSS` 형식이다. 결과에 파일 위치, 다룬 범위와 남은 상황, 설계에서 우선 결정할 사항을 요약한다.

Markdown 문서·다이어그램의 tools.camp 링크 생성 여부 확인과 전달은 [편집 링크 전달 기준](../guides/diagram-editor-link-guide.md)을 따른다.
