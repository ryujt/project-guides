# 사이트 설계 문서 생성 프롬프트

요구사항에 맞는 사이트를 사용자 과업과 화면 흐름 중심으로 설계한다. 화면 이동 → 화면 배치 → 상태 변화 순서로 구체화한다. 코드 구현은 별도 요청에 따른다.

## 파일 저장 위치

사용자 지정 또는 기존 문서 위치를 우선한다. 위치가 없으면 `docs/design/YYYYMMDD-HHMMSS/site/site-design.md`에 작성한다. 날짜와 시간은 문서 생성 일시로 정한다.

## site-design.md

다음 내용을 한 문서에 담는다. 복잡한 사용자 흐름만 별도 상세로 나누고 링크한다.

- 개요: 사용자·목적·설계 범위·성공 기준·제약
- 화면 목록과 전체 화면 이동 흐름
- 시나리오별 진입점·주요 동작·성공·실패·취소 흐름
- 필요한 화면 배치와 상태 변화
- 화면별 역할·입출력·공개 API·상태 소유자
- 주요 설계 결정과 참고 근거
- 검증 방법과 미확정 사항

## 다이어그램

| 종류 | 작성 내용 |
|---|---|
| [Navigation](../guides/navigation-diagram-guide.md) | 전체 화면 이동을 간략히 그리고, 사용자 목적별로 필요한 상세를 추가한다. 이동을 결정하는 API와 판단을 포함한다. |
| [Layout](../guides/screen-layout-guide.md) | 새로 설계하거나 변경하는 화면의 배치를 그린다. 공통 배치는 재사용하고 화면별 차이를 설명한다. |
| [State](../guides/state-diagram-guide.md) | 상태 소유자별로 로딩·입력·제출·오류·복구를 표현한다. 상태 변화가 없는 화면은 생략한다. |
| [Job Flow](../guides/job-flow-diagram-guide.md) | 화면 흐름과 구분해 설명할 내부 협력이 있을 때 작성한다. |

각 다이어그램은 전용 가이드의 문법을 따르고, 바로 아래에 주요 내용을 짧게 설명한다.

## 작성과 검증 기준

- 기존 사이트는 관련 화면·라우트·상태·공개 API를 확인한다. 확인된 동작과 새 설계·가정을 구분한다.
- 설계 범위에 해당하는 접근 조건·직접 URL 진입·새로고침·뒤로 가기·세션 만료를 포함한다.
- 화면 이동·배치·상태에서 화면 이름과 소유권을 일치시킨다. 서버의 권한·업무 정책은 공개 계약으로 확인한다.
- 책임과 계약은 [모듈 경계 가이드](../guides/module-boundary-guide.md)를 따른다. 필요한 반응형 배치·키보드 조작·포커스·오류 안내도 검증 기준에 포함한다.
- 참고 서비스는 [UX/UI 개선 프롬프트](./ux-ui-improvement-prompt.md)의 조사 기준에 따라 필요한 패턴을 확인하고, 출처·적용 이유·차이를 남긴다.
- 사용자 과업의 성공·실패 흐름과 다이어그램 간 일관성을 검토한다. 링크·문법을 확인하고 정적 검토와 실제 렌더링·사용성 검증을 구분한다.
