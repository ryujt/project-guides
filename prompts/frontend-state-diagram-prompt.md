# 프론트엔드 상태 다이어그램 작성 프롬프트

## 목적

 각 화면에서 **화면 이동 없이** 내부적으로 벌어지는 상태 변화를 문서화한다.

## 실행 규칙 — 자율 진행 · 병렬 조사 · 범위 고정 · 문장 절제

* **자율 모드**: 너는 자율 모드로 동작 중이다. 사용자는 실시간으로 보고 있지 않고 중간에 답할 수 없다. 확인이나 승인을 기다리며 멈추지 말고, 입력이 모호한 지점은 가정을 명시한 뒤 가장 합리적인 해석으로 산출물을 끝까지 완성한다. 가정·선택지·확인이 필요한 질문은 종료 보고에 모아 남긴다.
* **턴 종료 자기 검사**: 턴을 끝내기 전에 마지막 문단을 다시 읽어라. 그것이 계획이거나 질문이거나 아직 하지 않은 일에 대한 약속이면, 턴을 끝내지 말고 지금 그 일을 실행해라. "다음으로 …하겠습니다"로 끝나는 응답은 완료가 아니다.
* **병렬 조사**: 다음에 무엇이 필요한지 먼저 목록으로 정리한다. 서로 결과에 의존하지 않는 파일 읽기·검색·명령·문서 작성은 이번 응답에서 한 번에 모두 요청한다. 상관없는 파일 세 개를 세 턴에 걸쳐 읽지 않는다. 앞 결과가 있어야 다음을 정할 수 있는 경우만 순차로 진행한다.
* **범위 고정**: 이 프롬프트가 지정한 산출물만 만든다. 코드를 수정하지 않고, 지시 범위 밖 영역을 분석·재설계·개선하지 않는다. 작업 중 발견한 무관한 버그·설계 결함은 고치지 말고 종료 보고의 **후속 과제**에만 적는다. 지정된 산출물 외의 파일을 새로 만들지 않는다.
* **문장 절제 — 멋 부린 문장 금지**: 꾸민 표현을 쓰지 않는다. "돌려볼 만한 다이얼"이 아니라 "조정할 파라미터"라고 쓴다. 비유·은유는 글쓴이가 고르지도 통제하지도 못한 뉘앙스를 끌고 들어와 정확하지 않으므로 뺀다. 감탄·과장·불필요한 수식어도 뺀다. 남는 것은 사실과 판단뿐이어야 한다.

## 지시사항

**화면 이동이 없는 상태에서 벌어지는 모든 일들에 대한 상태 변화**를 작성해줘.

### 세부 요구사항

1. **화면(Screen) 단위로 작성한다.**
   * 각 화면마다 별도의 섹션으로 상태 다이어그램을 작성한다.
   * 단, 상태 변화 없이 정보만 보여주는 단순 설명서/안내 화면 등 **프로세스가 지나치게 단순한 화면은 스킵**한다.

2. **화면 이동이 없는 상태 전이만 다룬다.**
   * 로딩 → 성공/실패, 입력 검증, 편집 모드 토글, 모달 열림/닫힘, 폼 제출 중/완료, 데이터 fetch 상태 등
   * 다른 화면으로 넘어가는 전환은 이 문서의 대상이 아니다(그건 네비게이션 다이어그램에서 다룬다).

3. **가이드 표기법을 따른다.**
   * 시작: `<s> --> (Ready)`
   * 상태 전이: `(Loading) --> (Loaded)`
   * 종료: `(Done) --> <e>`
   * 액션/프로세스는 괄호 없는 텍스트 노드로: `Save Log`
   * 분기 조건: `: Error`, `: Success` 등 `: Text` 형식
   * 각 코드 블록은 ```` ```state ```` 언어 태그로 감싼다.

4. **실제 코드를 근거로 작성한다.**
   * 컴포넌트의 state, 로딩/에러 플래그, 조건부 렌더링, 이벤트 핸들러를 확인하여 상태를 도출한다.
   * 추측으로 상태를 만들지 않는다.

### 표기 규칙 요약 (가이드 참조)

| 요소 | 입력 문법 | 시각적 표현 |
| --- | --- | --- |
| Start Node | `<s>` | 흰색 원 |
| State | `(Name)` | 둥근 사각형 |
| Action | `Name` (괄호 없음) | 직사각형 |
| End Node | `<e>` | 검은색 원 |

## 산출물

* 화면별로 구분된 마크다운 문서 하나.
* 각 화면 섹션은 제목 + 설명 + ```` ```state ```` 다이어그램으로 구성.
* 설명은 **신입 엔지니어가 읽는다고 생각하고** 쉬운 말·짧은 문장으로 쓴다. 전문용어는 첫 등장에 한 번 풀어쓰고, 길고 장황하게 쓰지 않는다.
* **멋 부린 문장은 쓰지 않는다** — 비유·은유·과장·불필요한 수식어를 빼고 어떤 상태가 무엇 때문에 어디로 바뀌는지만 그대로 쓴다.
* 단순 화면은 제외한 사유를 짧게 남긴다(선택).
* 말미에 코드로 확인할 수 없어 가정으로 채운 부분과, 분석 중 발견했으나 고치지 않은 무관한 문제(후속 과제)를 적는다.
