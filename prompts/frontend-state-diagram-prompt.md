# 프론트엔드 상태 다이어그램 작성 프롬프트

화면 이동 없이 벌어지는 상태 변화를 **상태 소유자별로** 문서화한다. 한 페이지의 모든 플래그를 거대한 상태 조합으로 만들지 않고 독립된 수명주기를 구분한다.

## 입력과 실행 규칙

- 입력: 대상 프로젝트·화면/컴포넌트/상태 모듈, 분석 범위, 문서 위치.
- [모듈 경계 가이드](../guides/module-boundary-guide.md)의 최소 맥락에 따라 상태 소유자·공개 액션·구독/쓰기 위치·관련 테스트를 먼저 찾는다. 전이를 확인할 때 필요한 본문만 읽는다.
- 이미 허용된 조사/문서 작성은 자율 진행한다. 원본 코드와 기존 변경은 보존하고 확인한 사실·추론·미확인을 구분한다.
- [state 가이드](../guides/state-diagram-guide.md)의 DSL을 사용한다. 화면 간 이동은 [navigation 프롬프트](./frontend-navigation-diagram-prompt.md)에서 다룬다.

## 1. 상태 소유권 찾기

`소유 모듈/컴포넌트 · 상태 · 변경 입력/액션 · 구독자 · 근거`를 정리한다.

- 로딩·제출·편집·검증·오류·복구 등의 상태를 실제 코드에서 도출한다.
- 같은 세션/데이터를 여러 화면이 구독하면 원본 소유자의 상태도를 한 번 작성하고 화면별 차이만 설명한다.
- 독립된 상태는 분리하고 동시에 바뀌어야 하는 상태는 관련 제약을 적는다. boolean들의 모든 조합을 별도 노드로 늘리지 않는다.
- 상태 변화 없는 안내 화면은 도표를 만들지 않는다. 분석 범위에서 제외한 이유만 짧게 남긴다.

## 2. 전이 작성

- 시작은 `<s>`, 상태는 `(State)`, 액션은 괄호 없는 이름, 끝은 `<e>`를 사용한다.
- 분기는 가이드의 `: 조건` 라벨로 표시한다. 상태와 그 상태를 만드는 행동을 같은 노드로 혼동하지 않는다.
- 각 뷰의 관측 범위를 정하고 시작·종료의 의미를 설명한다. 계속 실행되는 UI/구독에 존재하지 않는 업무 종료를 만들지 않는다. 가이드가 요구하는 범위 표기와 실제 수명주기를 대조한다.
- 비동기 응답·취소·오래된 응답 폐기·재시도·타임아웃은 실제 관련 전이만 포함한다.
- 실패 처리나 전이가 코드에 없으면 설계된 사실처럼 추가하지 않는다. 누락된 처리로 기록한다.

복잡한 전이만 `현재 상태 · 트리거/조건 · 다음 상태 · 부작용 · 쓰기 소유자` 표로 보충한다. 다이어그램을 그대로 문장으로 반복하지 않는다.

## 3. 산출물과 검증

기존/사용자 지정 문서 위치에 **대상/소유권 → 상태 소유자별 도표 → 필요한 전이 설명 → 미확인/이슈** 순서로 작성한다. 위치가 없으면 `docs/design/{DATE}/frontend/state.md`를 사용한다.

- `state` 펜스와 사용자 DSL을 유지한다. 가이드 대신 임의 Mermaid 상태도로 치환하지 않는다.
- 각 도표에 범위·소유자·핵심 트리거·근거를 짧게 설명한다.
- 실제 쓰기 위치·전이 조건·실패/복구 경로가 코드와 일치하는지 확인한다.
- 다른 화면으로의 이동, 서버 권위 상태와 UI 표시 상태, 별도 수명주기가 섞이지 않았는지 검토한다.
- 문법·링크 대조와 실제 렌더링을 구분한다. 도구가 없으면 렌더링 미검증을 남긴다.

사실 오류·핵심 전이 누락을 수정하고 영향 부분을 재검증한다. 반복은 [협업 프롬프트](./multi-agent-task-prompt.md)의 기준을 따른다. 최종 보고에 문서 위치·분석 범위·검증/한계·발견 이슈를 적는다.
