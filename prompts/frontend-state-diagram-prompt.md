# 프론트엔드 상태 다이어그램 작성 프롬프트

화면 이동 없이 벌어지는 상태 변화를 **상태 소유자별로** 문서화한다. 독립된 수명주기를 구분하고 원본 코드는 수정하지 않는다. 화면 간 이동은 [Navigation 프롬프트](./frontend-navigation-diagram-prompt.md)에서 다룬다.

## 파일 저장 위치

사용자 지정·기존 문서 위치를 우선한다. 위치가 없으면 `docs/design/{DATE}/frontend/state.md` 한 파일에 작성한다. `{DATE}`는 생성 일시의 `YYYYMMDD-HHMMSS` 형식이다. 문서 간 링크는 상대 경로로 쓴다.

## 작성 내용

- 대상과 소유권: 상태 소유자·상태·변경 입력/액션·구독자·근거
- 상태 소유자별 다이어그램과 주요 전이 설명
- 미확인 사항과 누락된 처리

각 다이어그램에 관측 범위·소유자·시작과 종료의 의미·핵심 트리거를 짧게 설명한다. 복잡한 전이만 조건·부작용·쓰기 주체를 보충한다.

## 작성 기준

- [최소 맥락 기준](../guides/module-boundary-guide.md#6-ai에-전달할-작업-맥락)에 따라 상태 소유자·공개 액션·구독/쓰기 위치·관련 테스트부터 확인한다. 사실과 추론·미확인을 구분한다.
- 표기는 [State 가이드](../guides/state-diagram-guide.md)의 `state` 문법을 따른다. 상태와 그 상태를 만드는 행동을 구분한다.
- 로딩·제출·편집·검증·오류·복구 상태를 실제 코드에서 도출한다. boolean의 모든 조합을 별도 노드로 늘리지 않는다.
- 같은 세션·데이터를 여러 화면이 구독하면 원본 소유자의 상태도를 한 번 작성하고 화면별 차이만 설명한다.
- 독립 상태는 분리하고 함께 바뀌어야 하는 상태에는 제약을 적는다. 서버 권위 상태와 UI 표시 상태, 서로 다른 수명주기를 합치지 않는다.
- 비동기 응답·취소·오래된 응답 폐기·재시도·타임아웃은 실제 관련 전이만 넣는다. 없는 실패 처리·업무 종료를 추가하지 않는다.
- 상태 변화가 없는 대상은 도표를 만들지 않고 이유만 기록한다.

## 검증

실제 쓰기 위치·전이 조건·실패/복구 경로가 코드와 일치하는지 확인한다. 화면 이동이나 다른 소유자의 상태가 섞이지 않았는지, 범위와 수명주기가 맞는지 검토한다.

문법·링크 대조와 실제 렌더링을 구분하고 렌더러가 없으면 정적 검토라고 기록한다. 오류·핵심 전이 누락을 수정한 뒤 문서 위치·분석 범위·검증 결과와 한계·발견 이슈를 보고한다.

다이어그램을 작성·수정한 경우 Markdown을 완성한 뒤 [편집 링크 전달 기준](../guides/diagram-editor-link-guide.md)을 적용한다.
