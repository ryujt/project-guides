# 백엔드 없는 프론트엔드 프로토타입 구현 프롬프트

설계한 화면과 사용자 흐름을 직접 체험할 수 있는 웹·데스크톱 프로토타입을 만든다. 기본은 정상 처리 흐름이며, 백엔드 호출은 가짜 결과로 대신한다.

## 입력과 작업 위치

검토할 설계·대상 화면과 흐름·확인할 질문, 웹/데스크톱 여부·기존 실행 환경·기술 제약을 확인한다. 부족한 입력은 가정으로 남기고 진행 가능한 부분부터 만든다.

구현 위치와 문서는 사용자 지정·기존 관례를 우선한다. 실행·검토 안내는 프로토타입 가까이의 README에 두고 새 기록의 일시는 `YYYYMMDD-HHMMSS`, 파일 링크는 상대 경로로 쓴다.

기존 변경과 기술 스택을 보존하며 허용된 구현·실행·수정은 자율 진행한다. 책임 분리와 필요한 맥락은 [모듈 경계 가이드](../guides/module-boundary-guide.md)를 따른다.

## 구현

- [Navigation](../guides/navigation-diagram-guide.md)·[Layout](../guides/screen-layout-guide.md)·[State](../guides/state-diagram-guide.md)의 의미와 설계 용어를 유지한다. 미정 스타일은 기존 기준이나 잠정안으로 처리하고 제품 정책을 임의로 확정하지 않는다.
- 정상 흐름을 진입부터 완료까지 연결한다. 주요 버튼·입력·결과 화면이 작동하게 하고 설계의 입력 검증·확인·취소를 유지한다.
- 공유 가상 데이터는 한 원본에서 관리해 화면 간 변경이 일치하게 한다. 초기 데이터·초기화 방법을 제공하고 이동·뒤로 가기·재진입과 상태 유지/초기화를 연결한다.
- 업무 서버·DB·실제 인증·외부 서비스 없이 실행되게 한다. 가짜 계약을 실제 명세로 쓰지 않고, 앱 시작·초기 조회·백그라운드 동작까지 실제 업무 서비스 요청과 데이터 변경을 차단한다.
- 웹은 브라우저, 데스크톱은 지정 환경에서 동작하게 한다. 검토 질문에 필요한 빈값·오류 등만 추가하고 범위 밖 요소는 생략하거나 미지원으로 표시한다.

## 검증과 산출물

프로그램을 실행해 검토 질문에 해당하는 흐름을 직접 조작한다. 화면·데이터 반영, 초기화 후 재현, 실제 서비스 요청 차단과 필요한 프로젝트 검사를 확인한다. 결함을 수정하면 영향받는 흐름을 재검증한다.

코드와 함께 다음을 남긴다.

- 실행 방법·진입 화면·초기화와 체험 순서
- 설계/검토 질문별 구현한 흐름·관찰 결과·가정·미구현·미실행
- 개발자 의견과 유지·수정·보류할 사항, 후속 설계 변경

실행·조작과 정적 검사를 구분하고 확인하지 못한 플랫폼·흐름은 미검증으로 남긴다. 이 검증은 가상 결과에서의 UI 동작만 확인하며 실제 백엔드·보안·성능·외부 연동을 증명하지 않는다. 개발자 검토 전에는 수용·승인으로 보고하지 않는다.

최종 보고에는 위치·실행 방법·검증 결과와 한계를 적는다. 실제 제품 구현은 [검증 우선 구현 프롬프트](./verify-first-implementation-prompt.md)를 따르며 프로토타입 코드를 제품용으로 확정하지 않는다.
