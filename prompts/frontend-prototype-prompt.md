# 백엔드 없는 프론트엔드 프로토타입 구현 프롬프트

**어떻게 보이고 동작하는지 직접 체험하며 판단할 수 있는 웹·데스크톱 프로토타입**을 만든다. 화면은 실제 제품처럼 완성하고, 기능은 가상 데이터와 상태 변화로 자연스럽게 시뮬레이션한다. 작업의 중심은 UX/UI 완성도이며, 정상 흐름을 체험할 수 있는 수준으로 기능 구현을 한정한다.

## 입력과 작업 위치

대상 사용자·주요 과업·검토할 화면과 흐름·확인할 질문, 대상 기기와 화면 크기·웹/데스크톱 여부·기존 실행 환경·기술 제약을 확인한다. 기존 설계·화면·디자인 시스템·참고 이미지가 있으면 우선 활용한다. 부족한 입력은 가정으로 남기고 진행 가능한 부분부터 만든다. 설계 문서가 없으면 요청에서 대표 과업과 화면을 도출해 진행한다.

구현 위치와 문서는 사용자 지정·기존 관례를 우선한다. 실행·검토 안내는 프로토타입 가까이의 README에 간결하게 두고 새 기록의 일시는 `YYYYMMDD-HHMMSS`, 파일 링크는 상대 경로로 쓴다. 작성 컴퓨터에서만 유효한 절대 경로·설치 사본 경로를 산출 문서에 남기지 않는다.

기존 변경과 기술 스택을 보존하며 허용된 구현·실행·수정은 자율 진행한다. 책임 분리와 필요한 맥락은 [모듈 경계 가이드](../guides/module-boundary-guide.md)를 따른다.

## UX/UI 완성도

- **처음 열린 화면부터 실제 서비스의 화면으로 느껴져야 한다.** 와이어프레임·기본 컴포넌트 배치에 머물지 않고 정보 위계·콘텐츠·시각 스타일·상호작용을 함께 완성한다. 작업 시간과 구현 복잡도는 이 체험을 개선하는 데 우선 배분한다.
- 기존 디자인 기준을 우선한다. 기준이 없으면 사용자와 과업에 맞는 시각 방향을 정하고 타이포그래피·색상·간격·정렬·아이콘·컴포넌트 상태를 일관되게 적용한다. 특정 유행·색상·카드 배치를 모든 제품에 반복 적용하지 않는다. 미정 스타일은 잠정안으로 남기고 제품 정책을 임의로 확정하지 않는다.
- 대표 핵심 화면의 완성도를 먼저 확보한 뒤 공통 스타일과 컴포넌트를 다른 화면에 적용한다. [Navigation](../guides/navigation-diagram-guide.md)·[Layout](../guides/screen-layout-guide.md)·[State](../guides/state-diagram-guide.md)가 있으면 의미와 설계 용어를 유지한다.
- 사용자가 현재 위치·상태·다음 행동을 바로 알 수 있게 한다. 주요 행동과 보조 행동, 제목과 본문, 요약과 상세를 구분하고 과업에 맞게 정보 밀도·읽는 순서·탐색·입력 부담을 조정한다.
- 실제 맥락에 맞는 가상 이름·문장·날짜·수치·목록을 채운다. 화면 간 같은 대상의 정보와 합계·상태를 일치시키고, 긴 제목과 다양한 데이터 길이에서도 배치를 확인한다. 이미지·차트가 필요하면 화면 목적에 맞는 자산과 데이터를 사용하고 깨진 이미지·의미 없는 채움 문구를 남기지 않는다.
- 체험할 요소의 기본·호버·포커스·눌림·선택·비활성 상태를 입력 방식에 맞게 다듬는다. 필드 레이블·안내·오류 메시지·완료 피드백은 실제 제품의 말투로 쓰고, 빈 결과·로딩·실패 상태는 검토할 흐름에 필요한 만큼 자연스럽게 연결한다. 장식이나 불필요한 대기로 조작을 방해하지 않는다.
- 대상 화면 크기에서 줄바꿈·스크롤·고정 영역·모달·메뉴가 자연스럽게 동작하게 한다. 웹은 대상 기기에 맞춰 반응형 배치를 확인하고 데스크톱은 지정 창 크기와 크기 변경을 확인한다. 해당 입력 방식에서 키보드 탐색·포커스 표시와 복귀·명도 대비·조작 영역을 살피고, 모션은 상태 변화를 이해하는 데 필요한 만큼 사용하며 줄이기 설정을 존중한다.
- 프로토타입 안내·초기화·미지원 범위는 README나 별도 검토 도구에 정리한다. 화면 안에는 사용자의 판단에 필요한 안내를 두고 구현 설명·가짜 API 정보가 과업을 가리지 않게 한다.

## 동작 시뮬레이션

- 정상 흐름을 진입부터 완료까지 연결한다. 주요 버튼·입력·결과 화면이 작동하게 하고 설계의 입력 검증·확인·취소를 유지한다. 검색·필터·선택·추가·수정처럼 체험 범위에서 동작을 기대하게 하는 요소에는 그에 맞는 화면·데이터 변화를 연결한다. 완료 알림만 보여주고 결과가 바뀌지 않거나, 모든 버튼이 같은 결과로 이어지는 구현은 피한다.
- 공유 가상 데이터는 한 원본에서 관리해 화면 간 변경이 일치하게 한다. 초기 데이터·초기화 방법을 제공하고 이동·뒤로 가기·재진입과 상태 유지/초기화를 연결한다.
- 업무 서버·DB·실제 인증·외부 연동의 업무 처리는 가상 결과로 대체한다. 메모리나 브라우저 저장소 등 기존 환경에서 간단한 방식을 선택하며, UI 체험에 필요 없는 서버 계층·운영 기능·실제 연동을 추가하지 않는다. 가짜 계약을 실제 명세로 쓰지 않고, 앱 시작·초기 조회·백그라운드 동작까지 실제 업무 서비스 요청과 데이터 변경을 차단한다.
- 웹은 브라우저, 데스크톱은 지정 환경에서 동작하게 한다. 범위 밖 요소는 생략하거나 비활성 상태와 이유를 자연스럽게 표시하고, 활성 요소를 눌렀는데 반응이 없는 상태로 남기지 않는다.

## 검증과 산출물

프로그램을 실행해 다음을 확인하고, 결함을 수정하면 영향받는 화면과 흐름을 다시 확인한다.

1. **직접 체험**: 검토 질문에 해당하는 흐름을 진입부터 완료까지 조작한다. 화면·데이터 반영, 확인·취소·뒤로 가기, 초기화 후 재현, 실제 업무 서비스 요청 차단과 필요한 프로젝트 검사를 확인한다.
2. **화면 검수**: 대상 화면 크기의 실제 렌더링과 스크린샷으로 핵심 화면·상태를 살핀다. 첫 화면뿐 아니라 스크롤 아래·입력 중·메뉴나 모달을 연 모습·완료 후 결과도 확인한다. 잘림·겹침·불필요한 가로 스크롤·불균형한 간격·읽기 어려운 텍스트·깨진 자산을 수정한다. 빌드·타입 검사 통과만으로 화면 품질을 확인했다고 하지 않는다.
3. **독립 검토와 보완**: 작성자 외 검토자 또는 분리된 검토 단계가 처음 쓰는 사용자의 관점에서 핵심 행동의 발견 가능성·피드백·화면 간 일관성을 살핀다. 실제 제품처럼 보이는 데 방해가 되는 시각 결함과 핵심 흐름의 막힘을 수정하고 재평가한다. 점수·반복 횟수로 완료를 대신하지 않는다.

코드와 함께 다음을 남긴다.

- 실행 방법·진입 화면·초기화와 체험 순서
- 검토 질문별 구현한 흐름·관찰 결과·가정·미구현·미실행
- 주요 화면·상태의 검수 결과와 실제로 확보한 스크린샷, 검토 의견과 후속 수정 사항

실행·조작·화면 검수와 정적 검사를 구분하고 확인하지 못한 플랫폼·흐름·화면 상태는 미검증으로 남긴다. 렌더링·스크린샷 확인 도구가 없으면 가능한 정적 검토를 수행하고 시각 품질은 미검증으로 명시한다. 이 검증은 가상 결과에서의 UI 체험만 확인하며 실제 백엔드·보안·성능·외부 연동이나 실제 사용자의 사용성 검증을 증명하지 않는다. 사용자나 검토자의 수용·승인을 받지 않았으면 받았다고 보고하지 않는다.

최종 보고에는 위치·실행 방법·검증 결과와 한계를 적는다. 실제 제품 구현은 [검증 우선 구현 프롬프트](./verify-first-implementation-prompt.md)를 따르며 프로토타입 코드를 제품용으로 확정하지 않는다.
