# 쇼핑몰 매크로뷰

고객이 상품을 찾아 주문하면 운영자가 출고를 준비하고 택배기사가 상품을 배달한다. 고객은 출고 전에 취소를 신청하거나, 수령 후 반품·교환을 신청할 수 있다. 이 가상 예제에서는 고객 화면, 운영 화면과 내부 서비스를 **쇼핑몰** 한 객체에 포함한다. 쇼핑몰 안에서 같은 일을 분담하는 흐름은 [MSA 서비스뷰](system.md)에서 볼 수 있다.

## M00. 객체 사이의 업무 의존관계

| 업무 주체 | 누구에게서 무엇을 받는가 | 그것으로 누구에게 무엇을 하는가 |
| --- | --- | --- |
| 고객 | 쇼핑몰에서 상품·주문 정보, 발송사에서 인증 코드와 배송 메일, 택배기사에게서 상품을 받는다. | 쇼핑몰에 주문·조회·구매 후 처리를 신청하고 결제사에서 결제를 진행한다. |
| 쇼핑몰 | 고객의 신청, 결제사의 거래 결과, 운영자의 발송 등록, 택배사의 완료 통지, 물류센터의 검수 결과를 받는다. | 주문 확정·배송 안내·환불·교환 가능 여부를 판단하고 고객 또는 후속 담당자에게 결과를 보낸다. |
| 운영자 | 쇼핑몰에서 출고 목록과 배송지를, 택배사에서 운송장을 받는다. | 쇼핑몰에 운송장을 등록하고 포장한 상품을 택배사에 인계한다. |
| 택배사 | 운영자에게서 배송 의뢰와 포장한 상품을, 택배기사에게서 배달 완료 보고를 받는다. | 운영자에게 운송장을 발급하고 기사에게 배달을 배정하며 쇼핑몰에 배송 완료를 통지한다. |
| 택배기사 | 택배사에서 배달·수거할 상품 정보와 방문지를 받고, 수거 때는 고객에게서 실물을 받는다. | 고객에게 상품을 건네거나 고객의 반환 상품을 물류센터에 인계하고 택배사에 처리 결과를 등록한다. |
| 발송사 | 쇼핑몰에서 수신처와 발송할 인증 문자·배송 메일을 받는다. | 고객에게 인증 코드나 배송 안내를 전달한다. |
| 결제사 | 고객의 결제 요청과 쇼핑몰의 거래 조회·환불 의뢰를 받는다. | 쇼핑몰에 승인·환불 결과를 알려 주문과 환불을 확정할 근거를 제공한다. |
| 물류센터 | 쇼핑몰에서 검수 의뢰를, 택배기사에게서 반환 상품을 받는다. | 실물을 검사해 쇼핑몰에 결과를 보낸다. 쇼핑몰은 이를 근거로 환불 또는 교환을 결정한다. |

`운영자.On배송준비`는 **시작 사건**, `쇼핑몰.message.배송등록신청`은 **쇼핑몰이 받는 메시지**다. 신청을 받으면 `쇼핑몰.배송등록판정`이 주문과 운송장을 확인한다. 결과가 `입력보완필요`이면 `운영자.message.운송장보완요청`으로 이어진다. 별도로 `운영자.On상품인계 --> 택배사.On배송상품인수`는 실물이 누구 손에서 누구 손으로 넘어가는지 보여 준다.

아래에서 [배송 준비와 수령](#m06-1-운영자의-배송-준비부터-고객-수령까지), [비회원 주문 인증](#m02-비회원이-인증-문자를-받아-주문-한-건-조회하기), [주문과 결제](#m05-주문과-결제), [취소·반품·교환과 리뷰](#m07-취소반품교환과-구매-리뷰)를 각각 따라갈 수 있다.

## M06. 주문 조회와 배송

### M06-1. 운영자의 배송 준비부터 고객 수령까지

**시작 사건** 운영자가 포장할 주문을 확인하려고 배송 준비를 시작한다. 이 예제에서는 운영자가 택배사에 직접 배송을 의뢰하고, 받은 운송장을 쇼핑몰에 등록한다.

```jobflow
scope: 수동 출고부터 고객 수령과 배송 완료 안내까지
Object: 고객, 쇼핑몰, 운영자, 택배사, 택배기사, 발송사
운영자.On배송준비 --> 쇼핑몰.message.주문배송정보요청
쇼핑몰.message.주문배송정보요청 --> 쇼핑몰.출고대상판정
쇼핑몰.출고대상판정.출고할상품없음 --> 운영자.message.출고대상없음안내
쇼핑몰.출고대상판정.출고할상품있음 --> 운영자.message.출고목록과배송지
운영자.message.출고목록과배송지 --> 택배사.message.배송의뢰
택배사.message.배송의뢰 --> 운영자.message.운송장정보
운영자.message.운송장정보 --> 쇼핑몰.message.배송등록신청
쇼핑몰.message.배송등록신청 --> 쇼핑몰.배송등록판정
쇼핑몰.배송등록판정.주문과운송장확인 --> 운영자.message.배송등록결과
쇼핑몰.배송등록판정.입력보완필요 --> 운영자.message.운송장보완요청
쇼핑몰.배송등록판정.주문출고불가 --> 운영자.message.출고중단안내
운영자.On상품인계 --> 택배사.On배송상품인수
운영자.On발송등록 --> 쇼핑몰.message.발송등록신청
쇼핑몰.message.발송등록신청 --> 운영자.message.발송처리결과
쇼핑몰.message.발송등록신청 --> 쇼핑몰.발송안내판정
쇼핑몰.발송안내판정.첫발송안내대상 --> 발송사.message.발송안내메일요청
발송사.message.발송안내메일요청 --> 고객.message.발송안내메일
택배사.On배달배정 --> 택배기사.message.배달할화물과주소
택배기사.On상품배달 --> 고객.On상품수령
택배기사.On배송완료등록 --> 택배사.message.배송완료등록신청
택배사.message.배송완료등록신청 --> 택배기사.message.배송완료등록결과
택배사.On배송완료기록 --> 쇼핑몰.message.배송완료통지
쇼핑몰.message.배송완료통지 --> 쇼핑몰.배송완료안내판정
쇼핑몰.배송완료안내판정.첫완료안내대상 --> 발송사.message.배송완료메일요청
발송사.message.배송완료메일요청 --> 고객.message.배송완료메일
```

- **운영자 · 배송준비 → 쇼핑몰 · 주문배송정보요청** — 운영자가 배송 준비를 시작하면 쇼핑몰에 출고할 상품과 배송지를 요청한다.
- **쇼핑몰 · 주문배송정보요청 → 쇼핑몰 · 출고대상판정** — 쇼핑몰은 결제가 확인되고 지금 출고할 수 있는 상품을 찾는다.
- **쇼핑몰 · 출고대상판정 [출고할상품없음] → 운영자 · 출고대상없음안내** — 출고할 상품이 없으면 쇼핑몰이 운영자에게 이를 알리고 이번 준비를 마친다.
- **쇼핑몰 · 출고대상판정 [출고할상품있음] → 운영자 · 출고목록과배송지** — 출고할 상품이 있으면 쇼핑몰이 운영자에게 포장 목록과 배송지를 보낸다.
- **운영자 · 출고목록과배송지 → 택배사 · 배송의뢰** — 운영자는 받은 목록과 배송지로 택배사에 배송을 의뢰한다.
- **택배사 · 배송의뢰 → 운영자 · 운송장정보** — 택배사는 배송을 접수하고 운영자에게 운송장 번호를 돌려준다.
- **운영자 · 운송장정보 → 쇼핑몰 · 배송등록신청** — 운영자는 운송장을 해당 주문에 연결해 쇼핑몰에 배송 등록을 신청한다.
- **쇼핑몰 · 배송등록신청 → 쇼핑몰 · 배송등록판정** — 쇼핑몰은 주문이 여전히 출고 대상인지, 상품과 운송장 정보가 갖춰졌는지 확인한다.
- **쇼핑몰 · 배송등록판정 [주문과운송장확인] → 운영자 · 배송등록결과** — 등록할 수 있으면 쇼핑몰이 운영자에게 등록한 상품과 운송장을 알려 준다.
- **쇼핑몰 · 배송등록판정 [입력보완필요] → 운영자 · 운송장보완요청** — 입력이 부족하면 쇼핑몰이 운영자에게 보완할 항목을 보낸다. 운영자는 같은 주문의 정보를 고쳐 다시 신청한다.
- **쇼핑몰 · 배송등록판정 [주문출고불가] → 운영자 · 출고중단안내** — 그사이 주문이 취소되는 등 출고할 수 없게 됐으면 쇼핑몰이 운영자에게 인계를 중단하라고 알린다.
- **운영자 · 상품인계 → 택배사 · 배송상품인수** — 배송 등록을 마친 운영자가 포장한 상품을 건네면 택배사가 실물을 인수한다.
- **운영자 · 발송등록 → 쇼핑몰 · 발송등록신청** — 인계를 마친 운영자가 쇼핑몰에 발송 사실을 등록한다.
- **쇼핑몰 · 발송등록신청 → 운영자 · 발송처리결과** — 쇼핑몰은 운영자에게 발송 처리 결과를 돌려준다.
- **쇼핑몰 · 발송등록신청 → 쇼핑몰 · 발송안내판정** — 쇼핑몰은 이번 등록으로 발송이 처음 확인됐는지, 고객이 메일 안내 대상인지 판단한다.
- **쇼핑몰 · 발송안내판정 [첫발송안내대상] → 발송사 · 발송안내메일요청** — 처음 발송이 확인된 안내 대상 주문이면 쇼핑몰이 발송사에 운송장 번호를 담은 메일을 의뢰한다.
- **발송사 · 발송안내메일요청 → 고객 · 발송안내메일** — 발송사는 고객에게 운송장 번호가 적힌 발송 안내 메일을 보낸다.
- **택배사 · 배달배정 → 택배기사 · 배달할화물과주소** — 인수한 화물을 배정한 택배사가 기사에게 배달할 상품과 주소를 알려 준다.
- **택배기사 · 상품배달 → 고객 · 상품수령** — 택배기사가 상품을 건네면 고객이 실물을 받는다.
- **택배기사 · 배송완료등록 → 택배사 · 배송완료등록신청** — 배달을 마친 기사가 택배사에 배송 완료를 등록한다.
- **택배사 · 배송완료등록신청 → 택배기사 · 배송완료등록결과** — 택배사는 기사에게 완료 등록의 처리 결과를 돌려준다.
- **택배사 · 배송완료기록 → 쇼핑몰 · 배송완료통지** — 배송 완료를 기록한 택배사가 해당 운송장의 완료 사실을 쇼핑몰에 통지한다.
- **쇼핑몰 · 배송완료통지 → 쇼핑몰 · 배송완료안내판정** — 쇼핑몰은 통지된 운송장이 어느 주문에 속하며 이번이 첫 완료 안내 대상인지 판단한다.
- **쇼핑몰 · 배송완료안내판정 [첫완료안내대상] → 발송사 · 배송완료메일요청** — 처음 완료가 확인된 안내 대상 주문이면 쇼핑몰이 발송사에 완료 메일을 의뢰한다.
- **발송사 · 배송완료메일요청 → 고객 · 배송완료메일** — 발송사는 고객에게 배송 완료 메일을 보낸다.

고객은 기사에게서 **상품**을 받고 발송사에서 **메일**을 받는다. 쇼핑몰이 배송 완료를 알게 되는 시점은 택배사의 완료 통지를 받았을 때다. 같은 운송장의 완료 통지가 반복돼도 같은 메일은 한 번만 의뢰한다.

### M06-2. 고객의 주문·배송 조회

**시작 사건** 고객이 주문 내역을 연다. 배송 경과가 필요하면 별도로 배송 조회를 선택한다.

```jobflow
scope: 주문 내역과 배송 경과 조회
Object: 고객, 쇼핑몰, 택배사
고객.On주문조회 --> 쇼핑몰.message.주문내역요청
쇼핑몰.message.주문내역요청 --> 쇼핑몰.주문열람판정
쇼핑몰.주문열람판정.주문열람가능 --> 고객.message.주문내역과배송상태
쇼핑몰.주문열람판정.주문인증필요 --> 고객.message.주문인증안내
고객.On배송조회 --> 쇼핑몰.message.배송경과요청
쇼핑몰.message.배송경과요청 --> 쇼핑몰.배송조회판정
쇼핑몰.배송조회판정.운송장확인 --> 택배사.message.배송경과조회
쇼핑몰.배송조회판정.발송준비중 --> 고객.message.배송준비안내
쇼핑몰.배송조회판정.발송대상없음 --> 고객.message.발송대상없음안내
쇼핑몰.배송조회판정.주문인증필요 --> 고객.message.배송조회인증안내
택배사.message.배송경과조회 --> 쇼핑몰.message.운송장조회결과
쇼핑몰.message.운송장조회결과 --> 쇼핑몰.배송경과판정
쇼핑몰.배송경과판정.경과확인 --> 고객.message.현재배송경과
쇼핑몰.배송경과판정.조회불가 --> 고객.message.배송확인지연안내
```

- **고객 · 주문조회 → 쇼핑몰 · 주문내역요청** — 고객이 쇼핑몰에 주문 내역을 요청한다.
- **쇼핑몰 · 주문내역요청 → 쇼핑몰 · 주문열람판정** — 쇼핑몰은 고객이 해당 주문을 열람할 수 있는지 확인한다.
- **쇼핑몰 · 주문열람판정 [주문열람가능] → 고객 · 주문내역과배송상태** — 회원 본인의 주문이거나 비회원이 인증한 주문 한 건이면 주문 내역과 알려진 배송 상태를 보여 준다.
- **쇼핑몰 · 주문열람판정 [주문인증필요] → 고객 · 주문인증안내** — 열람 권한을 확인할 수 없으면 쇼핑몰은 고객에게 주문 인증을 안내한다.
- **고객 · 배송조회 → 쇼핑몰 · 배송경과요청** — 고객이 배송 조회를 선택해 쇼핑몰에 최근 배송 경과를 요청한다.
- **쇼핑몰 · 배송경과요청 → 쇼핑몰 · 배송조회판정** — 쇼핑몰은 주문 열람 권한과 등록된 운송장을 확인한다.
- **쇼핑몰 · 배송조회판정 [운송장확인] → 택배사 · 배송경과조회** — 열람할 수 있는 주문에 운송장이 있으면 쇼핑몰이 택배사에 배송 경과를 조회한다.
- **쇼핑몰 · 배송조회판정 [발송준비중] → 고객 · 배송준비안내** — 출고 예정인 주문에 아직 운송장이 없으면 고객에게 발송 준비 중이라고 안내한다.
- **쇼핑몰 · 배송조회판정 [발송대상없음] → 고객 · 발송대상없음안내** — 결제 대기나 출고 전 취소로 발송 대상이 없으면 쇼핑몰은 고객에게 현재 주문 상태와 사유를 알려 준다.
- **쇼핑몰 · 배송조회판정 [주문인증필요] → 고객 · 배송조회인증안내** — 열람 권한을 확인할 수 없으면 쇼핑몰이 고객에게 먼저 인증을 요청한다.
- **택배사 · 배송경과조회 → 쇼핑몰 · 운송장조회결과** — 택배사는 해당 운송장의 조회 결과를 쇼핑몰에 돌려준다.
- **쇼핑몰 · 운송장조회결과 → 쇼핑몰 · 배송경과판정** — 쇼핑몰은 회신에서 현재 배송 경과를 확인할 수 있는지 판단한다.
- **쇼핑몰 · 배송경과판정 [경과확인] → 고객 · 현재배송경과** — 배송 경과를 확인했으면 고객에게 택배사가 알려 준 경과와 시각을 보여 준다.
- **쇼핑몰 · 배송경과판정 [조회불가] → 고객 · 배송확인지연안내** — 조회가 지연되거나 실패하면 고객에게 마지막 확인 상태와 조회 지연 사실을 알려 준다.

## M02. 비회원이 인증 문자를 받아 주문 한 건 조회하기

**시작 사건** 비회원 고객이 자신의 주문을 찾으려고 주문번호와 연락처를 제출한다. 조회 권한은 인증에 사용한 주문 한 건에만 부여한다.

```jobflow
scope: 비회원 주문 조회 인증
Object: 고객, 쇼핑몰, 발송사
고객.On비회원주문찾기 --> 쇼핑몰.message.주문조회인증요청
쇼핑몰.message.주문조회인증요청 --> 고객.message.인증요청접수안내
쇼핑몰.message.주문조회인증요청 --> 쇼핑몰.인증발송대상확인
쇼핑몰.인증발송대상확인.주문연락처일치 --> 발송사.message.인증문자발송요청
발송사.message.인증문자발송요청 --> 쇼핑몰.message.문자발송접수결과
발송사.message.인증문자발송요청 --> 고객.message.주문조회인증문자
고객.On인증코드제출 --> 쇼핑몰.message.주문조회코드확인요청
쇼핑몰.message.주문조회코드확인요청 --> 쇼핑몰.조회권한판정
쇼핑몰.조회권한판정.유효한코드 --> 고객.message.인증한주문내역
쇼핑몰.조회권한판정.코드불일치 --> 고객.message.코드재입력안내
쇼핑몰.조회권한판정.유효기간경과 --> 고객.message.코드재발급안내
```

- **고객 · 비회원주문찾기 → 쇼핑몰 · 주문조회인증요청** — 고객이 주문번호와 연락처를 입력해 비회원 주문 조회를 신청한다.
- **쇼핑몰 · 주문조회인증요청 → 고객 · 인증요청접수안내** — 쇼핑몰은 주문이나 연락처의 일치 여부와 관계없이 같은 접수 안내를 보여 준다.
- **쇼핑몰 · 주문조회인증요청 → 쇼핑몰 · 인증발송대상확인** — 쇼핑몰은 신청에 적힌 연락처가 해당 주문의 연락처와 일치하는지 확인한다.
- **쇼핑몰 · 인증발송대상확인 [주문연락처일치] → 발송사 · 인증문자발송요청** — 연락처가 일치하면 쇼핑몰이 발송사에 인증 문자 발송을 의뢰한다.
- **발송사 · 인증문자발송요청 → 쇼핑몰 · 문자발송접수결과** — 발송사는 문자 발송을 접수했는지 쇼핑몰에 회신한다.
- **발송사 · 인증문자발송요청 → 고객 · 주문조회인증문자** — 발송사가 접수한 문자를 실제로 전달하면 고객이 주문 조회에 쓸 코드를 받는다.
- **고객 · 인증코드제출 → 쇼핑몰 · 주문조회코드확인요청** — 고객이 받은 코드를 쇼핑몰에 제출한다.
- **쇼핑몰 · 주문조회코드확인요청 → 쇼핑몰 · 조회권한판정** — 쇼핑몰은 제출한 코드와 유효기간을 확인한다.
- **쇼핑몰 · 조회권한판정 [유효한코드] → 고객 · 인증한주문내역** — 코드가 유효하면 고객에게 인증한 주문의 내역을 보여 준다.
- **쇼핑몰 · 조회권한판정 [코드불일치] → 고객 · 코드재입력안내** — 코드가 일치하지 않으면 고객에게 다시 입력하도록 안내한다.
- **쇼핑몰 · 조회권한판정 [유효기간경과] → 고객 · 코드재발급안내** — 코드가 만료됐으면 고객에게 새 코드를 요청하도록 안내한다.

비회원 주문서 인증은 주문 작성에 쓰인다. 회원가입과 비밀번호 찾기·재설정에서는 인증 목적에 맞는 코드나 링크를 발송한다. 비밀번호 찾기의 접수 안내는 계정 존재 여부를 드러내지 않으며, 만료되거나 이미 사용된 링크로는 새 링크를 요청해야 한다. 가입 완료, 로그인, 로그아웃은 각각 별도 계정 처리 결과를 갖는다.

## M05. 주문과 결제

### M05-1. 주문 접수에서 외부 결제창 복귀까지

**시작 사건** 회원 인증 또는 비회원 주문서 인증을 마친 고객이 상품·수량·배송지·할인 정보를 담은 주문서를 제출한다. 주문번호를 받은 고객이 결제를 선택하면 결제창 발급이 시작된다.

```jobflow
scope: 주문 생성과 결제창 이용
Object: 고객, 쇼핑몰, 결제사
고객.On주문서제출 --> 쇼핑몰.message.주문생성요청
쇼핑몰.message.주문생성요청 --> 쇼핑몰.주문접수판정
쇼핑몰.주문접수판정.주문생성됨 --> 고객.message.주문번호
쇼핑몰.주문접수판정.접수불가 --> 고객.message.주문접수불가사유
쇼핑몰.주문접수판정.접수여부확인중 --> 고객.message.주문확인중안내
고객.On주문결제선택 --> 쇼핑몰.message.결제시작요청
쇼핑몰.message.결제시작요청 --> 쇼핑몰.결제가능여부확인
쇼핑몰.결제가능여부확인.결제대기주문 --> 결제사.message.결제창발급요청
쇼핑몰.결제가능여부확인.새결제불가 --> 고객.message.현재주문상태
결제사.message.결제창발급요청 --> 쇼핑몰.message.결제창발급결과
쇼핑몰.message.결제창발급결과 --> 쇼핑몰.결제창안내판정
쇼핑몰.결제창안내판정.발급됨 --> 고객.message.결제창주소
쇼핑몰.결제창안내판정.사용할주소없음확정 --> 고객.message.결제시작불가안내
쇼핑몰.결제창안내판정.발급여부불명 --> 고객.message.결제창발급확인중안내
고객.On결제수단선택 --> 결제사.message.결제요청
결제사.message.결제요청 --> 고객.message.쇼핑몰복귀정보
고객.On결제창에서복귀 --> 쇼핑몰.message.결제확인요청
쇼핑몰.message.결제확인요청 --> 결제사.message.거래조회요청
```

- **고객 · 주문서제출 → 쇼핑몰 · 주문생성요청** — 고객이 주문서를 제출한다.
- **쇼핑몰 · 주문생성요청 → 쇼핑몰 · 주문접수판정** — 쇼핑몰은 인증, 가격, 재고와 주문 접수 결과를 확인한다.
- **쇼핑몰 · 주문접수판정 [주문생성됨] → 고객 · 주문번호** — 주문이 생성됐으면 고객에게 주문번호를 돌려준다.
- **쇼핑몰 · 주문접수판정 [접수불가] → 고객 · 주문접수불가사유** — 가격 변경·품절·인증 필요·처리 실패로 접수할 수 없으면 고객에게 사유를 알려 준다.
- **쇼핑몰 · 주문접수판정 [접수여부확인중] → 고객 · 주문확인중안내** — 접수 여부가 불명확하면 고객에게 같은 주문의 결과를 확인하도록 안내한다.
- **고객 · 주문결제선택 → 쇼핑몰 · 결제시작요청** — 고객이 해당 주문의 결제를 선택한다.
- **쇼핑몰 · 결제시작요청 → 쇼핑몰 · 결제가능여부확인** — 쇼핑몰이 현재 주문 상태에서 결제를 시작할 수 있는지 확인한다.
- **쇼핑몰 · 결제가능여부확인 [결제대기주문] → 결제사 · 결제창발급요청** — 결제 대기 주문이면 쇼핑몰이 결제사에 결제창을 요청한다.
- **쇼핑몰 · 결제가능여부확인 [새결제불가] → 고객 · 현재주문상태** — 이미 결제됐거나 취소·만료·처리 중이면 고객에게 현재 주문 상태를 보여 준다.
- **결제사 · 결제창발급요청 → 쇼핑몰 · 결제창발급결과** — 결제사는 쇼핑몰에 결제창 발급 결과를 돌려준다.
- **쇼핑몰 · 결제창발급결과 → 쇼핑몰 · 결제창안내판정** — 쇼핑몰이 결제창 주소를 확인한다. 발급 여부가 불명이면 같은 요청의 결과를 조회하고 확인된 결과에 따라 다시 안내한다.
- **쇼핑몰 · 결제창안내판정 [발급됨] → 고객 · 결제창주소** — 결제창이 발급됐으면 고객에게 그 주소를 제공한다.
- **쇼핑몰 · 결제창안내판정 [사용할주소없음확정] → 고객 · 결제시작불가안내** — 미발급 또는 주소 만료가 확인되면 고객에게 결제를 시작할 수 없는 사유를 안내한다.
- **쇼핑몰 · 결제창안내판정 [발급여부불명] → 고객 · 결제창발급확인중안내** — 발급 결과를 확인하고 있다고 고객에게 안내한다.
- **고객 · 결제수단선택 → 결제사 · 결제요청** — 고객이 결제사의 창에서 수단을 선택하고 결제를 요청한다.
- **결제사 · 결제요청 → 고객 · 쇼핑몰복귀정보** — 결제사는 고객이 쇼핑몰로 돌아갈 때 사용할 정보를 돌려준다.
- **고객 · 결제창에서복귀 → 쇼핑몰 · 결제확인요청** — 고객이 돌아오면 쇼핑몰에 해당 거래의 확인을 요청한다.
- **쇼핑몰 · 결제확인요청 → 결제사 · 거래조회요청** — 쇼핑몰은 결제사에 그 거래의 승인 상태를 조회한다. 결제사의 회신을 받은 뒤에는 M05-2의 주문 결제 판정을 따른다.

### M05-2. 거래 확인과 결제 취소·환불

**시작 사건** 결제사가 거래 상태 변경을 쇼핑몰에 통지한다. 고객 복귀와 통지는 어느 쪽이 먼저든 같은 거래를 조회한다. 아래의 거래 조회 결과와 주문 결제 판정은 M05-1에서 고객이 돌아와 보낸 조회에도 적용한다.

```jobflow
scope: 복귀 또는 독립 통지에 따른 거래 확인
Object: 고객, 쇼핑몰, 결제사
결제사.On거래상태통지 --> 쇼핑몰.message.거래상태알림
쇼핑몰.message.거래상태알림 --> 결제사.message.알림접수결과
쇼핑몰.message.거래상태알림 --> 결제사.message.거래조회요청
결제사.message.거래조회요청 --> 쇼핑몰.message.거래조회결과
쇼핑몰.message.거래조회결과 --> 쇼핑몰.주문결제판정
쇼핑몰.주문결제판정.승인주문확정 --> 고객.message.주문확정안내
쇼핑몰.주문결제판정.미승인확정 --> 고객.message.결제미승인안내
쇼핑몰.주문결제판정.승인여부확인중 --> 고객.message.결제확인중안내
쇼핑몰.주문결제판정.승인후주문불가환불미의뢰 --> 결제사.message.취소환불요청
쇼핑몰.주문결제판정.승인후주문불가환불미의뢰 --> 고객.message.주문불가환불안내
고객.On결제상태조회 --> 쇼핑몰.message.결제상태조회요청
쇼핑몰.message.결제상태조회요청 --> 고객.message.현재결제상태
```

- **결제사 · 거래상태통지 → 쇼핑몰 · 거래상태알림** — 고객이 창을 닫거나 로그인이 만료돼도 결제사는 거래 상태 변경을 쇼핑몰에 알린다.
- **쇼핑몰 · 거래상태알림 → 결제사 · 알림접수결과** — 쇼핑몰은 결제사에 통지 접수 결과를 회신한다.
- **쇼핑몰 · 거래상태알림 → 결제사 · 거래조회요청** — 쇼핑몰은 통지에 해당하는 거래를 결제사에 조회한다.
- **결제사 · 거래조회요청 → 쇼핑몰 · 거래조회결과** — 결제사는 거래 조회 결과를 쇼핑몰로 돌려준다.
- **쇼핑몰 · 거래조회결과 → 쇼핑몰 · 주문결제판정** — 쇼핑몰은 조회한 승인 상태와 주문을 대조해 고객에게 무엇을 알릴지 정한다.
- **쇼핑몰 · 주문결제판정 [승인주문확정] → 고객 · 주문확정안내** — 승인이 확인되고 주문이 확정되면 고객에게 확정을 알린다.
- **쇼핑몰 · 주문결제판정 [미승인확정] → 고객 · 결제미승인안내** — 최종 미승인이 확인되면 고객에게 결제가 성립하지 않았다고 알린다.
- **쇼핑몰 · 주문결제판정 [승인여부확인중] → 고객 · 결제확인중안내** — 승인 여부를 확인 중이면 고객에게 현재 상태를 안내하고 새 결제 요청을 보류한다.
- **쇼핑몰 · 주문결제판정 [승인후주문불가환불미의뢰] → 결제사 · 취소환불요청** — 결제가 승인됐지만 주문을 확정할 수 없고 아직 환불을 의뢰하지 않았으면, 쇼핑몰이 결제사에 해당 거래의 취소·환불을 의뢰한다.
- **쇼핑몰 · 주문결제판정 [승인후주문불가환불미의뢰] → 고객 · 주문불가환불안내** — 같은 경우 고객에게 주문을 이행할 수 없어 환불 절차를 시작한다고 알린다.
- **고객 · 결제상태조회 → 쇼핑몰 · 결제상태조회요청** — 고객은 나중에도 쇼핑몰에 해당 결제의 상태를 조회할 수 있다.
- **쇼핑몰 · 결제상태조회요청 → 고객 · 현재결제상태** — 쇼핑몰은 그 시점까지 확인된 결제 상태를 고객에게 보여 준다.

거래 조회가 지연되면 마지막으로 확인한 상태를 유지한다. 이후 같은 거래의 최종 결과가 확인되면 쇼핑몰은 그 결과를 고객에게 알린다. 고객 복귀와 결제사 통지로 같은 거래가 다시 확인되면 기존 주문·환불 결과를 사용한다. 이미 환불을 의뢰한 건은 기존 의뢰의 진행 상태를 확인한다.

#### 취소·환불을 의뢰한 뒤

**시작 사건** 쇼핑몰이 의뢰한 취소·환불 요청이 결제사에 도착한다. 의뢰가 생기는 시점은 앞 그림에서 승인 후 주문이 불가능하다고 판정했을 때 또는 M07에서 결제한 주문의 취소·반품 환불이 승인됐을 때다. 이후 결제사의 환불 상태 통지는 별도로 도착한다.

```jobflow
scope: 취소 환불 접수와 금융 처리 결과 안내
Object: 고객, 쇼핑몰, 운영자, 결제사
결제사.message.취소환불요청 --> 쇼핑몰.message.취소환불접수결과
쇼핑몰.message.취소환불접수결과 --> 쇼핑몰.환불접수판정
쇼핑몰.환불접수판정.접수됨 --> 고객.message.환불진행안내
쇼핑몰.환불접수판정.접수거절또는불명 --> 고객.message.환불접수지연안내
결제사.On환불상태통지 --> 쇼핑몰.message.환불상태알림
쇼핑몰.message.환불상태알림 --> 쇼핑몰.환불결과판정
쇼핑몰.환불결과판정.환불완료확정 --> 고객.message.환불완료안내
쇼핑몰.환불결과판정.실패통지 --> 고객.message.환불실패확인안내
쇼핑몰.환불결과판정.실패통지 --> 운영자.message.환불실패확인요청
운영자.message.환불실패확인요청 --> 결제사.message.환불내역대조요청
결제사.message.환불내역대조요청 --> 운영자.message.환불대조결과
운영자.message.환불대조결과 --> 쇼핑몰.message.환불조사회신
쇼핑몰.message.환불조사회신 --> 쇼핑몰.환불조사종결판정
쇼핑몰.환불조사종결판정.완료내역확보 --> 고객.message.환불완료정정안내
쇼핑몰.환불조사종결판정.실패사유확정 --> 고객.message.환불실패사유안내
```

- **결제사 · 취소환불요청 → 쇼핑몰 · 취소환불접수결과** — 결제사는 취소·환불 요청을 접수했는지 쇼핑몰에 회신한다.
- **쇼핑몰 · 취소환불접수결과 → 쇼핑몰 · 환불접수판정** — 쇼핑몰은 결제사가 보낸 접수 결과를 확인한다.
- **쇼핑몰 · 환불접수판정 [접수됨] → 고객 · 환불진행안내** — 접수됐으면 고객에게 환불이 진행 중이라고 알린다.
- **쇼핑몰 · 환불접수판정 [접수거절또는불명] → 고객 · 환불접수지연안내** — 접수가 거절됐거나 불명확하면 고객에게 지연을 알리고, 쇼핑몰은 같은 요청으로 접수 여부를 다시 확인한다.
- **결제사 · 환불상태통지 → 쇼핑몰 · 환불상태알림** — 결제사는 이후 해당 거래의 환불 상태가 바뀌면 쇼핑몰에 통지한다.
- **쇼핑몰 · 환불상태알림 → 쇼핑몰 · 환불결과판정** — 쇼핑몰은 통지된 상태로 금융 처리가 종결됐는지 확인한다.
- **쇼핑몰 · 환불결과판정 [환불완료확정] → 고객 · 환불완료안내** — 실제 환불이 완료됐으면 고객에게 환불 완료를 알린다.
- **쇼핑몰 · 환불결과판정 [실패통지] → 고객 · 환불실패확인안내** — 결제사가 실패를 통지하면 고객에게 그 사실과 운영자가 확인 중임을 알린다.
- **쇼핑몰 · 환불결과판정 [실패통지] → 운영자 · 환불실패확인요청** — 같은 실패 건에 대해 쇼핑몰이 운영자에게 확인을 요청한다.
- **운영자 · 환불실패확인요청 → 결제사 · 환불내역대조요청** — 운영자가 원거래와 환불 요청을 지정해 결제사에 처리 내역 대조를 의뢰한다.
- **결제사 · 환불내역대조요청 → 운영자 · 환불대조결과** — 결제사는 해당 환불의 처리 내역과 실패 사유를 운영자에게 회신한다.
- **운영자 · 환불대조결과 → 쇼핑몰 · 환불조사회신** — 운영자가 회신을 받은 뒤 근거와 확인 결과를 쇼핑몰에 등록한다.
- **쇼핑몰 · 환불조사회신 → 쇼핑몰 · 환불조사종결판정** — 쇼핑몰은 결제사 내역으로 환불 완료 또는 최종 실패를 확인할 수 있는지 판단한다.
- **쇼핑몰 · 환불조사종결판정 [완료내역확보] → 고객 · 환불완료정정안내** — 환불 완료가 뒤늦게 확인되면 고객에게 실제 완료 내역을 알려 앞선 안내를 정정한다.
- **쇼핑몰 · 환불조사종결판정 [실패사유확정] → 고객 · 환불실패사유안내** — 실패가 확정되면 고객에게 최종 사유와 후속 조치를 안내한다.

결제사 내역이 아직 불명확하면 운영자가 확인을 계속한다. 원거래의 환불 완료 여부가 밝혀지기 전에는 추가 환불을 의뢰하지 않는다.

## M07. 취소·반품·교환과 구매 리뷰

### M07-1. 출고 전 취소

**시작 사건** 고객이 주문에서 취소할 상품을 선택해 신청한다.

```jobflow
scope: 주문 취소와 환불 의뢰
Object: 고객, 쇼핑몰, 결제사
고객.On주문취소신청 --> 쇼핑몰.message.주문취소신청
쇼핑몰.message.주문취소신청 --> 쇼핑몰.취소가능판정
쇼핑몰.취소가능판정.출고전승인거래 --> 고객.message.취소접수안내
쇼핑몰.취소가능판정.출고전승인거래 --> 결제사.message.취소환불요청
쇼핑몰.취소가능판정.출고전미승인종결 --> 고객.message.주문취소완료
쇼핑몰.취소가능판정.결제상태미확정 --> 고객.message.취소확인중안내
쇼핑몰.취소가능판정.이미출고됨 --> 고객.message.취소불가안내
```

- **고객 · 주문취소신청 → 쇼핑몰 · 주문취소신청** — 고객이 취소할 주문과 상품, 사유를 제출한다.
- **쇼핑몰 · 주문취소신청 → 쇼핑몰 · 취소가능판정** — 쇼핑몰은 상품의 출고 여부와 결제 상태를 확인한다.
- **쇼핑몰 · 취소가능판정 [출고전승인거래] → 고객 · 취소접수안내** — 아직 출고하지 않은 상품의 결제가 승인됐으면 고객에게 취소 접수와 환불 대기를 알린다.
- **쇼핑몰 · 취소가능판정 [출고전승인거래] → 결제사 · 취소환불요청** — 쇼핑몰은 같은 결제 거래의 취소·환불을 결제사에 의뢰한다.
- **쇼핑몰 · 취소가능판정 [출고전미승인종결] → 고객 · 주문취소완료** — 승인 금액 없이 거래가 종결된 주문은 쇼핑몰이 취소를 마치고 고객에게 알린다.
- **쇼핑몰 · 취소가능판정 [결제상태미확정] → 고객 · 취소확인중안내** — 결제 결과를 확인 중이면 쇼핑몰은 고객에게 취소 대기를 안내한다.
- **쇼핑몰 · 취소가능판정 [이미출고됨] → 고객 · 취소불가안내** — 이미 출고한 상품이면 쇼핑몰은 취소가 어려운 이유와 반품 신청 방법을 알려 준다.

결제 결과가 늦어지면 쇼핑몰은 M05의 거래 조회로 원거래를 확인한 뒤 취소 가능 여부를 다시 판단한다. 환불을 의뢰한 주문의 완료 안내는 M05에서 결제사의 실제 환불 결과를 확인한 뒤 보낸다.

### M07-2. 반품·교환 접수와 상품 회수

**시작 사건** 상품을 받은 고객이 쇼핑몰에 반품이나 교환을 신청한다. 이 예제에서는 교환품 재고를 확보한 신청만 수거한다. 접수 뒤에는 택배사의 수거 배정, 고객과 기사의 상품 인계, 기사의 수거 등록, 택배사의 상태 통지가 각자 발생한 시점에 이어진다.

```jobflow
scope: 반품·교환 접수와 회수
Object: 택배기사, 택배사, 고객, 쇼핑몰, 물류센터
고객.On반품교환신청 --> 쇼핑몰.message.반품교환신청

쇼핑몰.수거대상판정.신청조건미충족 --> 고객.message.반품교환거절
쇼핑몰.수거대상판정.수거대상 --> 고객.message.반품교환접수안내
쇼핑몰.수거대상판정.수거대상 --> 택배사.message.반환상품수거요청
쇼핑몰.수거대상판정.수거대상 --> 물류센터.message.입고검수요청
물류센터.message.입고검수요청 --> 쇼핑몰.message.입고검수접수결과
택배사.message.반환상품수거요청 --> 쇼핑몰.message.수거접수결과
택배사.On수거배정 --> 택배기사.message.수거작업안내
고객.On반환상품전달 --> 택배기사.On반환상품인수
```

- **고객 · 반품교환신청 → 쇼핑몰 · 반품교환신청** — 고객이 주문 상품, 반품·교환 사유, 수거지와 필요한 교환 옵션을 제출한다.
- **쇼핑몰 · 반품교환신청 → 쇼핑몰 · 수거대상판정** — 쇼핑몰은 신청 기한과 상품 조건을 확인하고 교환이면 대체 재고도 확인한다.
- **쇼핑몰 · 수거대상판정 [신청조건미충족] → 고객 · 반품교환거절** — 기한이 지났거나 교환품을 확보할 수 없으면 쇼핑몰이 거절 사유를 알린다.
- **쇼핑몰 · 수거대상판정 [수거대상] → 고객 · 반품교환접수안내** — 수거할 수 있으면 쇼핑몰은 고객에게 신청 접수와 포장 방법을 안내한다.
- **쇼핑몰 · 수거대상판정 [수거대상] → 택배사 · 반환상품수거요청** — 쇼핑몰은 택배사에 수거지와 물류센터 도착지를 알려 수거를 의뢰한다.
- **쇼핑몰 · 수거대상판정 [수거대상] → 물류센터 · 입고검수요청** — 쇼핑몰은 물류센터에 도착 예정인 상품과 검수할 항목을 보낸다.
- **물류센터 · 입고검수요청 → 쇼핑몰 · 입고검수접수결과** — 물류센터는 입고·검수 의뢰의 접수 여부를 회신한다.
- **택배사 · 반환상품수거요청 → 쇼핑몰 · 수거접수결과** — 택배사는 수거 접수 여부를 쇼핑몰에 회신한다.
- **택배사 · 수거배정 → 택배기사 · 수거작업안내** — 수거 건을 배정한 택배사가 기사에게 방문지와 반환 상품을 알려 준다.
- **고객 · 반환상품전달 → 택배기사 · 반환상품인수** — 고객이 포장한 상품을 방문한 택배기사에게 건넨다.
- **택배기사 · 수거등록 → 택배사 · 수거완료등록** — 택배기사가 상품을 받은 뒤 택배사에 수거 사실을 등록한다.
- **택배사 · 수거상태통지 → 쇼핑몰 · 수거상태알림** — 택배사는 수거 상태가 바뀌면 쇼핑몰에 알리고 쇼핑몰은 신청 상태 조회에 반영한다.
- **택배기사 · 반환상품인계 → 물류센터 · 반환상품인수** — 택배기사가 반환 상품을 물류센터에 건네면 센터가 실물을 인수한다.

수거·검수 의뢰의 접수가 불분명하면 쇼핑몰은 같은 신청 건으로 접수 여부를 다시 확인한다. 검수 결과가 나오기 전에는 고객의 신청 상태에 수거 또는 검수 대기를 표시한다.

### M07-3. 검수 결과에 따른 환불·교환

**시작 사건** 실물을 검수한 물류센터가 쇼핑몰에 결과를 통지한다. 고객의 신청 상태 조회는 고객이 원할 때 시작하는 별도 사건이다.

```jobflow
scope: 검수 결과와 고객 신청의 처리
Object: 결제사, 고객, 쇼핑몰, 운영자, 물류센터
물류센터.On검수결과통지 --> 쇼핑몰.message.입고검수결과
쇼핑몰.message.입고검수결과 --> 쇼핑몰.검수후처리판정
쇼핑몰.검수후처리판정.반품수락 --> 결제사.message.취소환불요청
쇼핑몰.검수후처리판정.반품수락 --> 고객.message.반품환불진행안내
쇼핑몰.검수후처리판정.교환수락재고확보 --> 운영자.message.교환품출고의뢰
쇼핑몰.검수후처리판정.교환수락재고확보 --> 고객.message.교환품준비안내
쇼핑몰.검수후처리판정.검수기준미충족 --> 고객.message.검수거절안내
고객.On신청상태조회 --> 쇼핑몰.message.신청상태조회
쇼핑몰.message.신청상태조회 --> 고객.message.신청상태조회결과
```

- **물류센터 · 검수결과통지 → 쇼핑몰 · 입고검수결과** — 물류센터가 주문 상품과 회수한 상품의 일치 여부, 상품 상태와 검수 결과를 쇼핑몰에 보낸다.
- **쇼핑몰 · 입고검수결과 → 쇼핑몰 · 검수후처리판정** — 쇼핑몰은 검수 결과를 고객이 신청한 반품 또는 교환 건에 대조한다.
- **쇼핑몰 · 검수후처리판정 [반품수락] → 결제사 · 취소환불요청** — 반품을 수락하면 쇼핑몰이 결제사에 해당 상품 대금의 환불을 의뢰한다.
- **쇼핑몰 · 검수후처리판정 [반품수락] → 고객 · 반품환불진행안내** — 쇼핑몰은 고객에게 검수 통과와 환불 진행을 알린다.
- **쇼핑몰 · 검수후처리판정 [교환수락재고확보] → 운영자 · 교환품출고의뢰** — 교환을 수락하고 재고가 확보됐으면 쇼핑몰이 운영자에게 교환품 출고를 의뢰한다.
- **쇼핑몰 · 검수후처리판정 [교환수락재고확보] → 고객 · 교환품준비안내** — 쇼핑몰은 고객에게 검수 통과와 교환품 배송 준비를 알린다.
- **쇼핑몰 · 검수후처리판정 [검수기준미충족] → 고객 · 검수거절안내** — 상품이 검수 기준에 맞지 않으면 쇼핑몰은 고객에게 거절 사유와 상품 반환 방법을 알려 준다.
- **고객 · 신청상태조회 → 쇼핑몰 · 신청상태조회** — 고객이 접수한 주문에서 해당 신청의 진행 상황을 조회한다.
- **쇼핑몰 · 신청상태조회 → 고객 · 신청상태조회결과** — 쇼핑몰은 마지막으로 확인한 단계와 결과를 고객에게 보여 준다.

반품 대금의 환불 완료는 M05의 결제사 통지로 확인한다. 교환품은 M06의 배송 준비부터 고객 수령과 배송 완료 안내까지 이어진다.

### M07-4. 구매 리뷰 작성

**시작 사건** 고객이 주문 상품에서 리뷰 작성을 선택한다. 자격을 확인한 회원이 평점과 본문을 작성하고 제출하면 등록 판단이 시작된다.

```jobflow
scope: 구매 리뷰 작성 자격과 등록
Object: 고객, 쇼핑몰
고객.On리뷰작성시작 --> 쇼핑몰.message.리뷰작성자격조회
쇼핑몰.message.리뷰작성자격조회 --> 쇼핑몰.리뷰자격판정
쇼핑몰.리뷰자격판정.작성가능 --> 고객.message.리뷰작성안내
쇼핑몰.리뷰자격판정.회원인증필요 --> 고객.message.회원로그인안내
쇼핑몰.리뷰자격판정.작성자격없음 --> 고객.message.리뷰작성불가안내
고객.On리뷰제출 --> 쇼핑몰.message.리뷰등록요청
쇼핑몰.message.리뷰등록요청 --> 쇼핑몰.리뷰등록판정
쇼핑몰.리뷰등록판정.리뷰등록됨 --> 고객.message.리뷰등록완료
쇼핑몰.리뷰등록판정.입력보완필요 --> 고객.message.리뷰수정요청
쇼핑몰.리뷰등록판정.등록불가 --> 고객.message.리뷰등록불가안내
```

- **고객 · 리뷰작성시작 → 쇼핑몰 · 리뷰작성자격조회** — 고객이 주문 상품을 골라 리뷰를 작성할 수 있는지 확인한다.
- **쇼핑몰 · 리뷰작성자격조회 → 쇼핑몰 · 리뷰자격판정** — 쇼핑몰은 회원 본인의 구매인지, 이미 작성한 리뷰가 있는지 확인한다.
- **쇼핑몰 · 리뷰자격판정 [작성가능] → 고객 · 리뷰작성안내** — 구매 자격을 충족한 회원에게 쇼핑몰이 평점과 본문 입력을 안내한다.
- **쇼핑몰 · 리뷰자격판정 [회원인증필요] → 고객 · 회원로그인안내** — 로그인하지 않은 고객에게 쇼핑몰이 구매 회원 계정으로 로그인하도록 안내한다.
- **쇼핑몰 · 리뷰자격판정 [작성자격없음] → 고객 · 리뷰작성불가안내** — 해당 상품을 구매하지 않았거나 이미 작성한 회원에게 그 사유를 알린다.
- **고객 · 리뷰제출 → 쇼핑몰 · 리뷰등록요청** — 작성한 고객이 해당 상품의 평점과 본문을 제출한다.
- **쇼핑몰 · 리뷰등록요청 → 쇼핑몰 · 리뷰등록판정** — 쇼핑몰은 제출 시점의 자격과 입력 내용을 확인해 등록 결과를 판정한다.
- **쇼핑몰 · 리뷰등록판정 [리뷰등록됨] → 고객 · 리뷰등록완료** — 리뷰가 등록되면 쇼핑몰이 고객에게 작성 완료를 알린다.
- **쇼핑몰 · 리뷰등록판정 [입력보완필요] → 고객 · 리뷰수정요청** — 필수 항목이 빠졌으면 고객에게 수정할 항목을 알려 준다.
- **쇼핑몰 · 리뷰등록판정 [등록불가] → 고객 · 리뷰등록불가안내** — 쇼핑몰은 자격 변경, 중복 작성 또는 등록 실패의 사유와 고객이 취할 수 있는 조치를 알려 준다.
