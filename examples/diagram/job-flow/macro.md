# 쇼핑몰 매크로뷰

쇼핑몰을 **하나의 시스템**으로 보고, 그 시스템에 영향을 주는 외부 객체와의 관계를 그린다. 내부에 몇 개의 MSA 서비스가 있든 매크로에서는 모두 `쇼핑몰` 객체 하나에 포함한다.

이 그림의 목적은 **누가 쇼핑몰에 무엇을 요청하거나 알려 주고, 쇼핑몰이 외부에 무엇을 의뢰하고 돌려받는지** 확인하는 것이다. 서비스 호출 순서·저장소·검증 모듈·내부 타이머·재처리 작업은 [서비스뷰](services.md)와 [공통 계약](README.md)에서 다룬다.

## 외부 객체와 경계

| 객체 | 쇼핑몰과의 관계 |
| --- | --- |
| 사용자 | 회원·비회원으로 상품을 조회하고 주문·결제·구매 후 처리를 요청하며 결과를 확인한다. |
| 쇼핑몰 | 웹 UI와 모든 내부 서비스를 포함한 설계 대상 시스템 전체다. |
| 결제사 | PG의 역할이다. 외부 결제창·승인·거래 조회·취소·환불을 처리하고 거래 상태를 알린다. |
| 택배사 | 배송·수거를 접수하고 진행 상태를 알린다. |
| 물류센터 | 반환 상품의 입고·검수 결과를 알린다. 택배사와 같은 물류 사업자에 속하더라도 역할을 구분한다. |
| 인증발송사 | 이메일·문자로 가입·비밀번호 재설정·비회원 인증 정보를 전달한다. |

관리자나 입점업체도 설계 대상 시스템의 밖에서 운영·판매 업무를 요청하는 역할이라면 외부 객체다. 이 예제의 업무 범위는 고객의 탐색·구매·구매 후 처리이며, 관리자·입점업체의 별도 업무 시나리오는 범위에 포함하지 않는다.

객체명·프로세스명·메시지명은 한글로 쓴다. `scope`·`Object`·`message`는 Job Flow의 문법 키워드다. `사용자.주문하기`는 외부 객체의 행동, `쇼핑몰.배송의뢰`는 외부로 드러나는 쇼핑몰의 업무 요청을 뜻한다. 내부 함수 이름이나 실행 준비 이벤트를 나타내지 않는다.

## M00. 전체 외부 관계

```jobflow
scope: 쇼핑몰과 외부 객체의 관계
Object: 사용자, 쇼핑몰, 결제사, 택배사, 물류센터, 인증발송사
사용자.쇼핑이용 --> 쇼핑몰.message.이용요청
쇼핑몰.message.이용요청 --> 사용자.message.이용결과
쇼핑몰.결제의뢰 --> 결제사.message.결제처리요청
결제사.message.결제처리요청 --> 쇼핑몰.message.결제처리결과
쇼핑몰.배송수거의뢰 --> 택배사.message.배송수거요청
택배사.message.배송수거요청 --> 쇼핑몰.message.배송수거결과
쇼핑몰.입고검수의뢰 --> 물류센터.message.입고검수요청
물류센터.message.입고검수요청 --> 쇼핑몰.message.입고검수결과
쇼핑몰.인증전달의뢰 --> 인증발송사.message.인증발송요청
인증발송사.message.인증발송요청 --> 쇼핑몰.message.인증발송결과
```

- 한 선은 시스템 경계를 지나는 요청·결과·알림을 뜻한다. 전체 관계를 요약한 그림이며 내부 처리 순서를 뜻하지 않는다.
- 결제사·택배사·물류센터가 나중에 보내는 독립 알림은 해당 시나리오에서 따로 표시한다.

## M02. 계정·인증과 정보 전달

```jobflow
scope: 사용자 계정 요청과 외부 인증 발송
Object: 사용자, 쇼핑몰, 인증발송사
사용자.계정이용 --> 쇼핑몰.message.계정처리요청
쇼핑몰.message.계정처리요청 --> 사용자.message.계정처리결과
쇼핑몰.인증전달의뢰 --> 인증발송사.message.인증발송요청
인증발송사.message.인증발송요청 --> 쇼핑몰.message.인증발송결과
사용자.인증정보제출 --> 쇼핑몰.message.인증확인요청
쇼핑몰.message.인증확인요청 --> 사용자.message.인증확인결과
```

- 계정 요청은 가입·로그인·로그아웃·비밀번호 찾기와 재설정, 비회원 주문서 인증·주문 한 건의 조회 인증을 구분한다.
- 쇼핑몰은 필요한 인증 정보를 발송사에 전달하고 발송 결과를 받는다. 발송 접수, 사용자 인증 성공, 가입 완료, 로그인 완료는 서로 다른 결과다.
- 코드 불일치·만료·사용된 링크·인증 실패를 구분해 안내한다. 비밀번호 찾기와 비회원 주문 조회의 접수 안내로 계정·주문 존재 여부를 노출하지 않는다.

## M05. 주문 생성·결제사와의 관계

### M05-1. 주문 생성·결제창 발급과 사용자 복귀

```jobflow
scope: 주문 생성부터 외부 결제창 이용과 쇼핑몰 복귀까지
Object: 사용자, 쇼핑몰, 결제사
사용자.주문하기 --> 쇼핑몰.message.주문생성요청
쇼핑몰.message.주문생성요청 --> 사용자.message.주문생성결과
사용자.결제하기 --> 쇼핑몰.message.결제시작요청
쇼핑몰.결제창발급의뢰 --> 결제사.message.결제창발급요청
결제사.message.결제창발급요청 --> 쇼핑몰.message.결제창발급결과
쇼핑몰.message.결제시작요청 --> 사용자.message.결제시작결과
사용자.외부결제진행 --> 결제사.message.외부결제요청
결제사.message.외부결제요청 --> 사용자.message.결제창복귀정보
사용자.결제창에서복귀 --> 쇼핑몰.message.결제확인요청
쇼핑몰.message.결제확인요청 --> 사용자.message.결제확인결과
```

- 사용자는 회원 인증 또는 비회원 주문서 인증과 함께 상품·수량·배송지·할인 정보를 제출한다.
- 쇼핑몰은 생성한 주문 또는 가격 변경·품절·인증 필요·실패·확인 중을 구분해 반환한다. 주문 생성은 결제 완료가 아니다. 응답을 받지 못한 주문은 같은 주문 요청의 결과를 다시 확인한다.
- 쇼핑몰은 사용자의 결제 요청을 받아 결제 가능한 주문에 대해 결제창을 발급받고 사용자에게 제공한다. 이미 결제됐거나 취소·만료·처리 중인 주문은 새 결제창을 열지 않는 결과를 돌려준다.
- 사용자는 결제사의 화면에서 결제를 진행하고 쇼핑몰로 돌아온다. 브라우저의 복귀 정보만으로 결제·주문 완료를 확정하지 않는다. 결제사와의 서버 확인은 다음 그림의 거래 조회 관계를 이용한다.

### M05-2. 거래 확인·독립 알림·취소와 환불

```jobflow
scope: 쇼핑몰과 결제사의 거래 확인
Object: 사용자, 쇼핑몰, 결제사
결제사.거래상태통지 --> 쇼핑몰.message.거래상태알림
쇼핑몰.message.거래상태알림 --> 결제사.message.알림접수결과
쇼핑몰.거래확인의뢰 --> 결제사.message.거래조회요청
결제사.message.거래조회요청 --> 쇼핑몰.message.거래조회결과
쇼핑몰.취소환불의뢰 --> 결제사.message.취소환불요청
결제사.message.취소환불요청 --> 쇼핑몰.message.취소환불결과
결제사.환불상태통지 --> 쇼핑몰.message.환불상태알림
사용자.결제결과조회 --> 쇼핑몰.message.결제상태요청
쇼핑몰.message.결제상태요청 --> 사용자.message.결제상태결과
```

- 결제사의 서버 알림은 사용자의 브라우저 복귀와 별개다. 쇼핑몰은 거래를 조회해 승인·미승인·처리 중·결과 불명을 확인하고 사용자에게 현재 결과를 제공한다.
- 실제 결제 후 주문을 성립시킬 수 없거나 고객의 취소·반품 환불이 승인되면, 쇼핑몰은 같은 거래의 취소·환불을 의뢰한다. 접수 결과와 실제 환불 완료를 구분한다.
- 화면 이탈이나 로그인 만료가 승인된 결제의 취소를 뜻하지 않는다. 결과가 불명확한 동안 새 결제를 요구하지 않는다. 내부 복구 책임과 처리 순서는 서비스뷰에서 다룬다.

## M06. 주문 조회·배송

```jobflow
scope: 사용자와 택배사에 연결되는 주문 배송
Object: 사용자, 쇼핑몰, 택배사
사용자.주문조회 --> 쇼핑몰.message.주문조회요청
쇼핑몰.message.주문조회요청 --> 사용자.message.주문조회결과
쇼핑몰.배송의뢰 --> 택배사.message.배송접수요청
택배사.message.배송접수요청 --> 쇼핑몰.message.배송접수결과
택배사.배송상태통지 --> 쇼핑몰.message.배송상태알림
사용자.배송조회 --> 쇼핑몰.message.배송조회요청
쇼핑몰.message.배송조회요청 --> 사용자.message.배송조회결과
쇼핑몰.배송확인의뢰 --> 택배사.message.배송조회요청
택배사.message.배송조회요청 --> 쇼핑몰.message.배송조회결과
```

- 쇼핑몰은 결제와 출고 가능 여부가 확인된 주문의 배송을 택배사에 의뢰하고 접수 결과·배송 상태를 받는다. 접수와 실제 출고·배송 완료는 구분한다.
- 사용자는 본인 주문과 배송을 조회한다. 비회원 조회 권한은 인증한 주문 한 건으로 제한하며, 배송 준비 중·확인 지연·조회 실패를 배송 완료로 표시하지 않는다.

## M07. 취소·반품·교환·구매 리뷰

```jobflow
scope: 취소 반품 교환의 신청과 후속 처리 및 구매 리뷰
Object: 사용자, 쇼핑몰, 택배사, 물류센터, 결제사
사용자.취소반품교환신청 --> 쇼핑몰.message.구매후처리요청
쇼핑몰.message.구매후처리요청 --> 사용자.message.구매후처리결과
쇼핑몰.수거의뢰 --> 택배사.message.수거접수요청
택배사.message.수거접수요청 --> 쇼핑몰.message.수거접수결과
택배사.수거상태통지 --> 쇼핑몰.message.수거상태알림
쇼핑몰.입고검수의뢰 --> 물류센터.message.입고검수요청
물류센터.message.입고검수요청 --> 쇼핑몰.message.입고검수결과
물류센터.검수결과통지 --> 쇼핑몰.message.검수결과알림
쇼핑몰.취소환불의뢰 --> 결제사.message.취소환불요청
결제사.message.취소환불요청 --> 쇼핑몰.message.취소환불결과
결제사.환불상태통지 --> 쇼핑몰.message.환불상태알림
쇼핑몰.교환품배송의뢰 --> 택배사.message.배송접수요청
택배사.message.배송접수요청 --> 쇼핑몰.message.배송접수결과
택배사.배송상태통지 --> 쇼핑몰.message.배송상태알림
사용자.신청상태조회 --> 쇼핑몰.message.신청상태요청
쇼핑몰.message.신청상태요청 --> 사용자.message.신청상태결과
사용자.리뷰이용 --> 쇼핑몰.message.리뷰처리요청
쇼핑몰.message.리뷰처리요청 --> 사용자.message.리뷰처리결과
```

- 취소·반품·교환을 신청할 때 사용자는 대상 주문·상품·사유와 필요한 수거·교환 정보를 제출한다. 쇼핑몰은 신청 가능 여부·접수·거절·처리 중·완료를 구분해 제공한다.
- 출고·신청 기한·교환 재고 등의 조건이 달라지면 신청을 거절할 수 있다. 접수만으로 환불이나 교환 배송이 완료됐다고 표시하지 않는다.
- 출고 전 취소에는 수거를 의뢰하지 않는다. 반품·교환은 필요한 수거와 입고·검수를 외부에 의뢰하며, 수거 완료를 검수 합격으로 간주하지 않는다.
- 쇼핑몰은 취소 승인 또는 반품 검수 수락 후 필요한 취소·환불을 결제사에 의뢰하고 실제 완료를 확인한다. 결제가 승인되지 않은 취소는 금융 종결을 확인한 뒤 환불 없이 완료할 수 있다.
- 교환은 기존 상품의 검수 수락과 교환 재고 확보 후 교환품 배송을 의뢰한다. 환불·배송 메시지는 M05·M06과 같은 외부 계약을 사용한다.
- 사용자는 신청 상태를 조회해 수거·검수·환불·교환품 배송의 현재 결과를 확인한다. 검수 거절·확인 지연은 해당 신청 상태로 제공하며, 접수 결과와 실제 업무 완료를 구분한다.
- 구매 리뷰는 취소·반품·교환 신청과 별도로 이용한다. 사용자는 작성 자격을 확인하거나 평점·본문 등을 제출한다. 쇼핑몰은 구매 자격·중복 작성 여부와 등록 결과를 제공한다.
- 비회원은 리뷰를 작성할 수 없으며, 입력 오류·인증 필요·작성 불가·등록 실패를 성공과 구별한다.
- 각 선은 해당 조건에서 발생하는 외부 요청·결과·독립 알림이다. 모든 이용이 그림의 모든 관계를 거치거나, 알림이 앞선 요청의 즉시 응답으로 도착한다는 뜻은 아니다.
