# 쇼핑몰 MSA 서비스뷰

[쇼핑몰 매크로뷰](macro.md)의 **쇼핑몰**을 아홉 서비스로 나눈 설계 예제다. 예를 들어 결제사는 돈이 승인됐다고 알릴 수 있지만, 상품 재고까지 확보해 주문을 확정하는 서비스는 **주문**이다. **배송**은 그 주문의 확정 사건을 받은 뒤에야 출고 건을 연다.

| 서비스 | 이 서비스가 결정하고 기록하는 것 |
| --- | --- |
| 회원인증 | 회원의 신원, 비회원 인증 코드의 유효기간·사용 여부, 인증한 주문 한 건의 열람 권한 |
| 상품 | 판매 중인 상품과 옵션, 주문 시 적용할 가격·할인 조건 |
| 재고 | 상품별 가용 수량, 주문·교환에 예약한 수량, 예약의 확정·해제 |
| 주문 | 고객이 수락한 금액과 상품·배송지의 주문 시점 사본, 주문 확정과 상품별 취소 상태 |
| 결제 | 결제 시도, 결제사에서 확인한 승인·미승인 상태, 원거래별 환불 가능 잔액과 환불 결과 |
| 배송 | 일반·교환 출고 건, 출고 중지와 실물 인계 확인, 운송장, 배달·수거 경과 |
| 구매후처리 | 취소·반품·교환 신청, 물류센터의 검수 결과, 환불이나 교환 배송을 기다리는 신청의 상태 |
| 알림 | 업무별 수신 대상·채널, 발송사에 의뢰한 문자·메일과 발송 결과 |
| 리뷰 | 회원의 구매 리뷰, 같은 주문 상품에 대한 중복 등록 여부 |

도표의 열에는 백엔드 서비스와 공개 요청·응답을 주고받는 화면을 둔다. **고객프론트**는 고객 요청과 결과 표시, **운영대시보드**는 운영 작업 지시와 결과 확인을 맡는다. 주문·배송·결제 상태의 원본은 각 서비스가 소유한다. 화면에서 나중에 상태를 다시 여는 행동은 독립 진입점이다. `재고.message.재고예약요청`처럼 받는 쪽에 붙은 메시지는 특정 서비스에 건네는 요청이나 회신이다. `배송.On주문확정`은 주문 서비스가 **확정된 사실**을 발행한 뒤 배송이 독립적으로 일을 시작하는 지점이다. 제목 아래의 시작 사건에서 화면 요청·외부 통지·구독 사건을 구분한다. 각 서비스는 자기 기록을 먼저 확정하고 발행할 사건을 함께 남긴다. 통지나 회신이 늦으면 같은 주문·거래·신청의 처리 결과를 확인한다.

## S02. 비회원이 주문 한 건을 열람할 권한 얻기

주문 서비스는 주문 당시의 연락처와 주문 내역을 보관한다. 회원인증 서비스는 조회 코드를 발급하고 어느 주문을 열람할 수 있는지 판정한다. [매크로 M02](macro.md#m02-비회원이-인증-문자를-받아-주문-한-건-조회하기)

**시작 사건** 비회원이 주문번호와 연락처로 인증 문자를 신청한다. 회원인증은 주문의 존재나 연락처 일치 여부에 관계없이 화면에 같은 접수 안내를 돌려준다. 발송사가 문자를 전달하고 고객이 같은 주문번호와 받은 코드를 입력하면, 도표 아래쪽의 **고객프론트 · 인증코드제출**에서 조회가 이어진다.

```jobflow
scope: 비회원의 인증 문자 신청부터 코드 제출과 주문 한 건 열람까지
Object: 고객프론트, 주문, 회원인증, 알림, 발송사, 고객
고객프론트.On인증문자신청 --> 회원인증.message.주문조회인증요청
회원인증.message.주문조회인증요청 --> 고객프론트.message.인증신청접수안내
회원인증.message.주문조회인증요청 --> 주문.message.주문연락처대조요청
주문.message.주문연락처대조요청 --> 주문.주문연락처대조
주문.주문연락처대조.주문없음또는연락처불일치 --> 회원인증.message.주문연락처미확인
주문.주문연락처대조.연락처일치 --> 회원인증.message.주문연락처일치확인
회원인증.message.주문연락처일치확인 --> 알림.message.인증문자발송요청
알림.message.인증문자발송요청 --> 알림.문자발송의뢰
알림.문자발송의뢰 --> 발송사.message.인증문자발송요청
발송사.message.인증문자발송요청 --> 고객.message.주문조회인증문자
알림.문자발송의뢰.접수확인 --> 회원인증.message.인증문자발송접수
알림.문자발송의뢰.미접수확정 --> 회원인증.message.인증문자접수실패
알림.문자발송의뢰.접수여부불명 --> 회원인증.message.인증문자접수확인중
알림.On문자접수재확인시점 --> 알림.문자접수결과조회
알림.문자접수결과조회.접수확인 --> 회원인증.message.인증문자발송접수
알림.문자접수결과조회.미접수확정 --> 회원인증.message.인증문자접수실패
알림.문자접수결과조회.접수여부불명
고객프론트.On인증코드제출 --> 주문.message.주문조회코드확인요청
주문.message.주문조회코드확인요청 --> 회원인증.message.주문조회코드검증요청
회원인증.message.주문조회코드검증요청 --> 회원인증.주문조회코드검증
회원인증.주문조회코드검증.유효한코드 --> 주문.message.주문열람허용
주문.message.주문열람허용 --> 고객프론트.message.인증한주문내역
회원인증.주문조회코드검증.코드불일치 --> 주문.message.코드재입력필요
주문.message.코드재입력필요 --> 고객프론트.message.코드재입력안내
회원인증.주문조회코드검증.코드효력종료 --> 주문.message.코드재발급필요
주문.message.코드재발급필요 --> 고객프론트.message.코드재발급안내
회원인증.주문조회코드검증.판정기록미확정 --> 주문.message.인증코드검증확인중
주문.message.인증코드검증확인중 --> 고객프론트.message.인증코드검증대기안내
고객프론트.message.인증코드검증대기안내 --> 고객프론트.대기후검증재확인
고객프론트.대기후검증재확인 --> 주문.message.주문조회코드확인요청
주문.On검증응답기한경과 --> 주문.검증응답도착확인
주문.검증응답도착확인.응답없고요청대기중 --> 고객프론트.message.인증코드검증대기안내
고객프론트.message.인증코드검증대기안내 --> 고객프론트.대기후검증재확인
고객프론트.대기후검증재확인 --> 주문.message.주문조회코드확인요청
```

- **고객프론트 · 인증문자신청 → 회원인증 · 주문조회인증요청** — 고객이 입력한 주문번호와 연락처를 회원인증에 보낸다.
- **회원인증 · 주문조회인증요청 → 고객프론트 · 인증신청접수안내** — 회원인증은 모든 신청에 “요청을 받았습니다. 잠시 기다려 주세요”라고 안내한다. 주문 유무, 연락처 일치 여부, 발송 상태에 따라 이 안내를 바꾸지 않는다.
- **회원인증 · 주문조회인증요청 → 주문 · 주문연락처대조요청** — 회원인증은 신청에 적힌 주문번호와 연락처를 주문 서비스에 보내 대조를 요청한다.
- **주문 · 주문연락처대조요청 → 주문 · 주문연락처대조** — 주문 서비스는 해당 번호로 주문을 찾아 주문 당시의 연락처와 제출된 연락처를 비교한다.
- **주문 · 주문연락처대조 [주문없음또는연락처불일치] → 회원인증 · 주문연락처미확인** — 주문이 없거나 연락처가 다르면 주문 서비스는 두 경우를 같은 미확인 결과로 회신한다. 회원인증은 코드를 발급하지 않고 신청을 마친다.
- **주문 · 주문연락처대조 [연락처일치] → 회원인증 · 주문연락처일치확인** — 연락처가 일치하면 주문 서비스는 회원인증에 해당 주문번호의 연락처가 확인됐다고 회신한다.
- **회원인증 · 주문연락처일치확인 → 알림 · 인증문자발송요청** — 일치 회신을 받은 회원인증은 해당 주문에만 쓸 코드와 유효기한을 기록하고 알림 서비스에 확인된 연락처로 문자 발송을 요청한다.
- **알림 · 인증문자발송요청 → 알림 · 문자발송의뢰** — 알림 서비스는 코드가 담긴 문자를 발송사에 의뢰하고 응답을 확인한다. 일시적인 호출 제한으로 미접수가 명시되면 제한이 풀린 뒤 코드 유효기한 안에서 재시도한다.
- **알림 · 문자발송의뢰 → 발송사 · 인증문자발송요청** — 알림이 같은 의뢰 번호로 확인된 연락처에 인증 문자를 보내 달라고 요청한다.
- **발송사 · 인증문자발송요청 → 고객 · 주문조회인증문자** — 발송사가 단말기에 문자를 전달하면 고객이 코드를 확인한다. 이후 고객이 주문 화면에 직접 코드를 입력해 제출한다.
- **알림 · 문자발송의뢰 [접수확인] → 회원인증 · 인증문자발송접수** — 발송사가 접수를 확인하면 알림 서비스는 회원인증에 접수 사실을 알린다. 주문 열람 권한은 고객이 코드를 제출해 검증받을 때 생긴다.
- **알림 · 문자발송의뢰 [미접수확정] → 회원인증 · 인증문자접수실패** — 잘못된 요청 형식으로 접수할 수 없거나, 미접수 상태로 재시도 기한이 끝나면 알림 서비스는 접수 실패를 회신한다. 회원인증은 그 의뢰에 발급한 코드를 무효화한다.
- **알림 · 문자발송의뢰 [접수여부불명] → 회원인증 · 인증문자접수확인중** — 응답 시간 초과로 접수 여부를 알 수 없으면 알림 서비스는 확인 중으로 회신한다. 회원인증은 코드의 기존 유효기한을 유지하고, 알림 서비스는 발송사에서 같은 의뢰를 조회할 수 있는 경우에 재확인을 예약한다. 끝까지 확인할 수 없으면 코드는 원래 기한에 만료된다.
- **알림 · 문자접수재확인시점 → 알림 · 문자접수결과조회** — 접수 여부가 불명인 건은 유효기한 안에서 같은 의뢰의 접수 결과를 조회한다. 결과가 여전히 불명이면 다음 확인을 기다리고, 기한이 지나면 조회를 마친다.
- **알림 · 문자접수결과조회 [접수확인] → 회원인증 · 인증문자발송접수** — 뒤늦게 확인한 접수 결과를 회원인증에 알린다.
- **알림 · 문자접수결과조회 [미접수확정] → 회원인증 · 인증문자접수실패** — 미접수가 확정되고 재시도도 마쳤으면 알림이 접수 실패를 통지하고 회원인증은 해당 코드를 무효화한다.
- **고객프론트 · 인증코드제출 → 주문 · 주문조회코드확인요청** — 고객이 받은 문자에서 코드를 입력해 제출하면 화면은 검증 요청 번호를 붙여 코드와 주문번호를 주문 서비스에 보낸다.
- **주문 · 주문조회코드확인요청 → 회원인증 · 주문조회코드검증요청** — 주문은 해당 요청 번호로 회원인증에 검증을 요청하고 응답을 기다린다. 회원인증에 요청이 전달돼도 이 시점에는 아직 검증 결과를 받은 상태가 아니다.
- **회원인증 · 주문조회코드검증요청 → 회원인증 · 주문조회코드검증** — 회원인증은 그 주문에 발급한 코드와 제출값을 대조하고 유효기한과 사용 여부를 확인한다.
- **회원인증 · 주문조회코드검증 [유효한코드] → 주문 · 주문열람허용** — 유효하면 회원인증은 코드 사용과 해당 검증 요청의 허용 결과를 함께 기록하고 인증된 주문번호를 회신한다. 주문 서비스는 요청한 번호와 일치하는 한 건의 내역만 화면에 보여 준다.
- **주문 · 주문열람허용 → 고객프론트 · 인증한주문내역** — 주문은 인증된 번호와 일치하는 한 건의 주문 내역을 돌려준다.
- **회원인증 · 주문조회코드검증 [코드불일치] → 주문 · 코드재입력필요** — 해당 주문과 코드가 일치하지 않으면 회원인증은 재입력이 필요하다고 회신하고 주문 서비스는 화면에 코드 재입력을 안내한다.
- **주문 · 코드재입력필요 → 고객프론트 · 코드재입력안내** — 고객이 같은 주문의 코드를 다시 입력할 수 있게 한다.
- **회원인증 · 주문조회코드검증 [코드효력종료] → 주문 · 코드재발급필요** — 제출값이 해당 주문에 발급한 코드와 일치해도 만료됐거나 이미 사용·무효화된 코드이면 회원인증은 재발급이 필요하다고 회신한다. 주문 서비스는 화면에서 새 인증 문자를 신청하도록 안내한다.
- **주문 · 코드재발급필요 → 고객프론트 · 코드재발급안내** — 새 인증 문자를 신청할 수 있게 한다.
- **회원인증 · 주문조회코드검증 [판정기록미확정] → 주문 · 인증코드검증확인중** — 검증 결과를 확정해 기록했는지 확인할 수 없으면 회원인증은 같은 검증 요청을 확인 중이라고 회신한다.
- **주문 · 인증코드검증확인중 → 고객프론트 · 인증코드검증대기안내** — 주문은 화면에 “인증 결과를 확인 중입니다. 잠시 기다려 주세요”라고 안내한다.
- **고객프론트 · 인증코드검증대기안내 → 고객프론트 · 대기후검증재확인** — 확인 중이라는 응답을 받은 화면은 대기 안내를 표시하고 잠시 뒤 검증 결과를 재확인한다.
- **고객프론트 · 대기후검증재확인 → 주문 · 주문조회코드확인요청** — 최초 제출과 같은 검증 요청 번호·주문번호·코드로 다시 조회한다.
- **주문 · 검증응답기한경과 → 주문 · 검증응답도착확인** — 회원인증의 회신을 기다리던 주문은 응답 기한이 지나면 해당 요청의 확정 응답이 도착했는지 확인한다.
- **주문 · 검증응답도착확인 [응답없고요청대기중] → 고객프론트 · 인증코드검증대기안내** — 주문은 아직 회신하지 않은 화면에 확인 중을 돌려준다. 응답이 이미 도착했다면 그 판정을 사용한다. 대기 안내를 보낸 뒤 확정 회신이 도착하면 결과를 다음 재확인에 사용한다.
- **고객프론트 · 인증코드검증대기안내 → 고객프론트 · 대기후검증재확인** — 회원인증의 응답 기한이 지나 주문이 대기 안내를 보내면, 화면은 안내를 보여 주고 잠시 뒤 재확인한다.
- **고객프론트 · 대기후검증재확인 → 주문 · 주문조회코드확인요청** — 같은 검증 요청 번호·주문번호·코드로 앞의 검증 경로에 다시 들어간다.

접수 뒤에도 발송사가 단말기에 문자를 전달하지 못할 수 있다. 알림 서비스는 발송사의 결과 조회나 통지로 확인한 배달 결과를 같은 발송 건에 따로 기록한다. 고객 화면에는 신청 때의 공통 접수 안내가 유지되며, 문자를 받지 못한 고객은 새 코드를 신청할 수 있다.

화면의 재확인은 같은 번호·주문·코드에 묶인다. 회원인증은 이 요청에 확정한 판정이 있으면 그 판정을 돌려준다. 화면의 대기 기한이 지나도 결과가 불명이면 확인이 지연됐음을 표시하고 고객이 같은 요청의 결과를 다시 확인할 수 있게 한다. 새 입력으로 이미 사용한 코드를 제출하면 재발급 대상이다.

## S05. 주문과 결제

가격과 할인은 상품, 판매 수량은 재고, 결제와 환불의 근거가 되는 승인 기록은 결제가 제공한다. 주문이 이 결과를 모아 주문 상태를 결정한다. [매크로 M05](macro.md#m05-주문과-결제)

### S05-1. 주문 접수와 재고 예약

**시작 사건** 인증을 마친 고객이 주문서를 제출한다. 이 예제에서는 주문서의 모든 항목이 접수 가능해야 주문 한 건을 만든다. 주문 서비스는 주문 시점의 금액을 보관하고, 재고 서비스는 요청한 수량과 예약 기한을 관리한다.

```jobflow
scope: 주문서 가격 확인과 판매 수량 예약
Object: 고객프론트, 상품, 주문, 재고
고객프론트.On주문서제출 --> 주문.message.주문생성요청
주문.message.주문생성요청 --> 상품.message.판매조건조회
상품.message.판매조건조회 --> 상품.판매조건판정
상품.판매조건판정.판매중단 --> 주문.message.판매중단안내
주문.message.판매중단안내 --> 고객프론트.message.판매중단상품안내
상품.판매조건판정.판매가능 --> 주문.message.판매조건회신
주문.message.판매조건회신 --> 주문.주문서대조
주문.주문서대조.판매조건변경 --> 고객프론트.message.변경된가격과할인
주문.주문서대조.판매조건일치 --> 재고.message.재고예약요청
재고.message.재고예약요청 --> 재고.주문수량예약
재고.주문수량예약.가용수량부족 --> 주문.message.주문수량품절
주문.message.주문수량품절 --> 고객프론트.message.품절상품안내
재고.주문수량예약.요청수량예약됨 --> 주문.message.주문수량예약확인
주문.message.주문수량예약확인 --> 주문.주문생성판정
주문.주문생성판정.생성결과미확정 --> 고객프론트.message.주문생성확인중
주문.주문생성판정.주문생성확인 --> 고객프론트.message.결제대기주문번호
주문.주문생성판정.주문생성불가확정 --> 고객프론트.message.주문실패안내
주문.주문생성판정.주문생성불가확정 --> 재고.message.주문예약해제요청
고객프론트.On주문생성재확인 --> 주문.message.주문생성결과조회
주문.message.주문생성결과조회 --> 고객프론트.message.주문생성상태
```

- **고객프론트 · 주문서제출 → 주문 · 주문생성요청** — 고객이 확인한 상품·수량·판매 조건을 주문 서비스에 제출한다.
- **주문 · 주문생성요청 → 상품 · 판매조건조회** — 주문 서비스는 주문서의 상품·수량·할인 조건을 상품 서비스에 보내 현재 판매 조건을 묻는다.
- **상품 · 판매조건조회 → 상품 · 판매조건판정** — 상품 서비스는 요청한 상품·옵션이 판매 중인지 확인하고 판매 중인 항목에는 현재 가격과 적용할 할인을 계산한다.
- **상품 · 판매조건판정 [판매중단] → 주문 · 판매중단안내** — 상품 서비스는 판매가 중단된 항목을 회신한다. 주문 서비스는 해당 항목을 고객에게 알리고 이번 주문서 전체의 접수를 보류한다.
- **주문 · 판매중단안내 → 고객프론트 · 판매중단상품안내** — 주문을 접수할 수 없는 상품을 화면에 표시한다.
- **상품 · 판매조건판정 [판매가능] → 주문 · 판매조건회신** — 상품 서비스는 주문할 수 있는 항목의 현재 가격과 할인 조건을 주문 서비스에 돌려준다.
- **주문 · 판매조건회신 → 주문 · 주문서대조** — 주문은 회신과 고객이 동의한 주문서를 대조한다. 그림의 `판매조건변경`이면 달라진 가격·할인을 고객에게 보여 주고, 새 조건으로 다시 제출할 때까지 이 주문서의 재고 예약을 보류한다.
- **주문 · 주문서대조 [판매조건변경] → 고객프론트 · 변경된가격과할인** — 바뀐 주문 금액과 할인액을 보여 주고 고객의 재확인을 받는다.
- **주문 · 주문서대조 [판매조건일치] → 재고 · 재고예약요청** — 조건이 일치하면 주문 서비스가 주문 건을 식별하는 번호로 재고를 예약한다.
- **재고 · 재고예약요청 → 재고 · 주문수량예약** — 재고 서비스는 같은 예약 요청의 기존 결과를 먼저 확인하고, 새 요청이면 주문 수량을 확보할 수 있는지 판정한다.
- **재고 · 주문수량예약 [가용수량부족] → 주문 · 주문수량품절** — 한 항목이라도 요청 수량이 부족하면 재고 서비스는 이번 주문서의 수량을 예약하지 않고 품절 항목을 회신한다. 주문은 고객에게 해당 항목을 알리고 접수를 종료한다.
- **주문 · 주문수량품절 → 고객프론트 · 품절상품안내** — 재고를 확보하지 못한 상품을 고객에게 보여 준다.
- **재고 · 주문수량예약 [요청수량예약됨] → 주문 · 주문수량예약확인** — 재고 서비스는 확보한 예약 번호와 기한을 주문 서비스에 회신한다.
- **주문 · 주문수량예약확인 → 주문 · 주문생성판정** — 주문 서비스는 유효한 예약을 연결해 주문을 결제 대기로 저장한다. 생성이 확인되면 고객에게 주문번호를 돌려주고, 결과가 불명이면 같은 주문번호로 생성 여부를 확인한다.
- **주문 · 주문생성판정 [생성결과미확정] → 고객프론트 · 주문생성확인중** — 같은 주문의 생성 결과를 확인하고 있음을 표시한다.
- **주문 · 주문생성판정 [주문생성확인] → 고객프론트 · 결제대기주문번호** — 새 주문번호를 표시하고 고객이 결제를 시작할 수 있게 한다.
- **주문 · 주문생성판정 [주문생성불가확정] → 고객프론트 · 주문실패안내** — 주문이 생성되지 않았다는 결과와 사유를 반환한다.
- **주문 · 주문생성판정 [주문생성불가확정] → 재고 · 주문예약해제요청** — 주문을 끝내 생성할 수 없으면 주문이 예약 번호로 해제를 요청한다. 재고는 해당 예약에서 아직 잡혀 있는 수량만 풀어준다.
- **고객프론트 · 주문생성재확인 → 주문 · 주문생성결과조회** — 확인 중 안내를 본 화면이 잠시 뒤 같은 주문 요청 번호의 생성 결과를 조회한다.
- **주문 · 주문생성결과조회 → 고객프론트 · 주문생성상태** — 주문은 기존 요청의 생성 여부와 결제 가능한 주문번호를 조회해 화면에 돌려준다. 결과가 불명이면 같은 요청을 확인한다.

같은 주문서 제출은 기존 접수 결과를 돌려준다. 예약 회신이 끊기면 화면에는 확인 중으로 표시하고 같은 번호로 예약 결과를 다시 확인한다.

### S05-2. 결제창 발급과 승인 확인

#### 결제창 발급과 발급 결과 재확인

**시작 사건** 고객이 주문에서 결제를 선택한다. 이 예제에서는 발급 응답이 끊기면 주문 화면이 같은 발급 요청의 상태를 다시 조회한다. 결제사는 기존 발급 요청을 식별해 결과를 조회할 수 있다고 가정한다.


- **주문 · 결제확인요청 → 결제 · 거래조회요청** — 고객이 결제창에서 돌아오면 주문 서비스가 결제 서비스에 원거래의 상태를 묻는다.
- **결제 · 거래조회요청 → 결제 · 원거래조회** — 결제 서비스는 결제사에서 해당 시도의 승인 상태와 거래 금액을 확인한다.
- **결제 · 원거래조회 [승인확인] → 주문 · 거래승인확인** — 결제 서비스가 승인 번호와 금액을 회신하면 주문 서비스는 자신의 주문 확정 상태와 함께 보여 준다. 이 회신만으로 출고를 시작하지 않는다.
- **주문 · 거래승인확인 → 고객프론트 · 거래승인과주문상태** — 주문 서비스는 확인된 결제 승인과 현재 주문 상태를 함께 돌려준다.
- **고객프론트 · 거래승인과주문상태 → 고객프론트 · 결제승인과주문상태표시** — 화면은 결제 승인을 표시하고 주문 상태에 따라 확정 대기, 주문 확정 또는 상품을 제공할 수 없다는 안내를 보여 준다.
- **고객프론트 · 결제승인과주문상태표시 [주문확정대기] → 주문 · 주문결과조회요청** — 아직 주문 확정 전이면 화면은 “결제가 승인됐습니다. 주문 확인 중입니다”를 표시하고 잠시 뒤 같은 주문번호로 주문 처리 결과를 조회한다.
- **주문 · 주문결과조회요청 → 고객프론트 · 주문확정상태** — 주문은 현재 주문 상태를 반환한다.
- **고객프론트 · 주문확정상태 → 고객프론트 · 주문결과화면갱신** — 화면은 결과에 맞게 내용을 갱신한다. 대기가 계속되면 같은 주문을 다시 조회하고, 자동 확인 시간이 지나면 고객이 주문 내역에서 결과를 다시 볼 수 있게 한다.
- **결제 · 원거래조회 [승인최초확정] → 주문 · 결제승인확인** — 복귀 조회에서 승인을 처음 확정한 경우에도 결제가 사건을 발행하고 주문이 받는다.
- **주문 · 결제승인확인 → 주문 · 승인적용판정** — 주문이 승인 금액을 대조하고 주문 확정 절차로 이어간다. [S05-3 주문 확정](#s05-3-승인된-결제의-주문-확정)
- **결제 · 원거래조회 [미승인확정] → 주문 · 거래미승인** — 결제 서비스는 미승인 상태를 주문에 돌려준다. 이번 조회에서 미승인을 처음 확정했다면 거래를 먼저 종결하고 `결제미승인확정`을 발행한다. 주문은 주문 상태와 예약 기한으로 다시 결제할 수 있는지 판단한다.
- **주문 · 거래미승인 → 고객프론트 · 미승인과재시도안내** — 승인되지 않은 거래임을 알리고 다시 결제할 수 있는지 표시한다.
- **결제 · 원거래조회 [미승인최초확정] → 알림 · 결제미승인확정** — 복귀 조회가 미승인을 처음 확정한 경우에도 결제가 사건을 발행하고 알림이 받는다.
- **알림 · 결제미승인확정 → 알림 · 미승인안내** — 알림 서비스는 확정된 미승인 시도의 결과를 안내한다.
- **알림 · 미승인안내 → 고객 · 결제미승인안내** — 해당 시도의 결제가 성립하지 않았음을 등록 채널로 보낸다.
- **결제 · 원거래조회 [승인여부불명] → 주문 · 거래확인중** — 원거래가 아직 처리 중이거나 조회 응답이 없으면 결제 서비스가 같은 거래를 다시 확인하고 주문 서비스는 확인 중으로 표시한다.
- **주문 · 거래확인중 → 고객프론트 · 거래확인중안내** — 결제 결과 확인 중임을 표시한다. 다음 조회도 같은 결제 시도를 사용한다.
- **고객프론트 · 거래확인중안내 → 고객프론트 · 대기후거래재조회** — 화면은 결과를 확인 중이라고 표시하고 잠시 뒤 다시 조회한다. 자동 확인 시간이 지나면 고객이 같은 시도의 결과를 다시 열 수 있게 한다.
- **고객프론트 · 대기후거래재조회 → 주문 · 결제확인요청** — 고객프론트는 같은 결제 시도의 결과를 조회해 앞의 거래 확인 분기로 다시 들어간다.

##### 결제사가 거래 상태를 통지할 때

결제사가 고객의 화면 복귀와 별도로 거래 상태를 보낸다. 결제 서비스가 원거래와 대조하고, 결과가 미확정이면 같은 시도를 다시 확인한다.

```jobflow
scope: 결제사의 거래 상태 통지와 결과 확정
Object: 결제사, 결제, 주문, 알림, 고객
결제사.On거래상태통지 --> 결제.message.거래상태알림
결제.message.거래상태알림 --> 결제.거래결과대조
결제.거래결과대조.승인최초확정 --> 주문.On결제승인확인
주문.On결제승인확인 --> 주문.승인적용판정
결제.거래결과대조.미승인최초확정 --> 알림.On결제미승인확정
알림.On결제미승인확정 --> 알림.미승인안내
알림.미승인안내 --> 고객.message.결제미승인안내
결제.거래결과대조.결과미확정 --> 결제사.message.같은결제시도재조회
결제사.message.같은결제시도재조회 --> 결제.message.재조회거래상태
결제.message.재조회거래상태 --> 결제.거래결과대조
```

- **결제사 · 거래상태통지 → 결제 · 거래상태알림** — 결제사가 결제 시도의 상태를 웹훅으로 통지한다.
- **결제 · 거래상태알림 → 결제 · 거래결과대조** — 결제 서비스는 통지된 거래를 원래 결제 시도와 대조한다. 이미 확정한 결과의 중복 통지는 기존 결과로 처리한다.
- **결제 · 거래결과대조 [승인최초확정] → 주문 · 결제승인확인** — 결제 서비스가 최종 승인을 처음 확정하면 `결제승인확인`을 발행하고, 구독자인 주문이 받는다.
- **주문 · 결제승인확인 → 주문 · 승인적용판정** — 주문이 승인 사건을 구독해 승인 금액과 주문을 대조하고, 조건에 맞으면 예약 수량을 확정한다. 화면은 주문 상태를 조회하며 고객에게 보내는 주문 확정·환불 예정 안내는 다음 절의 흐름을 따른다. [S05-3 주문 확정](#s05-3-승인된-결제의-주문-확정)
- **결제 · 거래결과대조 [미승인최초확정] → 알림 · 결제미승인확정** — 결제 서비스가 미승인을 처음 확정하면 `결제미승인확정`을 발행하고, 구독자인 알림이 받는다.
- **알림 · 결제미승인확정 → 알림 · 미승인안내** — 알림이 최종 미승인 사건을 구독해 해당 결제 시도의 고객 안내를 준비한다.
- **알림 · 미승인안내 → 고객 · 결제미승인안내** — 알림이 해당 시도의 결제가 성립하지 않았다는 결과를 고객에게 보낸다. 이 예제에서는 고객이 주문 화면을 닫은 뒤에도 받을 수 있는 등록 채널을 사용한다.
- **결제 · 거래결과대조 [결과미확정] → 결제사 · 같은결제시도재조회** — 최종 결과를 알 수 없으면 결제 서비스가 잠시 뒤 같은 결제 시도를 결제사에 다시 조회한다.
- **결제사 · 같은결제시도재조회 → 결제 · 재조회거래상태** — 결제사는 같은 시도의 거래 상태를 돌려준다.
- **결제 · 재조회거래상태 → 결제 · 거래결과대조** — 조회 회신을 받아 앞의 거래 결과 대조로 돌아간다. 결과가 계속 미확정이면 같은 시도를 다시 확인한다.

승인 사건을 받은 주문은 [S05-3 주문 확정](#s05-3-승인된-결제의-주문-확정)으로 이어간다. 미승인 사건을 받은 알림은 해당 시도의 결과를 고객에게 보낸다. 결제 결과가 불명인 동안 새 결제 시도는 보류한다.

### S05-3. 승인된 결제의 주문 확정

**시작 사건** 주문 서비스가 결제 서비스의 `결제승인확인`을 받는다. 승인 금액과 주문을 대조하고, 유효한 예약 수량을 판매 수량으로 확정해야 출고를 시작할 수 있다.

```jobflow
scope: 승인된 거래의 재고 확정과 주문 이행 불가 보상
Object: 고객프론트, 결제, 주문, 재고, 배송, 알림, 고객
결제.결제승인확인발행 --> 주문.On결제승인확인
주문.On결제승인확인 --> 주문.승인적용판정
주문.승인적용판정.이행불가보상대상있음 --> 결제.message.환불요청
주문.승인적용판정.이행불가보상대상있음 --> 재고.On주문이행불가
주문.승인적용판정.이행불가보상대상있음 --> 알림.On주문이행불가
재고.On주문이행불가 --> 재고.남은예약해제
알림.On주문이행불가 --> 알림.환불예정안내
알림.환불예정안내 --> 고객.message.환불예정안내
주문.승인적용판정.결제대기주문금액일치 --> 재고.message.예약확정요청
재고.message.예약확정요청 --> 재고.예약수량확정
재고.예약수량확정.판매수량확정됨 --> 주문.message.예약수량확정
주문.message.예약수량확정 --> 주문.주문확정발행
주문.주문확정발행 --> 배송.On주문확정
주문.주문확정발행 --> 알림.On주문확정
알림.On주문확정 --> 알림.주문확정안내
알림.주문확정안내 --> 고객.message.주문확정안내
배송.On주문확정 --> 배송.출고개설판정
재고.예약수량확정.예약만료 --> 주문.message.예약만료통보
주문.message.예약만료통보 --> 주문.보상대상판정
주문.보상대상판정.주문실패보상수량있음 --> 결제.message.환불요청
주문.보상대상판정.주문실패보상수량있음 --> 재고.On주문이행불가
주문.보상대상판정.주문실패보상수량있음 --> 알림.On주문이행불가
재고.On주문이행불가 --> 재고.남은예약해제
알림.On주문이행불가 --> 알림.환불예정안내
알림.환불예정안내 --> 고객.message.환불예정안내
고객프론트.On주문결과조회 --> 주문.message.주문결과조회요청
주문.message.주문결과조회요청 --> 고객프론트.message.주문확정상태
고객프론트.message.주문확정상태 --> 고객프론트.주문결과화면갱신
```

- **결제 · 결제승인확인발행 → 주문 · 결제승인확인** — 결제 서비스가 해당 시도의 최초 승인을 확정해 발행한 사건을 주문이 받는다. [S05-2 거래 승인 확인](#결제창-복귀와-거래-승인-확인)
- **주문 · 결제승인확인 → 주문 · 승인적용판정** — 주문 서비스는 승인 거래를 주문 금액과 현재 처리 상태에 대조한다. 이미 반영한 거래는 기존 결과를 사용한다.
- **주문 · 승인적용판정 [이행불가보상대상있음] → 결제 · 환불요청** — 주문이 만료됐거나 승인 금액이 어긋나면 주문이 자신이 보상할 상품과 금액을 확인해 환불을 의뢰한다. 취소 신청에 배정한 수량은 S07에서 정산한다.
- **주문 · 승인적용판정 [이행불가보상대상있음] → 재고 · 주문이행불가** — 주문이 보상할 상품과 수량에 대해 주문이행불가를 발행하고 재고가 받아 해제할 수량을 확인한다.
- **주문 · 승인적용판정 [이행불가보상대상있음] → 알림 · 주문이행불가** — 주문이 보상할 상품과 수량에 대해 주문이행불가를 발행하고 알림이 별도로 받아 고객의 환불 예정 안내를 시작한다.
- **재고 · 주문이행불가 → 재고 · 남은예약해제** — 주문이 환불할 대상 상품을 결정해 `주문이행불가`를 발행하면 재고는 해당 상품의 남은 예약을 해제한다. 이미 해제되거나 만료된 수량은 다시 더하지 않는다.
- **알림 · 주문이행불가 → 알림 · 환불예정안내** — 승인된 거래로 상품을 제공할 수 없어 주문이 보상 건을 열고 `주문이행불가`를 발행하면 알림이 고객에게 대상 상품과 환불 예정 사실을 안내한다.
- **알림 · 환불예정안내 → 고객 · 환불예정안내** — 알림은 제공할 수 없는 상품과 환불 예정 사실을 고객에게 보낸다.
- **주문 · 승인적용판정 [결제대기주문금액일치] → 재고 · 예약확정요청** — 결제 대기 주문의 금액이 일치하면 재고 서비스에 해당 예약의 수량을 확정해 달라고 요청한다.
- **재고 · 예약확정요청 → 재고 · 예약수량확정** — 재고 서비스는 예약 기한과 수량을 확인한다. 이미 판매로 반영한 수량에는 이전 확정 결과를 사용한다.
- **재고 · 예약수량확정 [판매수량확정됨] → 주문 · 예약수량확정** — 재고가 판매 수량으로 확정한 상품과 수량을 주문에 돌려준다.
- **주문 · 예약수량확정 → 주문 · 주문확정발행** — 주문이 판매 수량으로 확정된 상품을 반영하고 주문확정 사건을 발행한다.
- **주문 · 주문확정발행 → 배송 · 주문확정** — 배송이 확정된 상품과 수량이 담긴 사건을 받는다.
- **주문 · 주문확정발행 → 알림 · 주문확정** — 알림이 같은 주문 확정 사건을 별도로 받는다.
- **알림 · 주문확정 → 알림 · 주문확정안내** — 알림은 배송과 독립적으로 `주문확정`을 받아 고객에게 확정된 상품을 알려 준다.
- **알림 · 주문확정안내 → 고객 · 주문확정안내** — 알림은 확정된 상품과 주문번호를 고객에게 보낸다.
- **배송 · 주문확정 → 배송 · 출고개설판정** — 배송은 확정된 상품의 출고 건을 열 수 있는지 판단한다. [S06-1 출고와 운송장 등록](#s06-1-주문-확정에서-운영자의-운송장-등록까지)
- **재고 · 예약수량확정 [예약만료] → 주문 · 예약만료통보** — 예약을 확정할 수 없으면 재고 서비스는 만료된 예약과 수량을 주문 서비스에 돌려준다.
- **주문 · 예약만료통보 → 주문 · 보상대상판정** — 주문 서비스는 확보하지 못한 수량 중 자신이 보상할 상품과 S07의 취소 신청에서 정산할 상품을 가린다.
- **주문 · 보상대상판정 [주문실패보상수량있음] → 결제 · 환불요청** — 주문은 자신이 보상을 맡은 수량에 배분된 승인 금액만 환불 의뢰한다.
- **주문 · 보상대상판정 [주문실패보상수량있음] → 재고 · 주문이행불가** — 주문이 보상할 상품과 수량에 대해 주문이행불가를 발행하고 재고가 받아 해제할 수량을 확인한다.
- **주문 · 보상대상판정 [주문실패보상수량있음] → 알림 · 주문이행불가** — 주문이 보상할 상품과 수량에 대해 주문이행불가를 발행하고 알림이 별도로 받아 고객의 환불 예정 안내를 시작한다.
- **재고 · 주문이행불가 → 재고 · 남은예약해제** — 주문이 환불할 대상 상품을 결정해 `주문이행불가`를 발행하면 재고는 해당 상품의 남은 예약을 해제한다. 이미 해제되거나 만료된 수량은 다시 더하지 않는다.
- **알림 · 주문이행불가 → 알림 · 환불예정안내** — 승인된 거래로 상품을 제공할 수 없어 주문이 보상 건을 열고 `주문이행불가`를 발행하면 알림이 고객에게 대상 상품과 환불 예정 사실을 안내한다.
- **알림 · 환불예정안내 → 고객 · 환불예정안내** — 알림은 제공할 수 없는 상품과 환불 예정 사실을 고객에게 보낸다.
- **고객프론트 · 주문결과조회 → 주문 · 주문결과조회요청** — 같은 주문의 확정 여부와 이행할 상품을 조회한다.
- **주문 · 주문결과조회요청 → 고객프론트 · 주문확정상태** — 주문은 확정 대기·주문 확정·이행 불가와 환불 진행 상태를 자신이 기록한 범위에서 돌려준다.
- **고객프론트 · 주문확정상태 → 고객프론트 · 주문결과화면갱신** — 고객은 같은 주문의 확정 상품과 이행 불가·환불 진행 내역을 확인한다.

예약 확정 회신이 끊기면 주문은 확정 대기에 둔다. 같은 예약 번호의 결과를 확인한 뒤 출고 또는 보상을 한 번만 시작한다. 주문은 승인 금액을 **그 결제 시도에 제출한 원래 금액**과 대조한다. 같은 주문 상품의 확정과 취소 진행은 순서를 정해 기록한다. 일부 상품이 취소 진행 중이면 나머지 수량만 확정 대상으로 삼고, 취소 수량의 늦은 승인은 S07의 기존 신청에서 정산한다. 주문 실패 보상과 고객 취소가 같은 수량을 환불 대상으로 잡지 않도록 주문이 처리 주체를 한 곳에 배정한다.


### S05-4. 주문 확정 실패 후 환불 종결

#### 주문에서 환불을 의뢰할 때

[S05-3](#s05-3-승인된-결제의-주문-확정)에서 주문을 확정할 수 없는 상품이 생기면 주문 서비스가 그 상품의 승인 금액을 환불 의뢰한다. 고객은 같은 주문의 상세 화면에서 접수부터 최종 결과까지 확인할 수 있다.

```jobflow
scope: 주문 이행 실패의 환불 의뢰와 결제사 접수 확인
Object: 고객, 알림, 주문, 결제, 결제사
주문.승인적용판정.이행불가보상대상있음 --> 결제.message.환불요청
주문.보상대상판정.주문실패보상수량있음 --> 결제.message.환불요청
결제.message.환불요청 --> 결제.환불의뢰대조
결제.환불의뢰대조.새의뢰이며환불가능 --> 결제사.message.환불접수요청
결제사.message.환불접수요청 --> 결제.message.환불접수결과
결제.message.환불접수결과 --> 결제.환불접수판정
결제.환불의뢰대조.기존미종결의뢰 --> 결제.환불접수판정
결제.환불의뢰대조.이미종결된의뢰 --> 주문.message.기존보상환불결과
결제.환불의뢰대조.환불가능액초과 --> 결제.환불접수판정
결제.On환불접수응답기한경과 --> 결제.환불접수판정
결제.환불접수판정.접수확인 --> 주문.message.환불접수확인
주문.message.환불접수확인 --> 알림.message.환불진행안내요청
알림.message.환불진행안내요청 --> 고객.message.환불진행안내
결제.환불접수판정.접수여부불명 --> 주문.message.환불접수확인중
주문.message.환불접수확인중 --> 알림.message.환불접수지연안내요청
결제.환불접수판정.미접수확정 --> 주문.message.환불미접수
주문.message.환불미접수 --> 알림.message.환불접수지연안내요청
알림.message.환불접수지연안내요청 --> 고객.message.환불접수지연안내
```

- **주문 · 승인적용판정 [이행불가보상대상있음] → 결제 · 환불요청** — 주문은 승인 거래를 적용할 수 없는 상품과 금액을 정해 환불 의뢰 번호와 함께 보낸다.
- **주문 · 보상대상판정 [주문실패보상수량있음] → 결제 · 환불요청** — 재고 예약이 만료된 경우에도 주문이 보상할 수량만 같은 환불 계약으로 보낸다.
- **결제 · 환불요청 → 결제 · 환불의뢰대조** — 결제는 의뢰 번호로 기존 건을 찾고 상품별 환불 가능액을 원승인 금액과 대조한다.
- **결제 · 환불의뢰대조 [새의뢰이며환불가능] → 결제사 · 환불접수요청** — 결제는 원거래와 환불 의뢰 번호, 금액을 결제사에 보낸다.
- **결제사 · 환불접수요청 → 결제 · 환불접수결과** — 결제사는 해당 의뢰의 접수 여부와 사유를 돌려준다.
- **결제 · 환불접수결과 → 결제 · 환불접수판정** — 결제는 회신이 어느 의뢰의 것인지 확인하고 접수 여부를 판정한다.
- **결제 · 환불의뢰대조 [기존미종결의뢰] → 결제 · 환불접수판정** — 같은 의뢰가 진행 중이면 결제가 보관한 접수 상태로 회신한다.
- **결제 · 환불의뢰대조 [이미종결된의뢰] → 주문 · 기존보상환불결과** — 종결된 의뢰를 다시 받으면 같은 완료 또는 최종 실패 결과를 돌려준다. 주문이 최종 사건을 놓쳤으면 아래의 보상 대조를 이어가고, 이미 반영한 건은 기존 결과를 유지한다.
- **결제 · 환불의뢰대조 [환불가능액초과] → 결제 · 환불접수판정** — 한도를 초과하면 결제가 미접수로 판정하고 초과 사유를 남긴다.
- **결제 · 환불접수응답기한경과 → 결제 · 환불접수판정** — 응답 기한이 지나면 결제가 해당 의뢰의 마지막 기록을 확인한다. 회신도 확정 기록도 없으면 접수 여부가 불명이다.
- **결제 · 환불접수판정 [접수확인] → 주문 · 환불접수확인** — 주문은 보상 건에 환불 진행 중을 기록한다. 고객에게 완료로 알리는 시점은 실제 환불 금액이 확인된 뒤다.
- **주문 · 환불접수확인 → 알림 · 환불진행안내요청** — 주문이 해당 보상을 환불 진행 중으로 처음 갱신하면 알림에 고객 안내를 요청한다.
- **알림 · 환불진행안내요청 → 고객 · 환불진행안내** — 고객에게 어떤 상품의 환불이 접수됐는지 알린다.
- **결제 · 환불접수판정 [접수여부불명] → 주문 · 환불접수확인중** — 주문은 접수 확인 중으로 기록한다. 결제는 아래 흐름에서 같은 의뢰를 다시 조회한다.
- **주문 · 환불접수확인중 → 알림 · 환불접수지연안내요청** — 접수 여부를 확인 중이면 주문이 알림에 지연 안내를 요청한다.
- **결제 · 환불접수판정 [미접수확정] → 주문 · 환불미접수** — 결제는 접수되지 않은 이유를 회신한다. 주문은 보상 건에 접수 지연을 기록한다.
- **주문 · 환불미접수 → 알림 · 환불접수지연안내요청** — 미접수 사유가 확인되면 주문이 해당 사유로 지연 안내를 요청한다.
- **알림 · 환불접수지연안내요청 → 고객 · 환불접수지연안내** — 고객에게 환불이 지연되는 이유와 주문 상세에서 진행 상황을 확인하는 방법을 알린다.

#### 환불 접수가 지연될 때

결제사가 의뢰를 받았는지 모르면 결제가 기존 의뢰를 조회한다. 다시 의뢰할 수 있는 때는 미접수가 확인되고 그 원인이 해소된 뒤다. 결제는 이미 환불했거나 접수 중인 상품별 금액까지 합산해 원승인 금액을 넘는 의뢰를 막는다. 주문과 알림은 같은 의뢰의 상태가 바뀌었을 때만 고객 안내를 보낸다.

```jobflow
scope: 같은 환불 의뢰의 접수 여부 재확인과 미접수 처리
Object: 주문, 결제, 결제사
결제.환불접수판정.접수여부불명 --> 결제.접수재조회예약
결제.접수재조회예약 --> 결제사.message.환불접수여부조회
결제사.message.환불접수여부조회 --> 결제.message.환불접수결과
결제.message.환불접수결과 --> 결제.환불접수판정
결제.환불접수판정.접수확인 --> 주문.message.환불접수확인
결제.환불접수판정.미접수확정 --> 주문.message.환불미접수
결제.환불접수판정.미접수확정 --> 결제.미접수사유판정
결제.미접수사유판정.일시제한 --> 결제.제한해소후재접수
결제.제한해소후재접수 --> 결제사.message.환불접수요청
결제.미접수사유판정.조사필요 --> 결제.환불조사등록
```

- **결제 · 환불접수판정 [접수여부불명] → 결제 · 접수재조회예약** — 결제가 원래 의뢰 번호로 다음 조회를 예약한다.
- **결제 · 접수재조회예약 → 결제사 · 환불접수여부조회** — 예약한 시각이 되면 결제사가 그 의뢰를 접수했는지 묻는다.
- **결제사 · 환불접수여부조회 → 결제 · 환불접수결과** — 결제사는 같은 의뢰의 접수 상태를 돌려준다.
- **결제 · 환불접수결과 → 결제 · 환불접수판정** — 새로 확인된 상태를 앞 도표의 접수 판정에 넣는다. 조회도 응답 기한을 넘기면 확인 중인 의뢰로 남겨 다시 조회한다.
- **결제 · 환불접수판정 [접수확인] → 주문 · 환불접수확인** — 접수가 확인되면 주문이 보상 건의 진행 상태를 갱신한다.
- **결제 · 환불접수판정 [미접수확정] → 주문 · 환불미접수** — 미접수가 확인되면 주문에 지연 사유를 돌려준다.
- **결제 · 환불접수판정 [미접수확정] → 결제 · 미접수사유판정** — 결제는 재접수가 가능한 사유인지, 운영자의 거래 대조가 필요한지 판정한다.
- **결제 · 미접수사유판정 [일시제한] → 결제 · 제한해소후재접수** — 일시 제한이면 결제가 원인 해소를 기다린다.
- **결제 · 제한해소후재접수 → 결제사 · 환불접수요청** — 원인이 해소되면 기존 의뢰 번호로 다시 접수한다. 회신은 앞 도표의 환불접수결과로 돌아온다.
- **결제 · 미접수사유판정 [조사필요] → 결제 · 환불조사등록** — 원거래나 금액을 확인해야 하면 결제는 해당 의뢰에 조사 건을 연다.

#### 결제사가 나중에 환불 상태를 알릴 때

결제사가 환불 상태를 통지하거나 접수 후 확인 기한이 되면 결제가 같은 의뢰의 실제 환불 금액을 대조한다.

```jobflow
scope: 결제사의 환불 상태 통지와 최종 결과 확인
Object: 주문, 결제, 결제사
결제사.On환불상태통지 --> 결제.message.환불상태알림
결제.message.환불상태알림 --> 결제.환불내역대조
결제.환불내역대조.의뢰금액환불완료 --> 주문.On환불완료
결제.환불내역대조.실패조사필요 --> 결제.환불조사등록
결제.환불내역대조.결과미확정 --> 결제사.message.같은환불의뢰재조회
결제.환불접수판정.접수확인 --> 결제.환불결과확인예약
결제.환불결과확인예약.기한까지최종통지없음 --> 결제사.message.같은환불의뢰재조회
결제사.message.같은환불의뢰재조회 --> 결제.message.환불상태알림
```

- **결제사 · 환불상태통지 → 결제 · 환불상태알림** — 결제사가 원거래와 환불 의뢰 번호를 지정해 처리 상태를 보낸다.
- **결제 · 환불상태알림 → 결제 · 환불내역대조** — 결제가 원거래와 실제 환불 금액을 확인한다. 이미 반영한 통지는 이전 결과를 유지한다.
- **결제 · 환불내역대조 [의뢰금액환불완료] → 주문 · 환불완료** — 결제가 의뢰 금액 전부의 환불을 처음 확인하면 환불완료를 발행한다. 주문이 자신의 보상 건을 찾아 고객에게 알린다.
- **결제 · 환불내역대조 [실패조사필요] → 결제 · 환불조사등록** — 확인이 필요한 실패이면 결제가 기존 의뢰에 조사 건을 연다. 다음 도표에서 운영자가 이 건을 받는다.
- **결제 · 환불내역대조 [결과미확정] → 결제사 · 같은환불의뢰재조회** — 최종 결과가 불명확하면 잠시 뒤 같은 의뢰 번호로 처리 내역을 조회한다.
- **결제 · 환불접수판정 [접수확인] → 결제 · 환불결과확인예약** — 접수가 확인되면 결제가 같은 의뢰의 최종 결과를 확인할 시점을 잡는다.
- **결제 · 환불결과확인예약 [기한까지최종통지없음] → 결제사 · 같은환불의뢰재조회** — 최종 통지가 기한까지 오지 않고 의뢰가 진행 중이면 결제가 기존 의뢰 번호로 처리 내역을 확인한다.
- **결제사 · 같은환불의뢰재조회 → 결제 · 환불상태알림** — 결제가 같은 의뢰의 조회 응답을 받아 통지와 같은 기준으로 대조한다.

#### 운영자가 환불 건을 조사할 때

미접수 사유나 결제사 통지에서 조사가 필요하다고 판정하면 결제가 같은 환불 의뢰에 조사 건을 연다. 운영자는 대시보드에서 조사 대상을 확인하고, 결제사의 거래 내역을 대조한 뒤 결과를 제출한다.

```jobflow
scope: 환불 조사 알림과 운영자의 거래 내역 대조
Object: 주문, 결제, 알림, 고객, 운영대시보드, 운영자, 결제사
결제.환불조사등록 --> 주문.On환불실패확인필요
주문.On환불실패확인필요 --> 주문.보상상태반영
결제.환불조사등록 --> 알림.message.환불조사안내요청
알림.message.환불조사안내요청 --> 고객.message.환불확인중안내
알림.message.환불조사안내요청 --> 운영대시보드.message.환불조사알림
운영대시보드.message.환불조사알림 --> 운영대시보드.조사대기목록표시
운영대시보드.On환불조사건열기 --> 결제.message.환불조사건조회
결제.message.환불조사건조회 --> 운영대시보드.message.환불조사대상
운영대시보드.message.환불조사대상 --> 운영자.message.조사대상거래정보
운영자.message.조사대상거래정보 --> 결제사.message.환불내역대조요청
결제사.message.환불내역대조요청 --> 운영자.message.환불대조결과
운영자.message.환불대조결과 --> 운영대시보드.On환불조사결과제출
```

- **결제 · 환불조사등록 → 주문 · 환불실패확인필요** — 결제가 조사 건을 열어 환불실패확인필요를 발행하고, 주문이 구독해 자신이 맡은 보상 건을 찾는다.
- **주문 · 환불실패확인필요 → 주문 · 보상상태반영** — 조사 필요 사건을 받은 주문 서비스는 해당 보상 건을 운영 확인 중으로 표시한다.
- **결제 · 환불조사등록 → 알림 · 환불조사안내요청** — 조사 건을 연 결제가 알림에 운영자 확인 요청과 고객의 확인 중 안내를 의뢰한다. 같은 의뢰에 열린 조사가 있으면 기존 건을 사용한다.
- **알림 · 환불조사안내요청 → 고객 · 환불확인중안내** — 알림이 고객에게 환불 결과를 확인 중이라고 안내한다.
- **알림 · 환불조사안내요청 → 운영대시보드 · 환불조사알림** — 알림이 조사 대상 의뢰 번호를 대시보드로 보낸다.
- **운영대시보드 · 환불조사알림 → 운영대시보드 · 조사대기목록표시** — 운영자가 목록에서 확인할 환불 건을 볼 수 있다.
- **운영대시보드 · 환불조사건열기 → 결제 · 환불조사건조회** — 운영자가 목록에서 건을 선택하면 대시보드가 결제에 해당 의뢰의 조사 내역을 요청한다.
- **결제 · 환불조사건조회 → 운영대시보드 · 환불조사대상** — 결제는 등록된 조사 사유와 거래 대조에 필요한 정보를 대시보드에 반환한다.
- **운영대시보드 · 환불조사대상 → 운영자 · 조사대상거래정보** — 대시보드가 운영자에게 원거래, 환불 의뢰 번호, 금액과 조사 사유를 보여 준다.
- **운영자 · 조사대상거래정보 → 결제사 · 환불내역대조요청** — 운영자는 화면에서 확인한 번호로 결제사에 실제 처리 내역을 요청한다.
- **결제사 · 환불내역대조요청 → 운영자 · 환불대조결과** — 결제사는 처리 내역과 근거를 운영자에게 제공한다.
- **운영자 · 환불대조결과 → 운영대시보드 · 환불조사결과제출** — 운영자가 근거를 확인하고 같은 조사 건의 결과를 대시보드에 제출한다.

```jobflow
scope: 운영자의 조사 결과 제출과 판정 회신
Object: 운영대시보드, 결제, 주문
운영대시보드.On환불조사결과제출 --> 결제.message.환불조사회신
결제.message.환불조사회신 --> 결제.환불조사종결판정
결제.환불조사종결판정.근거부족 --> 운영대시보드.message.환불조사보완요청
운영대시보드.message.환불조사보완요청 --> 운영대시보드.조사근거보완
운영대시보드.조사근거보완 --> 운영대시보드.On환불조사결과제출
결제.환불조사종결판정.완료내역확보 --> 운영대시보드.message.환불조사완료
결제.환불조사종결판정.완료내역확보 --> 주문.On환불완료
결제.환불조사종결판정.최종실패확인 --> 운영대시보드.message.환불조사실패확정
결제.환불조사종결판정.최종실패확인 --> 주문.On환불실패확정
```

- **운영대시보드 · 환불조사결과제출 → 결제 · 환불조사회신** — 운영자가 대조한 결과와 근거를 원래 환불 의뢰 번호로 제출한다.
- **결제 · 환불조사회신 → 결제 · 환불조사종결판정** — 운영자가 결제사와 대조한 내역을 제출하면 결제는 해당 의뢰의 금액과 최종 결과가 확인됐는지 판정한다.
- **결제 · 환불조사종결판정 [근거부족] → 운영대시보드 · 환불조사보완요청** — 결제가 부족한 근거를 알려 준다. 운영자는 같은 조사 건에서 요청 내역을 보고 증빙을 보완한다.
- **운영대시보드 · 환불조사보완요청 → 운영대시보드 · 조사근거보완** — 대시보드가 보완할 항목을 표시하고 운영자가 추가 확보한 근거를 입력한다.
- **운영대시보드 · 조사근거보완 → 운영대시보드 · 환불조사결과제출** — 운영자가 보완한 근거를 다시 제출하면 결제가 같은 의뢰를 판정한다.
- **결제 · 환불조사종결판정 [완료내역확보] → 운영대시보드 · 환불조사완료** — 운영자에게 대조가 끝난 환불 건의 결과를 보여 준다.
- **결제 · 환불조사종결판정 [완료내역확보] → 주문 · 환불완료** — 결제가 실제 환불 완료를 처음 확정하면 환불완료를 발행하고 주문이 받는다. 고객에게 알리는 경로는 다음 도표에서 이어진다.
- **결제 · 환불조사종결판정 [최종실패확인] → 운영대시보드 · 환불조사실패확정** — 운영자에게 최종 실패 사유와 후속 정산이 필요한 건을 보여 준다.
- **결제 · 환불조사종결판정 [최종실패확인] → 주문 · 환불실패확정** — 결제가 최종 실패를 처음 확정하면 환불실패확정을 발행하고 주문이 받는다. 고객에게 알리는 경로는 다음 도표에서 이어진다.

#### 확정된 환불 결과를 고객에게 알릴 때

결제사 통지 또는 운영 조사로 결과가 확정되면 주문은 자신이 맡은 보상을 마무리하고 알림에 고객 안내를 의뢰한다. 취소·반품 신청의 환불은 [S07-4](#s07-4-금융배송-결과로-신청-마감)에서 구매후처리가 같은 사건을 받아 마무리한다. 주문은 최신 결과를 유지하므로 늦게 도착한 접수 회신으로 완료된 보상이 다시 진행 중으로 표시되는 일은 없다.

```jobflow
scope: 환불 결과의 주문 반영과 고객 안내
Object: 결제, 주문, 알림, 고객
주문.message.기존보상환불결과 --> 주문.보상반영내역대조
주문.보상반영내역대조.환불완료미반영 --> 주문.보상완료대조
주문.보상반영내역대조.최종실패미반영 --> 주문.보상실패대조
결제.환불완료발행 --> 주문.On환불완료
주문.On환불완료 --> 주문.보상완료대조
주문.보상완료대조.주문실패보상건 --> 알림.message.보상환불완료안내
알림.message.보상환불완료안내 --> 고객.message.환불완료안내
결제.환불실패확정발행 --> 주문.On환불실패확정
주문.On환불실패확정 --> 주문.보상실패대조
주문.보상실패대조.주문실패보상건 --> 알림.message.보상환불실패안내
알림.message.보상환불실패안내 --> 고객.message.환불실패안내
```

- **주문 · 기존보상환불결과 → 주문 · 보상반영내역대조** — 결제가 앞 도표에서 돌려준 최종 결과를 주문이 같은 의뢰의 보상 기록과 대조한다. 반영을 마친 건은 그대로 둔다.
- **주문 · 보상반영내역대조 [환불완료미반영] → 주문 · 보상완료대조** — 주문이 아직 반영하지 않은 완료 결과는 환불완료 사건을 받았을 때와 같은 절차로 처리한다.
- **주문 · 보상반영내역대조 [최종실패미반영] → 주문 · 보상실패대조** — 주문이 아직 반영하지 않은 실패 결과는 환불실패확정 사건을 받았을 때와 같은 절차로 처리한다.
- **결제 · 환불완료발행 → 주문 · 환불완료** — 결제사 통지나 운영 조사에서 실제 환불이 확인되면 결제가 발행한 환불완료를 주문이 받는다.
- **주문 · 환불완료 → 주문 · 보상완료대조** — 결제 서비스가 실제 환불을 확인해 `환불완료`를 발행하면 주문 서비스는 원거래와 환불 의뢰 번호를 대조한다.
- **주문 · 보상완료대조 [주문실패보상건] → 알림 · 보상환불완료안내** — 자신이 맡은 주문 실패 보상이면 해당 건을 마치고 알림 서비스에 고객 완료 안내를 요청한다.
- **알림 · 보상환불완료안내 → 고객 · 환불완료안내** — 고객에게 환불이 완료된 상품과 금액을 안내한다.
- **결제 · 환불실패확정발행 → 주문 · 환불실패확정** — 운영 조사에서 최종 실패가 확인되면 결제가 발행한 환불실패확정을 주문이 받는다.
- **주문 · 환불실패확정 → 주문 · 보상실패대조** — 최종 실패 사건을 받은 주문 서비스는 의뢰 번호로 자신이 맡은 보상 건인지 확인한다.
- **주문 · 보상실패대조 [주문실패보상건] → 알림 · 보상환불실패안내** — 해당 보상 건이면 실패 사유를 반영하고 알림 서비스에 고객 후속 안내를 의뢰한다.
- **알림 · 보상환불실패안내 → 고객 · 환불실패안내** — 고객에게 확정된 사유와 후속 정산 방법을 안내한다.

#### 고객이 주문 상세에서 환불 상태를 확인할 때

고객은 환불 안내를 받았을 때나 나중에 주문 상세를 다시 열었을 때 같은 주문에서 상품별 환불 진행 상황을 확인한다.

```jobflow
scope: 주문 상세에서 고객이 확인하는 보상 환불 내역
Object: 고객프론트, 주문
고객프론트.On주문결과조회 --> 주문.message.주문결과조회요청
주문.message.주문결과조회요청 --> 주문.내역열람판정
주문.내역열람판정.인증필요 --> 고객프론트.message.주문내역인증안내
주문.내역열람판정.열람가능 --> 고객프론트.message.주문확정상태
고객프론트.message.주문확정상태 --> 고객프론트.주문결과화면갱신
```

- **고객프론트 · 주문결과조회 → 주문 · 주문결과조회요청** — 고객이 주문 상세를 열면 프론트가 해당 주문의 결과를 요청한다.
- **주문 · 주문결과조회요청 → 주문 · 내역열람판정** — 주문이 회원 본인의 주문인지, 비회원이면 인증한 주문 한 건인지 확인한다.
- **주문 · 내역열람판정 [인증필요] → 고객프론트 · 주문내역인증안내** — 고객은 로그인하거나 해당 주문을 인증한 뒤 다시 조회할 수 있다.
- **주문 · 내역열람판정 [열람가능] → 고객프론트 · 주문확정상태** — 주문은 해당 상품의 환불 금액과 마지막으로 확인한 접수·조사·완료·실패 상태를 돌려준다.
- **고객프론트 · 주문확정상태 → 고객프론트 · 주문결과화면갱신** — 주문 상세에 상품과 환불 금액을 표시한다. 처리 중이면 현재 단계, 완료면 환불된 금액, 최종 실패면 사유와 후속 정산 방법을 보여 준다.

## S06. 출고와 배송 조회

### S06-1. 주문 확정에서 운영자의 운송장 등록까지

#### 주문이 출고할 상품을 확정할 때

배송은 주문이 확정된 상품별로 출고 건을 연다. 운영자가 포장 목록을 열면 배송이 이 출고 건을 조회한다.

```jobflow
scope: 주문 확정 사건에 따른 출고 건 개설
Object: 주문, 배송
주문.주문확정발행 --> 배송.On주문확정
배송.On주문확정 --> 배송.출고개설판정
배송.출고개설판정.처음확정된출고가능상품 --> 배송.출고건개설
```

- **주문 · 주문확정발행 → 배송 · 주문확정** — S05-3에서 상품과 수량을 확정한 주문이 사건을 발행하고 배송이 받는다. [S05-3 주문 확정](#s05-3-승인된-결제의-주문-확정)
- **배송 · 주문확정 → 배송 · 출고개설판정** — 배송은 확정된 상품·수량에 대해 기존 출고 건과 출고 중지 기록을 확인한다.
- **배송 · 출고개설판정 [처음확정된출고가능상품] → 배송 · 출고건개설** — 처음 확정된 출고 가능 상품의 출고 건을 연다. 중지 기록이 있으면 중지를 유지하고, 중복 확정이면 기존 출고 건을 유지한다.

#### 운영자가 포장 목록을 열고 운송장을 등록할 때

운영자가 대시보드에서 포장 목록을 연다. 일반 주문은 앞에서 만든 출고 건, 교환품은 구매후처리가 의뢰한 출고 건이 대상이다. 운영자는 포장할 상품과 주소를 보고 택배사에 직접 배송을 의뢰한다. [S07-3 교환 출고](#s07-3-검수-결과에-따른-환불과-교환-출고) · [매크로 M06-1](macro.md#m06-1-운영자의-배송-준비부터-고객-수령까지)

```jobflow
scope: 운영대시보드의 포장 목록 확인과 운송장 등록
Object: 택배사, 운영자, 운영대시보드, 배송, 주문
운영대시보드.On포장목록요청 --> 배송.message.주문배송정보요청
배송.message.주문배송정보요청 --> 배송.출고대상판정
배송.출고대상판정.출고할상품없음 --> 운영대시보드.message.출고대상없음
배송.출고대상판정.출고할상품있음 --> 주문.message.출고명세조회
주문.message.출고명세조회 --> 배송.message.출고명세회신
배송.message.출고명세회신 --> 운영대시보드.message.포장목록과배송지
운영대시보드.message.포장목록과배송지 --> 운영대시보드.포장대상표시
운영대시보드.포장대상표시 --> 운영자.message.선택한출고명세
운영자.message.선택한출고명세 --> 택배사.message.배송의뢰
택배사.message.배송의뢰 --> 운영자.message.운송장정보
운영자.message.운송장정보 --> 운영대시보드.On운송장등록
운영대시보드.On운송장등록 --> 배송.message.배송등록신청
배송.message.배송등록신청 --> 배송.운송장등록판정
배송.운송장등록판정.입력보완필요 --> 운영대시보드.message.운송장보완안내
운영대시보드.message.운송장보완안내 --> 운영자.message.운송장수정항목
운영자.message.운송장수정항목 --> 운영대시보드.On운송장등록
배송.운송장등록판정.출고중지됨 --> 운영대시보드.message.인계중단안내
배송.운송장등록판정.출고가능하고운송장확인 --> 배송.인계작업시작
배송.인계작업시작 --> 운영대시보드.message.운송장등록확인
```

- **운영대시보드 · 포장목록요청 → 배송 · 주문배송정보요청** — 운영자가 지금 출고할 상품의 포장 명세와 배송지를 요청한다.
- **배송 · 주문배송정보요청 → 배송 · 출고대상판정** — 운영자가 포장 목록을 요청하면 배송이 출고할 건을 고른다. 대상이 없으면 운영자에게 빈 목록을 돌려준다.
- **배송 · 출고대상판정 [출고할상품없음] → 운영대시보드 · 출고대상없음** — 운영자에게 출고 가능한 상품이 없다고 표시한다.
- **배송 · 출고대상판정 [출고할상품있음] → 주문 · 출고명세조회** — 배송은 출고 건에 연결된 주문 상품을 지정해 명세를 요청한다.
- **주문 · 출고명세조회 → 배송 · 출고명세회신** — 주문은 해당 상품의 주문 시점 명세와 배송지를 돌려준다.
- **배송 · 출고명세회신 → 운영대시보드 · 포장목록과배송지** — 일반 출고에는 주문 상품과 배송지를, 교환 출고에는 같은 주문에 연결된 교환 의뢰의 확정 상품·수량·배송지를 표시한다.
- **운영대시보드 · 포장목록과배송지 → 운영대시보드 · 포장대상표시** — 대시보드는 일반 주문과 교환품을 구분해 출고 건별 포장 명세와 배송지를 표시한다.
- **운영대시보드 · 포장대상표시 → 운영자 · 선택한출고명세** — 운영자는 포장할 출고 건을 골라 상품과 수량, 배송지를 확인한다.
- **운영자 · 선택한출고명세 → 택배사 · 배송의뢰** — 운영자가 선택한 출고 건의 배송지로 택배사에 배송을 직접 의뢰한다.
- **택배사 · 배송의뢰 → 운영자 · 운송장정보** — 택배사가 의뢰를 접수하면 운영자에게 운송장 번호를 돌려준다.
- **운영자 · 운송장정보 → 운영대시보드 · 운송장등록** — 운영자가 발급받은 운송장 번호를 같은 출고 건의 등록 화면에 입력하고 제출한다.
- **운영대시보드 · 운송장등록 → 배송 · 배송등록신청** — 운영자가 출고 건을 선택하고 택배사에서 받은 운송장 번호를 제출한다.
- **배송 · 배송등록신청 → 배송 · 운송장등록판정** — 배송은 신청받은 상품을 여전히 출고할 수 있는지, 해당 상품의 운송장 정보가 갖춰졌는지 확인한다. 정보가 부족하면 보완을, 출고 중지 상태면 인계 중단을 운영자에게 안내한다.
- **배송 · 운송장등록판정 [입력보완필요] → 운영대시보드 · 운송장보완안내** — 운영자에게 빠진 항목이나 수정할 운송장 정보를 보여 준다.
- **운영대시보드 · 운송장보완안내 → 운영자 · 운송장수정항목** — 대시보드는 해당 출고 건에서 확인하거나 고쳐야 할 항목을 운영자에게 보여 준다.
- **운영자 · 운송장수정항목 → 운영대시보드 · 운송장등록** — 운영자가 입력값을 고쳐 제출하면 같은 출고 건을 다시 판정한다.
- **배송 · 운송장등록판정 [출고중지됨] → 운영대시보드 · 인계중단안내** — 대시보드에 출고 중지가 표시되면 운영자는 해당 포장 건의 택배 인계를 멈춘다.
- **배송 · 운송장등록판정 [출고가능하고운송장확인] → 배송 · 인계작업시작** — 출고할 수 있고 운송장도 확인되면 배송이 운송장을 등록하고 해당 상품을 인계 작업 중으로 기록한다. 운영자가 이후 실물을 인계한다.
- **배송 · 인계작업시작 → 운영대시보드 · 운송장등록확인** — 대시보드에 등록된 운송장 번호와 출고 건을 표시한다. 운영자가 실물을 택배사에 건넨 뒤 발송을 등록하는 과정은 다음 도표에서 이어진다. [발송 등록](#운영자가-발송을-등록할-때)

이 예제에서 유효한 운송장 등록은 해당 상품을 운영자의 **인계 작업 중**으로 표시한다. 출고 중지와 이 전환은 배송이 같은 출고 건에서 순서를 정한다. 인계 작업 중에 취소가 접수되면 배송은 운영자의 실물 인계 여부를 확인할 때까지 중지 결과를 보류한다. 운영자가 상품을 아직 보유하고 인계 작업을 멈췄다고 확인하면 배송이 중지를 확정한다. 이미 건넸다면 인계 사실을 기록한다.

### S06-2. 발송 등록과 배송 완료에 따른 고객 안내

#### 운영자가 발송을 등록할 때

운영자는 등록된 운송장을 붙인 상품을 택배사에 건넨 뒤, 대시보드에서 해당 출고 건의 발송을 등록한다. 실물 인수와 대시보드 등록은 각각 택배사와 운영자의 행동이다. [매크로 M06-1](macro.md#m06-1-운영자의-배송-준비부터-고객-수령까지)

```jobflow
scope: 운영자 발송 등록과 고객 안내
Object: 운영대시보드, 구매후처리, 배송, 주문, 알림, 발송사, 고객
운영대시보드.On발송등록 --> 배송.message.발송등록신청
배송.message.발송등록신청 --> 배송.인계기록대조
배송.인계기록대조.이미처리됨 --> 운영대시보드.message.현재출고상태
배송.인계기록대조.인계확인필요 --> 운영대시보드.message.인계확인안내
운영대시보드.message.인계확인안내 --> 운영대시보드.인계확인화면표시
운영대시보드.인계확인화면표시.실물인계확인후제출 --> 배송.message.발송등록신청
배송.인계기록대조.첫인계확인 --> 배송.발송확정
배송.발송확정 --> 운영대시보드.message.발송등록확인
배송.발송확정 --> 알림.On발송확정
배송.발송확정.보류된출고중지요청있음 --> 구매후처리.message.출고중지불가
알림.On발송확정 --> 알림.발송안내판정
알림.발송안내판정.완료전첫발송안내 --> 주문.message.발송안내정보조회
주문.message.발송안내정보조회 --> 알림.message.발송안내정보
알림.message.발송안내정보 --> 알림.발송메일대상확인
알림.발송메일대상확인.발송대상확인 --> 발송사.message.발송안내메일요청
발송사.message.발송안내메일요청 --> 고객.message.발송안내메일
```

- **운영대시보드 · 발송등록 → 배송 · 발송등록신청** — 운영자가 실물 인계를 마친 출고 건의 발송을 등록한다.
- **배송 · 발송등록신청 → 배송 · 인계기록대조** — 배송은 신청받은 운송장과 실물 인계를 대조한다. 인계가 확인되지 않으면 운영자에게 확인을 요청한다. 이미 반영한 발송이나 완료 건은 현재 상태를 돌려준다.
- **배송 · 인계기록대조 [이미처리됨] → 운영대시보드 · 현재출고상태** — 이미 반영된 발송이나 배달 완료 상태를 표시한다.
- **배송 · 인계기록대조 [인계확인필요] → 운영대시보드 · 인계확인안내** — 운영자에게 운송장과 실제 인계 여부를 다시 확인하도록 안내한다.
- **운영대시보드 · 인계확인안내 → 운영대시보드 · 인계확인화면표시** — 운영자가 확인할 출고 건과 운송장을 화면에 표시한다. 상품을 아직 보유 중이면 인계를 완료할 때까지 등록을 보류한다.
- **운영대시보드 · 인계확인화면표시 [실물인계확인후제출] → 배송 · 발송등록신청** — 운영자가 실물을 건넨 사실을 확인해 제출하면 배송이 같은 운송장의 발송 여부를 다시 대조한다.
- **배송 · 인계기록대조 [첫인계확인] → 배송 · 발송확정** — 배송이 해당 출고 건의 첫 인계를 기록하고 출고 번호와 운송장이 담긴 발송확정 사건을 발행한다.
- **배송 · 발송확정 → 운영대시보드 · 발송등록확인** — 해당 운송장의 발송 등록이 완료됐음을 표시한다.
- **배송 · 발송확정 → 알림 · 발송확정** — 배송이 실물 인계를 처음 확인해 발송확정 사건을 발행하고, 알림이 이 사건을 받는다.
- **배송 · 발송확정 [보류된출고중지요청있음] → 구매후처리 · 출고중지불가** — 인계 확인을 기다리는 취소 신청이 있으면 배송이 그 신청 번호로 중지 불가를 회신한다. 구매후처리가 취소 결과와 반품 방법을 신청 상세에 반영한다. [S07-1 출고 중지](#s07-1-출고-중지와-취소-거래-확인)
- **알림 · 발송확정 → 알림 · 발송안내판정** — 알림은 이 출고 건의 발송 안내 이력과 배송 완료가 먼저 반영됐는지 확인한다. 이미 안내했거나 완료된 건은 발송 메일을 생략한다.
- **알림 · 발송안내판정 [완료전첫발송안내] → 주문 · 발송안내정보조회** — 처음 안내할 발송이면 알림이 주문 서비스에 해당 고객의 수신 정보를 요청한다.
- **주문 · 발송안내정보조회 → 알림 · 발송안내정보** — 주문이 해당 주문의 연락처를 회신하면 알림은 메일 안내 대상인지 확인해 발송사에 운송장 안내를 의뢰한다.
- **알림 · 발송안내정보 → 알림 · 발송메일대상확인** — 알림은 고객 연락처와 해당 안내의 의뢰 이력을 확인한다.
- **알림 · 발송메일대상확인 [발송대상확인] → 발송사 · 발송안내메일요청** — 발송 대상이면 운송장 번호가 담긴 메일을 의뢰한다.
- **발송사 · 발송안내메일요청 → 고객 · 발송안내메일** — 고객은 메일에서 운송장 번호를 확인한다. 최근 경과를 보려면 주문 화면에서 해당 상품의 배송 조회를 선택한다. [S06-3 배송 조회](#s06-3-권한을-확인한-주문의-배송-조회)

#### 택배사가 배송 완료를 통지할 때

택배사는 배달을 완료한 뒤 같은 운송장의 완료를 통지한다. 이 통지는 운영자의 발송 등록과 별도 시점에 도착한다.

```jobflow
scope: 택배사 배송 완료 통지와 고객 안내
Object: 택배사, 구매후처리, 배송, 알림, 주문, 발송사, 고객
택배사.On배송완료기록 --> 배송.message.배송완료통지
배송.message.배송완료통지 --> 배송.완료통지대조
배송.완료통지대조.해당운송장첫완료 --> 배송.배달완료기록
배송.배달완료기록 --> 알림.On배송완료
배송.배달완료기록 --> 구매후처리.On배송완료
구매후처리.On배송완료 --> 구매후처리.교환배송대조
배송.배달완료기록.보류된출고중지요청있음 --> 구매후처리.message.출고중지불가
알림.On배송완료 --> 알림.완료안내판정
알림.완료안내판정.첫완료안내 --> 주문.message.완료안내정보조회
주문.message.완료안내정보조회 --> 알림.message.완료안내정보
알림.message.완료안내정보 --> 발송사.message.배송완료메일요청
발송사.message.배송완료메일요청 --> 고객.message.배송완료메일
```

- **택배사 · 배송완료기록 → 배송 · 배송완료통지** — 배달을 마친 택배사가 해당 운송장의 배송 완료를 통지한다.
- **배송 · 배송완료통지 → 배송 · 완료통지대조** — 배송 서비스는 통지를 출고 건의 운송장과 대조하고 이미 기록한 완료 통지는 기존 결과로 처리한다.
- **배송 · 완료통지대조 [해당운송장첫완료] → 배송 · 배달완료기록** — 확인한 운송장의 첫 완료를 기록하고 배송완료 사건을 발행한다. 교환 출고이면 원래 신청 번호도 담는다.
- **배송 · 배달완료기록 → 알림 · 배송완료** — 배송이 배달 완료를 처음 확정해 배송완료를 발행하면 알림이 구독해 받는다.
- **배송 · 배달완료기록 → 구매후처리 · 배송완료** — 구매후처리도 같은 배송완료 사건을 받는다.
- **구매후처리 · 배송완료 → 구매후처리 · 교환배송대조** — 구매후처리는 출고 건과 신청 번호가 진행 중인 교환과 일치할 때 교환 마감을 이어간다. [S07-4 신청 마감](#s07-4-금융배송-결과로-신청-마감)
- **배송 · 배달완료기록 [보류된출고중지요청있음] → 구매후처리 · 출고중지불가** — 운영자의 발송 등록보다 택배사 완료 통지가 먼저 오면 배송이 아직 답하지 않은 중지 요청에 회신한다. 구매후처리는 같은 취소 신청에 인계 사실과 반품 방법을 반영한다.
- **알림 · 배송완료 → 알림 · 완료안내판정** — 알림은 같은 출고 건의 완료 안내를 이미 의뢰했는지 확인한다.
- **알림 · 완료안내판정 [첫완료안내] → 주문 · 완료안내정보조회** — 처음 보낼 완료 안내이면 해당 고객의 수신 정보를 주문 서비스에 요청한다.
- **주문 · 완료안내정보조회 → 알림 · 완료안내정보** — 주문이 회신하면 알림은 대상 고객에게 배송 완료 메일을 의뢰한다. 출고 번호와 안내 종류별로 발송 이력을 확인해 같은 메일을 중복 의뢰하지 않는다.
- **알림 · 완료안내정보 → 발송사 · 배송완료메일요청** — 알림은 고객 연락처를 확인해 출고 번호와 안내 종류별로 같은 메일이 중복 의뢰되지 않도록 한다.
- **발송사 · 배송완료메일요청 → 고객 · 배송완료메일** — 고객은 완료 메일을 받는다. 나중에 주문 화면을 열면 배송이 기록한 배달 완료 상태를 확인할 수 있다. [S06-3 배송 조회](#s06-3-권한을-확인한-주문의-배송-조회)

실물 수령과 전산 통지 사이에는 시간차가 있다. 완료가 운영자의 발송 등록보다 먼저 들어오면 배송은 확인 가능한 운송장의 완료 사실을 보존하고, 뒤늦은 등록으로 완료 상태를 되돌리지 않는다. 알림에 완료가 먼저 반영된 건은 뒤늦은 발송 안내를 생략한다. 발송사 접수 뒤 회신만 끊긴 경우를 위해 같은 출고 번호·안내 종류에 동일 발송 의뢰 번호를 쓰고, 재의뢰 전에 접수 여부를 조회하는 계약을 둔다. 교환품의 `배송완료`에는 원래 신청 번호도 들어 있어 구매후처리가 해당 교환을 마칠 수 있다.

### S06-3. 권한을 확인한 주문의 배송 조회

**시작 사건** 고객이 주문 내역을 연다. 주문 화면에서 상품의 배송 조회를 선택하면 해당 운송장의 최신 경과를 별도로 조회한다. 주문은 두 요청 모두에서 회원 본인 또는 비회원이 인증한 주문 한 건인지 확인한다. [매크로 M06-2](macro.md#m06-2-고객의-주문배송-조회)

#### 고객이 주문 내역을 열 때

```jobflow
scope: 주문 상세 화면에서 확인하는 배송 현황
Object: 고객프론트, 주문, 배송
고객프론트.On주문내역열기 --> 주문.message.주문내역요청
주문.message.주문내역요청 --> 주문.내역열람판정
주문.내역열람판정.열람가능한출고대상없음 --> 고객프론트.message.출고전주문내역
주문.내역열람판정.인증필요 --> 고객프론트.message.주문내역인증안내
주문.내역열람판정.열람가능한출고대상 --> 배송.message.주문배송현황조회
배송.message.주문배송현황조회 --> 주문.message.주문배송현황
주문.message.주문배송현황 --> 고객프론트.message.주문내역과배송현황
고객프론트.message.주문내역과배송현황 --> 고객프론트.주문상세화면표시
```

- **고객프론트 · 주문내역열기 → 주문 · 주문내역요청** — 고객이 선택한 주문의 내역을 요청한다.
- **주문 · 주문내역요청 → 주문 · 내역열람판정** — 주문은 고객의 주문 열람 권한을 확인한다. 인증이 필요하면 화면에 인증 방법을 안내한다.
- **주문 · 내역열람판정 [열람가능한출고대상없음] → 고객프론트 · 출고전주문내역** — 출고 대상이 없는 주문의 내역과 결제·취소 상태를 표시한다.
- **주문 · 내역열람판정 [인증필요] → 고객프론트 · 주문내역인증안내** — 주문 화면은 회원 로그인을 안내한다. 비회원은 인증 문자를 신청해 해당 주문의 열람 권한을 얻을 수 있다. [S02 비회원 주문 인증](#s02-비회원이-주문-한-건을-열람할-권한-얻기)
- **주문 · 내역열람판정 [열람가능한출고대상] → 배송 · 주문배송현황조회** — 권한이 있고 출고할 상품이 있으면 주문은 배송에 출고 건의 현재 상태를 조회한다.
- **배송 · 주문배송현황조회 → 주문 · 주문배송현황** — 배송이 회신하면 주문은 내역과 마지막으로 확인된 배송 상태를 함께 보여 준다.
- **주문 · 주문배송현황 → 고객프론트 · 주문내역과배송현황** — 주문 내역에 마지막으로 확인된 배송 상태를 함께 표시한다.
- **고객프론트 · 주문내역과배송현황 → 고객프론트 · 주문상세화면표시** — 주문 상세 화면에 상품별 배송 상태를 표시한다. 고객이 한 상품의 배송 조회를 선택하면 다음 도표로 이어진다.

#### 고객이 상품의 배송 경과를 조회할 때

```jobflow
scope: 선택한 상품의 운송장 경과와 조회 지연 시 재확인
Object: 고객프론트, 주문, 배송, 택배사
고객프론트.On배송경과조회 --> 주문.message.배송경과요청
주문.message.배송경과요청 --> 주문.배송열람판정
주문.배송열람판정.인증필요 --> 고객프론트.message.배송조회인증안내
주문.배송열람판정.출고대상없음 --> 고객프론트.message.출고대상없음안내
주문.배송열람판정.열람가능한출고대상 --> 배송.message.최근배송경과조회
배송.message.최근배송경과조회 --> 배송.배송경과확인
배송.배송경과확인.운송장있고완료전 --> 배송.운송장조회
배송.운송장조회 --> 택배사.message.운송장경과조회
택배사.message.운송장경과조회 --> 배송.message.운송장경과회신
배송.message.운송장경과회신 --> 배송.최근경과판정
배송.배송경과확인.운송장등록전 --> 주문.message.배송준비중
주문.message.배송준비중 --> 고객프론트.message.배송준비안내
배송.배송경과확인.배달완료기록있음 --> 주문.message.배달완료내역
주문.message.배달완료내역 --> 고객프론트.message.배달완료표시
배송.최근경과판정.최근경과확인 --> 주문.message.최근배송경과
주문.message.최근배송경과 --> 고객프론트.message.배송경과표시
배송.운송장조회.응답기한경과 --> 주문.message.배송경과확인지연
배송.최근경과판정.회신에경과없음 --> 주문.message.배송경과확인지연
주문.message.배송경과확인지연 --> 고객프론트.message.배송확인지연안내
고객프론트.message.배송확인지연안내 --> 고객프론트.마지막상태와다시조회표시
고객프론트.마지막상태와다시조회표시.고객이재조회선택 --> 주문.message.배송경과요청
```

- **고객프론트 · 배송경과조회 → 주문 · 배송경과요청** — 고객이 선택한 주문 상품의 최근 배송 경과를 요청한다.
- **주문 · 배송경과요청 → 주문 · 배송열람판정** — 고객이 최근 경과를 요청하면 주문은 다시 열람 권한과 해당 배송 대상을 확인한다.
- **주문 · 배송열람판정 [인증필요] → 고객프론트 · 배송조회인증안내** — 고객 화면은 로그인 또는 해당 주문의 비회원 인증을 안내한다. 인증 후 배송 조회를 다시 선택하면 권한을 확인한다. [S02 비회원 주문 인증](#s02-비회원이-주문-한-건을-열람할-권한-얻기)
- **주문 · 배송열람판정 [출고대상없음] → 고객프론트 · 출고대상없음안내** — 주문의 현재 상태와 배송 조회 대상이 없다는 사실을 표시한다.
- **주문 · 배송열람판정 [열람가능한출고대상] → 배송 · 최근배송경과조회** — 권한이 있고 출고 대상이면 배송에 최근 경과를 요청한다. 결제 대기나 출고 전 취소로 출고 대상이 없으면 주문이 자체 상태를 안내한다.
- **배송 · 최근배송경과조회 → 배송 · 배송경과확인** — 배송은 해당 출고 건의 완료 기록과 운송장 등록 여부를 확인한다. 완료 기록이 없고 운송장이 있으면 택배사에 최신 경과를 조회한다.
- **배송 · 배송경과확인 [운송장있고완료전] → 배송 · 운송장조회** — 운송장은 있고 배달 완료 기록은 없으면 그 운송장의 최신 경과를 조회한다.
- **배송 · 운송장조회 → 택배사 · 운송장경과조회** — 배송이 택배사에 해당 운송장의 이동 내역을 요청한다.
- **택배사 · 운송장경과조회 → 배송 · 운송장경과회신** — 택배사가 확인할 수 있는 운송장의 경과를 회신한다.
- **배송 · 운송장경과회신 → 배송 · 최근경과판정** — 배송은 회신이 해당 운송장의 최근 경과인지 확인한다.
- **배송 · 배송경과확인 [운송장등록전] → 주문 · 배송준비중** — 배송은 아직 등록된 운송장이 없다고 회신하고 주문은 배송 준비 중임을 안내한다.
- **주문 · 배송준비중 → 고객프론트 · 배송준비안내** — 운송장 등록 전 단계임을 고객에게 표시한다.
- **배송 · 배송경과확인 [배달완료기록있음] → 주문 · 배달완료내역** — 완료 기록이 있으면 배송은 그 기록을 돌려주고 주문은 배달 완료를 표시한다.
- **주문 · 배달완료내역 → 고객프론트 · 배달완료표시** — 서비스가 기록한 배달 완료 상태를 보여 준다.
- **배송 · 최근경과판정 [최근경과확인] → 주문 · 최근배송경과** — 운송장의 경과를 확인하면 배송이 최신 이동 내역을 주문에 보낸다.
- **주문 · 최근배송경과 → 고객프론트 · 배송경과표시** — 조회한 운송장의 최근 이동 내역을 표시한다.
- **배송 · 운송장조회 [응답기한경과] → 주문 · 배송경과확인지연** — 택배사에 경과를 요청한 뒤 회신 기한이 지나면 배송은 마지막 확인 상태와 조회 지연을 주문에 보낸다.
- **배송 · 최근경과판정 [회신에경과없음] → 주문 · 배송경과확인지연** — 택배사가 회신했어도 해당 운송장의 최근 이동 내역이 없으면 마지막 확인 상태를 사용한다.
- **주문 · 배송경과확인지연 → 고객프론트 · 배송확인지연안내** — 최근 경과를 확인하지 못한 상황과 마지막 확인 상태를 함께 표시한다.
- **고객프론트 · 배송확인지연안내 → 고객프론트 · 마지막상태와다시조회표시** — 화면은 마지막으로 확인된 배송 상태와 확인 시각, 다시 조회 버튼을 표시한다.
- **고객프론트 · 마지막상태와다시조회표시 [고객이재조회선택] → 주문 · 배송경과요청** — 고객이 다시 조회를 선택하면 같은 주문 상품의 열람 권한과 최근 배송 경과를 다시 확인한다.

## S07. 취소·반품·교환과 구매 리뷰

구매후처리는 신청을 받은 시점과 금융·배송 결과가 확정된 시점을 구분한다. 고객이 신청 상태를 조회하면 이 서비스가 수거·검수·환불·교환 배송 중 마지막으로 확인된 단계를 보여 준다. [매크로 M07](macro.md#m07-취소반품교환과-구매-리뷰)

### S07-1. 출고 중지와 취소 거래 확인

**시작 사건** 고객이 주문 화면에서 취소할 상품과 수량을 제출한다. 주문이 구매 내역을 확인하고 배송이 실제 인계 여부를 판단한다.

```jobflow

구매후처리.message.취소대상정보 --> 구매후처리.취소접수판정
구매후처리.취소접수판정.취소할수량없음 --> 고객프론트.message.취소접수불가안내
구매후처리.취소접수판정.취소할수량있음 --> 배송.message.출고중지요청
배송.message.출고중지요청 --> 배송.인계상태대조
배송.인계상태대조.이미인계됨 --> 구매후처리.message.출고중지불가
구매후처리.message.출고중지불가 --> 고객프론트.message.취소불가와반품안내
배송.인계상태대조.인계작업중 --> 구매후처리.message.인계확인대기
구매후처리.message.인계확인대기 --> 고객프론트.message.출고중지확인중안내
배송.인계상태대조.인계전중지확정 --> 구매후처리.message.출고중지확인
구매후처리.message.출고중지확인 --> 주문.message.취소진행등록
주문.message.취소진행등록 --> 주문.취소수량배정판정
주문.취소수량배정판정.배정불가 --> 구매후처리.message.취소진행등록불가
구매후처리.message.취소진행등록불가 --> 배송.message.출고중지해제요청
배송.message.출고중지해제요청 --> 구매후처리.message.출고중지해제결과
구매후처리.message.출고중지해제결과 --> 고객프론트.message.취소등록불가안내
주문.취소수량배정판정.신청수량배정됨 --> 구매후처리.message.취소진행등록확인
구매후처리.message.취소진행등록확인 --> 결제.message.취소거래종결요청
```

- **고객프론트 · 취소신청 → 구매후처리 · 주문취소신청** — 고객이 취소할 상품과 수량을 제출한다.
- **구매후처리 · 주문취소신청 → 주문 · 취소대상조회** — 구매후처리는 주문에 신청자의 주문과 취소 대상 상품을 조회한다.
- **주문 · 취소대상조회 → 구매후처리 · 취소대상정보** — 주문은 소유자 일치 여부, 구매 수량, 거래 참조와 이미 취소한 수량을 회신한다.
- **구매후처리 · 취소대상정보 → 구매후처리 · 취소접수판정** — 구매후처리는 다른 신청에 배정한 수량까지 대조해 이번 신청의 취소 가능 수량을 정한다.
- **구매후처리 · 취소접수판정 [취소할수량없음] → 고객프론트 · 취소접수불가안내** — 취소를 신청할 수 있는 수량이 없음을 안내한다.
- **구매후처리 · 취소접수판정 [취소할수량있음] → 배송 · 출고중지요청** — 취소할 수량이 있으면 배송에 해당 주문 상품의 출고를 막아 달라고 요청한다.
- **배송 · 출고중지요청 → 배송 · 인계상태대조** — 배송은 신청 상품·수량의 실물 인계 기록을 대조한다. 운영자의 인계 작업과 출고 중지 중 먼저 확정된 처리를 기록한다.
- **배송 · 인계상태대조 [이미인계됨] → 구매후처리 · 출고중지불가** — 이미 기사에게 넘긴 수량이면 구매후처리가 취소 불가 사유와 반품 방법을 고객에게 안내한다.
- **구매후처리 · 출고중지불가 → 고객프론트 · 취소불가와반품안내** — 신청 화면에 취소할 수 없는 수량과 반품 방법을 표시한다.
- **배송 · 인계상태대조 [인계작업중] → 구매후처리 · 인계확인대기** — 인계 작업이 시작돼 실물이 어디 있는지 확인해야 하면 배송은 이 출고 건을 현장 확인 대상으로 남기고 구매후처리에 대기를 알린다.
- **구매후처리 · 인계확인대기 → 고객프론트 · 출고중지확인중안내** — 출고가 중지됐는지 운영자가 확인하고 있음을 고객에게 보여 준다.
- **배송 · 인계상태대조 [인계전중지확정] → 구매후처리 · 출고중지확인** — 배송은 인계 전 수량에 이번 신청의 출고 중지를 기록하고, 중지된 상품과 수량을 회신한다.
- **구매후처리 · 출고중지확인 → 주문 · 취소진행등록** — 구매후처리는 중지가 확인된 수량을 주문에 취소 진행으로 등록한다.
- **주문 · 취소진행등록 → 주문 · 취소수량배정판정** — 주문은 다른 취소·보상에 배정된 수량과 신청 번호를 대조해 이번 신청 몫을 정한다.
- **주문 · 취소수량배정판정 [배정불가] → 구매후처리 · 취소진행등록불가** — 다른 처리에 배정된 수량 등으로 최종 등록할 수 없으면 주문이 사유를 회신한다.
- **구매후처리 · 취소진행등록불가 → 배송 · 출고중지해제요청** — 구매후처리는 이번 신청이 건 중지만 풀도록 배송에 요청한다.
- **배송 · 출고중지해제요청 → 구매후처리 · 출고중지해제결과** — 배송은 해당 신청의 중지만 해제한 결과를 돌려준다. 주문의 출고 자격과 다른 중지 사유를 확인해야 다시 인계할 수 있다.
- **구매후처리 · 출고중지해제결과 → 고객프론트 · 취소등록불가안내** — 취소를 등록하지 못한 사유를 고객에게 보여 준다.
- **주문 · 취소수량배정판정 [신청수량배정됨] → 구매후처리 · 취소진행등록확인** — 주문은 취소 진행으로 기록한 신청 번호·상품·수량과 원거래 참조를 회신한다. 같은 신청의 재확인은 기존 배정을 돌려준다.
- **구매후처리 · 취소진행등록확인 → 결제 · 취소거래종결요청** — 구매후처리는 결제에 기존 결제 시도를 종결하고 원거래의 상태를 확인하도록 요청한다.

배송은 출고 건을 개설하기 전에 받은 중지도 기록한다. 뒤늦게 주문이 확정돼도 중지한 수량은 출고 대상에서 제외한다.

#### 출고 중지나 원거래 확인이 보류됐을 때

운영자는 인계 작업 중인 건을 대시보드에서 찾아 현장에서 확인한 결과를 제출한다. 구매후처리는 인계 전 중지 결과를 받으면 같은 신청 번호로 취소 수량 배정을 이어 간다.

```jobflow
scope: 운영자의 인계 확인과 취소 신청 재개
Object: 운영대시보드, 배송, 구매후처리, 주문
운영대시보드.On인계확인목록열기 --> 배송.message.인계확인대상조회
배송.message.인계확인대상조회 --> 운영대시보드.message.인계확인대상목록
운영대시보드.On인계여부확인제출 --> 배송.message.인계여부확인
배송.message.인계여부확인 --> 배송.현장인계결과판정
배송.현장인계결과판정.인계전중지확정 --> 구매후처리.message.출고중지확인
배송.현장인계결과판정.인계전중지확정 --> 운영대시보드.message.출고중지완료안내
구매후처리.message.출고중지확인 --> 주문.message.취소진행등록
배송.현장인계결과판정.이미인계됨 --> 구매후처리.message.출고중지불가
배송.현장인계결과판정.이미인계됨 --> 운영대시보드.message.인계사실반영안내
배송.현장인계결과판정.이미인계됨 --> 배송.인계기록대조
배송.인계기록대조.첫인계확인 --> 배송.발송확정
```

- **운영대시보드 · 인계확인목록열기 → 배송 · 인계확인대상조회** — 운영자가 실물 인계 여부를 확인해야 하는 출고 건을 조회한다.
- **배송 · 인계확인대상조회 → 운영대시보드 · 인계확인대상목록** — 배송은 앞 도표에서 인계 작업 중으로 보류한 건을 반환한다. 운영자는 대상 건의 상품과 운송장을 확인한다.
- **운영대시보드 · 인계여부확인제출 → 배송 · 인계여부확인** — 운영자가 목록에서 선택한 출고 건의 실물 보유 또는 기사 인계 사실을 제출한다.
- **배송 · 인계여부확인 → 배송 · 현장인계결과판정** — 배송은 확인한 출고 건과 보류 중인 취소 신청을 대조한다.
- **배송 · 현장인계결과판정 [인계전중지확정] → 구매후처리 · 출고중지확인** — 실물을 보유하고 작업을 중지했다면 기존 취소 신청을 앞 도표의 출고중지확인부터 이어간다.
- **배송 · 현장인계결과판정 [인계전중지확정] → 운영대시보드 · 출고중지완료안내** — 운영자는 해당 수량의 인계가 중지됐음을 확인한다.
- **구매후처리 · 출고중지확인 → 주문 · 취소진행등록** — 구매후처리는 이 수량으로 앞 도표의 취소 등록을 재개한다. 고객은 기존 신청의 상세 화면에서 진행 상태를 확인한다.
- **배송 · 현장인계결과판정 [이미인계됨] → 구매후처리 · 출고중지불가** — 이미 인계됐으면 구매후처리가 결과를 기록한다. 고객은 신청 결과 조회에서 취소 불가와 반품 절차를 확인한다.
- **배송 · 현장인계결과판정 [이미인계됨] → 운영대시보드 · 인계사실반영안내** — 운영자는 실물 인계가 확인됐음을 본다. 구매후처리는 해당 신청에 취소 불가 사유를 남긴다.
- **배송 · 현장인계결과판정 [이미인계됨] → 배송 · 인계기록대조** — 배송은 현장 확인된 운송장을 기존 발송 기록과 대조한다.
- **배송 · 인계기록대조 [첫인계확인] → 배송 · 발송확정** — 이 확인이 첫 인계 기록이면 [S06-2의 발송 확정과 고객 안내](#운영자가-발송을-등록할-때)로 이어진다. 이미 처리한 운송장은 기존 발송 기록을 유지한다.

취소 진행 등록을 요청한 뒤 주문의 회신이 늦는 경우도 있다. 구매후처리는 대기 중인 신청의 출고 중지를 유지한 채 같은 신청 번호로 등록 결과를 확인한다.

```jobflow
scope: 취소 수량 배정 회신의 재확인
Object: 구매후처리, 주문
구매후처리.On취소등록응답기한경과 --> 구매후처리.취소등록응답확인
구매후처리.취소등록응답확인.회신대기중 --> 주문.message.취소진행등록
```

- **구매후처리 · 취소등록응답기한경과 → 구매후처리 · 취소등록응답확인** — 구매후처리는 정해 둔 응답 시간 안에 해당 신청의 배정 결과를 받았는지 확인한다.
- **구매후처리 · 취소등록응답확인 [회신대기중] → 주문 · 취소진행등록** — 아직 회신이 없으면 같은 신청과 수량으로 주문에 요청한다. 주문은 이미 배정한 신청이면 기존 결과를 돌려주고, 구매후처리는 앞 도표의 등록 확인 또는 등록 불가에서 이어 간다.

#### 결제가 취소할 원거래를 확인할 때

주문이 취소 수량을 배정하면 구매후처리가 결제에 원거래 종결을 요청한다. 결제는 기존 시도가 있으면 그 거래의 최종 상태를 결제사에 확인한다.

```jobflow
scope: 원거래 재확인과 취소 또는 환불 의뢰
Object: 고객프론트, 구매후처리, 결제, 결제사, 주문
구매후처리.message.취소진행등록확인 --> 결제.message.취소거래종결요청
결제.message.취소거래종결요청 --> 결제.결제시도확인
결제.결제시도확인.결제시도없음 --> 구매후처리.message.취소거래미승인종결
결제.결제시도확인.기존시도있음 --> 결제사.message.취소대상거래확인
결제사.message.취소대상거래확인 --> 결제.message.취소대상거래상태
결제.message.취소대상거래상태 --> 결제.취소원거래대조
결제.On취소거래조회응답기한경과 --> 결제.취소조회응답확인
결제.취소조회응답확인.응답대기중 --> 구매후처리.message.취소거래확인중
결제.취소원거래대조.결과미확정 --> 구매후처리.message.취소거래확인중
구매후처리.message.취소거래확인중 --> 고객프론트.message.취소거래확인중안내
구매후처리.message.취소거래확인중 --> 구매후처리.거래재확인예약
구매후처리.거래재확인예약 --> 구매후처리.On거래재확인시점
구매후처리.On거래재확인시점 --> 결제.message.취소거래종결요청
결제.취소원거래대조.승인금액있음 --> 구매후처리.message.취소거래승인확인
구매후처리.message.취소거래승인확인 --> 고객프론트.message.취소진행접수안내
구매후처리.message.취소거래승인확인 --> 결제.message.환불요청
결제.취소원거래대조.미승인종결 --> 구매후처리.message.취소거래미승인종결
구매후처리.message.취소거래미승인종결 --> 고객프론트.message.취소진행접수안내
구매후처리.message.취소거래미승인종결 --> 주문.message.취소반영요청
```

- **구매후처리 · 취소진행등록확인 → 결제 · 취소거래종결요청** — 구매후처리는 결제에 기존 결제 시도를 종결하고 원거래의 상태를 확인하도록 요청한다.
- **결제 · 취소거래종결요청 → 결제 · 결제시도확인** — 결제는 해당 주문 금액으로 새 결제 시도를 열 수 없게 한 뒤, 이미 시작한 시도가 있는지 확인한다.
- **결제 · 결제시도확인 [결제시도없음] → 구매후처리 · 취소거래미승인종결** — 한 번도 시작한 시도가 없으면 결제가 해당 금액의 미승인 종결을 직접 회신한다. 구매후처리는 주문에 취소 반영을 요청한다.
- **결제 · 결제시도확인 [기존시도있음] → 결제사 · 취소대상거래확인** — 결제는 이미 시작한 거래가 있으면 결제사에 그 원거래 번호의 승인·종결 상태를 묻는다.
- **결제사 · 취소대상거래확인 → 결제 · 취소대상거래상태** — 결제사는 원래 거래 번호에 대한 승인 금액 또는 미승인 종결 여부를 회신한다.
- **결제 · 취소대상거래상태 → 결제 · 취소원거래대조** — 결제는 결제사 응답과 신청에 연결된 거래를 대조한다.
- **결제 · 취소거래조회응답기한경과 → 결제 · 취소조회응답확인** — 조회 기한에 결제가 같은 요청의 응답이 남아 있는지 확인한다.
- **결제 · 취소조회응답확인 [응답대기중] → 구매후처리 · 취소거래확인중** — 거래 결과를 받지 못한 신청은 구매후처리가 기존 원거래로 다시 확인한다.
- **결제 · 취소원거래대조 [결과미확정] → 구매후처리 · 취소거래확인중** — 승인 여부가 불명확하면 구매후처리는 취소 진행 상태를 유지하고 같은 원거래의 종결 결과를 재확인한다.
- **구매후처리 · 취소거래확인중 → 고객프론트 · 취소거래확인중안내** — 고객에게 취소 신청 번호와 원래 결제 결과를 확인 중이라는 상태를 표시한다.
- **구매후처리 · 취소거래확인중 → 구매후처리 · 거래재확인예약** — 구매후처리는 이미 받은 신청 번호로 원래 결제 시도를 다시 확인하도록 예약한다.
- **구매후처리 · 거래재확인예약 → 구매후처리 · 거래재확인시점** — 예약한 시간이 되면 아직 종결을 기다리는 같은 신청의 재확인을 시작한다.
- **구매후처리 · 거래재확인시점 → 결제 · 취소거래종결요청** — 구매후처리는 같은 신청과 원거래로 다시 요청한다. 먼저 결과가 확정되면 예약을 끝낸다.
- **결제 · 취소원거래대조 [승인금액있음] → 구매후처리 · 취소거래승인확인** — 결제는 실제 승인 거래와 금액을 구매후처리에 회신한다.
- **구매후처리 · 취소거래승인확인 → 고객프론트 · 취소진행접수안내** — 고객에게 접수된 수량과 환불 예정 금액을 보여 준다.
- **구매후처리 · 취소거래승인확인 → 결제 · 환불요청** — 구매후처리는 취소 진행으로 배정받은 수량의 금액만 같은 환불 의뢰 번호로 요청한다.
- **결제 · 취소원거래대조 [미승인종결] → 구매후처리 · 취소거래미승인종결** — 결제는 뒤늦은 승인이 가능한 시도까지 확인하고 승인 없이 거래가 종결됐을 때 회신한다.
- **구매후처리 · 취소거래미승인종결 → 고객프론트 · 취소진행접수안내** — 고객에게 접수된 수량과 환불할 금액이 없음을 보여 준다.
- **구매후처리 · 취소거래미승인종결 → 주문 · 취소반영요청** — 구매후처리는 돈이 빠져나가지 않은 대상 수량을 주문에 취소 반영해 달라고 요청한다.

고객이 신청 화면을 닫은 뒤 확정된 결과는 같은 신청의 상세 화면에서 확인한다. 환불 확인, 주문 수량·재고 반영, 고객 안내는 [S07-4](#s07-4-금융배송-결과로-신청-마감)로 이어진다. 기존 시도가 미승인으로 끝나고 일부 수량만 취소된 주문은 남은 상품의 금액으로 다시 결제를 시작할 수 있다.

### S07-2. 반품·교환 수거 접수

**시작 사건** 상품을 받은 고객이 반품이나 교환을 신청한다. 구매후처리는 주문의 구매 내역과 배송의 인도 내역을 대조한다.

```jobflow
scope: 반품·교환 신청 자격과 수거 대상 확정
Object: 고객프론트, 주문, 구매후처리, 배송, 재고
고객프론트.On반품교환신청 --> 구매후처리.message.반품교환신청
구매후처리.message.반품교환신청 --> 주문.message.구매상품조회
주문.message.구매상품조회 --> 구매후처리.message.구매상품정보
구매후처리.message.구매상품정보 --> 구매후처리.신청수량판정
구매후처리.신청수량판정.본인구매잔여수량없음 --> 고객프론트.message.신청수량확인안내
구매후처리.신청수량판정.본인구매잔여수량있음 --> 배송.message.인도내역조회
배송.message.인도내역조회 --> 구매후처리.message.상품인도내역
구매후처리.message.상품인도내역 --> 구매후처리.회수대상판정
구매후처리.회수대상판정.인도내역미확정 --> 고객프론트.message.인도확인대기안내
구매후처리.회수대상판정.인도내역미확정 --> 구매후처리.대기후인도재확인
구매후처리.대기후인도재확인 --> 배송.message.인도내역조회
구매후처리.회수대상판정.회수대상아님 --> 고객프론트.message.반품교환접수불가안내
구매후처리.회수대상판정.반품접수가능 --> 배송.message.반환상품수거요청
구매후처리.회수대상판정.교환접수가능 --> 재고.message.교환품예약요청
재고.message.교환품예약요청 --> 재고.교환품예약판정
재고.교환품예약판정.수량부족 --> 구매후처리.message.교환품예약불가
구매후처리.message.교환품예약불가 --> 고객프론트.message.교환품품절안내
재고.교환품예약판정.교환수량예약됨 --> 구매후처리.message.교환품예약확인
구매후처리.message.교환품예약확인 --> 배송.message.반환상품수거요청
```

- **고객프론트 · 반품교환신청 → 구매후처리 · 반품교환신청** — 고객이 신청 종류와 대상 상품·수량을 제출한다.
- **구매후처리 · 반품교환신청 → 주문 · 구매상품조회** — 구매후처리는 주문에 대상 주문 상품의 구매 내역을 요청한다.
- **주문 · 구매상품조회 → 구매후처리 · 구매상품정보** — 주문은 구매자와 주문 상품·수량·거래 참조를 회신한다.
- **구매후처리 · 구매상품정보 → 구매후처리 · 신청수량판정** — 구매후처리는 구매자와 이미 신청한 수량을 대조한다.
- **구매후처리 · 신청수량판정 [본인구매잔여수량없음] → 고객프론트 · 신청수량확인안내** — 신청 가능한 구매 수량과 확인할 항목을 표시한다.
- **구매후처리 · 신청수량판정 [본인구매잔여수량있음] → 배송 · 인도내역조회** — 신청할 수량이 남았으면 배송에 해당 상품의 인도 내역을 요청한다.
- **배송 · 인도내역조회 → 구매후처리 · 상품인도내역** — 배송은 고객에게 배송 완료된 수량과 확인 시각을 회신한다.
- **구매후처리 · 상품인도내역 → 구매후처리 · 회수대상판정** — 구매후처리는 인도 내역과 신청 기한을 기준으로 회수 여부를 정한다.
- **구매후처리 · 회수대상판정 [인도내역미확정] → 고객프론트 · 인도확인대기안내** — 인도 사실을 확인 중인 신청의 번호를 표시한다. 구매후처리가 같은 배송 건의 결과를 확인한다.
- **구매후처리 · 회수대상판정 [인도내역미확정] → 구매후처리 · 대기후인도재확인** — 같은 신청을 대기 상태로 두고 확인 간격이 지난 뒤에도 인도 내역을 기다리는지 확인한다.
- **구매후처리 · 대기후인도재확인 → 배송 · 인도내역조회** — 구매후처리는 같은 배송 건을 다시 조회한다. 인도 사실이 확인되면 원래 신청의 기한과 수량으로 회수 가능 여부를 다시 판단한다.
- **구매후처리 · 회수대상판정 [회수대상아님] → 고객프론트 · 반품교환접수불가안내** — 회수 대상이 아니라고 판단한 사유를 고객에게 보여 준다.
- **구매후처리 · 회수대상판정 [반품접수가능] → 배송 · 반환상품수거요청** — 반품이 가능하면 배송에 반환 상품, 수거지와 도착지를 보낸다.
- **구매후처리 · 회수대상판정 [교환접수가능] → 재고 · 교환품예약요청** — 교환 신청이 가능하면 재고에 원하는 옵션과 수량을 예약한다.
- **재고 · 교환품예약요청 → 재고 · 교환품예약판정** — 재고는 요청한 옵션과 수량을 같은 신청 번호로 확보할 수 있는지 확인한다.
- **재고 · 교환품예약판정 [수량부족] → 구매후처리 · 교환품예약불가** — 수량이 부족하면 구매후처리는 고객에게 교환품을 확보할 수 없다고 안내하고 수거를 시작하지 않는다.
- **구매후처리 · 교환품예약불가 → 고객프론트 · 교환품품절안내** — 요청한 교환품 수량을 확보할 수 없다고 안내한다.
- **재고 · 교환품예약판정 [교환수량예약됨] → 구매후처리 · 교환품예약확인** — 재고는 해당 신청에 확보한 교환품의 예약 번호와 수량을 회신한다.
- **구매후처리 · 교환품예약확인 → 배송 · 반환상품수거요청** — 구매후처리는 교환품 예약이 확인된 신청의 반환 상품을 수거해 달라고 요청한다.

- **구매후처리 · 회수대상판정 [반품접수가능] → 배송 · 반환상품수거요청** — 반품이 가능하면 배송에 반환 상품, 수거지와 도착지를 보낸다.
- **구매후처리 · 교환품예약확인 → 배송 · 반환상품수거요청** — 구매후처리는 교환품 예약이 확인된 신청의 반환 상품을 수거해 달라고 요청한다.
- **배송 · 반환상품수거요청 → 택배사 · 수거의뢰** — 배송이 해당 신청 번호로 택배사에 수거를 의뢰한다.
- **택배사 · 수거의뢰 → 배송 · 수거접수결과** — 택배사는 의뢰 번호에 대한 접수 결과를 배송에 회신한다.
- **배송 · 수거접수결과 → 배송 · 수거접수확인** — 배송은 택배사의 응답을 원래 수거 의뢰와 대조한다.
- **배송 · 수거접수확인 [접수확인] → 구매후처리 · 수거접수확인** — 구매후처리는 수거 접수 사실과 포장 방법을 안내하고 물류센터에 해당 신청의 입고 검수를 의뢰한다.
- **구매후처리 · 수거접수확인 → 고객프론트 · 수거예정안내** — 고객에게 수거가 접수된 신청의 번호와 준비할 사항을 보여 준다.
- **구매후처리 · 수거접수확인 → 물류센터 · 반환상품검수의뢰** — 구매후처리는 접수된 신청과 수거 건을 물류센터에 보낸다. 물류센터가 상품을 받으면 검수하고 S07-3의 결과를 통지한다.
- **배송 · 수거접수확인 [수거불가확정] → 구매후처리 · 수거접수불가** — 배송은 수거가 최종 무산됐다는 사실을 회신한다.
- **구매후처리 · 수거접수불가 → 고객프론트 · 수거접수불가안내** — 고객에게 수거할 수 없는 사유를 표시한다.
- **구매후처리 · 수거접수불가 → 구매후처리 · 수거실패정리** — 구매후처리는 신청 종류를 확인해 수거 불가를 안내하고, 교환에 배정한 예약이 있으면 돌려준다.
- **구매후처리 · 수거실패정리 [교환품예약있음] → 재고 · 교환품예약해제요청** — 재고는 이번 신청에 배정된 교환품 수량만 해제한다. 같은 신청의 해제를 한 번만 반영한다.
- **배송 · 수거접수응답기한경과 → 배송 · 수거응답도착확인** — 응답 기한이 지나면 배송은 해당 의뢰의 결과가 이미 도착했는지 확인한다.
- **배송 · 수거응답도착확인 [회신대기중] → 구매후처리 · 수거접수확인중** — 아직 회신을 받지 못했으면 구매후처리에 접수 결과를 확인 중이라고 알려 준다.
- **배송 · 수거접수확인 [접수여부불명] → 구매후처리 · 수거접수확인중** — 구매후처리는 확인 대기로 두고 배송은 같은 의뢰의 접수 여부를 재확인한다. 이미 잡은 교환품 예약은 유지한다.
- **구매후처리 · 수거접수확인중 → 고객프론트 · 수거접수대기안내** — 신청의 수거 접수 결과를 확인하고 있다고 표시한다.
- **구매후처리 · 수거접수확인중 → 배송 · 수거접수상태조회** — 구매후처리는 대기 중인 같은 신청의 수거 상태를 잠시 뒤 배송에 묻는다. 교환품 예약은 유지한다.
- **배송 · 수거접수상태조회 → 택배사 · 기존수거의뢰조회** — 배송은 기존 의뢰 번호로 접수 상태를 조회한다.
- **택배사 · 기존수거의뢰조회 → 배송 · 수거접수결과** — 배송은 조회 회신을 같은 접수 판정에 적용한다. 수거 접수가 확인된 신청만 검수를 의뢰한다.

- **구매후처리 · 검수접수응답확인 [회신대기중] → 물류센터 · 기존검수의뢰조회** — 아직 회신이 없으면 같은 신청과 의뢰 번호로 센터에 조회한다.
- **물류센터 · 기존검수의뢰조회 → 구매후처리 · 검수접수결과** — 물류센터가 기존 의뢰의 접수 결과를 회신하면 구매후처리가 다시 판정한다.

- **구매후처리 · 검수보완대상조회 → 운영대시보드 · 검수보완목록** — 구매후처리는 보완 등록한 신청과 센터의 사유를 운영자에게 보여 준다.

- **구매후처리 · 검수의뢰정정 → 운영대시보드 · 보완접수확인** — 운영자에게 수정 사항을 접수한 신청 번호를 표시한다.
- **구매후처리 · 검수의뢰정정 → 물류센터 · 반환상품검수의뢰** — 구매후처리는 기존 의뢰 번호로 정정한 정보를 보내 접수 결과를 다시 확인한다.

#### 택배사가 실제 수거를 완료했을 때

고객이 포장한 상품을 기사에게 건네면 기사가 수거를 등록한다. 택배사의 수거 통지와 물류센터의 실물 입고는 각자 일어난 시점에 처리한다. [매크로의 상품 인계](macro.md#m07-2-반품교환-접수와-상품-회수)


- **택배사 · 수거완료기록 → 배송 · 수거완료통지** — 택배사가 실제 수거를 마치면 수거 건의 완료를 배송에 통지한다.
- **배송 · 수거완료통지 → 배송 · 수거완료확인** — 배송은 통지의 수거 번호를 기존 의뢰와 대조한다.
- **배송 · 수거완료확인 [첫수거완료] → 구매후처리 · 수거완료** — 같은 의뢰의 첫 완료를 확인한 배송이 수거완료 사건을 발행해 구매후처리에 전달한다.
- **구매후처리 · 수거완료 → 구매후처리 · 수거상태반영** — 구매후처리는 같은 신청의 수거 사실을 기록한다. 검수나 종결 결과가 먼저 도착했다면 이미 확인한 단계도 함께 보존한다.
- **고객프론트 · 신청결과조회 → 구매후처리 · 신청결과조회요청** — 고객이 반품·교환 신청 상세 화면을 열어 진행 상태를 조회한다.
- **구매후처리 · 신청결과조회요청 → 고객프론트 · 신청처리결과** — 구매후처리는 해당 고객 신청에 기록된 최신 단계를 돌려준다. 화면에는 수거 확인 중, 수거 완료·검수 대기, 검수 이후 결과 중 확인된 단계가 표시된다.
- **고객프론트 · 신청처리결과 → 고객프론트 · 신청결과표시** — 고객은 같은 신청 번호에서 수거 진행 상황과 이후 검수 결과를 확인한다.

기사가 상품을 물류센터에 인계하고 센터가 접수된 의뢰와 실물을 대조해 검수를 마치면 [S07-3](#s07-3-검수-결과에-따른-환불과-교환-출고)으로 이어진다. 택배사 통지가 늦더라도 센터가 확인한 검수 결과를 반영할 수 있다.

### S07-3. 검수 결과에 따른 환불과 교환 출고

**시작 사건** [S07-2에서 검수를 의뢰받은 물류센터](#s07-2-반품교환-수거-접수)가 반환 상품을 받아 검사하고, 신청 번호와 함께 판정을 보낸다.

#### 물류센터에서 검수 결과가 도착할 때


- **구매후처리 · 입고검수결과 → 구매후처리 · 검수후처리판정** — 구매후처리는 통지된 상품·수량과 판정을 해당 신청에 대조한다.
- **구매후처리 · 검수후처리판정 [반품수락] → 결제 · 환불요청** — 반품을 수락하면 원거래와 수락한 수량의 결제 금액으로 환불을 의뢰한다.
- **구매후처리 · 검수후처리판정 [반품수락] → 알림 · 환불진행안내요청** — 반품을 수락해 환불 절차에 들어갔다는 사실을 알림에 전달한다.
- **알림 · 환불진행안내요청 → 고객 · 환불진행안내** — 고객은 환불 절차가 시작됐음을 확인한다. 결과는 S07-4의 종결 안내에서 확인한다.
- **구매후처리 · 검수후처리판정 [교환수락] → 재고 · 교환품예약확정요청** — 교환을 수락하면 S07-2에서 잡아 둔 예약을 출고 수량으로 확정해 달라고 요청한다. 바로 아래 그림에서 재고가 이 요청을 받는다.
- **구매후처리 · 검수후처리판정 [반품거절] → 알림 · 검수거절안내요청** — 반품을 수락할 수 없으면 구매후처리가 검수 사유와 신청 번호를 알림에 보낸다.
- **구매후처리 · 검수후처리판정 [교환거절] → 재고 · 교환품예약해제요청** — 교환을 거절하면 재고에 해당 신청의 교환품 예약을 해제하도록 요청한다.
- **구매후처리 · 검수후처리판정 [교환거절] → 알림 · 검수거절안내요청** — 교환을 수락할 수 없으면 구매후처리가 검수 사유와 신청 번호를 알림에 보낸다.
- **알림 · 검수거절안내요청 → 고객 · 검수거절안내** — 고객에게 해당 신청의 거절 사유와 검수한 물건을 돌려받는 방법을 보낸다.

같은 검수 통지가 다시 도착하면 구매후처리는 신청과 검수 건을 대조해 기존 의뢰를 이어간다. 반품 수락 후의 환불은 [S07-4](#s07-4-금융배송-결과로-신청-마감)에서 추적한다.

- **구매후처리 · 검수후처리판정 [교환수락] → 재고 · 교환품예약확정요청** — 앞 그림에서 승인한 신청 번호와 교환품 예약을 재고에 넘긴다.
- **재고 · 교환품예약확정요청 → 재고 · 교환예약대조** — 재고는 검수를 통과한 수량이 해당 교환 신청의 예약에 배정돼 있는지 확인한다.
- **재고 · 교환예약대조 [교환수량확정] → 구매후처리 · 교환품확정확인** — 재고는 교환품 예약을 해당 신청의 출고 수량으로 전환해 구매후처리에 회신한다.
- **구매후처리 · 교환품확정확인 → 배송 · 교환출고요청** — 구매후처리는 출고 수량이 확정된 교환 신청의 번호·상품·수량·배송지를 보내 출고를 의뢰한다.
- **구매후처리 · 교환품확정확인 → 알림 · 교환준비안내요청** — 교환품 수량을 확보해 출고를 준비한다고 알림에 전달한다.
- **알림 · 교환준비안내요청 → 고객 · 교환준비안내** — 고객은 확보된 교환품과 출고 준비 상태를 확인한다.
- **배송 · 교환출고요청 → 배송 · 교환출고건개설** — 배송은 신청 번호로 기존 출고 건을 찾거나 새 건을 열고 교환 상품·수량·배송지를 포장 목록에 올린다.
- **배송 · 교환출고건개설 → 구매후처리 · 교환출고접수결과** — 배송이 출고 번호를 돌려주면 구매후처리가 같은 신청에 운송 진행을 연결한다.
- **재고 · 교환예약대조 [예약수량불일치] → 구매후처리 · 교환품확정불가** — 재고는 확정할 수 없는 상품·옵션·수량을 회신한다. 구매후처리는 해당 교환 신청의 출고를 보류하고 고객에게 확인 중으로 표시한다.
- **구매후처리 · 교환품확정불가 → 재고 · 교환예약재대조요청** — 구매후처리는 원래 예약 번호와 검수 수락 수량을 보내 재고에 재대조를 요청한다.
- **재고 · 교환예약재대조요청 → 재고 · 교환예약재대조** — 재고는 해당 신청의 예약 원장, 같은 옵션의 실제 가용 수량과 이미 배정한 수량을 대조한다. 미확정이면 출고를 보류하고 같은 건으로 확인을 계속한다.
- **재고 · 교환예약재대조 [예약기록정정됨] → 재고 · 교환예약대조** — 기록을 바로잡았으면 재고가 같은 신청·예약 번호로 수량 확정을 다시 시도한다. 확정되면 같은 교환품확정확인 회신으로 이어진다.
- **재고 · 교환예약재대조 [공급불가확정] → 구매후처리 · 교환품공급불가** — 재고는 남은 예약을 정리하고 공급 불가 사유를 회신한다. 구매후처리는 출고를 중단하고 신청에 사유와 반품 선택 방법을 남긴다.
- **구매후처리 · 교환품공급불가 → 알림 · 교환품공급불가안내요청** — 구매후처리는 교환 신청 번호와 공급할 수 없는 사유, 고객이 반품을 선택할 수 있는 방법을 알림에 보낸다.
- **알림 · 교환품공급불가안내요청 → 고객 · 교환품공급불가안내** — 고객에게 교환품을 보낼 수 없는 이유와 반품 선택 방법을 알린다. 고객은 같은 신청의 검수 결과 화면에서도 이 내용을 확인할 수 있다.

- **배송 · 교환출고접수조회 → 배송 · 교환출고의뢰대조** — 배송은 신청 번호에 대응하는 출고 건과 처리 중인 의뢰를 찾는다.

- **배송 · 교환출고의뢰대조 [접수여부불명] → 구매후처리 · 교환출고확인중** — 아직 접수 결과를 알 수 없으면 구매후처리가 신청을 확인 중으로 유지한다.
- **구매후처리 · 교환출고확인중 → 구매후처리 · 대기후출고재조회** — 구매후처리가 원래 의뢰의 결과를 다시 확인할 시점을 잡는다.
- **구매후처리 · 대기후출고재조회 → 배송 · 교환출고접수조회** — 대기 후 같은 신청 번호의 접수 결과를 조회한다. 조회 회신 자체가 늦을 때도 같은 조회를 이어간다.

- **운영대시보드 · 포장목록요청 → 배송 · 주문배송정보요청** — 운영자가 포장 목록을 열면 대시보드가 출고할 건을 요청한다.
- **배송 · 주문배송정보요청 → 배송 · 출고대상판정** — 배송은 앞 그림의 교환출고건개설에서 만든 건도 포장 대상에 포함한다.
- **배송 · 출고대상판정 [출고할상품없음] → 운영대시보드 · 출고대상없음** — 운영자에게 출고 가능한 상품이 없다고 표시한다.
- **배송 · 출고대상판정 [출고할상품있음] → 주문 · 출고명세조회** — 배송은 출고 대상에 연결된 주문 명세를 요청한다.
- **주문 · 출고명세조회 → 배송 · 출고명세회신** — 주문은 해당 주문의 명세를 회신한다. 배송은 이를 교환 신청에서 확정한 상품·수량·배송지와 연결한다.
- **배송 · 출고명세회신 → 운영대시보드 · 포장목록과배송지** — 배송은 일반 출고와 구분한 교환 출고 번호, 포장할 상품, 배송지를 회신한다.
- **운영대시보드 · 포장목록과배송지 → 운영대시보드 · 포장대상표시** — 운영자가 해당 교환 건을 선택해 [S06-1의 운송장 등록](#s06-1-주문-확정에서-운영자의-운송장-등록까지)으로 이어 간다.

#### 고객이 검수 진행 상황을 열 때

```jobflow
scope: 본인의 검수 결과와 다음 절차 확인
Object: 고객프론트, 구매후처리
고객프론트.On검수진행조회 --> 구매후처리.message.검수진행조회요청
구매후처리.message.검수진행조회요청 --> 고객프론트.message.검수와후속처리상태
고객프론트.message.검수와후속처리상태 --> 고객프론트.검수결과표시
```

- **고객프론트 · 검수진행조회 → 구매후처리 · 검수진행조회요청** — 고객이 자신의 반품·교환 신청 상태를 다시 연다.
- **구매후처리 · 검수진행조회요청 → 고객프론트 · 검수와후속처리상태** — 구매후처리는 본인 신청의 검수 결과와 마지막으로 확인한 환불·출고 단계, 사유를 돌려준다.
- **고객프론트 · 검수와후속처리상태 → 고객프론트 · 검수결과표시** — 화면에 검수 결과와 후속 절차를 표시한다. 교환 수량을 확인 중이면 그 상태를, 공급 불가가 확정됐으면 사유와 반품 선택 방법을 보여 준다.

### S07-4. 금융·배송 결과로 신청 마감

취소·반품의 환불은 결제가, 교환품 인도는 배송이 확인한다. 구매후처리는 원래 신청에 해당하는 결과를 받아 주문의 상품·수량 반영까지 확인한 뒤 고객에게 알린다.

#### 구매후처리가 취소·반품의 환불을 의뢰할 때

```jobflow
scope: 취소·반품 신청의 환불 의뢰와 접수 결과
Object: 구매후처리, 결제
결제.취소원거래대조.승인금액있음 --> 구매후처리.message.취소거래승인확인
구매후처리.message.취소거래승인확인 --> 결제.message.환불요청
구매후처리.검수후처리판정.반품수락 --> 결제.message.환불요청
결제.message.환불요청 --> 결제.환불의뢰대조
결제.환불의뢰대조.새의뢰이며환불가능 --> 결제.환불접수판정
결제.환불의뢰대조.기존미종결의뢰 --> 결제.환불접수판정
결제.환불의뢰대조.환불가능액초과 --> 결제.환불접수판정
결제.환불접수판정.접수확인 --> 구매후처리.message.환불접수확인
결제.환불접수판정.미접수확정 --> 구매후처리.message.환불미접수
결제.환불접수판정.접수여부불명 --> 구매후처리.message.환불접수확인중
결제.환불의뢰대조.이미종결된의뢰 --> 구매후처리.message.기존신청환불결과
구매후처리.message.기존신청환불결과 --> 구매후처리.기존환불결과대조
구매후처리.기존환불결과대조.환불완료미반영 --> 구매후처리.환불신청대조
구매후처리.기존환불결과대조.최종실패미반영 --> 구매후처리.환불실패대상확인
```

- **결제 · 취소원거래대조 [승인금액있음] → 구매후처리 · 취소거래승인확인** — 결제는 실제 승인 거래와 금액을 구매후처리에 회신한다.
- **구매후처리 · 취소거래승인확인 → 결제 · 환불요청** — S07-1에서 취소 대상의 승인 금액을 확인한 구매후처리가 같은 신청의 환불을 의뢰한다.
- **구매후처리 · 검수후처리판정 [반품수락] → 결제 · 환불요청** — S07-3에서 수락한 반품은 검수 수량에 해당하는 금액만 원거래에 환불 의뢰한다.
- **결제 · 환불요청 → 결제 · 환불의뢰대조** — 결제는 원거래와 환불 의뢰 번호로 기존 건과 환불 가능한 금액을 확인한다.
- **결제 · 환불의뢰대조 [새의뢰이며환불가능] → 결제 · 환불접수판정** — 결제는 S05-4의 결제사 접수 요청과 회신으로 새 의뢰의 접수 상태를 판정한다.
- **결제 · 환불의뢰대조 [기존미종결의뢰] → 결제 · 환불접수판정** — 같은 의뢰가 진행 중이면 기존 접수 상태를 사용한다.
- **결제 · 환불의뢰대조 [환불가능액초과] → 결제 · 환불접수판정** — 환불할 수 있는 금액을 넘으면 미접수 사유를 돌려준다.
- **결제 · 환불접수판정 [접수확인] → 구매후처리 · 환불접수확인** — 구매후처리는 해당 신청을 ‘환불 진행 중’으로 표시하고 결제의 최종 사건을 기다린다.
- **결제 · 환불접수판정 [미접수확정] → 구매후처리 · 환불미접수** — 구매후처리는 미접수 사유를 기록하고 완료 반영을 보류한다. 결제는 원인을 정정하거나 조사 건을 연다.
- **결제 · 환불접수판정 [접수여부불명] → 구매후처리 · 환불접수확인중** — 구매후처리는 해당 신청을 ‘접수 확인 중’으로 표시한다. 결제가 같은 의뢰 번호로 결제사에 재조회해 결과를 회신한다.
- **결제 · 환불의뢰대조 [이미종결된의뢰] → 구매후처리 · 기존신청환불결과** — 이미 완료 또는 최종 실패로 확정된 의뢰에는 결제가 기존 결과와 변경 순번을 돌려준다.
- **구매후처리 · 기존신청환불결과 → 구매후처리 · 기존환불결과대조** — 구매후처리는 의뢰 번호와 자신이 마지막으로 반영한 순번을 확인한다. 이미 반영한 결과는 유지한다.
- **구매후처리 · 기존환불결과대조 [환불완료미반영] → 구매후처리 · 환불신청대조** — 완료 사건을 놓친 신청이면 아래 환불 완료 경로에서 상품·금액을 대조하고 주문 반영을 이어간다.
- **구매후처리 · 기존환불결과대조 [최종실패미반영] → 구매후처리 · 환불실패대상확인** — 최종 실패 사건을 놓친 신청이면 아래 환불 조사 경로의 실패 대조와 고객 안내를 이어간다.

결제사가 접수했는지 확인하는 과정과 조사할 건을 운영대시보드에 올리는 과정은 [S05-4의 환불 처리](#s05-4-주문-확정-실패-후-환불-종결)를 따른다. 그 예제의 의뢰인은 주문이며, 여기서는 구매후처리가 자기 신청 번호에 결과를 반영한다.

#### 환불 결과를 받아 취소·반품을 마감할 때

```jobflow
scope: 실제 환불 완료 또는 미승인 종결에 따른 주문 반영
Object: 결제, 구매후처리, 주문, 재고, 알림, 고객
결제.환불완료발행 --> 구매후처리.On환불완료
구매후처리.On환불완료 --> 구매후처리.환불신청대조
구매후처리.환불신청대조.취소대금환불됨 --> 주문.message.취소반영요청
결제.취소원거래대조.미승인종결 --> 구매후처리.message.취소거래미승인종결
구매후처리.message.취소거래미승인종결 --> 주문.message.취소반영요청
주문.message.취소반영요청 --> 재고.message.취소수량복원요청
재고.message.취소수량복원요청 --> 주문.message.취소재고처리결과
주문.message.취소재고처리결과 --> 구매후처리.message.취소반영결과
구매후처리.message.취소반영결과 --> 구매후처리.신청마감판정
구매후처리.환불신청대조.반품대금환불됨 --> 주문.message.반품반영요청
주문.message.반품반영요청 --> 구매후처리.message.반품반영결과
구매후처리.message.반품반영결과 --> 구매후처리.신청마감판정
구매후처리.신청마감판정.대상수량반영완료 --> 알림.On구매후처리종결
알림.On구매후처리종결 --> 알림.신청결과안내
알림.신청결과안내 --> 고객.message.신청결과안내
구매후처리.신청마감판정.반영수량미확정 --> 구매후처리.주문반영재확인
```

- **결제 · 환불완료발행 → 구매후처리 · 환불완료** — 결제사 통지·재조회 또는 운영 조사에서 의뢰 금액의 실제 환불을 처음 확인한 결제가 사건을 발행한다.
- **구매후처리 · 환불완료 → 구매후처리 · 환불신청대조** — 결제가 환불 완료를 발행하면 구매후처리는 원거래·환불 의뢰 번호·금액을 신청에 대조한다.
- **구매후처리 · 환불신청대조 [취소대금환불됨] → 주문 · 취소반영요청** — 취소한 상품 대금의 환불이 확인되면 구매후처리가 주문에 취소 반영을 요청한다.
- **결제 · 취소원거래대조 [미승인종결] → 구매후처리 · 취소거래미승인종결** — 결제는 뒤늦은 승인이 가능한 시도까지 확인하고 승인 없이 거래가 종결됐을 때 회신한다.
- **구매후처리 · 취소거래미승인종결 → 주문 · 취소반영요청** — S07-1에서 결제가 승인 없이 거래를 종결했다고 회신한 신청도 같은 취소 반영으로 이어진다.
- **주문 · 취소반영요청 → 재고 · 취소수량복원요청** — 주문은 미승인 취소 또는 환불된 취소 수량에 대해 재고에 기존 예약 해제나 출고 전 배정 수량 복원을 요청한다.
- **재고 · 취소수량복원요청 → 주문 · 취소재고처리결과** — 재고는 해당 수량의 예약을 해제하거나 출고 전 배정을 복원한 결과를 주문에 돌려준다. 이미 반영한 요청에는 기존 결과를 돌려준다.
- **주문 · 취소재고처리결과 → 구매후처리 · 취소반영결과** — 주문은 취소 수량과 재고 처리 결과를 회신한다. 구매후처리는 반영이 확인된 건만 마감한다.
- **구매후처리 · 취소반영결과 → 구매후처리 · 신청마감판정** — 구매후처리는 신청에 배정된 취소 수량과 주문이 실제 반영한 수량을 대조한다.
- **구매후처리 · 환불신청대조 [반품대금환불됨] → 주문 · 반품반영요청** — 반품 대금이 환불됐으면 구매후처리는 주문에 반품 수량을 반영하도록 요청한다.
- **주문 · 반품반영요청 → 구매후처리 · 반품반영결과** — 주문은 반품 수량을 반영하고 그 결과를 구매후처리에 회신한다.
- **구매후처리 · 반품반영결과 → 구매후처리 · 신청마감판정** — 구매후처리는 반품 신청과 주문이 반영한 상품·수량을 대조한다.
- **구매후처리 · 신청마감판정 [대상수량반영완료] → 알림 · 구매후처리종결** — 신청 수량의 반영을 확인하면 구매후처리가 신청을 마감하고 종결 사건을 발행한다.
- **알림 · 구매후처리종결 → 알림 · 신청결과안내** — 구매후처리가 신청 상태를 확정해 발행한 종결 사건을 알림이 받아 고객에게 결과를 안내한다.
- **알림 · 신청결과안내 → 고객 · 신청결과안내** — 알림은 확정된 신청 결과와 후속 절차를 고객에게 보낸다.
- **구매후처리 · 신청마감판정 [반영수량미확정] → 구매후처리 · 주문반영재확인** — 주문이 반영한 수량과 신청 수량이 맞지 않으면 해당 신청을 열어 두고 아래 주문 반영 재확인으로 이어 간다.

같은 신청의 반영 결과를 기다리는 동안 구매후처리는 진행 상태를 유지한다. 반품 상품을 다시 판매할 수 있는지는 물류센터가 실물을 확인한 뒤 결정한다.

#### 환불 조사 또는 최종 실패가 통지될 때

```jobflow
결제.환불조사종결판정.근거부족 --> 운영대시보드.message.환불조사보완요청
결제.환불조사종결판정.최종실패확인 --> 운영대시보드.message.환불조사실패확정
결제.환불조사종결판정.최종실패확인 --> 결제.환불실패확정발행
결제.환불실패확정발행 --> 구매후처리.On환불실패확정
구매후처리.On환불실패확정 --> 구매후처리.환불실패대상확인
구매후처리.환불실패대상확인.해당신청최종실패 --> 알림.On구매후처리종결
알림.On구매후처리종결 --> 알림.신청결과안내
알림.신청결과안내 --> 고객.message.신청결과안내
```

- **결제 · 환불조사등록 → 구매후처리 · 환불실패확인필요** — 결제가 환불 조사 건을 열어 확인이 필요하다는 사건을 발행한다.
- **구매후처리 · 환불실패확인필요 → 구매후처리 · 환불조사대상확인** — 구매후처리는 최신 사건의 의뢰 번호가 자신이 맡은 취소·반품과 일치하면 해당 신청을 ‘환불 조사 중’으로 표시한다.
- **결제 · 환불조사등록 → 알림 · 환불조사안내요청** — 조사 건을 연 결제가 알림에 운영자 확인 요청과 고객의 확인 중 안내를 의뢰한다. 같은 의뢰에 열린 조사가 있으면 기존 건을 사용한다.
- **알림 · 환불조사안내요청 → 운영대시보드 · 환불조사알림** — 운영자에게 조사 대상 의뢰 번호를 표시한다. 운영자는 이 건을 열어 결제사 기록을 대조한다.
- **알림 · 환불조사안내요청 → 고객 · 환불확인중안내** — 고객에게 해당 신청의 환불 결과를 확인 중이라고 안내한다.
- **운영대시보드 · 환불조사결과제출 → 결제 · 환불조사회신** — 운영자가 이 의뢰의 실제 정산 내역과 근거를 조사 화면에서 제출한다.
- **결제 · 환불조사회신 → 결제 · 환불조사종결판정** — 운영자가 결제사와 대조한 내역을 제출하면 결제는 해당 의뢰의 금액과 최종 결과가 확인됐는지 판정한다.
- **결제 · 환불조사종결판정 [완료내역확보] → 운영대시보드 · 환불조사완료** — 운영자에게 대조가 끝난 환불 건의 결과를 보여 준다.
- **결제 · 환불조사종결판정 [완료내역확보] → 결제 · 환불완료발행** — 실제 환불을 확인하면 앞 그림의 환불완료가 구매후처리에 전달된다.
- **결제 · 환불조사종결판정 [근거부족] → 운영대시보드 · 환불조사보완요청** — 결제가 부족한 근거를 알려 준다. 운영자는 같은 조사 건에서 요청 내역을 보고 증빙을 보완한다.
- **결제 · 환불조사종결판정 [최종실패확인] → 운영대시보드 · 환불조사실패확정** — 운영자에게 최종 실패 사유와 후속 정산이 필요한 건을 보여 준다.
- **결제 · 환불조사종결판정 [최종실패확인] → 결제 · 환불실패확정발행** — 결제가 의뢰의 최종 실패를 처음 확정하면 실패 사유와 운영자가 확인한 후속 정산 절차를 담아 발행한다.
- **결제 · 환불실패확정발행 → 구매후처리 · 환불실패확정** — 운영 조사로 최종 실패를 확인한 결제가 실패 확정 사건을 발행한다.
- **구매후처리 · 환불실패확정 → 구매후처리 · 환불실패대상확인** — 구매후처리는 최신 결제 결과가 자기 신청의 환불과 일치할 때만 실패 사유를 기록하고 신청을 종결해 구매후처리종결을 발행한다.
- **구매후처리 · 환불실패대상확인 [해당신청최종실패] → 알림 · 구매후처리종결** — 자신이 맡은 신청에서 최종 실패를 확인해 마감하면 알림에 종결 사실이 전달된다.
- **알림 · 구매후처리종결 → 알림 · 신청결과안내** — 구매후처리가 신청 상태를 확정해 발행한 종결 사건을 알림이 받아 고객에게 결과를 안내한다.
- **알림 · 신청결과안내 → 고객 · 신청결과안내** — 고객에게 환불 실패 사유와 운영자가 확인한 후속 정산 방법을 보낸다. 주문 상품의 취소·반품 완료 처리는 보류한다.

결제는 같은 환불 의뢰에 상태 변경 순번을 붙인다. 구매후처리는 신청·의뢰 번호와 순번을 대조해 늦게 도착한 조사 통지로 종결 건을 다시 열지 않는다.

- **구매후처리 · 교환배송대조 [교환품인도확정] → 주문 · 교환반영요청** — 교환품 인도가 확인됐으면 구매후처리가 주문에 교환 수량과 인도 완료를 반영하도록 요청한다.
- **주문 · 교환반영요청 → 구매후처리 · 교환반영결과** — 주문은 해당 교환의 반영 결과와 수량을 구매후처리에 회신한다.
- **구매후처리 · 교환반영결과 → 구매후처리 · 신청마감판정** — 구매후처리는 교환품 인도 수량과 주문이 반영한 교환 수량을 대조한다.
- **구매후처리 · 신청마감판정 [대상수량반영완료] → 알림 · 구매후처리종결** — 교환 수량의 반영을 확인하면 구매후처리가 신청을 마감하고 종결 사건을 발행한다.
- **알림 · 구매후처리종결 → 알림 · 신청결과안내** — 구매후처리가 신청 상태를 확정해 발행한 종결 사건을 알림이 받아 고객에게 결과를 안내한다.
- **알림 · 신청결과안내 → 고객 · 신청결과안내** — 고객에게 해당 신청에서 어떤 상품의 교환이 끝났는지 알린다.
- **구매후처리 · 신청마감판정 [반영수량미확정] → 구매후처리 · 주문반영재확인** — 주문이 반영한 수량과 신청 수량이 맞지 않으면 해당 신청을 열어 두고 아래 주문 반영 재확인으로 이어 간다.

- **구매후처리 · 주문반영응답기한경과 → 주문 · 신청반영결과조회** — 주문의 회신이 도착하지 않아도 같은 신청의 기존 결과를 먼저 조회한다.
- **주문 · 신청반영결과조회 → 주문 · 신청반영내역대조** — 주문은 신청 상품의 배정 수량과 실제 반영 수량, 진행 중인 작업을 대조한다.
- **주문 · 신청반영내역대조 [대상수량반영완료] → 구매후처리 · 주문반영확인** — 이미 처리한 건이면 그 신청에 반영한 수량을 회신한다.
- **구매후처리 · 주문반영확인 → 구매후처리 · 신청마감판정** — 신청과 수량이 맞으면 앞 그림의 신청 마감과 고객 통지로 돌아간다.
- **주문 · 신청반영내역대조 [반영진행중] → 구매후처리 · 주문반영확인중** — 주문 또는 재고가 처리 중이면 구매후처리는 화면 조회에 진행 중 상태를 돌려준다.
- **구매후처리 · 주문반영확인중 → 구매후처리 · 주문반영재확인** — 잠시 뒤 같은 신청의 반영 결과를 다시 조회한다.
- **주문 · 신청반영내역대조 [미반영수량확정] → 구매후처리 · 미반영신청수량** — 처리 중인 작업이 없고 빠진 수량을 확인하면 주문이 해당 상품과 수량을 회신한다.
- **구매후처리 · 미반영신청수량 → 구매후처리 · 반영재요청판정** — 구매후처리는 같은 신청 번호에서 실제 빠진 수량과 신청 종류를 확인한다.
- **구매후처리 · 반영재요청판정 [취소] → 주문 · 취소반영요청** — 취소의 미반영 수량을 앞 그림과 같은 주문·재고 반영 경로로 보낸다.
- **구매후처리 · 반영재요청판정 [반품] → 주문 · 반품반영요청** — 반품의 미반영 수량만 주문에 다시 보낸다. 결제의 기존 환불 결과를 사용한다.
- **구매후처리 · 반영재요청판정 [교환] → 주문 · 교환반영요청** — 인도를 확인한 교환품의 미반영 수량만 같은 신청으로 다시 보낸다.

#### 고객이 신청 결과를 확인할 때

```jobflow
scope: 내 신청의 진행 단계와 확정 결과 표시
Object: 고객프론트, 구매후처리
고객프론트.On신청결과조회 --> 구매후처리.message.신청결과조회요청
구매후처리.message.신청결과조회요청 --> 고객프론트.message.신청처리결과
고객프론트.message.신청처리결과 --> 고객프론트.신청결과표시
```

- **고객프론트 · 신청결과조회 → 구매후처리 · 신청결과조회요청** — 고객이 주문 내역이나 종결 안내에서 신청을 열면 화면이 그 신청 번호로 결과를 요청한다.
- **구매후처리 · 신청결과조회요청 → 고객프론트 · 신청처리결과** — 구매후처리는 본인의 신청에 대해 마지막으로 확인한 수거·검수·환불·배송 단계, 확정 결과와 후속 절차를 돌려준다.
- **고객프론트 · 신청처리결과 → 고객프론트 · 신청결과표시** — 화면에 취소·반품·교환 중 해당 신청 결과를 표시한다. 처리 중이면 다음 확인 단계, 최종 실패이면 사유와 후속 정산 안내를 보여 준다.

### S07-5. 구매 리뷰 작성 자격과 등록

**시작 사건** 회원이 주문 상품의 리뷰 작성 화면을 연다. 리뷰 서비스는 자격 조회와 등록 요청마다 로그인한 회원인지 먼저 확인한다. 비회원에게는 이 단계에서 로그인을 안내한다. [매크로 M07-4](macro.md#m07-4-구매-리뷰-작성)

#### 고객이 주문 상품에서 리뷰 작성을 선택할 때

```jobflow
scope: 회원과 구매 자격 확인 후 리뷰 작성 화면 열기
Object: 고객프론트, 리뷰, 주문
고객프론트.On리뷰작성화면열기 --> 리뷰.message.리뷰작성자격조회
리뷰.message.리뷰작성자격조회 --> 리뷰.조회회원확인
리뷰.조회회원확인.로그인필요 --> 고객프론트.message.리뷰조회로그인안내
리뷰.조회회원확인.회원확인됨 --> 주문.message.리뷰구매내역조회
주문.message.리뷰구매내역조회 --> 리뷰.message.작성자격용구매내역
리뷰.message.작성자격용구매내역 --> 리뷰.작성자격판정
리뷰.작성자격판정.작성가능 --> 고객프론트.message.리뷰작성폼열기
고객프론트.message.리뷰작성폼열기 --> 고객프론트.리뷰입력폼표시
리뷰.작성자격판정.대상구매없음 --> 고객프론트.message.리뷰작성불가안내
리뷰.작성자격판정.이미작성함 --> 고객프론트.message.기존리뷰안내
```

- **고객프론트 · 리뷰작성화면열기 → 리뷰 · 리뷰작성자격조회** — 고객이 선택한 주문 상품의 리뷰 작성 자격을 조회한다.
- **리뷰 · 리뷰작성자격조회 → 리뷰 · 조회회원확인** — 리뷰는 화면에서 넘어온 요청의 회원을 확인한다. 비회원이면 로그인을 안내한다.
- **리뷰 · 조회회원확인 [로그인필요] → 고객프론트 · 리뷰조회로그인안내** — 리뷰 작성 자격을 조회할 수 있도록 고객에게 로그인을 안내한다.
- **리뷰 · 조회회원확인 [회원확인됨] → 주문 · 리뷰구매내역조회** — 회원을 확인하면 리뷰는 주문에 해당 회원과 주문 상품의 구매 내역을 묻는다.
- **주문 · 리뷰구매내역조회 → 리뷰 · 작성자격용구매내역** — 주문은 요청한 회원과 주문 상품의 구매 상태를 회신한다.
- **리뷰 · 작성자격용구매내역 → 리뷰 · 작성자격판정** — 리뷰는 구매 상태와 자신의 등록 이력을 대조한다. 대상 구매가 있고 아직 작성하지 않았으면 작성 가능으로, 그 밖에는 구매 자격이 없거나 이미 작성한 것으로 안내한다.
- **리뷰 · 작성자격판정 [작성가능] → 고객프론트 · 리뷰작성폼열기** — 리뷰는 해당 주문 상품에 리뷰를 작성할 수 있다고 화면에 회신한다.
- **고객프론트 · 리뷰작성폼열기 → 고객프론트 · 리뷰입력폼표시** — 화면에 해당 상품과 평점·본문 입력란을 표시한다. 고객이 작성한 뒤 제출을 선택하면 다음 그림이 시작된다.
- **리뷰 · 작성자격판정 [대상구매없음] → 고객프론트 · 리뷰작성불가안내** — 해당 회원의 리뷰 작성 대상 구매가 없다고 안내한다.
- **리뷰 · 작성자격판정 [이미작성함] → 고객프론트 · 기존리뷰안내** — 해당 주문 상품에 이미 작성한 리뷰가 있다고 안내한다.

#### 고객이 평점과 본문을 제출할 때

```jobflow
scope: 리뷰 제출 시 자격 재확인과 등록 결과 표시
Object: 고객프론트, 리뷰, 주문
고객프론트.On리뷰제출 --> 리뷰.message.리뷰등록요청
리뷰.message.리뷰등록요청 --> 리뷰.제출요건판정
리뷰.제출요건판정.로그인필요 --> 고객프론트.message.리뷰제출로그인안내
리뷰.제출요건판정.입력보완필요 --> 고객프론트.message.리뷰입력보완안내
고객프론트.message.리뷰입력보완안내 --> 고객프론트.리뷰입력폼표시
고객프론트.On보완후리뷰제출 --> 리뷰.message.리뷰등록요청
리뷰.제출요건판정.회원과입력확인됨 --> 주문.message.제출시구매확인요청
주문.message.제출시구매확인요청 --> 리뷰.message.제출시구매내역
리뷰.message.제출시구매내역 --> 리뷰.구매리뷰등록판정
리뷰.구매리뷰등록판정.구매자격없음 --> 고객프론트.message.리뷰등록불가안내
리뷰.구매리뷰등록판정.이미등록됨 --> 고객프론트.message.기존리뷰등록결과
고객프론트.message.기존리뷰등록결과 --> 고객프론트.등록리뷰표시
리뷰.구매리뷰등록판정.등록가능 --> 리뷰.리뷰등록
리뷰.리뷰등록 --> 고객프론트.message.리뷰등록완료
고객프론트.message.리뷰등록완료 --> 고객프론트.등록리뷰표시
```

- **고객프론트 · 리뷰제출 → 리뷰 · 리뷰등록요청** — 고객이 작성한 평점과 본문을 제출한다.
- **리뷰 · 리뷰등록요청 → 리뷰 · 제출요건판정** — 고객이 작성한 평점과 본문을 제출하면 리뷰는 회원과 필수 입력을 다시 확인한다. 세션이 끝났으면 로그인, 입력이 부족하면 수정을 안내한다.
- **리뷰 · 제출요건판정 [로그인필요] → 고객프론트 · 리뷰제출로그인안내** — 리뷰 제출을 계속하기 위해 고객에게 로그인을 안내한다.
- **리뷰 · 제출요건판정 [입력보완필요] → 고객프론트 · 리뷰입력보완안내** — 평점이나 본문 등 보완할 입력을 표시한다.
- **고객프론트 · 리뷰입력보완안내 → 고객프론트 · 리뷰입력폼표시** — 화면에 작성한 내용을 유지하고 고칠 항목을 표시한다.
- **고객프론트 · 보완후리뷰제출 → 리뷰 · 리뷰등록요청** — 고객이 평점이나 본문을 고쳐 다시 제출하면 리뷰가 같은 등록 요청의 자격과 입력 요건을 다시 검사한다.
- **리뷰 · 제출요건판정 [회원과입력확인됨] → 주문 · 제출시구매확인요청** — 리뷰는 회원과 입력 요건을 충족한 제출에 대해 주문에 현재 구매 상태를 요청한다.
- **주문 · 제출시구매확인요청 → 리뷰 · 제출시구매내역** — 주문은 해당 회원의 주문 상품이 현재 리뷰 대상인지 확인할 구매 정보를 회신한다.
- **리뷰 · 제출시구매내역 → 리뷰 · 구매리뷰등록판정** — 리뷰는 제출 시점의 구매 자격과 기존 리뷰를 확인한다. 자격이 없으면 사유를, 이미 등록된 제출이면 기존 결과를 돌려준다.
- **리뷰 · 구매리뷰등록판정 [구매자격없음] → 고객프론트 · 리뷰등록불가안내** — 제출 시점에 구매 자격을 확인하지 못한 사유를 표시한다.
- **리뷰 · 구매리뷰등록판정 [이미등록됨] → 고객프론트 · 기존리뷰등록결과** — 같은 주문 상품에 이미 등록된 리뷰 결과를 보여 준다.
- **고객프론트 · 기존리뷰등록결과 → 고객프론트 · 등록리뷰표시** — 중복 제출에는 같은 주문 상품에 이미 등록된 리뷰를 표시한다.
- **리뷰 · 구매리뷰등록판정 [등록가능] → 리뷰 · 리뷰등록** — 리뷰는 자격이 확인된 회원·주문 상품에 한 건만 등록하고 고객에게 결과를 알린다.
- **리뷰 · 리뷰등록 → 고객프론트 · 리뷰등록완료** — 리뷰는 등록한 리뷰의 식별자와 내용을 제출한 화면에 돌려준다.
- **고객프론트 · 리뷰등록완료 → 고객프론트 · 등록리뷰표시** — 새로 등록한 리뷰를 화면에 표시한다.
