# 쇼핑몰 MSA 서비스뷰

[쇼핑몰 매크로뷰](macro.md)의 **쇼핑몰**을 아홉 서비스로 나눈 설계 예제다. 예를 들어 결제사는 돈이 승인됐다고 알릴 수 있지만, 상품 재고까지 확보해 주문을 확정하는 서비스는 **주문**이다. **배송**은 그 주문의 확정 사건을 받은 뒤에야 출고 건을 연다.

| 서비스 | 이 서비스가 결정하고 기록하는 것 |
| --- | --- |
| 회원인증 | 회원의 신원, 비회원 인증 코드의 유효기간·사용 여부, 인증한 주문 한 건의 열람 권한 |
| 상품 | 판매 중인 상품과 옵션, 주문 시 적용할 가격·할인 조건 |
| 재고 | 상품별 가용 수량, 주문·교환에 예약한 수량, 예약의 확정·해제 |
| 주문 | 고객이 수락한 금액과 상품·배송지의 주문 시점 사본, 주문 확정과 상품별 취소 상태 |
| 결제 | 결제 시도, 결제사에서 확인한 승인·미승인 상태, 원거래별 환불 가능 잔액과 환불 결과 |
| 배송 | 일반·교환 출고 건, 출고 중지와 실물 인계 확인, 운송장, 배달·수거 경과 |
| 구매후처리 | 취소·반품·교환 신청, 물류센터의 검수 결과, 환불이나 교환 배송을 기다리는 신청의 상태 |
| 알림 | 업무별 수신 대상·채널, 발송사에 의뢰한 문자·메일과 발송 결과 |
| 리뷰 | 회원의 구매 리뷰, 같은 주문 상품에 대한 중복 등록 여부 |

도표의 열에는 백엔드 서비스와 공개 요청·응답을 주고받는 화면을 둔다. **고객프론트**는 고객 요청과 결과 표시, **운영대시보드**는 운영 작업 지시와 결과 확인을 맡는다. 주문·배송·결제 상태의 원본은 각 서비스가 소유한다. 화면에서 나중에 상태를 다시 여는 행동은 독립 진입점이다. `재고.message.재고예약요청`처럼 받는 쪽에 붙은 메시지는 특정 서비스에 건네는 요청이나 회신이다. `배송.On주문확정`은 주문 서비스가 **확정된 사실**을 발행한 뒤 배송이 독립적으로 일을 시작하는 지점이다. 제목 아래의 시작 사건에서 화면 요청·외부 통지·구독 사건을 구분한다. 각 서비스는 자기 기록을 먼저 확정하고 발행할 사건을 함께 남긴다. 통지나 회신이 늦으면 같은 주문·거래·신청의 처리 결과를 확인한다.

## S02. 비회원이 주문 한 건을 열람할 권한 얻기

주문 서비스는 주문 당시의 연락처와 주문 내역을 보관한다. 회원인증 서비스는 조회 코드를 발급하고 어느 주문을 열람할 수 있는지 판정한다. [매크로 M02](macro.md#m02-비회원이-인증-문자를-받아-주문-한-건-조회하기)

**시작 사건** 비회원이 주문번호와 연락처로 인증 문자를 신청한다. 회원인증은 주문의 존재나 연락처 일치 여부에 관계없이 화면에 같은 접수 안내를 돌려준다. 발송사가 문자를 전달하고 고객이 같은 주문번호와 받은 코드를 입력하면, 도표 아래쪽의 **고객프론트 · 인증코드제출**에서 조회가 이어진다.

```jobflow
scope: 비회원의 인증 문자 신청부터 코드 제출과 주문 한 건 열람까지
Object: 고객프론트, 주문, 회원인증, 알림
고객프론트.On인증문자신청 --> 회원인증.message.주문조회인증요청
회원인증.message.주문조회인증요청 --> 고객프론트.message.인증신청접수안내
회원인증.message.주문조회인증요청 --> 주문.message.주문연락처대조요청
주문.message.주문연락처대조요청 --> 주문.주문연락처대조
주문.주문연락처대조.주문없음또는연락처불일치 --> 회원인증.message.주문연락처미확인
주문.주문연락처대조.연락처일치 --> 회원인증.message.주문연락처일치확인
회원인증.message.주문연락처일치확인 --> 알림.message.인증문자발송요청
알림.message.인증문자발송요청 --> 알림.문자발송의뢰
알림.문자발송의뢰.접수확인 --> 회원인증.message.인증문자발송접수
알림.문자발송의뢰.미접수확정 --> 회원인증.message.인증문자접수실패
알림.문자발송의뢰.접수여부불명 --> 회원인증.message.인증문자접수확인중
알림.On문자접수재확인시점 --> 알림.문자접수결과조회
알림.문자접수결과조회.접수확인 --> 회원인증.message.인증문자발송접수
알림.문자접수결과조회.미접수확정 --> 회원인증.message.인증문자접수실패
알림.문자접수결과조회.접수여부불명
고객프론트.On인증코드제출 --> 주문.message.주문조회코드확인요청
주문.message.주문조회코드확인요청 --> 회원인증.message.주문조회코드검증요청
회원인증.message.주문조회코드검증요청 --> 회원인증.주문조회코드검증
회원인증.주문조회코드검증.유효한코드 --> 주문.message.주문열람허용
주문.message.주문열람허용 --> 고객프론트.message.인증한주문내역
회원인증.주문조회코드검증.코드불일치 --> 주문.message.코드재입력필요
주문.message.코드재입력필요 --> 고객프론트.message.코드재입력안내
회원인증.주문조회코드검증.코드효력종료 --> 주문.message.코드재발급필요
주문.message.코드재발급필요 --> 고객프론트.message.코드재발급안내
회원인증.주문조회코드검증.판정기록미확정 --> 주문.message.인증코드검증확인중
주문.message.인증코드검증확인중 --> 고객프론트.message.인증코드검증대기안내
고객프론트.message.인증코드검증대기안내 --> 고객프론트.대기후검증재확인
고객프론트.대기후검증재확인 --> 주문.message.주문조회코드확인요청
주문.On검증응답기한경과 --> 주문.검증응답도착확인
주문.검증응답도착확인.응답없고요청대기중 --> 고객프론트.message.인증코드검증대기안내
고객프론트.message.인증코드검증대기안내 --> 고객프론트.대기후검증재확인
고객프론트.대기후검증재확인 --> 주문.message.주문조회코드확인요청
```

- **고객프론트 · 인증문자신청 → 회원인증 · 주문조회인증요청** — 고객이 입력한 주문번호와 연락처를 회원인증에 보낸다.
- **회원인증 · 주문조회인증요청 → 고객프론트 · 인증신청접수안내** — 회원인증은 모든 신청에 “요청을 받았습니다. 잠시 기다려 주세요”라고 안내한다. 주문 유무, 연락처 일치 여부, 발송 상태에 따라 이 안내를 바꾸지 않는다.
- **회원인증 · 주문조회인증요청 → 주문 · 주문연락처대조요청** — 회원인증은 신청에 적힌 주문번호와 연락처를 주문 서비스에 보내 대조를 요청한다.
- **주문 · 주문연락처대조요청 → 주문 · 주문연락처대조** — 주문 서비스는 해당 번호로 주문을 찾아 주문 당시의 연락처와 제출된 연락처를 비교한다.
- **주문 · 주문연락처대조 [주문없음또는연락처불일치] → 회원인증 · 주문연락처미확인** — 주문이 없거나 연락처가 다르면 주문 서비스는 두 경우를 같은 미확인 결과로 회신한다. 회원인증은 코드를 발급하지 않고 신청을 마친다.
- **주문 · 주문연락처대조 [연락처일치] → 회원인증 · 주문연락처일치확인** — 연락처가 일치하면 주문 서비스는 회원인증에 해당 주문번호의 연락처가 확인됐다고 회신한다.
- **회원인증 · 주문연락처일치확인 → 알림 · 인증문자발송요청** — 일치 회신을 받은 회원인증은 해당 주문에만 쓸 코드와 유효기한을 기록하고 알림 서비스에 확인된 연락처로 문자 발송을 요청한다.
- **알림 · 인증문자발송요청 → 알림 · 문자발송의뢰** — 알림 서비스는 코드가 담긴 문자를 발송사에 의뢰하고 응답을 확인한다. 일시적인 호출 제한으로 미접수가 명시되면 제한이 풀린 뒤 코드 유효기한 안에서 재시도한다.
- **알림 · 문자발송의뢰 [접수확인] → 회원인증 · 인증문자발송접수** — 발송사가 접수를 확인하면 알림 서비스는 회원인증에 접수 사실을 알린다. 주문 열람 권한은 고객이 코드를 제출해 검증받을 때 생긴다.
- **알림 · 문자발송의뢰 [미접수확정] → 회원인증 · 인증문자접수실패** — 잘못된 요청 형식으로 접수할 수 없거나, 미접수 상태로 재시도 기한이 끝나면 알림 서비스는 접수 실패를 회신한다. 회원인증은 그 의뢰에 발급한 코드를 무효화한다.
- **알림 · 문자발송의뢰 [접수여부불명] → 회원인증 · 인증문자접수확인중** — 응답 시간 초과로 접수 여부를 알 수 없으면 알림 서비스는 확인 중으로 회신한다. 회원인증은 코드의 기존 유효기한을 유지하고, 알림 서비스는 발송사에서 같은 의뢰를 조회할 수 있는 경우에 재확인을 예약한다. 끝까지 확인할 수 없으면 코드는 원래 기한에 만료된다.
- **알림 · 문자접수재확인시점 → 알림 · 문자접수결과조회** — 접수 여부가 불명인 건은 유효기한 안에서 같은 의뢰의 접수 결과를 조회한다. 결과가 여전히 불명이면 다음 확인을 기다리고, 기한이 지나면 조회를 마친다.
- **알림 · 문자접수결과조회 [접수확인] → 회원인증 · 인증문자발송접수** — 뒤늦게 확인한 접수 결과를 회원인증에 알린다.
- **알림 · 문자접수결과조회 [미접수확정] → 회원인증 · 인증문자접수실패** — 미접수가 확정되고 재시도도 마쳤으면 알림이 접수 실패를 통지하고 회원인증은 해당 코드를 무효화한다.
- **고객프론트 · 인증코드제출 → 주문 · 주문조회코드확인요청** — 고객이 받은 문자에서 코드를 입력해 제출하면 화면은 검증 요청 번호를 붙여 코드와 주문번호를 주문 서비스에 보낸다.
- **주문 · 주문조회코드확인요청 → 회원인증 · 주문조회코드검증요청** — 주문은 해당 요청 번호로 회원인증에 검증을 요청하고 응답을 기다린다. 회원인증에 요청이 전달돼도 이 시점에는 아직 검증 결과를 받은 상태가 아니다.
- **회원인증 · 주문조회코드검증요청 → 회원인증 · 주문조회코드검증** — 회원인증은 그 주문에 발급한 코드와 제출값을 대조하고 유효기한과 사용 여부를 확인한다.
- **회원인증 · 주문조회코드검증 [유효한코드] → 주문 · 주문열람허용** — 유효하면 회원인증은 코드 사용과 해당 검증 요청의 허용 결과를 함께 기록하고 인증된 주문번호를 회신한다. 주문 서비스는 요청한 번호와 일치하는 한 건의 내역만 화면에 보여 준다.
- **주문 · 주문열람허용 → 고객프론트 · 인증한주문내역** — 주문은 인증된 번호와 일치하는 한 건의 주문 내역을 돌려준다.
- **회원인증 · 주문조회코드검증 [코드불일치] → 주문 · 코드재입력필요** — 해당 주문과 코드가 일치하지 않으면 회원인증은 재입력이 필요하다고 회신하고 주문 서비스는 화면에 코드 재입력을 안내한다.
- **주문 · 코드재입력필요 → 고객프론트 · 코드재입력안내** — 고객이 같은 주문의 코드를 다시 입력할 수 있게 한다.
- **회원인증 · 주문조회코드검증 [코드효력종료] → 주문 · 코드재발급필요** — 제출값이 해당 주문에 발급한 코드와 일치해도 만료됐거나 이미 사용·무효화된 코드이면 회원인증은 재발급이 필요하다고 회신한다. 주문 서비스는 화면에서 새 인증 문자를 신청하도록 안내한다.
- **주문 · 코드재발급필요 → 고객프론트 · 코드재발급안내** — 새 인증 문자를 신청할 수 있게 한다.
- **회원인증 · 주문조회코드검증 [판정기록미확정] → 주문 · 인증코드검증확인중** — 검증 결과를 확정해 기록했는지 확인할 수 없으면 회원인증은 같은 검증 요청을 확인 중이라고 회신한다.
- **주문 · 인증코드검증확인중 → 고객프론트 · 인증코드검증대기안내** — 주문은 화면에 “인증 결과를 확인 중입니다. 잠시 기다려 주세요”라고 안내한다.
- **고객프론트 · 인증코드검증대기안내 → 고객프론트 · 대기후검증재확인** — 확인 중이라는 응답을 받은 화면은 대기 안내를 표시하고 잠시 뒤 검증 결과를 재확인한다.
- **고객프론트 · 대기후검증재확인 → 주문 · 주문조회코드확인요청** — 최초 제출과 같은 검증 요청 번호·주문번호·코드로 다시 조회한다.
- **주문 · 검증응답기한경과 → 주문 · 검증응답도착확인** — 회원인증의 회신을 기다리던 주문은 응답 기한이 지나면 해당 요청의 확정 응답이 도착했는지 확인한다.
- **주문 · 검증응답도착확인 [응답없고요청대기중] → 고객프론트 · 인증코드검증대기안내** — 주문은 아직 회신하지 않은 화면에 확인 중을 돌려준다. 응답이 이미 도착했다면 그 판정을 사용한다. 대기 안내를 보낸 뒤 확정 회신이 도착하면 결과를 다음 재확인에 사용한다.
- **고객프론트 · 인증코드검증대기안내 → 고객프론트 · 대기후검증재확인** — 회원인증의 응답 기한이 지나 주문이 대기 안내를 보내면, 화면은 안내를 보여 주고 잠시 뒤 재확인한다.
- **고객프론트 · 대기후검증재확인 → 주문 · 주문조회코드확인요청** — 같은 검증 요청 번호·주문번호·코드로 앞의 검증 경로에 다시 들어간다.

접수 뒤에도 발송사가 단말기에 문자를 전달하지 못할 수 있다. 알림 서비스는 발송사의 결과 조회나 통지로 확인한 배달 결과를 같은 발송 건에 따로 기록한다. 고객 화면에는 신청 때의 공통 접수 안내가 유지되며, 문자를 받지 못한 고객은 새 코드를 신청할 수 있다.

화면의 재확인은 같은 번호·주문·코드에 묶인다. 회원인증은 이 요청에 확정한 판정이 있으면 그 판정을 돌려준다. 화면의 대기 기한이 지나도 결과가 불명이면 확인이 지연됐음을 표시하고 고객이 같은 요청의 결과를 다시 확인할 수 있게 한다. 새 입력으로 이미 사용한 코드를 제출하면 재발급 대상이다.

## S05. 주문과 결제

가격과 할인은 상품, 판매 수량은 재고, 결제와 환불의 근거가 되는 승인 기록은 결제가 제공한다. 주문이 이 결과를 모아 주문 상태를 결정한다. [매크로 M05](macro.md#m05-주문과-결제)

### S05-1. 주문 접수와 재고 예약

**시작 사건** 인증을 마친 고객이 주문서를 제출한다. 이 예제에서는 주문서의 모든 항목이 접수 가능해야 주문 한 건을 만든다. 주문 서비스는 주문 시점의 금액을 보관하고, 재고 서비스는 요청한 수량과 예약 기한을 관리한다.

```jobflow
scope: 주문서 가격 확인과 판매 수량 예약
Object: 고객프론트, 상품, 주문, 재고
고객프론트.On주문서제출 --> 주문.message.주문생성요청
주문.message.주문생성요청 --> 상품.message.판매조건조회
상품.message.판매조건조회 --> 상품.판매조건판정
상품.판매조건판정.판매중단 --> 주문.message.판매중단안내
주문.message.판매중단안내 --> 고객프론트.message.판매중단상품안내
상품.판매조건판정.판매가능 --> 주문.message.판매조건회신
주문.message.판매조건회신 --> 주문.주문서대조
주문.주문서대조.판매조건변경 --> 고객프론트.message.변경된가격과할인
주문.주문서대조.판매조건일치 --> 재고.message.재고예약요청
재고.message.재고예약요청 --> 재고.주문수량예약
재고.주문수량예약.가용수량부족 --> 주문.message.주문수량품절
주문.message.주문수량품절 --> 고객프론트.message.품절상품안내
재고.주문수량예약.요청수량예약됨 --> 주문.message.주문수량예약확인
주문.message.주문수량예약확인 --> 주문.주문생성판정
주문.주문생성판정.생성결과미확정 --> 고객프론트.message.주문생성확인중
주문.주문생성판정.주문생성확인 --> 고객프론트.message.결제대기주문번호
주문.주문생성판정.주문생성불가확정 --> 고객프론트.message.주문실패안내
주문.주문생성판정.주문생성불가확정 --> 재고.message.주문예약해제요청
```

- **고객프론트 · 주문서제출 → 주문 · 주문생성요청** — 고객이 확인한 상품·수량·판매 조건을 주문 서비스에 제출한다.
- **주문 · 주문생성요청 → 상품 · 판매조건조회** — 주문 서비스는 주문서의 상품·수량·할인 조건을 상품 서비스에 보내 현재 판매 조건을 묻는다.
- **상품 · 판매조건조회 → 상품 · 판매조건판정** — 상품 서비스는 요청한 상품·옵션이 판매 중인지 확인하고 판매 중인 항목에는 현재 가격과 적용할 할인을 계산한다.
- **상품 · 판매조건판정 [판매중단] → 주문 · 판매중단안내** — 상품 서비스는 판매가 중단된 항목을 회신한다. 주문 서비스는 해당 항목을 고객에게 알리고 이번 주문서 전체의 접수를 보류한다.
- **주문 · 판매중단안내 → 고객프론트 · 판매중단상품안내** — 주문을 접수할 수 없는 상품을 화면에 표시한다.
- **상품 · 판매조건판정 [판매가능] → 주문 · 판매조건회신** — 상품 서비스는 주문할 수 있는 항목의 현재 가격과 할인 조건을 주문 서비스에 돌려준다.
- **주문 · 판매조건회신 → 주문 · 주문서대조** — 주문은 회신과 고객이 동의한 주문서를 대조한다. 그림의 `판매조건변경`이면 달라진 가격·할인을 고객에게 보여 주고, 새 조건으로 다시 제출할 때까지 이 주문서의 재고 예약을 보류한다.
- **주문 · 주문서대조 [판매조건변경] → 고객프론트 · 변경된가격과할인** — 바뀐 주문 금액과 할인액을 보여 주고 고객의 재확인을 받는다.
- **주문 · 주문서대조 [판매조건일치] → 재고 · 재고예약요청** — 조건이 일치하면 주문 서비스가 주문 건을 식별하는 번호로 재고를 예약한다.
- **재고 · 재고예약요청 → 재고 · 주문수량예약** — 재고 서비스는 같은 예약 요청의 기존 결과를 먼저 확인하고, 새 요청이면 주문 수량을 확보할 수 있는지 판정한다.
- **재고 · 주문수량예약 [가용수량부족] → 주문 · 주문수량품절** — 한 항목이라도 요청 수량이 부족하면 재고 서비스는 이번 주문서의 수량을 예약하지 않고 품절 항목을 회신한다. 주문은 고객에게 해당 항목을 알리고 접수를 종료한다.
- **주문 · 주문수량품절 → 고객프론트 · 품절상품안내** — 재고를 확보하지 못한 상품을 고객에게 보여 준다.
- **재고 · 주문수량예약 [요청수량예약됨] → 주문 · 주문수량예약확인** — 재고 서비스는 확보한 예약 번호와 기한을 주문 서비스에 회신한다.
- **주문 · 주문수량예약확인 → 주문 · 주문생성판정** — 주문 서비스는 유효한 예약을 연결해 주문을 결제 대기로 저장한다. 생성이 확인되면 고객에게 주문번호를 돌려주고, 결과가 불명이면 같은 주문번호로 생성 여부를 확인한다.
- **주문 · 주문생성판정 [생성결과미확정] → 고객프론트 · 주문생성확인중** — 같은 주문의 생성 결과를 확인하고 있음을 표시한다.
- **주문 · 주문생성판정 [주문생성확인] → 고객프론트 · 결제대기주문번호** — 새 주문번호를 표시하고 고객이 결제를 시작할 수 있게 한다.
- **주문 · 주문생성판정 [주문생성불가확정] → 고객프론트 · 주문실패안내** — 주문이 생성되지 않았다는 결과와 사유를 반환한다.
- **주문 · 주문생성판정 [주문생성불가확정] → 재고 · 주문예약해제요청** — 주문을 끝내 생성할 수 없으면 주문이 예약 번호로 해제를 요청한다. 재고는 해당 예약에서 아직 잡혀 있는 수량만 풀어준다.

같은 주문서 제출은 기존 접수 결과를 돌려준다. 예약 회신이 끊기면 화면에는 확인 중으로 표시하고 같은 번호로 예약 결과를 다시 확인한다.

### S05-2. 결제창 발급과 승인 확인

#### 결제창 발급과 발급 결과 재확인

**시작 사건** 고객이 주문에서 결제를 선택한다. 이 예제에서는 발급 응답이 끊기면 주문 화면이 같은 발급 요청의 상태를 다시 조회한다. 결제사는 기존 발급 요청을 식별해 결과를 조회할 수 있다고 가정한다.

```jobflow
scope: 결제창 발급과 기존 발급 요청의 결과 확인
Object: 고객프론트, 주문, 결제
고객프론트.On결제선택 --> 주문.message.결제시작요청
주문.message.결제시작요청 --> 주문.결제가능판정
주문.결제가능판정.결제불가주문 --> 고객프론트.message.결제불가상태안내
주문.결제가능판정.결제가능주문 --> 결제.message.결제창발급요청
결제.message.결제창발급요청 --> 결제.결제창확보
결제.결제창확보.사용할주소있음 --> 주문.message.결제창주소
주문.message.결제창주소 --> 주문.결제창제공판정
주문.결제창제공판정.결제가능상태유지 --> 고객프론트.message.결제창열기정보
주문.결제창제공판정.주문상태변경 --> 고객프론트.message.결제불가상태안내
결제.결제창확보.발급실패확정 --> 주문.message.결제창발급실패
주문.message.결제창발급실패 --> 고객프론트.message.결제창발급실패안내

고객프론트.On발급상태재조회 --> 주문.message.결제창발급상태조회
주문.message.결제창발급상태조회 --> 결제.message.기존발급결과조회
결제.message.기존발급결과조회 --> 결제.발급결과재확인
결제.발급결과재확인.유효한주소확인 --> 주문.message.기존결제창주소
```

- **주문 · 결제창주소 → 주문 · 결제창제공판정** — 주소를 돌려받은 주문은 주문 상태와 재고 예약 기한을 다시 확인한다.
- **주문 · 결제창제공판정 [결제가능상태유지] → 고객프론트 · 결제창열기정보** — 주문을 여전히 결제할 수 있으면 유효한 주소를 돌려주고 고객프론트가 결제창을 연다.
- **주문 · 결제창제공판정 [주문상태변경] → 고객프론트 · 결제불가상태안내** — 취소되었거나 예약이 만료됐으면 현재 주문 상태를 보여 준다.
- **결제 · 결제창확보 [발급실패확정] → 주문 · 결제창발급실패** — 발급할 수 없다는 결과가 확정되면 주문 서비스가 고객에게 결제를 시작할 수 없는 사유를 안내한다.
- **주문 · 결제창발급실패 → 고객프론트 · 결제창발급실패안내** — 화면에 발급 실패 사유와 다시 시도할 수 있는 조건을 표시한다.

- **주문 · 결제창발급확인중 → 고객프론트 · 결제창발급대기안내** — 화면은 발급 확인 중을 보여 주고 같은 발급 요청 번호로 상태를 다시 조회한다.
- **고객프론트 · 발급상태재조회 → 주문 · 결제창발급상태조회** — 발급 대기 화면에서 같은 발급 요청 번호로 다시 조회한다.
- **주문 · 결제창발급상태조회 → 결제 · 기존발급결과조회** — 확인 중 화면이 상태를 다시 요청하면 주문은 요청자의 권한과 원래 주문에 속한 발급 요청인지 확인한 뒤, 같은 발급 요청 번호로 결제에 결과를 묻는다.
- **결제 · 기존발급결과조회 → 결제 · 발급결과재확인** — 결제는 기존 기록을 읽고, 미확정이면 결제사에서 같은 요청의 발급 결과를 조회한다.
- **결제 · 발급결과재확인 [유효한주소확인] → 주문 · 기존결제창주소** — 기존 시도에서 사용할 수 있는 주소가 확인되면 결제는 그 주소를 주문에 회신한다.
- **주문 · 기존결제창주소 → 주문 · 재조회주소제공판정** — 주소를 돌려받은 주문은 주문 상태와 재고 예약 기한을 다시 확인한다.
- **주문 · 재조회주소제공판정 [결제가능상태유지] → 고객프론트 · 결제창열기정보** — 주문을 여전히 결제할 수 있으면 유효한 주소를 돌려주고 고객프론트가 결제창을 연다.
- **주문 · 재조회주소제공판정 [주문상태변경] → 고객프론트 · 결제불가상태안내** — 취소되었거나 예약이 만료됐으면 현재 주문 상태를 보여 준다.
- **결제 · 발급결과재확인 [사용할주소없음확정] → 주문 · 결제창발급실패** — 미발급 또는 주소 만료가 확정되면 결제는 이유를 회신하고 주문은 고객에게 안내한다. 이전 시도에서 결제가 더 이상 이뤄질 수 없고 주문이 여전히 결제 가능하면, 고객은 원인을 해소한 뒤 새로 시도할 수 있다.
- **주문 · 결제창발급실패 → 고객프론트 · 결제창발급실패안내** — 화면에 발급 실패 사유와 다시 시도할 수 있는 조건을 표시한다.
- **결제 · 발급결과재확인 [아직미확정] → 주문 · 결제창발급확인중** — 결제는 기존 시도를 확인 중으로 유지하고 새 발급을 보류한다. 화면은 예약 기한 안에서 같은 요청을 다시 조회한다. 기한이 지나면 화면 조회를 멈추고, 결제는 기존 시도의 결과를 추적한다.
- **주문 · 결제창발급확인중 → 고객프론트 · 결제창발급대기안내** — 화면은 발급 확인 중을 보여 주고 같은 발급 요청 번호로 상태를 다시 조회한다.

#### 결제창 복귀와 거래 승인 확인

**시작 사건** 결제창을 열었던 고객이 주문 화면으로 돌아와 해당 결제 시도의 결과를 요청한다. 결제사가 거래 상태를 통지하는 경로도 같은 시도의 승인 여부를 확인한다.

```jobflow
scope: 결제창 복귀와 결제사 통지에 따른 원거래 승인 확인
Object: 고객프론트, 주문, 결제, 알림
고객프론트.On결제창복귀 --> 주문.message.결제확인요청
주문.message.결제확인요청 --> 결제.message.거래조회요청
결제.message.거래조회요청 --> 결제.원거래조회
결제.원거래조회.승인확인 --> 주문.message.거래승인확인
주문.message.거래승인확인 --> 고객프론트.message.거래승인과주문상태
결제.원거래조회.미승인확정 --> 주문.message.거래미승인
주문.message.거래미승인 --> 고객프론트.message.미승인과재시도안내
결제.원거래조회.승인여부불명 --> 주문.message.거래확인중
주문.message.거래확인중 --> 고객프론트.message.거래확인중안내
결제.On거래상태알림 --> 결제.승인내역대조
결제.승인내역대조.승인최초확인
결제.승인내역대조.미승인최초확정
알림.On결제미승인확정 --> 알림.미승인안내
```

- **고객프론트 · 결제창복귀 → 주문 · 결제확인요청** — 고객이 주문 화면으로 돌아오면 해당 결제 시도의 상태를 요청한다.
- **주문 · 결제확인요청 → 결제 · 거래조회요청** — 고객이 결제창에서 돌아오면 주문 서비스가 결제 서비스에 원거래의 상태를 묻는다.
- **결제 · 거래조회요청 → 결제 · 원거래조회** — 결제 서비스는 결제사에서 해당 시도의 승인 상태와 거래 금액을 확인한다.
- **결제 · 원거래조회 [승인확인] → 주문 · 거래승인확인** — 결제 서비스가 승인 번호와 금액을 회신하면 주문 서비스는 자신의 주문 확정 상태와 함께 보여 준다. 이 회신만으로 출고를 시작하지 않는다.
- **주문 · 거래승인확인 → 고객프론트 · 거래승인과주문상태** — 결제 승인 여부와 주문 확정 상태를 각각 보여 준다.
- **결제 · 원거래조회 [미승인확정] → 주문 · 거래미승인** — 미승인이 확정되면 주문 서비스는 고객에게 결과를 보여 주고 주문 상태와 예약 기한으로 다시 결제할 수 있는지 판단한다.
- **주문 · 거래미승인 → 고객프론트 · 미승인과재시도안내** — 승인되지 않은 거래임을 알리고 다시 결제할 수 있는지 표시한다.
- **결제 · 원거래조회 [승인여부불명] → 주문 · 거래확인중** — 원거래가 아직 처리 중이거나 조회 응답이 없으면 결제 서비스가 같은 거래를 다시 확인하고 주문 서비스는 확인 중으로 표시한다.
- **주문 · 거래확인중 → 고객프론트 · 거래확인중안내** — 결제 결과 확인 중임을 표시한다. 다음 조회도 같은 결제 시도를 사용한다.
- **결제 · 거래상태알림 → 결제 · 승인내역대조** — 결제사는 고객의 복귀와 별개로 거래 상태를 통지한다. 결제는 원거래를 대조하고 결과가 불명이면 같은 시도를 재확인한다. 처음 승인을 확인하면 승인 번호·금액을 기록하고 `결제승인확인`을 발행한다. S05-3의 주문 서비스가 이 사건을 받는다. 미승인을 처음 확정하면 해당 시도를 종결하고 `결제미승인확정`을 발행한다. 이미 확정한 결과는 한 번만 발행한다.
- **알림 · 결제미승인확정 → 알림 · 미승인안내** — 결제 서비스가 해당 시도의 최종 미승인을 기록해 `결제미승인확정`을 발행하면 알림 서비스가 결과를 기다리는 고객에게 그 시도의 결과를 안내한다.

결제 서비스는 어떤 경로로 확인하든 원거래의 최초 승인을 기록할 때 `결제승인확인`을 발행한다. 결제 결과가 불명이면 같은 거래를 계속 조회하며 새 결제 시도는 보류한다. 결제사가 미승인을 최종 확인하면 결제 상태를 갱신한다. 유효한 예약으로 다시 결제할 수 있는지는 주문 서비스가 판단한다.

### S05-3. 승인된 결제의 주문 확정

**시작 사건** 주문 서비스가 결제 서비스의 `결제승인확인`을 받는다. 승인 금액과 주문을 대조하고, 유효한 예약 수량을 판매 수량으로 확정해야 출고를 시작할 수 있다.

```jobflow
scope: 승인된 거래의 재고 확정과 주문 이행 불가 보상
Object: 고객프론트, 결제, 주문, 재고, 알림
주문.On결제승인확인 --> 주문.승인적용판정
주문.승인적용판정.이행불가보상대상있음 --> 결제.message.환불요청
주문.승인적용판정.결제대기주문금액일치 --> 재고.message.예약확정요청
재고.message.예약확정요청 --> 재고.예약수량확정
재고.예약수량확정.판매수량확정됨 --> 주문.message.예약수량확정
재고.예약수량확정.예약만료 --> 주문.message.예약만료통보
주문.message.예약만료통보 --> 주문.보상대상판정
주문.보상대상판정.주문실패보상수량있음 --> 결제.message.환불요청
재고.On주문이행불가 --> 재고.남은예약해제
알림.On주문확정 --> 알림.주문확정안내
알림.On주문이행불가 --> 알림.환불예정안내
고객프론트.On주문결과조회 --> 주문.message.주문결과조회요청
주문.message.주문결과조회요청 --> 고객프론트.message.주문확정상태
```

- **주문 · 결제승인확인 → 주문 · 승인적용판정** — 주문 서비스는 승인 거래를 주문 금액과 현재 처리 상태에 대조한다. 이미 반영한 거래는 기존 결과를 사용한다.
- **주문 · 승인적용판정 [이행불가보상대상있음] → 결제 · 환불요청** — 주문이 만료됐거나 승인 금액이 어긋나면 주문 서비스는 자신이 보상할 상품과 금액을 기록해 환불을 의뢰하고 대상 수량의 `주문이행불가`를 발행한다. 취소 신청에 배정한 수량은 S07에서 정산한다.
- **주문 · 승인적용판정 [결제대기주문금액일치] → 재고 · 예약확정요청** — 결제 대기 주문의 금액이 일치하면 재고 서비스에 해당 예약의 수량을 확정해 달라고 요청한다.
- **재고 · 예약확정요청 → 재고 · 예약수량확정** — 재고 서비스는 예약 기한과 수량을 확인한다. 이미 판매로 반영한 수량에는 이전 확정 결과를 사용한다.
- **재고 · 예약수량확정 [판매수량확정됨] → 주문 · 예약수량확정** — 판매로 반영한 수량을 받은 주문 서비스는 해당 상품을 확정하고 `주문확정`을 발행한다. 배송과 알림은 이 사건을 독립적으로 받는다.
- **재고 · 예약수량확정 [예약만료] → 주문 · 예약만료통보** — 예약을 확정할 수 없으면 재고 서비스는 만료된 예약과 수량을 주문 서비스에 돌려준다.
- **주문 · 예약만료통보 → 주문 · 보상대상판정** — 주문 서비스는 확보하지 못한 수량 중 자신이 보상할 상품과 S07의 취소 신청에서 정산할 상품을 가린다.
- **주문 · 보상대상판정 [주문실패보상수량있음] → 결제 · 환불요청** — 자신이 보상을 맡은 수량이 있으면 주문은 그 수량에 배분된 승인 금액만 환불 의뢰하고 `주문이행불가`를 발행한다.
- **재고 · 주문이행불가 → 재고 · 남은예약해제** — 주문이 환불할 대상 상품을 결정해 `주문이행불가`를 발행하면 재고는 해당 상품의 남은 예약을 해제한다. 이미 해제되거나 만료된 수량은 다시 더하지 않는다.
- **알림 · 주문확정 → 알림 · 주문확정안내** — 알림은 배송과 독립적으로 `주문확정`을 받아 고객에게 확정된 상품을 알려 준다.
- **알림 · 주문이행불가 → 알림 · 환불예정안내** — 승인된 거래로 상품을 제공할 수 없어 주문이 보상 건을 열고 `주문이행불가`를 발행하면 알림이 고객에게 대상 상품과 환불 예정 사실을 안내한다.
- **고객프론트 · 주문결과조회 → 주문 · 주문결과조회요청** — 같은 주문의 확정 여부와 이행할 상품을 조회한다.
- **주문 · 주문결과조회요청 → 고객프론트 · 주문확정상태** — 주문은 확정 대기·주문 확정·이행 불가와 환불 진행 상태를 자신이 기록한 범위에서 돌려준다.

예약 확정 회신이 끊기면 주문은 확정 대기에 둔다. 같은 예약 번호의 결과를 확인한 뒤 출고 또는 보상을 한 번만 시작한다. 주문은 승인 금액을 **그 결제 시도에 제출한 원래 금액**과 대조한다. 같은 주문 상품의 확정과 취소 진행은 순서를 정해 기록한다. 일부 상품이 취소 진행 중이면 나머지 수량만 확정 대상으로 삼고, 취소 수량의 늦은 승인은 S07의 기존 신청에서 정산한다. 주문 실패 보상과 고객 취소가 같은 수량을 환불 대상으로 잡지 않도록 주문이 처리 주체를 한 곳에 배정한다.

### S05-4. 주문 확정 실패 후 환불 종결

**시작 사건** 주문 서비스가 보낸 환불 의뢰를 결제 서비스가 받는다. 결제 서비스가 원거래의 환불 여부를 확인하고, 주문 서비스가 주문 실패에 따른 보상 건의 상태를 관리한다.

```jobflow
scope: 주문 이행 실패에 대한 환불 접수와 사후 확인
Object: 운영대시보드, 주문, 결제, 알림
결제.message.환불요청 --> 결제.환불접수판정
결제.환불접수판정.접수확인 --> 주문.message.환불접수확인
결제.환불접수판정.미접수확정 --> 주문.message.환불미접수
결제.환불접수판정.미접수확정 --> 결제.미접수사유판정
결제.미접수사유판정.조사필요 --> 결제.환불조사등록
결제.환불접수판정.접수여부불명 --> 주문.message.환불접수확인중
결제.On환불상태알림 --> 결제.환불내역대조
결제.환불내역대조.의뢰금액환불완료 --> 결제.환불완료기록
결제.환불내역대조.실패조사필요 --> 결제.환불조사등록
결제.환불조사등록 --> 알림.message.환불조사안내요청
주문.On환불완료 --> 주문.보상완료대조
주문.보상완료대조.주문실패보상건 --> 알림.message.보상환불완료안내
주문.On환불실패확인필요 --> 주문.보상상태반영
운영대시보드.On환불조사결과제출 --> 결제.message.환불조사회신
결제.message.환불조사회신 --> 결제.환불조사종결판정
결제.환불조사종결판정.근거부족 --> 운영대시보드.message.환불조사보완요청
결제.환불조사종결판정.완료내역확보 --> 운영대시보드.message.환불조사완료
결제.환불조사종결판정.완료내역확보 --> 결제.환불완료기록
결제.환불조사종결판정.최종실패확인 --> 운영대시보드.message.환불조사실패확정
결제.환불조사종결판정.최종실패확인 --> 결제.환불실패기록
주문.On환불실패확정 --> 주문.보상실패대조
주문.보상실패대조.주문실패보상건 --> 알림.message.보상환불실패안내
운영대시보드.On환불조사건열기 --> 결제.message.환불조사건조회
결제.message.환불조사건조회 --> 운영대시보드.message.환불조사대상
```

- **결제 · 환불요청 → 결제 · 환불접수판정** — 결제 서비스는 의뢰 번호로 기존 처리 결과를 찾는다. 새 의뢰라면 원승인·대상 수량·남은 환불 가능액을 대조한 뒤 유효한 금액을 결제사에 의뢰한다.
- **결제 · 환불접수판정 [접수확인] → 주문 · 환불접수확인** — 결제가 환불 접수를 확인하면 주문은 해당 보상 건을 환불 진행 중으로 표시하고 최종 결과를 기다린다.
- **결제 · 환불접수판정 [미접수확정] → 주문 · 환불미접수** — 한도 초과나 결제사의 명시적 미접수 사유를 결제가 회신한다. 주문은 보상 건에 접수 지연 사유를 남긴다.
- **결제 · 환불접수판정 [미접수확정] → 결제 · 미접수사유판정** — 결제는 접수되지 않은 이유를 확인한다. 일시적인 제한이면 원인을 해소한 뒤 같은 의뢰로 재시도하고, 원거래·금액에 확인이 필요하면 운영 조사를 연다.
- **결제 · 미접수사유판정 [조사필요] → 결제 · 환불조사등록** — 결제는 의뢰 번호로 조사 건을 기록해 `환불실패확인필요`를 발행한다. 주문 보상 의뢰는 주문이, 취소·반품 의뢰는 구매후처리가 자기 건을 확인 대기로 둔다.
- **결제 · 환불접수판정 [접수여부불명] → 주문 · 환불접수확인중** — 응답이 끊기면 결제는 같은 의뢰의 상태를 확인한다. 주문은 접수 결과를 받을 때까지 보상 건을 확인 중으로 유지한다.
- **결제 · 환불상태알림 → 결제 · 환불내역대조** — 결제사에서 후속 환불 상태를 통지하면 결제 서비스가 같은 거래의 실제 처리 내역과 금액을 대조한다.
- **결제 · 환불내역대조 [의뢰금액환불완료] → 결제 · 환불완료기록** — 결제는 이번 의뢰 금액의 환불이 실제로 완료됐음을 기록하고 `환불완료`를 발행한다. 진행 중이거나 확인이 덜 된 금액은 계속 대조한다.
- **결제 · 환불내역대조 [실패조사필요] → 결제 · 환불조사등록** — 접수 이후 확인한 실패도 결제가 같은 의뢰 번호로 조사에 등록한다. 접수 전에 연 조사와 같은 절차로 `환불실패확인필요`를 발행한다.
- **결제 · 환불조사등록 → 알림 · 환불조사안내요청** — 조사 건을 연 결제가 알림에 운영자 확인 요청과 고객의 확인 중 안내를 의뢰한다. 같은 의뢰에 열린 조사가 있으면 기존 건을 사용한다.
- **주문 · 환불완료 → 주문 · 보상완료대조** — 결제 서비스가 실제 환불을 확인해 `환불완료`를 발행하면 주문 서비스는 원거래와 환불 의뢰 번호를 대조한다.
- **주문 · 보상완료대조 [주문실패보상건] → 알림 · 보상환불완료안내** — 자신이 맡은 주문 실패 보상이면 해당 건을 마치고 알림 서비스에 고객 완료 안내를 요청한다.
- **주문 · 환불실패확인필요 → 주문 · 보상상태반영** — 조사 필요 사건을 받은 주문 서비스는 해당 보상 건을 운영 확인 중으로 표시한다.
- **운영대시보드 · 환불조사결과제출 → 결제 · 환불조사회신** — 운영자가 대조한 결과와 근거를 원래 환불 의뢰 번호로 제출한다.
- **결제 · 환불조사회신 → 결제 · 환불조사종결판정** — 운영자가 결제사와 대조한 내역을 제출하면 결제는 해당 의뢰의 금액과 최종 결과가 확인됐는지 판정한다.
- **결제 · 환불조사종결판정 [근거부족] → 운영대시보드 · 환불조사보완요청** — 확정할 근거가 부족하면 조사 상태를 유지하고 운영자에게 보완할 내역을 표시한다.
- **결제 · 환불조사종결판정 [완료내역확보] → 운영대시보드 · 환불조사완료** — 운영자에게 대조가 끝난 환불 건의 결과를 보여 준다.
- **결제 · 환불조사종결판정 [완료내역확보] → 결제 · 환불완료기록** — 조사로 이번 의뢰의 실제 환불 내역을 확인하면 결제가 완료로 기록하고 `환불완료`를 발행한다.
- **결제 · 환불조사종결판정 [최종실패확인] → 운영대시보드 · 환불조사실패확정** — 운영자에게 최종 실패 사유와 후속 정산이 필요한 건을 보여 준다.
- **결제 · 환불조사종결판정 [최종실패확인] → 결제 · 환불실패기록** — 실패의 최종 사유가 확인되면 결제는 조사 건을 실패로 종결하고 `환불실패확정`을 발행한다. 근거가 부족하면 조사를 계속한다.
- **주문 · 환불실패확정 → 주문 · 보상실패대조** — 최종 실패 사건을 받은 주문 서비스는 의뢰 번호로 자신이 맡은 보상 건인지 확인한다.
- **주문 · 보상실패대조 [주문실패보상건] → 알림 · 보상환불실패안내** — 해당 보상 건이면 실패 사유를 반영하고 알림 서비스에 고객 후속 안내를 의뢰한다.
- **운영대시보드 · 환불조사건열기 → 결제 · 환불조사건조회** — 운영자가 조사할 의뢰 번호로 조사 기록을 요청한다.
- **결제 · 환불조사건조회 → 운영대시보드 · 환불조사대상** — 결제는 등록된 조사 사유와 거래 대조에 필요한 정보를 대시보드에 반환한다.

환불 접수 여부가 불명확하면 같은 의뢰 번호로 진행 상태를 다시 확인한다. 결제 서비스는 같은 환불 의뢰 번호를 재사용하고, 상품별로 이미 환불했거나 접수해 둔 금액까지 합산해 원승인 금액을 초과하는 의뢰를 막는다. 조사 결과가 불명확한 동안 결제 서비스는 같은 건의 확인을 계속한다. 취소·반품에서 의뢰한 환불은 S07의 구매후처리 서비스가 같은 계약으로 추적한다.

## S06. 출고와 배송 조회

### S06-1. 주문 확정에서 운영자의 운송장 등록까지

**시작 사건** 배송이 주문의 `주문확정` 사건을 받는다. 사건에는 출고할 주문 상품과 수량이 들어간다. 이후 운영자가 배송 준비를 시작하면 포장에 필요한 명세와 배송지를 조회한다. [매크로 M06-1](macro.md#m06-1-운영자의-배송-준비부터-고객-수령까지)

```jobflow
scope: 주문 확정 후 출고 건 개설과 포장 목록 조회
Object: 운영대시보드, 배송, 주문
배송.On주문확정 --> 배송.출고개설판정
배송.출고개설판정.처음확정된출고가능상품 --> 배송.출고건개설
운영대시보드.On포장목록요청 --> 배송.message.주문배송정보요청
배송.message.주문배송정보요청 --> 배송.출고대상판정
배송.출고대상판정.출고할상품없음 --> 운영대시보드.message.출고대상없음
배송.출고대상판정.출고할상품있음 --> 주문.message.출고명세조회
주문.message.출고명세조회 --> 배송.message.출고명세회신
배송.message.출고명세회신 --> 운영대시보드.message.포장목록과배송지
운영대시보드.On운송장등록 --> 배송.message.배송등록신청
배송.message.배송등록신청 --> 배송.운송장등록판정
배송.운송장등록판정.입력보완필요 --> 운영대시보드.message.운송장보완안내
배송.운송장등록판정.출고중지됨 --> 운영대시보드.message.인계중단안내
배송.운송장등록판정.출고가능하고운송장확인 --> 배송.인계작업시작
배송.인계작업시작 --> 운영대시보드.message.운송장등록확인
```

- **배송 · 주문확정 → 배송 · 출고개설판정** — 배송은 확정된 상품·수량에 대해 기존 출고 건과 출고 중지 기록을 확인한다.
- **배송 · 출고개설판정 [처음확정된출고가능상품] → 배송 · 출고건개설** — 처음 확정된 출고 가능 상품의 출고 건을 연다. 중지 기록이 있으면 중지를 유지하고, 중복 확정이면 기존 출고 건을 유지한다.
- **운영대시보드 · 포장목록요청 → 배송 · 주문배송정보요청** — 운영자가 지금 출고할 상품의 포장 명세와 배송지를 요청한다.
- **배송 · 주문배송정보요청 → 배송 · 출고대상판정** — 운영자가 포장 목록을 요청하면 배송이 출고할 건을 고른다. 대상이 없으면 운영자에게 빈 목록을 돌려준다.
- **배송 · 출고대상판정 [출고할상품없음] → 운영대시보드 · 출고대상없음** — 운영자에게 출고 가능한 상품이 없다고 표시한다.
- **배송 · 출고대상판정 [출고할상품있음] → 주문 · 출고명세조회** — 출고할 상품이 있으면 배송은 주문에 그 상품의 포장 명세와 주문 시 지정한 배송지를 요청한다.
- **주문 · 출고명세조회 → 배송 · 출고명세회신** — 주문은 요청받은 명세와 배송지를 배송에 회신하고, 배송은 해당 출고 건과 묶어 운영자에게 보여 준다.
- **배송 · 출고명세회신 → 운영대시보드 · 포장목록과배송지** — 출고 건별로 포장할 상품과 인계할 주소를 표시한다.
- **운영대시보드 · 운송장등록 → 배송 · 배송등록신청** — 운영자가 출고 건을 선택하고 택배사에서 받은 운송장 번호를 제출한다.
- **배송 · 배송등록신청 → 배송 · 운송장등록판정** — 배송은 신청받은 상품을 여전히 출고할 수 있는지, 해당 상품의 운송장 정보가 갖춰졌는지 확인한다. 정보가 부족하면 보완을, 출고 중지 상태면 인계 중단을 운영자에게 안내한다.
- **배송 · 운송장등록판정 [입력보완필요] → 운영대시보드 · 운송장보완안내** — 운영자에게 빠진 항목이나 수정할 운송장 정보를 보여 준다.
- **배송 · 운송장등록판정 [출고중지됨] → 운영대시보드 · 인계중단안내** — 해당 출고 건을 인계할 수 없다는 결과를 운영자에게 표시한다.
- **배송 · 운송장등록판정 [출고가능하고운송장확인] → 배송 · 인계작업시작** — 출고할 수 있고 운송장도 확인되면 배송이 운송장을 등록하고 해당 상품을 인계 작업 중으로 기록한다. 운영자가 이후 실물을 인계한다.
- **배송 · 인계작업시작 → 운영대시보드 · 운송장등록확인** — 출고 건과 연결된 운송장 번호를 운영자에게 표시한다.

이 예제에서 유효한 운송장 등록은 해당 상품을 운영자의 **인계 작업 중**으로 표시한다. 출고 중지와 이 전환은 배송이 같은 출고 건에서 순서를 정한다. 인계 작업 중에 취소가 접수되면 배송은 운영자의 실물 인계 여부를 확인할 때까지 중지 결과를 보류한다. 운영자가 상품을 아직 보유하고 인계 작업을 멈췄다고 확인하면 배송이 중지를 확정한다. 이미 건넸다면 인계 사실을 기록한다.

### S06-2. 발송 등록과 배송 완료에 따른 고객 안내

**시작 사건** 운영자가 택배사에 상품을 건넨 뒤 발송을 등록한다. 배송 완료는 나중에 택배사가 해당 운송장의 완료를 통지할 때 별도로 확인한다.

```jobflow
scope: 배송 상태 확정과 발송 및 완료 안내
Object: 운영대시보드, 배송, 알림, 주문
운영대시보드.On발송등록 --> 배송.message.발송등록신청
배송.message.발송등록신청 --> 배송.인계기록대조
배송.인계기록대조.이미처리됨 --> 운영대시보드.message.현재출고상태
배송.인계기록대조.인계확인필요 --> 운영대시보드.message.인계확인안내
배송.인계기록대조.첫인계확인 --> 배송.발송확정
배송.발송확정 --> 운영대시보드.message.발송등록확인
알림.On발송확정 --> 알림.발송안내판정
알림.발송안내판정.완료전첫발송안내 --> 주문.message.발송안내정보조회
주문.message.발송안내정보조회 --> 알림.message.발송안내정보
배송.On배송완료통지 --> 배송.완료통지대조
배송.완료통지대조.해당운송장첫완료 --> 배송.배달완료기록
알림.On배송완료 --> 알림.완료안내판정
알림.완료안내판정.첫완료안내 --> 주문.message.완료안내정보조회
주문.message.완료안내정보조회 --> 알림.message.완료안내정보
```

- **운영대시보드 · 발송등록 → 배송 · 발송등록신청** — 운영자가 실물 인계를 마친 출고 건의 발송을 등록한다.
- **배송 · 발송등록신청 → 배송 · 인계기록대조** — 배송은 신청받은 운송장과 실물 인계를 대조한다. 인계가 확인되지 않으면 운영자에게 확인을 요청한다. 이미 반영한 발송이나 완료 건은 현재 상태를 돌려준다.
- **배송 · 인계기록대조 [이미처리됨] → 운영대시보드 · 현재출고상태** — 이미 반영된 발송이나 배달 완료 상태를 표시한다.
- **배송 · 인계기록대조 [인계확인필요] → 운영대시보드 · 인계확인안내** — 운영자에게 운송장과 실제 인계 여부를 다시 확인하도록 안내한다.
- **배송 · 인계기록대조 [첫인계확인] → 배송 · 발송확정** — 배송이 해당 출고 건의 첫 인계를 기록하고 출고 번호와 운송장이 담긴 발송확정 사건을 발행한다.
- **배송 · 발송확정 → 운영대시보드 · 발송등록확인** — 해당 운송장의 발송 등록이 완료됐음을 표시한다.
- **알림 · 발송확정 → 알림 · 발송안내판정** — 알림은 이 출고 건의 발송 안내 이력과 배송 완료가 먼저 반영됐는지 확인한다. 이미 안내했거나 완료된 건은 발송 메일을 생략한다.
- **알림 · 발송안내판정 [완료전첫발송안내] → 주문 · 발송안내정보조회** — 처음 안내할 발송이면 알림이 주문 서비스에 해당 고객의 수신 정보를 요청한다.
- **주문 · 발송안내정보조회 → 알림 · 발송안내정보** — 주문이 해당 주문의 연락처를 회신하면 알림은 메일 안내 대상인지 확인해 발송사에 운송장 안내를 의뢰한다.
- **배송 · 배송완료통지 → 배송 · 완료통지대조** — 배송은 택배사의 통지를 출고 건·운송장과 대조한다. 일치하는 건을 확인할 수 없으면 완료 처리를 보류하고, 중복 통지는 기존 완료 기록에 대응시킨다.
- **배송 · 완료통지대조 [해당운송장첫완료] → 배송 · 배달완료기록** — 확인한 운송장의 첫 완료를 기록하고 배송완료 사건을 발행한다. 교환 출고이면 원래 신청 번호도 담는다.
- **알림 · 배송완료 → 알림 · 완료안내판정** — 알림은 같은 출고 건의 완료 안내를 이미 의뢰했는지 확인한다.
- **알림 · 완료안내판정 [첫완료안내] → 주문 · 완료안내정보조회** — 처음 보낼 완료 안내이면 해당 고객의 수신 정보를 주문 서비스에 요청한다.
- **주문 · 완료안내정보조회 → 알림 · 완료안내정보** — 주문이 회신하면 알림은 대상 고객에게 배송 완료 메일을 의뢰한다. 출고 번호와 안내 종류별로 발송 이력을 확인해 같은 메일을 중복 의뢰하지 않는다.

실물 수령과 전산 통지 사이에는 시간차가 있다. 완료가 운영자의 발송 등록보다 먼저 들어오면 배송은 확인 가능한 운송장의 완료 사실을 보존하고, 뒤늦은 등록으로 완료 상태를 되돌리지 않는다. 알림에 완료가 먼저 반영된 건은 뒤늦은 발송 안내를 생략한다. 발송사 접수 뒤 회신만 끊긴 경우를 위해 같은 출고 번호·안내 종류에 동일 발송 의뢰 번호를 쓰고, 재의뢰 전에 접수 여부를 조회하는 계약을 둔다. 교환품의 `배송완료`에는 원래 신청 번호도 들어 있어 구매후처리가 해당 교환을 마칠 수 있다.

### S06-3. 권한을 확인한 주문의 배송 조회

**시작 사건** 고객이 주문 내역을 열거나 배송 경과를 새로 조회한다. 주문은 두 요청 모두에서 회원 본인 또는 비회원이 인증한 주문 한 건인지 확인한다. [매크로 M06-2](macro.md#m06-2-고객의-주문배송-조회)

```jobflow
scope: 열람 권한이 있는 주문의 배송 상태 조회
Object: 고객프론트, 주문, 배송
고객프론트.On주문내역열기 --> 주문.message.주문내역요청
주문.message.주문내역요청 --> 주문.내역열람판정
주문.내역열람판정.열람가능한출고대상없음 --> 고객프론트.message.출고전주문내역
주문.내역열람판정.인증필요 --> 고객프론트.message.주문내역인증안내
주문.내역열람판정.열람가능한출고대상 --> 배송.message.주문배송현황조회
```

- **고객프론트 · 주문내역열기 → 주문 · 주문내역요청** — 고객이 선택한 주문의 내역을 요청한다.
- **주문 · 주문내역요청 → 주문 · 내역열람판정** — 주문은 고객의 주문 열람 권한을 확인한다. 인증이 필요하면 화면에 인증 방법을 안내한다.
- **주문 · 내역열람판정 [열람가능한출고대상없음] → 고객프론트 · 출고전주문내역** — 출고 대상이 없는 주문의 내역과 결제·취소 상태를 표시한다.
- **주문 · 내역열람판정 [인증필요] → 고객프론트 · 주문내역인증안내** — 고객에게 회원 로그인 또는 비회원 주문 인증을 안내한다.
- **주문 · 내역열람판정 [열람가능한출고대상] → 배송 · 주문배송현황조회** — 권한이 있고 출고할 상품이 있으면 주문은 배송에 출고 건의 현재 상태를 조회한다.
- **배송 · 주문배송현황조회 → 주문 · 주문배송현황** — 배송이 회신하면 주문은 내역과 마지막으로 확인된 배송 상태를 함께 보여 준다.
- **주문 · 주문배송현황 → 고객프론트 · 주문내역과배송현황** — 주문 내역에 마지막으로 확인된 배송 상태를 함께 표시한다.
- **고객프론트 · 배송경과조회 → 주문 · 배송경과요청** — 고객이 선택한 주문 상품의 최근 배송 경과를 요청한다.
- **주문 · 배송경과요청 → 주문 · 배송열람판정** — 고객이 최근 경과를 요청하면 주문은 다시 열람 권한과 해당 배송 대상을 확인한다.
- **주문 · 배송열람판정 [인증필요] → 고객프론트 · 배송조회인증안내** — 배송 정보를 열기 전에 해당 주문을 인증하도록 안내한다.
- **주문 · 배송열람판정 [출고대상없음] → 고객프론트 · 출고대상없음안내** — 주문의 현재 상태와 배송 조회 대상이 없다는 사실을 표시한다.
- **주문 · 배송열람판정 [열람가능한출고대상] → 배송 · 최근배송경과조회** — 권한이 있고 출고 대상이면 배송에 최근 경과를 요청한다. 결제 대기나 출고 전 취소로 출고 대상이 없으면 주문이 자체 상태를 안내한다.
- **배송 · 최근배송경과조회 → 배송 · 배송경과확인** — 배송은 해당 출고 건의 완료 기록과 운송장 등록 여부를 확인한다. 완료 기록이 없고 운송장이 있으면 택배사에 최신 경과를 조회한다.
- **배송 · 배송경과확인 [운송장등록전] → 주문 · 배송준비중** — 배송은 아직 등록된 운송장이 없다고 회신하고 주문은 배송 준비 중임을 안내한다.
- **주문 · 배송준비중 → 고객프론트 · 배송준비안내** — 운송장 등록 전 단계임을 고객에게 표시한다.
- **배송 · 배송경과확인 [배달완료기록있음] → 주문 · 배달완료내역** — 완료 기록이 있으면 배송은 그 기록을 돌려주고 주문은 배달 완료를 표시한다.
- **주문 · 배달완료내역 → 고객프론트 · 배달완료표시** — 서비스가 기록한 배달 완료 상태를 보여 준다.
- **배송 · 배송경과확인 [최근경과확인] → 주문 · 최근배송경과** — 운송장의 현재 경과를 확인하면 배송은 최근 이동 내역을 보내고 주문은 고객에게 보여 준다.
- **주문 · 최근배송경과 → 고객프론트 · 배송경과표시** — 조회한 운송장의 최근 이동 내역을 표시한다.
- **배송 · 배송경과확인 [택배사조회지연] → 주문 · 배송경과확인지연** — 최신 경과를 확인할 수 없으면 지연으로 회신하고 주문은 마지막 확인 상태와 조회 지연을 함께 안내한다.
- **주문 · 배송경과확인지연 → 고객프론트 · 배송확인지연안내** — 최근 경과를 확인하지 못한 상황과 마지막 확인 상태를 함께 표시한다.

## S07. 취소·반품·교환과 구매 리뷰

구매후처리는 신청을 받은 시점과 금융·배송 결과가 확정된 시점을 구분한다. 고객이 신청 상태를 조회하면 이 서비스가 수거·검수·환불·교환 배송 중 마지막으로 확인된 단계를 보여 준다. [매크로 M07](macro.md#m07-취소반품교환과-구매-리뷰)

### S07-1. 출고 중지와 취소 거래 확인

**시작 사건** 고객의 취소 신청을 구매후처리가 받는다. 주문은 구매자와 대상 상품·수량을 확인하고, 배송은 해당 수량을 택배사에 넘겼는지 판단한다.

```jobflow
scope: 취소 대상의 출고 중지와 원거래 확인
Object: 고객프론트, 주문, 배송, 구매후처리, 결제
고객프론트.On취소신청 --> 구매후처리.message.주문취소신청

배송.message.출고중지요청 --> 배송.인계상태대조
배송.인계상태대조.이미인계됨 --> 구매후처리.message.출고중지불가
구매후처리.message.출고중지불가 --> 고객프론트.message.취소불가와반품안내

주문.취소수량배정판정.배정불가 --> 구매후처리.message.취소진행등록불가

구매후처리.message.취소진행등록확인 --> 결제.message.취소거래종결요청
```

- **고객프론트 · 취소신청 → 구매후처리 · 주문취소신청** — 고객이 취소할 상품과 수량을 제출한다.
- **구매후처리 · 주문취소신청 → 주문 · 취소대상조회** — 구매후처리는 주문에 신청자의 주문과 취소 대상 상품을 조회한다.
- **주문 · 취소대상조회 → 구매후처리 · 취소대상정보** — 주문은 소유자 일치 여부, 구매 수량, 거래 참조와 이미 취소한 수량을 회신한다.
- **구매후처리 · 취소대상정보 → 구매후처리 · 취소접수판정** — 구매후처리는 다른 신청에 배정한 수량까지 대조해 이번 신청의 취소 가능 수량을 정한다.
- **구매후처리 · 취소접수판정 [취소할수량없음] → 고객프론트 · 취소접수불가안내** — 취소를 신청할 수 있는 수량이 없음을 안내한다.
- **구매후처리 · 취소접수판정 [취소할수량있음] → 배송 · 출고중지요청** — 취소할 수량이 있으면 배송에 해당 주문 상품의 출고를 막아 달라고 요청한다.
- **배송 · 출고중지요청 → 배송 · 인계상태대조** — 배송은 신청 상품·수량의 실물 인계 기록을 대조한다. 운영자의 인계 작업과 출고 중지 중 먼저 확정된 처리를 기록한다.
- **배송 · 인계상태대조 [이미인계됨] → 구매후처리 · 출고중지불가** — 이미 기사에게 넘긴 수량이면 구매후처리가 취소 불가 사유와 반품 방법을 고객에게 안내한다.
- **구매후처리 · 출고중지불가 → 고객프론트 · 취소불가와반품안내** — 이미 인계된 상품의 취소 사유와 반품 신청 방법을 표시한다.
- **배송 · 인계상태대조 [인계작업중] → 구매후처리 · 인계확인대기** — 인계 중이면 배송은 현장 확인을 기다리고 구매후처리는 고객에게 확인 중으로 표시한다. 같은 신청의 처리 결과를 다시 확인한다.
- **구매후처리 · 인계확인대기 → 고객프론트 · 출고중지확인중안내** — 출고가 중지됐는지 운영자가 확인하고 있음을 고객에게 보여 준다.
- **배송 · 인계상태대조 [인계전중지확정] → 구매후처리 · 출고중지확인** — 배송은 인계 전 수량에 이번 신청의 출고 중지를 기록하고, 중지된 상품과 수량을 회신한다.
- **구매후처리 · 출고중지확인 → 주문 · 취소진행등록** — 구매후처리는 중지가 확인된 수량을 주문에 취소 진행으로 등록한다.
- **주문 · 취소진행등록 → 주문 · 취소수량배정판정** — 주문은 다른 취소·보상에 배정된 수량과 신청 번호를 대조해 이번 신청 몫을 정한다.
- **주문 · 취소수량배정판정 [배정불가] → 구매후처리 · 취소진행등록불가** — 다른 처리에 배정된 수량 등으로 최종 등록할 수 없으면 주문이 사유를 회신한다.
- **구매후처리 · 취소진행등록불가 → 배송 · 출고중지해제요청** — 구매후처리는 이번 신청이 건 중지만 풀도록 배송에 요청한다.
- **주문 · 취소수량배정판정 [신청수량배정됨] → 구매후처리 · 취소진행등록확인** — 주문은 취소 진행으로 기록한 신청 번호·상품·수량과 원거래 참조를 회신한다. 같은 신청의 재확인은 기존 배정을 돌려준다.
- **구매후처리 · 취소진행등록확인 → 결제 · 취소거래종결요청** — 구매후처리는 결제에 기존 결제 시도를 종결하고 원거래의 상태를 확인하도록 요청한다.
- **배송 · 출고중지해제요청 → 구매후처리 · 출고중지해제결과** — 배송은 해당 신청의 중지만 해제한 결과를 돌려준다. 주문의 출고 자격과 다른 중지 사유를 확인해야 다시 인계할 수 있다.
- **구매후처리 · 출고중지해제결과 → 고객프론트 · 취소등록불가안내** — 취소를 등록하지 못한 사유를 고객에게 보여 준다.
- **결제 · 취소거래종결요청 → 결제 · 취소원거래대조** — 결제는 기존 금액으로 새 시도를 열지 못하게 하고 결제사 기록에서 해당 시도의 상태를 확인한다.
- **결제 · 취소원거래대조 [결과미확정] → 구매후처리 · 취소거래확인중** — 승인 여부가 불명확하면 구매후처리는 취소 진행 상태를 유지하고 같은 원거래의 종결 결과를 재확인한다.
- **구매후처리 · 취소거래확인중 → 고객프론트 · 취소거래확인중안내** — 원래 결제 시도의 종결 결과를 확인하는 중임을 표시한다.
- **결제 · 취소원거래대조 [승인금액있음] → 구매후처리 · 취소거래승인확인** — 결제는 실제 승인 거래와 금액을 구매후처리에 회신한다.
- **구매후처리 · 취소거래승인확인 → 고객프론트 · 취소진행접수안내** — 접수한 수량과 신청 번호를 표시한다. 고객은 S07-4의 신청 결과 조회에서 환불 진행과 취소 확정을 확인한다.
- **구매후처리 · 취소거래승인확인 → 결제 · 환불요청** — 구매후처리는 취소 진행으로 배정받은 수량의 금액만 같은 환불 의뢰 번호로 요청한다.
- **결제 · 취소원거래대조 [미승인종결] → 구매후처리 · 취소거래미승인종결** — 결제는 뒤늦은 승인이 가능한 시도까지 확인하고 승인 없이 거래가 종결됐을 때 회신한다.
- **구매후처리 · 취소거래미승인종결 → 고객프론트 · 취소진행접수안내** — 접수한 수량과 신청 번호를 표시한다. 고객은 S07-4의 신청 결과 조회에서 취소 반영 결과를 확인한다.
- **구매후처리 · 취소거래미승인종결 → 주문 · 취소반영요청** — 구매후처리는 돈이 빠져나가지 않은 대상 수량을 주문에 취소 반영해 달라고 요청한다.

배송은 출고 대상을 만들기 전에 중지 요청을 받아도 그 효력을 기록한다. 뒤늦은 주문확정 사건은 중지한 수량을 출고할 수 없다. 기사에게 인계하는 중이면 배송은 운영자의 인계 확인까지 중지 확정을 보류한다. 이미 인계했으면 구매후처리가 반품 방법을 안내한다. 주문의 취소 진행 등록 회신이 끊기면 중지를 유지하고 같은 신청 번호로 주문에 확인한다. 인계 또는 결제가 확인 중이면 같은 신청으로 상태를 다시 확인한다. 결제 전 일부 수량이 취소되고 기존 시도가 미승인으로 종결되면 주문은 남은 상품의 금액으로 새 결제 시도를 열 수 있다. 늦은 승인은 위 환불 경로로 이어지고, 취소 진행 상품의 환불 의뢰는 구매후처리가 담당한다.

### S07-2. 반품·교환 수거 접수

**시작 사건** 상품을 받은 고객이 반품이나 교환을 신청한다. 구매후처리는 주문의 구매 내역과 배송의 인도 내역을 함께 확인한다.

```jobflow
scope: 반품·교환 자격과 교환품 예약 후 수거
Object: 고객프론트, 주문, 구매후처리, 배송, 재고
고객프론트.On반품교환신청 --> 구매후처리.message.반품교환신청
구매후처리.message.반품교환신청 --> 주문.message.구매상품조회
주문.message.구매상품조회 --> 구매후처리.message.구매상품정보
구매후처리.message.구매상품정보 --> 구매후처리.신청수량판정
구매후처리.신청수량판정.본인구매잔여수량없음 --> 고객프론트.message.신청수량확인안내
구매후처리.신청수량판정.본인구매잔여수량있음 --> 배송.message.인도내역조회
배송.message.인도내역조회 --> 구매후처리.message.상품인도내역
구매후처리.message.상품인도내역 --> 구매후처리.회수대상판정
구매후처리.회수대상판정.인도내역미확정 --> 고객프론트.message.인도확인대기안내
구매후처리.회수대상판정.회수대상아님 --> 고객프론트.message.반품교환접수불가안내
구매후처리.회수대상판정.반품접수가능 --> 배송.message.반환상품수거요청
구매후처리.회수대상판정.교환접수가능 --> 재고.message.교환품예약요청
재고.message.교환품예약요청 --> 재고.교환품예약판정
재고.교환품예약판정.수량부족 --> 구매후처리.message.교환품예약불가
구매후처리.message.교환품예약불가 --> 고객프론트.message.교환품품절안내
재고.교환품예약판정.교환수량예약됨 --> 구매후처리.message.교환품예약확인
구매후처리.message.교환품예약확인 --> 배송.message.반환상품수거요청
배송.message.반환상품수거요청 --> 배송.수거접수확인
배송.수거접수확인.접수확인 --> 구매후처리.message.수거접수확인
구매후처리.message.수거접수확인 --> 고객프론트.message.수거예정안내
배송.수거접수확인.접수여부불명 --> 구매후처리.message.수거접수확인중
구매후처리.message.수거접수확인중 --> 고객프론트.message.수거접수대기안내
배송.수거접수확인.수거불가확정 --> 구매후처리.message.수거접수불가
구매후처리.message.수거접수불가 --> 고객프론트.message.수거접수불가안내
구매후처리.message.수거접수불가 --> 구매후처리.수거실패정리
구매후처리.수거실패정리.교환품예약있음 --> 재고.message.교환품예약해제요청
구매후처리.On수거완료 --> 구매후처리.수거상태반영
```

- **고객프론트 · 반품교환신청 → 구매후처리 · 반품교환신청** — 고객이 신청 종류와 대상 상품·수량을 제출한다.
- **구매후처리 · 반품교환신청 → 주문 · 구매상품조회** — 구매후처리는 주문에 대상 주문 상품의 구매 내역을 요청한다.
- **주문 · 구매상품조회 → 구매후처리 · 구매상품정보** — 주문은 구매자와 주문 상품·수량·거래 참조를 회신한다.
- **구매후처리 · 구매상품정보 → 구매후처리 · 신청수량판정** — 구매후처리는 구매자와 이미 신청한 수량을 대조한다.
- **구매후처리 · 신청수량판정 [본인구매잔여수량없음] → 고객프론트 · 신청수량확인안내** — 신청 가능한 구매 수량과 확인할 항목을 표시한다.
- **구매후처리 · 신청수량판정 [본인구매잔여수량있음] → 배송 · 인도내역조회** — 신청할 수량이 남았으면 배송에 해당 상품의 인도 내역을 요청한다.
- **배송 · 인도내역조회 → 구매후처리 · 상품인도내역** — 배송은 고객에게 배송 완료된 수량과 확인 시각을 회신한다.
- **구매후처리 · 상품인도내역 → 구매후처리 · 회수대상판정** — 구매후처리는 인도 내역과 신청 기한을 기준으로 회수 여부를 정한다.
- **구매후처리 · 회수대상판정 [인도내역미확정] → 고객프론트 · 인도확인대기안내** — 인도 사실을 확인 중인 신청의 번호를 표시한다. 구매후처리가 같은 배송 건의 결과를 확인한다.
- **구매후처리 · 회수대상판정 [회수대상아님] → 고객프론트 · 반품교환접수불가안내** — 회수 대상이 아니라고 판단한 사유를 고객에게 보여 준다.
- **구매후처리 · 회수대상판정 [반품접수가능] → 배송 · 반환상품수거요청** — 반품이 가능하면 배송에 반환 상품, 수거지와 도착지를 보낸다.
- **구매후처리 · 회수대상판정 [교환접수가능] → 재고 · 교환품예약요청** — 교환 신청이 가능하면 재고에 원하는 옵션과 수량을 예약한다.
- **재고 · 교환품예약요청 → 재고 · 교환품예약판정** — 재고는 요청한 옵션과 수량을 같은 신청 번호로 확보할 수 있는지 확인한다.
- **재고 · 교환품예약판정 [수량부족] → 구매후처리 · 교환품예약불가** — 수량이 부족하면 구매후처리는 고객에게 교환품을 확보할 수 없다고 안내하고 수거를 시작하지 않는다.
- **구매후처리 · 교환품예약불가 → 고객프론트 · 교환품품절안내** — 요청한 교환품 수량을 확보할 수 없다고 안내한다.
- **재고 · 교환품예약판정 [교환수량예약됨] → 구매후처리 · 교환품예약확인** — 재고는 해당 신청에 확보한 교환품의 예약 번호와 수량을 회신한다.
- **구매후처리 · 교환품예약확인 → 배송 · 반환상품수거요청** — 구매후처리는 교환품 예약이 확인된 신청의 반환 상품을 수거해 달라고 요청한다.
- **배송 · 반환상품수거요청 → 배송 · 수거접수확인** — 배송은 같은 수거 의뢰 번호로 택배사의 접수 여부를 확인한다.
- **배송 · 수거접수확인 [접수확인] → 구매후처리 · 수거접수확인** — 구매후처리는 수거 접수 사실과 포장 방법을 안내하고 물류센터에 해당 신청의 입고 검수를 의뢰한다.
- **구매후처리 · 수거접수확인 → 고객프론트 · 수거예정안내** — 고객에게 수거가 접수된 신청의 번호와 준비할 사항을 보여 준다.
- **배송 · 수거접수확인 [접수여부불명] → 구매후처리 · 수거접수확인중** — 구매후처리는 확인 대기로 두고 배송은 같은 의뢰의 접수 여부를 재확인한다. 이미 잡은 교환품 예약은 유지한다.
- **구매후처리 · 수거접수확인중 → 고객프론트 · 수거접수대기안내** — 신청의 수거 접수 결과를 확인하고 있다고 표시한다.
- **배송 · 수거접수확인 [수거불가확정] → 구매후처리 · 수거접수불가** — 배송은 수거가 최종 무산됐다는 사실을 회신한다.
- **구매후처리 · 수거접수불가 → 고객프론트 · 수거접수불가안내** — 고객에게 수거할 수 없는 사유를 표시한다.
- **구매후처리 · 수거접수불가 → 구매후처리 · 수거실패정리** — 구매후처리는 신청 종류를 확인해 수거 불가를 안내하고, 교환에 배정한 예약이 있으면 돌려준다.
- **구매후처리 · 수거실패정리 [교환품예약있음] → 재고 · 교환품예약해제요청** — 재고는 이번 신청에 배정된 교환품 수량만 해제한다. 같은 신청의 해제를 한 번만 반영한다.
- **구매후처리 · 수거완료 → 구매후처리 · 수거상태반영** — 배송이 택배사의 수거 완료를 확인해 발행한 사건을 받으면 구매후처리가 수거 상태를 갱신한다.

구매후처리는 접수된 신청 번호로 물류센터에 검수를 의뢰한다. 기한이 지났거나 교환품이 부족하면 거절 사유를 고객에게 안내한다. 수거 접수 여부가 불분명하면 같은 건을 재확인하고, 수거가 최종 무산된 교환의 예약은 해제한다. 수거에 들어간 교환품 예약은 검수 결과가 확정될 때까지 유지한다. 고객이 물건을 받았어도 인도 내역이 늦으면 배송 확인 대기로 안내한다. 검수가 수거 완료 통지보다 먼저 도착하면 신청·수거 건을 대조해 확인한 사실을 기록하고, 뒤늦은 수거 통지로 검수나 종결 상태를 되돌리지 않는다.

### S07-3. 검수 결과에 따른 환불과 교환 출고

**시작 사건** 물류센터가 접수한 상품의 검수 결과를 구매후처리에 통지한다.

```jobflow
scope: 검수 승인·거절에 따른 금전 및 재고 처리
Object: 고객프론트, 결제, 구매후처리, 재고, 배송
구매후처리.On입고검수결과 --> 구매후처리.검수후처리판정
구매후처리.검수후처리판정.반품수락 --> 결제.message.환불요청
구매후처리.검수후처리판정.교환거절 --> 재고.message.교환품예약해제요청
구매후처리.검수후처리판정.교환수락 --> 재고.message.교환품예약확정요청
재고.message.교환품예약확정요청 --> 재고.교환예약대조
재고.교환예약대조.교환수량확정 --> 구매후처리.message.교환품확정확인
구매후처리.message.교환품확정확인 --> 배송.message.교환출고요청
배송.message.교환출고요청 --> 구매후처리.message.교환출고접수결과
재고.교환예약대조.예약수량불일치 --> 구매후처리.message.교환품확정불가
구매후처리.message.교환품확정불가 --> 재고.message.교환예약재대조요청
재고.message.교환예약재대조요청 --> 재고.교환예약재대조
재고.교환예약재대조.공급불가확정 --> 구매후처리.message.교환품공급불가
재고.교환예약재대조.예약기록정정됨 --> 재고.교환예약대조
고객프론트.On검수진행조회 --> 구매후처리.message.검수진행조회요청
구매후처리.message.검수진행조회요청 --> 고객프론트.message.검수와후속처리상태
```

- **구매후처리 · 입고검수결과 → 구매후처리 · 검수후처리판정** — 구매후처리는 검수한 상품·수량과 결과를 해당 반품·교환 신청에 대조한다.
- **구매후처리 · 검수후처리판정 [반품수락] → 결제 · 환불요청** — 반품을 수락하면 원거래와 수락한 수량의 결제 금액으로 환불을 의뢰한다.
- **구매후처리 · 검수후처리판정 [교환거절] → 재고 · 교환품예약해제요청** — 교환을 거절하면 재고에 해당 신청의 교환품 예약을 해제하도록 요청한다.
- **구매후처리 · 검수후처리판정 [교환수락] → 재고 · 교환품예약확정요청** — 교환을 수락하면 재고에 기존 예약을 출고 수량으로 확정하도록 요청한다.
- **재고 · 교환품예약확정요청 → 재고 · 교환예약대조** — 재고는 검수를 통과한 수량이 해당 교환 신청의 예약에 배정돼 있는지 확인한다.
- **재고 · 교환예약대조 [교환수량확정] → 구매후처리 · 교환품확정확인** — 재고는 교환품 예약을 해당 신청의 출고 수량으로 전환해 구매후처리에 회신한다.
- **구매후처리 · 교환품확정확인 → 배송 · 교환출고요청** — 구매후처리는 출고 수량이 확정된 교환 신청의 번호·상품·수량·배송지를 보내 출고를 의뢰한다.
- **배송 · 교환출고요청 → 구매후처리 · 교환출고접수결과** — 배송은 교환 출고 건을 생성해 접수 결과를 구매후처리에 회신한다.
- **재고 · 교환예약대조 [예약수량불일치] → 구매후처리 · 교환품확정불가** — 재고는 확정할 수 없는 상품·옵션·수량을 회신한다. 구매후처리는 해당 교환 신청의 출고를 보류하고 고객에게 확인 중으로 표시한다.
- **구매후처리 · 교환품확정불가 → 재고 · 교환예약재대조요청** — 구매후처리는 원래 예약 번호와 검수 수락 수량을 보내 재고에 재대조를 요청한다.
- **재고 · 교환예약재대조요청 → 재고 · 교환예약재대조** — 재고는 해당 신청의 예약 원장, 같은 옵션의 실제 가용 수량과 이미 배정한 수량을 대조한다. 미확정이면 출고를 보류하고 같은 건으로 확인을 계속한다.
- **재고 · 교환예약재대조 [공급불가확정] → 구매후처리 · 교환품공급불가** — 더 이상 공급할 수 없으면 재고는 해당 신청에 남은 예약을 정리하고 사유를 회신한다. 구매후처리는 교환 출고를 중단하고 공급 불가 사유를 신청에 남긴다. 고객은 화면에서 진행 상태를 열 때 사유와 반품 선택 방법을 확인한다.
- **재고 · 교환예약재대조 [예약기록정정됨] → 재고 · 교환예약대조** — 기록을 바로잡았으면 재고가 같은 신청·예약 번호로 수량 확정을 다시 시도한다. 확정되면 같은 교환품확정확인 회신으로 이어진다.
- **고객프론트 · 검수진행조회 → 구매후처리 · 검수진행조회요청** — 고객이 자신의 반품·교환 신청 상태를 다시 연다.
- **구매후처리 · 검수진행조회요청 → 고객프론트 · 검수와후속처리상태** — 구매후처리는 검수 결과와 환불·교환 출고 진행 상태를 화면에 돌려준다. 교환품 공급 불가가 확정됐으면 사유와 반품 선택 방법을 함께 제공한다.

검수가 끝나면 구매후처리가 접수 상태를 갱신하고 고객에게 검수 거절 사유나 환불·교환 진행 상태를 알린다. 같은 검수 결과를 다시 받아도 신청과 검수 건을 대조해 기존 의뢰를 이어간다. 교환 출고 회신이 지연되면 같은 신청 번호로 접수 결과를 재확인한다.

### S07-4. 금융·배송 결과로 신청 마감

**시작 사건** 결제가 취소·반품 환불 의뢰를 접수해 회신한다. 이후 구매후처리가 신청을 마감하는 계기는 결제의 최종 환불 사건 또는 배송의 교환품 배송 완료 사건이다. 주문 실패에 대한 환불과 일반 배송의 사건도 도착할 수 있어 신청·거래·배송 식별자로 대상을 가린다.

```jobflow
scope: 취소·반품·교환의 최종 결과 반영
Object: 고객프론트, 재고, 주문, 구매후처리, 결제, 알림
결제.message.환불요청 --> 결제.환불접수판정
결제.환불접수판정.접수확인 --> 구매후처리.message.환불접수확인
결제.환불접수판정.미접수확정 --> 구매후처리.message.환불미접수
결제.환불접수판정.접수여부불명 --> 구매후처리.message.환불접수확인중
구매후처리.On환불완료 --> 구매후처리.환불신청대조
구매후처리.환불신청대조.취소대금환불됨 --> 주문.message.취소반영요청
주문.message.취소반영요청 --> 재고.message.취소수량복원요청
구매후처리.환불신청대조.반품대금환불됨 --> 주문.message.반품반영요청
주문.message.반품반영요청 --> 구매후처리.message.반품반영결과
재고.message.취소수량복원요청 --> 주문.message.취소재고처리결과
주문.message.취소재고처리결과 --> 구매후처리.message.취소반영결과
구매후처리.On환불실패확인필요 --> 구매후처리.환불조사대상확인
구매후처리.On환불실패확정 --> 구매후처리.환불실패대상확인
구매후처리.On배송완료 --> 구매후처리.교환배송대조
구매후처리.교환배송대조.교환품인도확정 --> 주문.message.교환반영요청
주문.message.교환반영요청 --> 구매후처리.message.교환반영결과
알림.On구매후처리종결 --> 알림.신청결과안내
고객프론트.On신청결과조회 --> 구매후처리.message.신청결과조회요청
구매후처리.message.신청결과조회요청 --> 고객프론트.message.신청처리결과
```

- **결제 · 환불요청 → 결제 · 환불접수판정** — 결제는 원승인 거래에서 기존 환불·접수 금액을 공제해 이번 의뢰 금액을 확인하고 결제사의 접수 결과를 판정한다.
- **결제 · 환불접수판정 [접수확인] → 구매후처리 · 환불접수확인** — 구매후처리는 해당 취소·반품 신청을 환불 진행 중으로 두고 결제의 최종 결과를 기다린다.
- **결제 · 환불접수판정 [미접수확정] → 구매후처리 · 환불미접수** — 환불이 접수되지 않았으면 구매후처리는 미접수 사유를 기록하고 취소·반품 완료 반영을 보류한다. 결제는 [S05-4의 미접수 사유 판정](#s05-4-주문-확정-실패-후-환불-종결)을 적용한다. 정정 가능한 원인을 해결하면 같은 의뢰를 이어가고, 조사가 필요하면 환불조사등록 후 알림에 환불조사안내요청을 보내고 환불실패확인필요를 발행한다.
- **결제 · 환불접수판정 [접수여부불명] → 구매후처리 · 환불접수확인중** — 접수 결과를 모르면 구매후처리는 같은 의뢰 번호의 결과를 확인하고 새 의뢰를 보류한다.
- **구매후처리 · 환불완료 → 구매후처리 · 환불신청대조** — 결제가 환불 완료를 발행하면 구매후처리는 원거래·환불 의뢰 번호·금액을 신청에 대조한다.
- **구매후처리 · 환불신청대조 [취소대금환불됨] → 주문 · 취소반영요청** — 취소한 상품 대금의 환불이 확인되면 구매후처리가 주문에 취소 반영을 요청한다.
- **주문 · 취소반영요청 → 재고 · 취소수량복원요청** — 주문은 미승인 취소 또는 환불된 취소 수량에 대해 재고에 기존 예약 해제나 출고 전 배정 수량 복원을 요청한다.
- **구매후처리 · 환불신청대조 [반품대금환불됨] → 주문 · 반품반영요청** — 반품 대금이 환불됐으면 구매후처리는 주문에 반품 수량을 반영하도록 요청한다.
- **주문 · 반품반영요청 → 구매후처리 · 반품반영결과** — 주문이 반품 반영 결과를 회신하면 구매후처리는 해당 반품을 마감한다.
- **재고 · 취소수량복원요청 → 주문 · 취소재고처리결과** — 재고는 해당 수량의 예약을 해제하거나 출고 전 배정을 복원한 결과를 주문에 돌려준다. 이미 반영한 요청에는 기존 결과를 돌려준다.
- **주문 · 취소재고처리결과 → 구매후처리 · 취소반영결과** — 주문은 취소 수량과 재고 처리 결과를 회신한다. 구매후처리는 반영이 확인된 건만 마감한다.
- **구매후처리 · 환불실패확인필요 → 구매후처리 · 환불조사대상확인** — 결제의 조사 필요 사건이 자기 취소·반품 의뢰와 일치하면 확인 대기로 둔다. 주문 이행 실패 보상은 주문 서비스가 처리한다.
- **구매후처리 · 환불실패확정 → 구매후처리 · 환불실패대상확인** — 구매후처리는 최신 결제 결과가 자기 신청의 환불과 일치할 때만 실패 사유를 기록하고 신청을 종결해 구매후처리종결을 발행한다.
- **구매후처리 · 배송완료 → 구매후처리 · 교환배송대조** — 배송 완료 사건을 받은 구매후처리는 배송 번호와 목적을 대조한다.
- **구매후처리 · 교환배송대조 [교환품인도확정] → 주문 · 교환반영요청** — 교환품 인도가 확인됐으면 구매후처리가 주문에 교환 수량과 인도 완료를 반영하도록 요청한다.
- **주문 · 교환반영요청 → 구매후처리 · 교환반영결과** — 주문이 교환 반영 결과를 회신하면 구매후처리는 해당 교환을 마감한다.
- **알림 · 구매후처리종결 → 알림 · 신청결과안내** — 구매후처리가 신청 상태를 확정해 발행한 종결 사건을 알림이 받아 고객에게 결과를 안내한다.
- **고객프론트 · 신청결과조회 → 구매후처리 · 신청결과조회요청** — 고객이 자신의 취소·반품·교환 신청 결과를 조회한다.
- **구매후처리 · 신청결과조회요청 → 고객프론트 · 신청처리결과** — 구매후처리는 신청의 진행 상태 또는 확정 결과와 후속 안내를 돌려준다.

환불 실패는 결제가 운영자와 원거래의 실제 처리 내역을 대조한다. 결제의 정정 완료나 최종 실패가 확정될 때까지 같은 신청의 추가 환불을 보류한다. 실패로 마감하면 운영자가 고객에게 후속 정산 방법을 안내하며, 환불이 필요한 주문 상품의 취소 완료는 보류한다. 결제는 동일 환불 의뢰에 상태 변경 순번을 부여하고, 구매후처리와 주문은 마지막으로 반영한 순번보다 오래된 조사 요청으로 종결된 건을 다시 열지 않는다. 반품 상품의 판매 가능 수량은 물류센터의 실물 상태 판정 후 별도로 결정한다.

### S07-5. 구매 리뷰 작성 자격과 등록

**시작 사건** 회원이 주문 상품의 리뷰 작성 화면을 연다. 리뷰 서비스는 자격 조회와 등록 요청마다 로그인한 회원인지 먼저 확인한다. 비회원에게는 이 단계에서 로그인을 안내한다. [매크로 M07-4](macro.md#m07-4-구매-리뷰-작성)

```jobflow
scope: 회원의 구매 확인과 상품 리뷰 등록
Object: 고객프론트, 리뷰, 주문
고객프론트.On리뷰작성화면열기 --> 리뷰.message.리뷰작성자격조회
리뷰.message.리뷰작성자격조회 --> 리뷰.조회회원확인
리뷰.조회회원확인.로그인필요 --> 고객프론트.message.리뷰조회로그인안내
리뷰.조회회원확인.회원확인됨 --> 주문.message.리뷰구매내역조회
주문.message.리뷰구매내역조회 --> 리뷰.message.작성자격용구매내역
리뷰.message.작성자격용구매내역 --> 리뷰.작성자격판정
리뷰.작성자격판정.작성가능 --> 고객프론트.message.리뷰작성폼열기
리뷰.작성자격판정.대상구매없음 --> 고객프론트.message.리뷰작성불가안내
리뷰.작성자격판정.이미작성함 --> 고객프론트.message.기존리뷰안내
고객프론트.On리뷰제출 --> 리뷰.message.리뷰등록요청
리뷰.message.리뷰등록요청 --> 리뷰.제출요건판정
리뷰.제출요건판정.로그인필요 --> 고객프론트.message.리뷰제출로그인안내
리뷰.제출요건판정.입력보완필요 --> 고객프론트.message.리뷰입력보완안내
리뷰.제출요건판정.회원과입력확인됨 --> 주문.message.제출시구매확인요청
주문.message.제출시구매확인요청 --> 리뷰.message.제출시구매내역
리뷰.message.제출시구매내역 --> 리뷰.구매리뷰등록판정
리뷰.구매리뷰등록판정.구매자격없음 --> 고객프론트.message.리뷰등록불가안내
리뷰.구매리뷰등록판정.이미등록됨 --> 고객프론트.message.기존리뷰등록결과
리뷰.구매리뷰등록판정.등록가능 --> 리뷰.리뷰등록
리뷰.리뷰등록 --> 고객프론트.message.리뷰등록완료
```

- **고객프론트 · 리뷰작성화면열기 → 리뷰 · 리뷰작성자격조회** — 고객이 선택한 주문 상품의 리뷰 작성 자격을 조회한다.
- **리뷰 · 리뷰작성자격조회 → 리뷰 · 조회회원확인** — 리뷰는 화면에서 넘어온 요청의 회원을 확인한다. 비회원이면 로그인을 안내한다.
- **리뷰 · 조회회원확인 [로그인필요] → 고객프론트 · 리뷰조회로그인안내** — 리뷰 작성 자격을 조회할 수 있도록 고객에게 로그인을 안내한다.
- **리뷰 · 조회회원확인 [회원확인됨] → 주문 · 리뷰구매내역조회** — 회원을 확인하면 리뷰는 주문에 해당 회원과 주문 상품의 구매 내역을 묻는다.
- **주문 · 리뷰구매내역조회 → 리뷰 · 작성자격용구매내역** — 주문은 요청한 회원과 주문 상품의 구매 상태를 회신한다.
- **리뷰 · 작성자격용구매내역 → 리뷰 · 작성자격판정** — 리뷰는 구매 상태와 자신의 등록 이력을 대조한다. 대상 구매가 있고 아직 작성하지 않았으면 작성 가능으로, 그 밖에는 구매 자격이 없거나 이미 작성한 것으로 안내한다.
- **리뷰 · 작성자격판정 [작성가능] → 고객프론트 · 리뷰작성폼열기** — 작성 가능한 주문 상품의 리뷰 입력 폼을 연다.
- **리뷰 · 작성자격판정 [대상구매없음] → 고객프론트 · 리뷰작성불가안내** — 해당 회원의 리뷰 작성 대상 구매가 없다고 안내한다.
- **리뷰 · 작성자격판정 [이미작성함] → 고객프론트 · 기존리뷰안내** — 해당 주문 상품에 이미 작성한 리뷰가 있다고 안내한다.
- **고객프론트 · 리뷰제출 → 리뷰 · 리뷰등록요청** — 고객이 작성한 평점과 본문을 제출한다.
- **리뷰 · 리뷰등록요청 → 리뷰 · 제출요건판정** — 고객이 작성한 평점과 본문을 제출하면 리뷰는 회원과 필수 입력을 다시 확인한다. 세션이 끝났으면 로그인, 입력이 부족하면 수정을 안내한다.
- **리뷰 · 제출요건판정 [로그인필요] → 고객프론트 · 리뷰제출로그인안내** — 리뷰 제출을 계속하기 위해 고객에게 로그인을 안내한다.
- **리뷰 · 제출요건판정 [입력보완필요] → 고객프론트 · 리뷰입력보완안내** — 평점이나 본문 등 보완할 입력을 표시한다.
- **리뷰 · 제출요건판정 [회원과입력확인됨] → 주문 · 제출시구매확인요청** — 리뷰는 회원과 입력 요건을 충족한 제출에 대해 주문에 현재 구매 상태를 요청한다.
- **주문 · 제출시구매확인요청 → 리뷰 · 제출시구매내역** — 주문은 해당 회원의 주문 상품이 현재 리뷰 대상인지 확인할 구매 정보를 회신한다.
- **리뷰 · 제출시구매내역 → 리뷰 · 구매리뷰등록판정** — 리뷰는 제출 시점의 구매 자격과 기존 리뷰를 확인한다. 자격이 없으면 사유를, 이미 등록된 제출이면 기존 결과를 돌려준다.
- **리뷰 · 구매리뷰등록판정 [구매자격없음] → 고객프론트 · 리뷰등록불가안내** — 제출 시점에 구매 자격을 확인하지 못한 사유를 표시한다.
- **리뷰 · 구매리뷰등록판정 [이미등록됨] → 고객프론트 · 기존리뷰등록결과** — 같은 주문 상품에 이미 등록된 리뷰 결과를 보여 준다.
- **리뷰 · 구매리뷰등록판정 [등록가능] → 리뷰 · 리뷰등록** — 리뷰는 자격이 확인된 회원·주문 상품에 한 건만 등록하고 고객에게 결과를 알린다.
- **리뷰 · 리뷰등록 → 고객프론트 · 리뷰등록완료** — 등록된 리뷰를 고객에게 보여 준다.
