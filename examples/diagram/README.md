# 다이어그램 예제 인덱스

Navigation 문서를 작성·수정할 때는 [작성 샘플](navigation/document-template.md)과 작은 완성 예제의 해당 시나리오를 먼저 확인한다. 다른 다이어그램의 구성이나 추가 시나리오 예제는 필요할 때만 사용한다. 예제 본문을 처음부터 모두 읽거나 스킬 본문에 포함하지 않는다. 문법과 의미는 각 전용 가이드가 기준이며, 예제의 화면·API·정책·규모는 현재 작업의 요구사항이 아니다.

## 종류별 진입점

| 종류 | 제공하는 예제 | 문법 기준 |
| --- | --- | --- |
| `navigation` | [작성 샘플과 시나리오 선택 목록](navigation/README.md) | [Navigation 가이드](../../guides/navigation-diagram-guide.md) |
| `jobflow` (Job Flow) | 아직 별도 예제 없음. 가이드 안의 필요한 문법 예시만 참고한다. | [Job Flow 가이드](../../guides/job-flow-diagram-guide.md) |
| `state` | 아직 별도 예제 없음 | [State 가이드](../../guides/state-diagram-guide.md) |
| `layout` | 아직 별도 예제 없음 | [Layout 가이드](../../guides/screen-layout-guide.md) |

## 필요한 만큼 읽기

1. 현재 작성할 다이어그램의 종류와 참고하려는 문제를 정하고, 위 표에서 해당 종류만 선택한다. Navigation은 작성 샘플을 먼저 확인하며, 다른 종류는 예제 없이 가이드만으로 충분하면 본문을 읽지 않는다.
2. 종류별 목록에서 필요한 파일·시나리오 절을 고른다. 링크의 앵커는 절을 찾는 식별자이며 파일 전체를 읽으라는 뜻이 아니다. 제목을 검색해 선택한 절의 시작부터 다음 같은 수준 또는 상위 제목 직전까지 읽고, 코드 펜스와 그 해설을 함께 확인한다. 하위 시나리오로 나뉘면 필요한 하위 절만 선택한다.
3. 선택한 절의 전제·화면 이름·API 결과가 불명확할 때만 목록에 안내된 범위·라우트 맵·공통 규칙·계약 표의 관련 부분으로 넓힌다. 연결된 모든 시나리오나 API 계약을 한꺼번에 읽지 않는다.
4. 현재 프로젝트의 확인한 계약이나 설계 요구에 맞춰 구조를 적용한다. 예제의 이름만 바꿔 전체 문서를 옮기거나 가정·도메인 정책을 강제 규칙으로 승격하지 않는다. 문법이 가이드와 다르면 가이드 기준으로 작성하고 차이를 알린다.
5. 예제에 적힌 과거 검증 기록을 현재 산출물의 검증으로 보고하지 않는다. 렌더러 없이 확인했으면 정적 검토와 렌더링 미검증을 구분한다.

문서 경로는 이 파일 기준 상대 경로다. 설치 후에도 같은 구조를 사용하며 산출물에 작성 컴퓨터의 절대 경로나 설치 사본 경로를 남기지 않는다. tools.camp 링크 생성 여부 확인과 전달은 [편집 링크 전달 기준](../../guides/diagram-editor-link-guide.md)을 따른다.

## 예제 추가·변경

종류별 폴더에 예제를 두고 이 표와 종류별 선택 목록을 함께 갱신한다. 긴 예제는 시나리오별 제목을 두고, 선택 목록에는 선택 기준과 해당 절의 링크를 적는다. 예제 원문은 한 곳에서 관리하며 인덱스나 스킬에 복제하지 않는다. 아직 없는 종류의 예제 경로를 유효한 링크로 안내하지 않는다.
