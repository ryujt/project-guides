# 다이어그램 예제 인덱스

[예제 선택 기준](../)에 따라 현재 작업과 조건이 가까운 절을 고른다.

## Job Flow 매크로뷰

[쇼핑몰 매크로뷰](job-flow/macro.md)는 쇼핑몰을 한 객체로 두고 고객·운영자·외부 사업자가 주고받는 정보와 실물을 추적한다. 처음 작성할 때는 **배송 준비부터 고객 수령까지**를 보면 시작 사건, 메시지를 받은 뒤의 판단, 최종 수신자가 한 흐름에 어떻게 나타나는지 확인할 수 있다.

| 살펴볼 내용 | 예제에서 읽을 절 |
| --- | --- |
| 각 역할이 누구에게서 무엇을 받아 다음 일을 하는가 | [M00. 객체 사이의 업무 의존관계](job-flow/macro.md#m00-객체-사이의-업무-의존관계) |
| 수동 배송 의뢰, 운송장 등록 판단, 실물 인계와 완료 통지는 어떻게 이어지는가 | [M06-1. 운영자의 배송 준비부터 고객 수령까지](job-flow/macro.md#m06-1-운영자의-배송-준비부터-고객-수령까지) |
| 비회원은 누구에게서 인증 코드를 받고 어떤 주문을 열람하는가 | [M02. 비회원 주문 조회](job-flow/macro.md#m02-비회원이-인증-문자를-받아-주문-한-건-조회하기) |
| 고객의 복귀와 결제사의 독립 통지는 어떻게 같은 거래의 확인으로 이어지는가 | [M05-2. 거래 확인과 결제 취소·환불](job-flow/macro.md#m05-2-거래-확인과-결제-취소환불) |
| 검수 결과에 따라 누가 환불 또는 교환품 출고를 맡는가 | [M07-3. 검수 결과에 따른 환불·교환](job-flow/macro.md#m07-3-검수-결과에-따른-환불교환) |

## Job Flow 서비스뷰

[쇼핑몰 MSA 서비스뷰](job-flow/system.md)는 같은 업무에서 주문·결제·재고·배송 등 서비스가 각각 소유하는 상태와 공개 계약을 그린다. 매크로뷰에서 쇼핑몰 한 객체가 하던 일을 어떤 서비스가 맡는지 비교할 수 있다.

| 살펴볼 내용 | 예제에서 읽을 절 |
| --- | --- |
| 누가 주문 연락처를 대조하고, 코드 검증 결과에 따라 어느 주문의 열람을 허용하는가 | [S02. 비회원 주문 조회 인증](job-flow/system.md#s02-비회원이-주문-한-건을-열람할-권한-얻기) |
| 결제창 발급 결과가 불명일 때 무엇을 다시 조회하고, 결제창에서 돌아온 뒤에는 무엇을 확인하는가 | [S05-2. 결제창 발급과 승인 확인](job-flow/system.md#s05-2-결제창-발급과-승인-확인) |
| 결제 승인 뒤 어떤 조건을 확인해야 주문을 확정하고 출고할 수 있는가 | [S05-3. 승인된 결제의 주문 확정](job-flow/system.md#s05-3-승인된-결제의-주문-확정) |
| 발송 등록과 택배사 완료 통지를 어느 서비스가 받고, 누가 고객에게 알리는가 | [S06-2. 발송 등록과 배송 완료에 따른 고객 안내](job-flow/system.md#s06-2-발송-등록과-배송-완료에-따른-고객-안내) |
| 취소 신청과 상품 인계가 겹치면 누가 출고와 환불을 결정하는가 | [S07-1. 출고 중지와 취소 거래 확인](job-flow/system.md#s07-1-출고-중지와-취소-거래-확인) |
| 반품 검수 후 환불과 교환품 출고는 어떤 계약으로 갈리는가 | [S07-3. 검수 결과에 따른 환불과 교환 출고](job-flow/system.md#s07-3-검수-결과에-따른-환불과-교환-출고) |

## Job Flow 모듈뷰와 상세뷰

[구현 코드로 읽는 Job Flow](job-flow/implementation.md)는 실행할 수 있는 JavaScript와 그 코드의 객체·메서드·이벤트를 같은 이름으로 보여 준다. 영상 재생기에서 모듈뷰의 메서드 하나를 상세뷰로 펼치는 과정을 볼 수 있다.

| 살펴볼 내용 | 예제에서 읽을 절 |
| --- | --- |
| 영상 데이터가 도착하는 시점과 화면이 프레임을 요청하는 시점은 어떻게 연결되는가 | [재생기의 협력](job-flow/implementation.md#모듈뷰--재생기의-협력) · [영상 패킷을 프레임 큐에 넣기](job-flow/implementation.md#상세뷰--한-영상-패킷을-프레임-큐에-넣기) |
| 같은 주문의 재시도가 들어오면 어느 분기에서 재고 차감을 건너뛰는가 | [주문별 예약 결과와 재고 차감](job-flow/implementation.md#모듈뷰--주문별-예약-결과와-재고-차감) |
| 요청 콜백에서 값을 돌려받은 뒤 어느 객체가 작업을 이어가는가 | [상품 라벨의 표시 이름 조회](job-flow/implementation.md#상세뷰--표시-이름을-요청하는-동기-콜백) |

## 필요한 만큼 읽기

현재 설계와 관련된 절의 시작 사건, `jobflow` 코드와 화살표별 설명을 함께 읽는다. 사례의 참여자와 절차는 해당 업무의 가정이다. 실제 대상의 관찰 근거나 설계 결정에 맞게 적용한다. 관찰 수준별 기준은 Method-R의 [매크로 시나리오](../../guides/method-R.md#33-매크로-시나리오-작성과-검토), [서비스 간 협력](../../guides/method-R.md#44-서비스-간-협력-그림-수신-처리와-결과-분기), [모듈 설계](../../guides/method-R.md#5-모듈-설계-공개-계약-안을-확대하기), [상세 설계](../../guides/method-R.md#6-상세-설계-불확실한-부분만-더-확대하기)에서 확인한다. 표기는 [Job Flow 가이드](../../guides/job-flow-diagram-guide.md)를 따른다.

## 예제 추가·변경

이 가이드 묶음의 `examples/`에서는 설치 옵션과 관계없이 SmartMD 원문을 코드 펜스에 보관한다. 생성하는 설계 문서에는 [설치된 출력 형식](../../guides/diagram-output-guide.md)을 적용한다. 새 예제를 추가하면 이 목록에 참고할 문제와 절의 상대 링크를 적고, 예제를 옮기거나 삭제하면 해당 링크도 갱신한다.
