# 고객 구매 흐름의 매크로 AS-IS

고객 UI·도메인·DB·내부 스케줄러·모듈을 모두 `쇼핑몰` 경계 안에 둔다. 고객·결제사·인증 제공자·메일 수신자는 외부 역할이다. 메시지는 업무 계약 이름이며 실제 endpoint·필드는 [화면 이동](../../navigation.md)과 구현 링크를 따른다. 제공자의 실제 화면·통신은 실행하지 않았다.

## 상품 탐색과 장바구니

```jobflow
scope: 상품 탐색과 구매 준비
Object: 고객, 쇼핑몰
고객.On상품탐색 --> 쇼핑몰.message.상품조회
쇼핑몰.message.상품조회 --> 쇼핑몰.상품노출판정
쇼핑몰.상품노출판정.조회가능 --> 고객.message.상품목록또는상세
쇼핑몰.상품노출판정.조회불가 --> 고객.message.조회불가안내
고객.On담기 --> 쇼핑몰.message.상품담기
쇼핑몰.message.상품담기 --> 쇼핑몰.담기결과판정
쇼핑몰.담기결과판정.필수선택필요 --> 고객.message.상품상세이동
쇼핑몰.담기결과판정.오류있음 --> 고객.message.담기경고
쇼핑몰.담기결과판정.담기허용 --> 고객.message.장바구니갱신
```

- 게시·매장·ACL·상품 상태로 노출을 판단한다.
- 옵션·수량·재고 검증에 따라 담기 경고 또는 상세 입력으로 돌아간다.
- 갱신 결과는 설정에 따라 현재 화면의 패널 또는 전체 장바구니로 보인다.

근거: [N10–N26](../../navigation.md#n10), `CatalogController`, `ProductController`, `ShoppingCartController`.

## 회원가입과 로그인

```jobflow
scope: 고객 계정과 복귀
Object: 고객, 쇼핑몰, 인증제공자
고객.On일반로그인 --> 쇼핑몰.message.로그인신청
쇼핑몰.message.로그인신청 --> 쇼핑몰.계정판정
쇼핑몰.계정판정.로그인허용 --> 고객.message.로그인복귀
쇼핑몰.계정판정.로그인불가 --> 고객.message.로그인오류
고객.On외부로그인 --> 쇼핑몰.message.외부로그인신청
쇼핑몰.message.외부로그인신청 --> 인증제공자.message.인증요청
인증제공자.message.인증요청 --> 쇼핑몰.message.인증응답
쇼핑몰.message.인증응답 --> 쇼핑몰.외부계정판정
쇼핑몰.외부계정판정.기존계정허용 --> 고객.message.로그인복귀
쇼핑몰.외부계정판정.신규등록처리 --> 고객.message.등록정책별결과
쇼핑몰.외부계정판정.인증불가 --> 고객.message.로그인오류
```

- 일반 로그인 성공 시 게스트 장바구니를 회원 계정으로 이관한다.
- return URL은 로컬 URL인지 확인한다. checkout에서 로그인할 때의 복귀 대상은 장바구니다.
- 신규 외부 고객은 가입 중지·표준·메일 확인·관리자 승인 정책을 따른다.
- 외부 제공자의 내부 판단·SDK 수행 순서는 열지 않는다.

근거: [N03–N09](../../navigation.md#n03), `IdentityController`.

## 주문과 외부 결제

```jobflow
scope: 주문 확정과 제공자 확인
Object: 고객, 쇼핑몰, 결제사
고객.On구매확정 --> 쇼핑몰.message.주문신청
쇼핑몰.message.주문신청 --> 쇼핑몰.구매조건판정
쇼핑몰.구매조건판정.입력보완필요 --> 고객.message.주문입력안내
쇼핑몰.구매조건판정.외부확인필요 --> 결제사.message.결제확인요청
쇼핑몰.구매조건판정.직접주문처리가능 --> 고객.message.주문처리결과
결제사.message.결제확인요청 --> 쇼핑몰.message.결제복귀
쇼핑몰.message.결제복귀 --> 쇼핑몰.결제복귀판정
쇼핑몰.결제복귀판정.주문기록확인 --> 고객.message.주문처리결과
쇼핑몰.결제복귀판정.결제선택보완 --> 고객.message.결제선택안내
결제사.On결제통지 --> 쇼핑몰.message.결제제공자통지
```

- 주소·배송·결제·동의 검사는 적용 단계와 설정에 따라 수행한다.
- 브라우저 복귀와 provider webhook은 서로 다른 입력이다. 통지가 먼저 주문 복구를 끝냈으면 복귀 시 기존 주문을 확인할 수 있다.
- 통지 후 동작·고객 알림은 provider별 계약이다. 위 통지 수신 노드는 그 존재를 나타내며 모든 모듈에 같은 처리 순서·보장을 가정하지 않는다.
- 일반 주문 처리 결과에는 결제 대기 상태도 가능하다. 생성 완료를 결제·배송 완료로 해석하지 않는다.
- 외부 timeout·취소·중복 통지의 실제 결과와 재처리는 provider 계정·로그가 없어 미확인이다.

근거: [N27–N34](../../navigation.md#n27), `CheckoutWorkflow`, `OrderProcessingService`, 선택 결제 모듈.

## 주문 후 조회·반품·다운로드

```jobflow
scope: 주문 후 고객 과업
Object: 고객, 쇼핑몰
고객.On내주문조회 --> 쇼핑몰.message.주문조회
쇼핑몰.message.주문조회 --> 쇼핑몰.주문접근판정
쇼핑몰.주문접근판정.조회허용 --> 고객.message.주문배송내역
쇼핑몰.주문접근판정.조회불가 --> 고객.message.접근오류
고객.On반품신청 --> 쇼핑몰.message.반품신청
쇼핑몰.message.반품신청 --> 쇼핑몰.반품조건판정
쇼핑몰.반품조건판정.접수가능 --> 고객.message.주문상세복귀
쇼핑몰.반품조건판정.입력보완필요 --> 고객.message.반품입력오류
고객.On구매파일요청 --> 쇼핑몰.message.다운로드요청
쇼핑몰.message.다운로드요청 --> 쇼핑몰.다운로드조건판정
쇼핑몰.다운로드조건판정.동의필요 --> 고객.message.이용약관
쇼핑몰.다운로드조건판정.제공가능 --> 고객.message.파일또는파일주소
쇼핑몰.다운로드조건판정.제공불가 --> 고객.message.다운로드오류
```

- 일반 고객의 주문 소유권과 관리 권한의 예외를 구분한다.
- 반품 접수는 운영자의 승인·환불 완료를 뜻하지 않는다.
- 다운로드는 주문 항목 GUID·버전·권한·주문 상태·약관을 확인한다. 고객 일치 검사는 설정별 조건이다.

근거: [N38–N46](../../navigation.md#n38), `OrderController`, `ReturnCaseController`, `DownloadController`.

## 메일을 통한 확인·복구

```jobflow
scope: 확인 메일과 링크 재진입
Object: 고객, 쇼핑몰, 메일서버
고객.On복구메일신청 --> 쇼핑몰.message.복구메일신청
쇼핑몰.message.복구메일신청 --> 쇼핑몰.복구대상판정
쇼핑몰.복구대상판정.활성고객있음 --> 메일서버.message.복구메일발송
쇼핑몰.message.복구메일신청 --> 고객.message.복구신청안내
메일서버.message.복구메일발송 --> 고객.message.복구링크메일
고객.On복구링크열기 --> 쇼핑몰.message.비밀번호재설정접속
쇼핑몰.message.비밀번호재설정접속 --> 고객.message.재설정화면
```

- 실제 전송에는 내부 템플릿·큐·발송 작업이 관여하며 이 매크로뷰에서는 열지 않는다.
- 복구 안내가 보였다는 사실과 메일 배달 성공은 다르다. 활성 고객이 없어도 동일한 안내 문구를 사용할 수 있다.
- 계정 활성화·뉴스레터 활성화도 링크 재진입이지만 token과 완료 결과는 각각 별도 시나리오를 따른다.

근거: [N07](../../navigation.md#n07), [N48](../../navigation.md#n48), 메시지·이메일 큐 서비스.

## 검증 범위

업무 경계·판정·응답을 코드와 정적으로 대조했다. Job Flow 파서·렌더러로 배치·겹침을 확인하지 않았다. 외부 요청을 실행하거나 결제·메일을 발생시키지 않았다. 본문의 수신 메시지 이름은 설명용 계약 이름이며 실제 DTO·endpoint와 동일하다고 주장하지 않는다.
